## 三、顺带修复 — IsActive 列缺失 BUG

### 3.1 问题发现

POST `/api/basics/equipment-readings` 返回 `DB_ERROR`：

> 「列名 'IsActive' 无效，表 'WaterMeterDB.dbo.EquipmentReading'；列不允许有 Null 值。INSERT 失败。」

### 3.2 根因（v2.13.161 残留 BUG）

v2.13.161 修复时把 `BaseEntity.UpdatedAt` 从可空 `DateTime?` 改为非空 `DateTime`，并保持 `IsActive` 为非空 `bool`。

EF Core 默认行为：所有继承 BaseEntity 的实体在 INSERT 时都会包含 `IsActive` 列。但 DB schema 中**8 张表无 IsActive 列**：

| 实体 | 继承 BaseEntity | DB IsActive 列 | 是否需 Ignore |
|---|---|---|---|
| EquipmentReading | ✓ | ✗ | **✓** |
| SysUserRole | ✗ | ✗ | （不需，模型本身无此字段）|
| SysRolePermission | ✗ | ✗ | （不需）|
| MeterImage | ✗ | ✗ | （不需）|
| SysConfig | ✗ | ✗ | （不需）|
| SysUserFilterCache | ✗ | ✗ | （不需）|
| SysOpLog | ✗ | ✗ | （不需）|
| SysParameter | ✗ | ✗ | （不需）|

**最终只有 EquipmentReading 需要 Ignore**（其它 7 个不继承 BaseEntity 也就没有 IsActive 字段）。

### 3.3 修复

```csharp
// v2.13.162：BaseEntity.IsActive 对 EquipmentReading 表必须 Ignore
modelBuilder.Entity<EquipmentReading>().Ignore(e => e.IsActive);
```

## 四、基础设施配套：Razor 运行时编译

v2.13.161 之后，**Razor 视图不再被打包到 `DormManage.Admin.dll`**（默认 Release 模式 + Obfuscar 混淆），导致后续修改 `.cshtml` 看不到效果。

**修复**：

1. **NuGet 包**：`Microsoft.AspNetCore.Mvc.Razor.RuntimeCompilation 8.0.10`
2. **Program.cs**：`builder.Services.AddRazorPages(...)` 前加注释标注运行时编译启用
3. **csproj `<ItemGroup>`**：
   ```xml
   <None Include="Pages\**\*.cshtml" CopyToOutputDirectory="PreserveNewest" />
   ```
   → 让 `dotnet publish` 把 `.cshtml` 包含到 publish 输出，运行时编译立即生效

**未来开发者修改 `.cshtml` 后只需重发布 + 重启服务，无需重新编译 DLL。**

## 七、永久教训

| # | 教训 |
|---|------|
| 1 | **「基类属性 = DB 列假设」是跨表一致性的隐性约束**。BaseEntity 加 IsActive 时必须立刻审计所有子实体的表结构。本次 v2.13.161 修改未同步审计，导致 6 张表立即崩 INSERT。 |
| 2 | **「EF 字段映射 ≠ 模型存在」**。`Ignore(e => e.IsActive)` 是 EF 用来"告诉 ORM 这个属性不映射到列"的开关。当模型有字段但表无列，必须 Ignore；反之若模型无字段（不继承），EF 自动跳过。 |
| 3 | **「Razor 视图发布需 `<None>` 显式声明」**。SDK Web 默认不复制源代码 .cshtml 到 publish。运行时编译启用时，cshtml 必须出现在 publish 输出中——这是 v2.13.158 之后我多次以为"代码改了 UI 不变"的根因。 |
| 4 | **「终端乱码 ≠ 字符串未渲染」**。本次验证时 GBK 终端把 `⚡电表` 显示为乱码，让我误以为 badge 未生效——但实际渲染 HTML 完整。**真机验证必须看原始字节而非终端转码**。 |
| 5 | **「用户连续诉求应合并处理」**。同一 tab 连续 3 个诉求（badge 紧凑、备注 tooltip、刷新按钮）属于"同一 UI 区段优化"，应在一个 commit 中统一实现，避免多次重复发布。 |
| 6 | **「Inspectors 必须验证」**。简单用 `inspect -E.IsActive` 检查表 schema 才能避免"应该存在但不存在"的列遗漏。init_schema.sql 是基线，但实际 DB 可能与 schema 文件漂移（v2.13.161 时已发现 Id 列漂移）。 |
