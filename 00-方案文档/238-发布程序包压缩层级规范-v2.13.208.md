**v2.13.208**（2026-07-28）

## 一、Context（背景）

### 1.1 用户原话

> "关于发布程序包的打包压缩文件规范要求：程序包内，只建组件名称的文件夹为第一层，不要将组件多层压缩文件"

### 1.2 业务诉求

发布归档压缩包在生产部署时被运维人员解压后，必须**直接复制粘贴**到目标服务器即可使用。任何额外的目录嵌套层级（`DormManage-v2.13.x/Admin/...` 或 `Admin.zip/Admin/...`）都会：
- 浪费运维识别时间（必须进入多层目录才能找到可执行文件）
- 增加路径过长导致 260 字符 Windows MAX_PATH 限制触发的风险
- 在批处理脚本中出现路径错误
- 破坏与 `Directory.Build.props` 中 Obfuscar / PublishReadyToRun 工具链的预期路径匹配

## 二、规范强制要求

### 2.1 压缩包**内部**必须是扁平层级

**正确结构**（✅）：
```
DormManage-v{版本}_{YYYYMMDD_HHMMSS}.zip
├── Admin/                  ← 组件名文件夹（第一层）
│   ├── DormManage.Admin.exe
│   ├── DormManage.Admin.dll
│   ├── appsettings.json
│   └── wwwroot/...
├── Api/                    ← 组件名文件夹（第一层）
│   ├── DormManage.Api.exe
│   ├── DormManage.Api.dll
│   └── ...
└── TrayApp/                ← 组件名文件夹（第一层）
    ├── DormManage.TrayApp.exe
    ├── DormManage.TrayApp.dll
    └── ...
```

**禁止结构**（❌）：

| ❌ 反模式 | 描述 | 风险 |
|-----------|------|------|
| `DormManage-v{版本}/Admin/...` | 用版本号作为根目录嵌套 | 部署多版本时需手动进入子目录 |
| `publish/Admin/...` 或 `output/Admin/...` | 通用 publish 目录名 | 含义不清，运维误操作风险 |
| `Admin/admin_files/...` | 组件下再嵌套子目录 | 路径膨胀，MAX_PATH 限制 |
| `Admin.7z` 或 `Admin.zip` | 组件内嵌压缩文件 | 必须二次解压，无法直接部署 |
| `bin/Debug/...` | 调试输出目录混淆 | 不应作为发布源 |
| `obj/...` | MSBuild 中间产物 | 严禁发布 |

### 2.2 压缩包本身**外部**命名规范

```
DormManage-v{版本}_{YYYYMMDD_HHMMSS}.zip
```

| 段 | 格式 | 示例 |
|----|------|------|
| 项目名 | `DormManage` | `DormManage` |
| 版本号 | `v{MAJOR}.{MINOR}.{BUILD}` 严格递增 | `v2.13.208` |
| 时间戳 | `YYYYMMDD_HHMMSS` | `20260728_150512` |
| 扩展名 | `.zip` | `.zip` |

## 三、操作规范（PowerShell / Bash 兼容）

### 3.1 推荐打包命令

**Bash / Git Bash（推荐用于脚本自动化）**：

```bash
# -C release/latest . 表示进入 release/latest 目录打包其下所有内容（不包含外层目录）
tar -czf release/_archive/DormManage-v2.13.208_20260728_150512.zip \
    -C release/latest \
    .
```

### 3.2 压缩包内部的内容结构验证脚本

发布前必须运行此检查脚本，确保符合规范（无嵌套多层、无压缩嵌入）：

```powershell
# PowerShell 检查压缩包结构（运行于项目根目录）
$archive = "release\_archive\DormManage-v2.13.208_20260728_150512.zip"

# 1. 检查第一层目录必须是 3 个组件名
$topLevel = [System.IO.Compression.ZipFile]::OpenRead($archive).Entries |
    Where-Object { $_.FullName -notmatch '/' -or ($_.FullName -match '^[^/]+/$') } |
    Select-Object -ExpandProperty FullName
$expected = @('Admin/', 'Api/', 'TrayApp/')
if (($topLevel | Sort-Object) -join ',' -ne ($expected | Sort-Object) -join ',') {
    Write-Error "归档包第一层目录不规范！应为 $($expected -join ',')"
    exit 1
}

# 2. 检查无内部 .zip / .7z / .tar / .gz 嵌套压缩
$nestedArchives = [System.IO.Compression.ZipFile]::OpenRead($archive).Entries |
    Where-Object { $_.FullName -match '\.(zip|7z|tar|gz|rar)$' }
if ($nestedArchives.Count -gt 0) {
    Write-Error "归档包内禁止嵌套其他压缩文件：$($nestedArchives.FullName -join ', ')"
    exit 1
}

# 3. 检查每个组件名文件夹下都包含 .exe
foreach ($component in $expected) {
    $hasExe = [System.IO.Compression.ZipFile]::OpenRead($archive).Entries |
        Where-Object { $_.FullName -like "$component*.exe" }
    if (-not $hasExe) {
        Write-Error "组件 $component 下缺少可执行文件（*.exe）"
        exit 1
    }
}

Write-Host "✓ 归档包结构验证通过（$archive）" -ForegroundColor Green
```

**Bash 验证脚本**：

```bash
#!/bin/bash
ARCHIVE="$1"
echo "校验归档包: $ARCHIVE"

# 检查顶层目录必须是组件名（排除根条目 ./）
TOP_LEVEL=$(tar -tzf "$ARCHIVE" | awk -F'/' 'NF==2 && $2!="" {print $2"/"}' | sort -u)
EXPECTED=$(printf "Admin/\nApi/\nTrayApp/\n" | sort -u)

if [ "$TOP_LEVEL" != "$EXPECTED" ]; then
    echo "❌ 第一层目录不规范：$TOP_LEVEL（期望: Admin/, Api/, TrayApp/）"
    exit 1
fi

# 检查无嵌套压缩文件
NESTED=$(tar -tzf "$ARCHIVE" | grep -E '\.(zip|7z|tar|gz|rar)$' || true)
if [ -n "$NESTED" ]; then
    echo "❌ 归档包内禁止嵌套其他压缩文件：$NESTED"
    exit 1
fi

# 检查每组件下都有 .exe
for component in Admin Api TrayApp; do
    if ! tar -tzf "$ARCHIVE" | grep -q "^$component/.*\.exe$"; then
        echo "❌ 组件 $component 下缺少 .exe"
        exit 1
    fi
done

echo "✓ 归档包结构验证通过"
```

## 四、发布 SOP（标准操作流程）

### 4.1 发布前准备

```bash
# 1) 停止所有运行的 dotnet 进程（避免 DLL 文件锁定）
taskkill /F /IM dotnet.exe 2>/dev/null

# 2) 清理发布目录
rm -rf bin obj release/latest/*
mkdir -p release/latest/{Admin,Api,TrayApp}

# 3) 全量编译
dotnet build DormManage.sln -c Release

# 4) 逐个 Publish 到 release/latest 子目录
dotnet publish DormManage.Admin/DormManage.Admin.csproj -c Release \
    -r win-x64 --self-contained true -o release/latest/Admin
dotnet publish DormManage.Api/DormManage.Api.csproj -c Release \
    -r win-x64 --self-contained true -o release/latest/Api
dotnet publish DormManage.TrayApp/DormManage.TrayApp.csproj -c Release \
    -r win-x64 --self-contained true -o release/latest/TrayApp
```

### 4.2 打包归档

```bash
# 5) 打包（关键：-C release/latest . 进入 release/latest 目录，仅打包下层 3 个组件目录）
NEW_VERSION=$(date +%Y%m%d_%H%M%S)
# 版本号需手动更新（如 v2.13.208 → v2.13.209），递增规则见 CLAUDE.md
tar -czf release/_archive/DormManage-v2.13.209_${NEW_VERSION}.zip \
    -C release/latest .
```

### 4.3 归档验证

```bash
# 6) 运行验证脚本
bash scripts/verify-archive.sh release/_archive/DormManage-v2.13.209_${NEW_VERSION}.zip

# 7) 验证通过后输出成功
echo "✓ 发布包 v2.13.209 已生成"
```

## 七、永久规则（CLAUDE.md 永久生效）

> **v2.13.208+ 强制规范**：所有发布程序包压缩归档**必须**满足以下层级约束：
>
> 1. **扁平层级**：压缩包内第一层**只允许** `Admin/` `Api/` `TrayApp/` 三个组件名文件夹
>
> 2. **禁止嵌套**：组件内部**禁止**二次压缩（`.zip` / `.7z` / `.tar` / `.gz`），也**禁止**多余包装层（如 `DormManage-v{x}/` 根目录、`publish/`、`output/` 等）
>
> 3. **强制验证**：发布前**必须**运行 `scripts/verify-archive.sh <archive>` 或等价的 PowerShell 脚本
>
> 4. **失败阻断**：验证失败**禁止**对外发布，必须重新打包
>
> 5. **脚本化**：使用 `tar -czf ... -C release/latest .` 命令，禁止使用 `tar -czf ... release/latest`（后者会把 `release/latest/` 作为顶层目录）

## 八、永久教训

1. **路径扁平化** — 任何部署物的目录层级**只应该有组件本身 + 必要子目录**（如 `wwwroot/`），禁止额外的"发布"或"打包"包装目录
2. **外部命名可读** — 压缩包用 `DormManage-v{版本}_{时间戳}.zip` 单层命名；内部必须对应扁平 3 组件目录
3. **自动化脚本防范** — 通过预发布验证脚本拦截违规发布，避免人工失误
4. **版本可追溯** — 历史违规版本必须明确标注"已废弃"或保留作为对比，不允许重命名替代
