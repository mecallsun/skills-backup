## 二、核心架构重构：合并入住/退房到单 Modal

### 2.1 旧架构（v2.13.33）

```
Booking/Index.cshtml
├── checkInModal（独立）: 选择员工 + 选房间 + 入住提交
└── checkOutModal（独立）: 选择员工 + 选在宿记录 + 退房提交
                          ↑ PageHeader 有 2 个按钮（办理入住 + 办理退房）
```

**问题**：
- 用户视角：办理登记有"办入住"和"办退房"两个独立入口，但本质上是同一业务流程
- 原型视角：业务只用一个页面，通过"操作类型 radio"切换

### 2.2 新架构（v2.13.34）

```
Booking/Index.cshtml
├── checkInModal（合并入住 + 退房，对齐原型）
│   ├── 区块 1: 员工选择
│   ├── 区块 2: 入住日期与原因
│   ├── 区块 3: 操作类型 radio（入住/退房）
│   ├── 区块 4a: 选择房间（opType=1 显示）
│   └── 区块 4b: 选择在宿记录（opType=2 显示）
└── checkOutModal（保留为列表行"退房"按钮的快速入口，fallback）
```

**改进**：
- ✅ PageHeader 只剩"办理入住"一个主按钮（不再有"办理退房"）
- ✅ checkInModal 通过 radio 切换两种业务模式
- ✅ checkOutModal 仍保留（作为列表行的快速退房入口，但 UI 不需要 100% 对齐原型，因为它本身就是 fallback）

## 六、保留为 Fallback 的功能

### 6.1 checkOutModal 保留

虽然 v2.13.34 把退房合并到了 checkInModal 的 opType=2 分支，但 `checkOutModal` 仍保留在文件中，原因：
1. **列表行的"退房"按钮** 仍调用 `checkOut(id)` 函数（位于 `Booking/Index.cshtml` 的列表操作列）
2. 提供更快速的退房路径（不需要先选员工再选记录，直接输入记录 ID 和日期）

### 6.2 列表行的"退房"按钮

```javascript
async function checkOut(id) {
    if (!confirm('确定要为该员工办理退房吗？')) return;
    const date = prompt('请输入退房日期（格式：YYYY-MM-DD）', new Date().toISOString().split('T')[0]);
    if (!date) return;
    // POST /api/v1/bookings/{id}/check-out
}
```

**保留原因**：列表行已经显示了"在宿"状态的 DormBooking 记录，可以直接调用退房，不需要走"选员工 → 选记录"流程。
