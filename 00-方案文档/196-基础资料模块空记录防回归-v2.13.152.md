### 2.3 根因分析（v2.13.149 现状 loadData）

```javascript
async function loadData(type) {
    currentType = type;
    const apiType = typeToApi[type];
    try {
        const resp = await fetch(`${API_BASE}/${apiType}`);
        const result = await resp.json();
        if (result.success) {                  // ← 只有 success=true 才渲染
            renderTable(type, result.data.items);
        }
        // ← else 分支完全缺失：result.success=false 时静默吞掉
    } catch (err) {
        console.error('加载数据失败:', err);  // ← 只打 console，不显示 UI
    }
}
```

**4 类静默失败场景**：

| # | 触发条件 | 原行为 | 用户感知 |
|---|---------|--------|---------|
| 1 | HTTP 404/500/网络错 | catch 吞掉 → 表格空白 | "空记录"（掩盖真因） |
| 2 | `result.success === false`（API 业务失败） | **完全静默** 不渲染不报错 | "空记录"（掩盖真因） |
| 3 | `result.data.items` 是 undefined | `renderTable` 抛 TypeError → catch | "空记录"（掩盖真因） |
| 4 | `result.data.items === []` | 渲染 "暂无数据" | "空记录"（掩盖真因，但符合事实） |

**核心问题**：与 v2.13.151 设备档案加载失败 BUG **同源** —— 错误被 catch/if 静默吞掉，UI 永远显示空白或通用错误，看不到根因。

### 2.4 renderTable 兜底缺失

```javascript
function renderTable(type, items) {
    const tableId = getTableId(type);
    let html = '';
    items.forEach((item, idx) => {
        if (type === 'dept') { ... }
        else if (type === 'building' || type === 'address') { ... }
        // ... 7 个分支 ...
        // ← 没有 else 兜底：未知 type 静默跳过
    });
    document.getElementById(tableId).innerHTML = html || '<tr>暂无数据</tr>';
    // ← tableId 缺失时 document.getElementById 返回 null → TypeError
}
```

**附加问题**：
- `document.getElementById(tableId)` 在 tableId 缺失或元素未渲染时返回 null → `null.innerHTML = ...` 抛 TypeError
- 未知 type 没有兜底渲染 → 用户看到「暂无数据」

## 三、修复方案（v2.13.152）

### 3.1 loadData 完整错误处理（核心修复）

```javascript
async function loadData(type) {
    currentType = type;
    const apiType = typeToApi[type];
    const tableId = getTableId(type);
    if (!apiType || !tableId) {
        console.error('[v2.13.152 loadData] type 无效:', type, '(apiType=' + apiType + ', tableId=' + tableId + ')');
        return;
    }
    const tbody = document.getElementById(tableId);
    if (!tbody) {
        console.error('[v2.13.152 loadData] 找不到 tbody #' + tableId);
        return;
    }
    // 加载中状态
    tbody.innerHTML = '<tr><td colspan="7" class="text-center text-muted py-4"><i class="bi bi-hourglass-split"></i> 加载中…</td></tr>';

    try {
        const resp = await fetch(`${API_BASE}/${apiType}`, { credentials: 'same-origin' });

        // 关键 1：HTTP 状态码检查
        if (!resp.ok) {
            tbody.innerHTML = `<tr><td colspan="7" class="text-center text-danger py-4">
                ❌ HTTP ${resp.status} ${resp.statusText}<br>
                <small>请检查 API 端点 ${apiType} 是否可访问（F12 查看 Network）</small>
            </td></tr>`;
            console.error('[v2.13.152 loadData] HTTP ' + resp.status + ' for ' + apiType);
            return;
        }
        const result = await resp.json();

        // 关键 2：API 业务失败处理
        if (!result) {
            tbody.innerHTML = '<tr><td colspan="7" class="text-center text-danger py-4">API 响应为空</td></tr>';
            return;
        }
        if (result.success !== true) {
            tbody.innerHTML = `<tr><td colspan="7" class="text-center text-danger py-4">
                ❌ ${escapeHtml(result.message || 'API 返回失败')}<br>
                <small>code: ${escapeHtml(result.code || 'N/A')}</small>
            </td></tr>`;
            console.error('[v2.13.152 loadData] API failure:', result);
            return;
        }

        // 关键 3：items 数组检查（防止 renderTable 抛 TypeError）
        const items = (result.data && Array.isArray(result.data.items)) ? result.data.items : [];
        if (items.length === 0) {
            tbody.innerHTML = '<tr><td colspan="7" class="text-center text-muted py-4">暂无数据</td></tr>';
            return;
        }
        renderTable(type, items);
    } catch (err) {
        // 关键 4：异常时显示真实错误
        console.error('[v2.13.152 loadData] 异常:', err);
        const errMsg = (err && err.message) ? err.message : err.toString();
        tbody.innerHTML = `<tr><td colspan="7" class="text-center text-danger py-4">
            ❌ 加载失败：${escapeHtml(errMsg)}<br>
            <small>请查看浏览器控制台(F12)获取详情</small>
        </td></tr>`;
    }
}
```

### 3.2 renderTable 防御 + 兜底模板

```javascript
function renderTable(type, items) {
    const tableId = getTableId(type);
    if (!tableId) {
        console.error('[v2.13.152 renderTable] type 无效:', type);
        return;
    }
    const tbody = document.getElementById(tableId);
    if (!tbody) {
        console.error('[v2.13.152 renderTable] 找不到 tbody #' + tableId);
        return;  // ← 关键：不 throw，避免空对象赋值异常
    }
    let html = '';
    items.forEach((item, idx) => {
        // ... 原有 7 个 type 分支 ...
        else {
            // v2.13.152 兜底：未知 type 用通用模板（code + name + remark + status + 操作）
            html += `<tr>
                <td>${idx + 1}</td>
                <td><code>${item.code || '-'}</code></td>
                <td>${item.name || item.addressText || '-'}</td>
                <td>${item.remark || '-'}</td>
                <td>${statusBadge}</td>
                <td>
                    <button class="btn btn-sm btn-outline-primary" onclick="editItem('${type}', ${item.id})">编辑</button>
                    <button class="btn btn-sm btn-outline-danger" onclick="deleteItem('${type}', ${item.id})">删除</button>
                </td>
            </tr>`;
        }
    });

    if (html === '') {
        // v2.13.152：所有分支都不匹配时显示默认调试信息（防止静默空白）
        html = `<tr><td colspan="7" class="text-center text-warning py-4">
            ⚠️ 未匹配任何渲染模板（type=${type}），数据项数=${items.length}<br>
            <small>请报告此问题给开发者</small>
        </td></tr>`;
    }
    tbody.innerHTML = html;  // ← 直接赋给已 null 检查过的 tbody
}
```

## 五、可清理的过时描述

### 过时 1：「loadData 出错时只 console.error 即可」
**原描述**：v2.13.94-149 普遍
**过时原因**：v2.13.152 起错误必须**同时显示在 UI**（用户无法打开 F12）
**修正**：所有 loadData 类函数必须同时 console.error + 设置 tbody.innerHTML 为错误提示

### 过时 2：「renderTable 无需兜底模板」
**原描述**：v2.13.94-149
**过时原因**：未知 type 会导致「暂无数据」误显示
**修正**：renderTable 必须有 else 兜底分支 + 空 html 时显示「未匹配模板」警告

### 过时 3：「表格空白 = 数据为空」
**原描述**：用户感知的常见误判
**过时原因**：v2.13.152 表格空白可能是 4 类失败之一（HTTP/业务/items/未知 type）
**修正**：表格空白时必须看 UI 错误提示 + 控制台日志双重诊断

### 过时 4：「Basics 模块加载是简单的 fetch+render」
**原描述**：v2.13.94
**过时原因**：12 个 API 端点 × 12 个 type × 12 种 data shape → 错误路径覆盖不足
**修正**：所有路径必须经过 `tbody null 检查 → HTTP 状态 → API success → items 数组 → renderTable type 分支 → 兜底` 6 层防御

## 七、永久教训（4 条新增）

### 教训 #1：「异步加载 UI 必须自带错误可见性」
与 v2.13.151 设备记录 BUG 同源。**任何 async fetch + DOM render 链路，错误必须既输出 console 又更新 DOM**。用户可能不会打开 F12。

### 教训 #2：「tbody 不是永远存在」
`document.getElementById('xxx')` 在以下情况返回 null：
- 元素 ID 错（typo）
- 元素在另一个 Tab Pane 内（class="tab-pane fade"）
- 元素被异步渲染组件动态注入

**对策**：每次赋值前必须 null check 或使用 safeElement 包装。

### 教训 #3：「if (result.success) 隐藏 else 是反模式」
```js
if (result.success) { render(...) }
// ← 没有 else：API 返回 success=false 时完全静默
```
正确写法：
```js
if (result.success) { render(...); return; }
showError(result.message);  // ← 显式 else 分支
```

### 教训 #4：「未知 type 必须有兜底渲染」
if-else 链的最后必须有 else 分支（即使只渲染 code + name），否则 type 字符串 typo / 路由改名 时页面静默空白。**永远不要信任 type 参数**。
