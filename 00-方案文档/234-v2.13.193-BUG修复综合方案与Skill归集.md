## 2. 永久教训（10 条）

### 教训 1：文档与代码必须同步 commit
- ❌ v2.13.176 文档先行 17+ 版本才实装
- ✅ 任何 v2.13.x 翻转必须同 commit 文档 + 代码

### 教训 2：发布双胞胎必须同步
- ❌ 发布路径 ≠ 运行路径
- ✅ 用 `scripts/sync_publish_to_trayapp.sh`

### 教训 3：Shared DLL 必须全子目录同步
- ❌ TypeLoadException = DLL 漏同步
- ✅ 同步到 4 处

### 教训 4：deny-by-default 是默认安全选择
- ❌ allow-by-default 容易 BUG
- ✅ 默认隐藏，勾选才显示

### 教训 5：方法名必须反映语义
- ❌ `HasEnabled` 模糊
- ✅ `AllowDisplay` 明确

### 教训 6：跨权限测试必须 2 角色
- ❌ 只测 admin 漏 BUG
- ✅ admin + 未授权角色

### 教训 7：.NET DLL 字符串是 UTF-16 LE 编码
- ❌ `grep "中文"` 找不到
- ✅ `python3 -c "codecs.encode('中文', 'utf-16-le')"`

### 教训 8：git 操作可能回滚修改
- ❌ Edit 后不验证
- ✅ 立即 `git diff` 确认

### 教训 9：同一业务规则不要有多个独立实现
- ❌ 3 处独立 ExpiresAt
- ✅ 统一助手函数

### 教训 10：HTTP 200 + success:true 不一定生效
- ❌ 只信 API 返回值
- ✅ 跨连接查询验证

## 6. 使用方法

### 6.1 遇到 BUG 时

```
1. 加载 skills/dorm-bugfix-master/SKILL.md
2. 加载 bug-categories.md 确定类别
3. 加载 known-bugs.md 查看是否已有类似案例
4. 加载 bugfix-procedures.md 走 7 步流程
5. 加载 code-style-standards.md 防止引入新 BUG
6. 加载 testing-checklist.md 验证修复
7. 加载 deployment-checklist.md 安全发布
8. 加载 emergency-procedures.md（如紧急）
```

### 6.2 发布前

```
1. 加载 skills/release-bugfix-v2.13.193/SKILL.md
2. 运行 scripts/sync_publish_to_trayapp.sh
3. 加载 deployment-checklist.md
4. 加载 testing-checklist.md
```

### 6.3 紧急情况

```
1. 加载 emergency-procedures.md
2. 按 4 阶段执行：立即响应 → 快速诊断 → 快速 patch → 延后完善
```
