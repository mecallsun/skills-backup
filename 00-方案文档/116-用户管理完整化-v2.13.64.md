## 二、修复方案

### 2.1 后端：UserController 添加 `/enable` 和 `/disable` 端点

```csharp
[HttpPost("{id}/enable")]
public async Task<ApiResponse> EnableUser(int id)
{
    var user = await _db.SysUsers.FindAsync(id);
    if (user is null) return ApiResponse.Fail("NOT_FOUND", "用户不存在");
    user.IsActive = true;
    user.UpdatedAt = DateTime.Now;
    await _db.SaveChangesAsync();
    return ApiResponse.Ok("已启用");
}

[HttpPost("{id}/disable")]
public async Task<ApiResponse> DisableUser(int id)
{
    var user = await _db.SysUsers.FindAsync(id);
    if (user is null) return ApiResponse.Fail("NOT_FOUND", "用户不存在");
    if (user.UserName == "admin")
        return ApiResponse.Fail("PROTECTED", "内置 admin 账号不允许停用");
    user.IsActive = false;
    user.UpdatedAt = DateTime.Now;
    await _db.SaveChangesAsync();
    return ApiResponse.Ok("已停用");
}
```

### 2.2 后端：DeleteUser 级联清理 4 个子表

```csharp
[HttpDelete("{id}")]
public async Task<ApiResponse> DeleteUser(int id)
{
    var user = await _db.SysUsers.FindAsync(id);
    if (user is null) return ApiResponse.Fail("NOT_FOUND", "用户不存在");
    if (user.UserName == "admin")
        return ApiResponse.Fail("PROTECTED", "内置 admin 账号不允许删除");

    // v2.13.64 修复：级联清理所有引用该用户的子表（FK 约束）
    var urs = _db.SysUserRoles.Where(ur => ur.UserId == id);
    _db.SysUserRoles.RemoveRange(urs);
    var sqs = _db.SysUserSecurityQuestions.Where(sq => sq.UserId == id);
    _db.SysUserSecurityQuestions.RemoveRange(sqs);
    var logs = _db.SysOpLogs.Where(l => l.UserId == id);
    _db.SysOpLogs.RemoveRange(logs);
    var filters = _db.SysUserFilterCaches.Where(c => c.UserId == id);
    _db.SysUserFilterCaches.RemoveRange(filters);

    _db.SysUsers.Remove(user);
    await _db.SaveChangesAsync();
    return ApiResponse.Ok("删除成功");
}
```

同样的级联修复应用到 `User.cshtml.cs` 的 `OnPostDeleteAsync`。

### 2.5 前端：Edit Modal IsActive 移除外层多余 div

v2.13.62 经验教训：`asp-for` 复选框会自动生成 hidden field。在 Razor Pages form 中手动加 `<input type="hidden" name="IsActive" value="false">` 会导致 ModelBinder 永远取 false。

旧代码（v2.13.46 BUG）：
```html
<input class="form-check-input" type="checkbox" name="IsActive" value="true" id="editIsActive">
<input type="hidden" name="IsActive" value="false">  <!-- ← 错误保留 -->
<label class="form-check-label" for="editIsActive">启用账号</label>
```

新代码（v2.13.64）：
```html
<div class="form-check pb-2">
    <input class="form-check-input" type="checkbox" name="IsActive" value="true" id="editIsActive">
    <label class="form-check-label" for="editIsActive">启用账号</label>
</div>
```

由于非 `asp-for` 而是用 `name` 属性，**不会自动生成 hidden**，因此 ModelBinder 能正确取到第一个值（true 或不发送）。但保留手动 hidden 在非 asp-for 场景下是多余的，已移除。

## 三、PageModel 升级（User.cshtml.cs）

### 3.1 新增查询参数 + 分页

```csharp
[BindProperty(SupportsGet = true)] public string? Search { get; set; }
[BindProperty(SupportsGet = true)] public int? RoleId { get; set; }
[BindProperty(SupportsGet = true)] public string? Status { get; set; }
[BindProperty(SupportsGet = true)] public int PageIndex { get; set; } = 1;
[BindProperty(SupportsGet = true)] public int PageSize { get; set; } = 20;

public int TotalCount { get; set; }
public int TotalPages => Math.Max(1, (int)Math.Ceiling(TotalCount / (double)PageSize));
```

### 3.2 LoadDataAsync 改造

```csharp
var query = _db.SysUsers.AsQueryable();

// 搜索：用户名 OR 姓名
if (!string.IsNullOrWhiteSpace(Search))
    query = query.Where(u => u.UserName.Contains(Search.Trim()) || u.DisplayName.Contains(Search.Trim()));

// 状态筛选
if (Status == "active") query = query.Where(u => u.IsActive && !u.IsLocked);
else if (Status == "disabled") query = query.Where(u => !u.IsActive);
else if (Status == "locked") query = query.Where(u => u.IsLocked);

var allUsers = await query.OrderByDescending(u => u.CreatedAt).ToListAsync();
// 角色筛选（内存中二次过滤）
if (RoleId.HasValue) {
    var userIdsInRole = userRoles.Where(ur => ur.RoleId == RoleId.Value).Select(ur => ur.UserId).ToHashSet();
    allUsers = allUsers.Where(u => userIdsInRole.Contains(u.Id)).ToList();
}

TotalCount = allUsers.Count;
// 分页
var pagedUsers = allUsers.Skip((PageIndex - 1) * PageSize).Take(PageSize).ToList();
```

## 七、教训总结

### 7.1 关键教训

1. ❌ **JS 调用的端点必须存在** — UI 层调用 `/enable` `/disable` 之前要确认 Controller 端点存在，否则 404 静默失败
2. ❌ **角色匹配用 Id 不用 Name** — 名称前缀匹配容易误判同名（"管理员" / "管理员细分"），Id 严格匹配最稳妥
3. ❌ **删除用户要级联清理所有 FK 引用** — SysUser 至少有 4 个子表有 FK，不级联删除会 500 DB_ERROR
4. ✅ **列表页 UI 必须与原型一致** — 搜索/角色/状态筛选/分页是现代列表页标配

### 7.2 强制检查清单（CRUD 完成度自检）

- [ ] 后端：增/改/删/启/停/重置密码 6 个端点都存在
- [ ] 前端 JS：调用的每个端点都已在 Controller 实现
- [ ] 编辑 Modal 回显：用 Id 匹配，不用 Name 匹配
- [ ] 删除操作：级联清理所有引用该行的子表（依据 FK 约束）
- [ ] UI：与原型比对字段/筛选/分页是否 1:1 一致
