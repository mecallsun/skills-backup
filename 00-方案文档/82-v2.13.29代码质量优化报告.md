## 二、优化 1：清理代码 TODO 标记

### 1.1 BookingController 真实用户名获取

**问题**：6 处 `Request.Headers["X-User-Name"].FirstOrDefault() ?? "admin"` 兜底，所有用户都记为 admin

**修复**：新增 `HttpContextExtensions.GetCurrentUserName()`，统一从登录会话/请求头获取真实用户名

**修改**：
- `DormManage.Shared/Extensions/HttpContextExtensions.cs` 新增 `GetCurrentUserName()`
- `DormManage.Api/Controllers/Booking/BookingController.cs` 6 处替换为 `HttpContext.GetCurrentUserName()`

**改进**：
- 优先级：X-User-Name Header > Claims.Identity.Name > "system"
- 办理登记、撤销等关键操作记录真实操作人

### 1.2 Settings/Index.cshtml.cs 删除 stub Post-handler

**问题**：3 个 Post-handler 标记 `// TODO: 实际项目中应写入配置文件或数据库`，但实际上对应的 API 端点已实现

**修复**：
- 删除 `OnPostSaveDatabaseConfig`、`OnPostSaveIntegrationConfig`（已迁移到 /api/v1/system/dbconfig/save）
- `OnPostSaveServiceConfig` 改为"服务配置须通过托盘程序修改"的友好提示（保证唯一真源）

**影响**：避免前端误调用无效端点

### 1.3 Personnel/Import.cshtml.cs 真实 Excel 解析

**问题**：原代码仅返回模拟结果（"TotalRows=200, SuccessRows=195" 硬编码）

**修复**：
- 使用 `ClosedXML` 解析上传的 .xlsx 文件
- 实际遍历数据行，校验必填字段、查重、统计结果
- 下载模板功能使用 ClosedXML 生成标准 7 列模板

**新增功能**：
- 真实的 Excel 解析逻辑
- 校验失败行级错误信息
- 重复工号自动跳过（除非勾选覆盖模式）
- 模板下载：含示例行 + 列标题加粗

### 1.4 Meter/Import.cshtml.cs 真实 Excel 解析

**修复**：同上，使用 ClosedXML 实现：
- 模板下载（含表头加粗 + 示例行）
- 校验逻辑：宿舍编号、月份格式、表读数有效性
- 行级错误信息：冷水读数不能为负数、表读数不能为空等

## 三、优化 2：统一操作日志记录服务

### 3.1 新增 OperationLogService

**文件**：`DormManage.Shared/Services/OperationLogService.cs`

**核心方法**：
- `LogAsync(action, target, detail)`：通用日志记录
- `LogLoginAsync(username, success, detail)`：登录日志（成功/失败）
- `LogLogoutAsync(username)`：登出日志
- `LogConfigChangeAsync(key, oldValue, newValue)`：配置变更日志
- `LogDataChangeAsync(entityType, entityId, operation, detail)`：数据 CRUD 日志

**自动从 HttpContext 提取**：
- 当前用户 ID（从 Claims）
- 当前用户名（从 Header/Claims）
- 客户端 IP（处理 X-Forwarded-For / X-Real-IP 反向代理场景）

### 3.2 注册到 Admin/Api

```csharp
builder.Services.AddScoped<IOperationLogService, OperationLogService>();
```

## 四、优化 3：全局异常处理

### 4.1 新增 BusinessException

**文件**：`DormManage.Shared/Exceptions/BusinessException.cs`

用于业务规则校验失败等**可预期**的用户级错误。中间件会捕获并返回 200 + 错误码，前端可正常处理。

```csharp
if (await IsConflict())
    throw new BusinessException("DUPLICATE", "该员工已在住宿中");
```

### 4.2 API 全局异常中间件

**文件**：`DormManage.Api/Middleware/GlobalExceptionMiddleware.cs`

**异常分类处理**：

| 异常类型 | HTTP 状态码 | 错误码 | 处理 |
|---------|-------------|--------|------|
| `BusinessException` | 200 | 业务码 | 警告日志 + 友好消息 |
| `UnauthorizedAccessException` | 401 | UNAUTHORIZED | 警告日志 |
| `KeyNotFoundException` | 404 | NOT_FOUND | 警告日志 |
| `DbUpdateException` | 500 | DB_ERROR | 错误日志 + 数据库错误 |
| 其它 `Exception` | 500 | INTERNAL_ERROR | 错误日志 + 通用消息 |

**开发/生产环境区分**：
- Development：返回详细异常消息
- Production：返回通用消息（"服务器内部错误，请稍后重试"）

### 4.3 Admin 全局异常过滤器

**文件**：`DormManage.Admin/Filters/GlobalExceptionFilter.cs`

Razor Pages 通过 `IExceptionFilter` 重定向到 `/Error?code=XXX&message=YYY`

## 五、优化 4：API 性能监控中间件

### 4.1 PerformanceMonitoringMiddleware

**文件**：`DormManage.Api/Middleware/PerformanceMonitoringMiddleware.cs`

**核心功能**：
- 仅监控 `/api/*` 请求
- 记录所有 API 请求的响应时间
- 慢请求（> 3s）记录到警告日志
- 错误请求（5xx）记录到错误日志
- 响应头返回 `X-Response-Time-Ms`

**日志格式**：
```
[API] GET /api/v1/personnel?page=1 → 200 (45ms)
[SLOW-API] POST /api/v1/booking/check-in → 200 (3521ms) from 192.168.1.10
[API-ERROR] POST /api/v1/dorm → 500 (123ms)
```

### 4.2 中间件注册顺序

```
UseMiddleware<PerformanceMonitoringMiddleware>()  // 最外层（计时）
UseMiddleware<GlobalExceptionMiddleware>()        // 次外层（捕获异常）
UseSwagger() / UseSwaggerUI()
MapControllers() / MapRazorPages()
```
