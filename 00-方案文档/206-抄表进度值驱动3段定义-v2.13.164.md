## 二、新定义（v2.13.164 终极统一定义）

### 2.1 关键不变量（保持不变）

> **「所有房间每月抄表数据去重，仅保留一条最新覆盖同房号同月的旧记录」**

- 业务主键：`(DormCode, ReadMonth)`
- 去重策略：按 `Id DESC` 取最新（最后写入优先）
- 这是历史业务原则，v2.13.164 **完全保留**，未做改动

### 2.2 三状态判定（值驱动，互斥级联）

读取该房号该月 **去重后最新** MeterRecord 的三表读数（ColdMeter / HotMeter / ElectricMeter）：

```
已抄表  = ColdMeter > 0  AND  HotMeter > 0  AND  ElectricMeter > 0
抄表中  = (ColdMeter > 0  OR  HotMeter > 0  OR  ElectricMeter > 0)
        AND NOT 已抄表
未抄表  = (该房号本月无任何 MeterRecord)
        OR (存在记录但 ColdMeter == 0  AND  HotMeter == 0  AND  ElectricMeter == 0)
```

**互斥关系**：
- 已抄表 ⊂ 抄表中（所有 3 表 > 0 必满足至少 1 表 > 0）
- 抄表中 ∩ 未抄表 = ∅
- 3 状态对所有房间的并集 = 所有房间

### 2.3 重要变更（vs v2.13.133）

| 维度 | v2.13.133 旧实现 | v2.13.164 新实现 |
|---|---|---|
| 判定依据 | MeterRecordStatus 枚举（0-4）| ColdMeter/HotMeter/ElectricMeter 实际读数值 |
| "未完成" | Status=Incomplete(0) 占位记录 | **废弃此概念** |
| "未覆盖" | Dorm 存在但无任何 MeterRecord | **并入"未抄表"**（Dorm 存在但本月记录全 0 或无任何记录）|
| 段落命名 | 已抄 / 未完成 / 未覆盖 | **已抄表 / 抄表中 / 未抄表** |
| KPI 标签 | 本月抄表覆盖 | **本月抄表进度** |

-- 140 房间 → 0 已抄表 / 1 抄表中 / 139 未抄表 / 0.0% 进度
WITH latest AS (
    SELECT DormCode, ColdMeter, HotMeter, ElectricMeter, Status,
           ROW_NUMBER() OVER (PARTITION BY DormCode ORDER BY RecordId DESC) rn
    FROM MeterRecord WHERE ReadMonth = '2026-07'
)
SELECT
    已抄表 = SUM(CASE WHEN ColdMeter > 0 AND HotMeter > 0 AND ElectricMeter > 0 THEN 1 ELSE 0 END),
    抄表中 = SUM(CASE WHEN (ColdMeter > 0 OR HotMeter > 0 OR ElectricMeter > 0) 
                       AND NOT (ColdMeter > 0 AND HotMeter > 0 AND ElectricMeter > 0) THEN 1 ELSE 0 END),
    全0未抄表 = SUM(CASE WHEN ColdMeter = 0 AND HotMeter = 0 AND ElectricMeter = 0 THEN 1 ELSE 0 END),
    总Dorm数 = (SELECT COUNT(*) FROM Dorm)
FROM latest WHERE rn = 1;

## 四、代码实现

### 4.1 DashboardService.cs（KPI 5 + Chart 8 重构）

**核心变化**：

```csharp
// 1. 取每房号最新记录（去重不变量）
var latestRecords = await _db.MeterRecords
    .Where(r => r.ReadMonth == monthStr)
    .GroupBy(r => r.DormCode)
    .Select(g => g.OrderByDescending(r => r.Id).First())  // ← 关键不变量
    .ToListAsync();

// 2. 三段互斥判定
var readDormCodes = latestRecords
    .Where(r => r.ColdMeter > 0 && r.HotMeter > 0 && r.ElectricMeter > 0)  // 已抄表
    .Select(r => r.DormCode).ToList();

var meterUnfinishedDormCodes = latestRecords
    .Where(r => (r.ColdMeter > 0 || r.HotMeter > 0 || r.ElectricMeter > 0)
             && !(r.ColdMeter > 0 && r.HotMeter > 0 && r.ElectricMeter > 0))  // 抄表中
    .Select(r => r.DormCode).ToList();

var allMeterDormCodes = latestRecords.Select(r => r.DormCode).ToList();
var allZeroDormCodes = latestRecords
    .Where(r => r.ColdMeter == 0 && r.HotMeter == 0 && r.ElectricMeter == 0)
    .Select(r => r.DormCode).ToList();
var noRecordDormCodes = await _db.Dorms
    .Where(d => !allMeterDormCodes.Contains(d.DormCode))
    .Select(d => d.DormCode).ToListAsync();
var meterUncoveredDormCodes = allZeroDormCodes.Concat(noRecordDormCodes).Distinct().ToList();
// 未抄表 = 全 0 + 无记录（合并）
```

## 七、永久教训

| # | 教训 |
|---|------|
| 1 | **「业务状态」应贴近真源数据，不应固化在 Status 枚举里**。v2.13.133 用 5 个 Status 枚举驱动 3 段统计，导致"记录已写入但读数是 0"和"记录未写入"被错误归为不同类别。改用读数值直接判定，简洁且符合业务直觉。 |
| 2 | **「3 段互斥级联」必须明确写顺序**：已抄表 ⊂ 抄表中（所有 > 0 隐含至少 1 个 > 0）。代码顺序应是「先检 All → 再检 Any → 否则默认」三个 IF-ELSE 链。 |
| 3 | **「关键不变量」必须显式保留并标记**。用户特别强调"每月去重仅保留最新"这一原则不变——文档中单独用章节标记是业务约束的尊重。 |
| 4 | **「Status 枚举」与「业务 3 段」是不同维度**。MeterRecordStatus（0-4）描述"录入状态"，3 段抄表进度描述"数据完整度"——互不替代。Status 保留供其他业务使用（详情/列表 badge），不参与 KPI 计算。 |
| 5 | **「去重」与「取值」必须分开**：先 GroupBy + OrderByDescending(r => r.Id).First() 取最新，然后基于此做 3 段判定。如果不先去重，会被同一房号的多次写入重复计数。 |
