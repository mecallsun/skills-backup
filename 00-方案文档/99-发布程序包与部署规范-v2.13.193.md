## ⚠️ 系统核心规则（v2.13.184 强托管 — 不可妥协）

> **用户原话**：「所有程序 必须 由 托盘程序守卫并拉起服务运行，禁止其他方式运行」

### 1. 启动关系矩阵（系统级唯一真相）

| 程序 | 启动方式 | 独立运行 | 备注 |
|------|---------|---------|------|
| **DormManage.TrayApp.exe** | 用户双击 / `start.bat` / Windows 服务 | ✅ 允许 | **唯一权威入口** |
| **DormManage.Admin.exe** | 必须由 TrayApp 拉起 | ❌ 严禁（v2.13.155 强制） | 双击 → `[TRAY-GUARD]` 拒绝并退出 |
| **DormManage.Api.exe** | 必须由 TrayApp 拉起 | ❌ 严禁（v2.13.184 恢复强制） | 双击 → `[TRAY-GUARD]` 拒绝并退出 |

### 2. 程序永远启动原则（v2.13.169 + v2.13.184 + v2.13.193 双固化）

> **核心承诺**：在所有 5 种注册状态下，托盘都成功拉起 Web/Api 子进程（不再 throw）。

| 注册状态 | TrayApp 行为 | 子进程运行模式 |
|---------|------------|---------------|
| Valid(1) | ✅ 拉起 | 全功能 |
| Expired(2) | ✅ 拉起 | 只读「许可已过期」（LicenseGuard + LicenseReadOnlyMiddleware 拦截写操作） |
| Invalid(3) | ✅ 拉起 | 只读「校验失败」（机器码/公司名不匹配） |
| Unregistered(-1) | ✅ 拉起 | 试用模式（v2.13.150 分模块上限：住宿登记 500 / 宿舍档案 5 / 人员清单 5） |
| TrayApp 未运行 | 子进程不应启动（强托管） | 服务不可用 |

```
        └── Api/                                  ← 🔴 v2.13.193 必须同步的子目录
            ├── DormManage.Api.dll                 ← TrayApp 实际加载这个
            ├── DormManage.Shared.dll
            └── ...
```

### 3.2 TrayApp 配置（appsettings.json）

```json
{
  "Tray": {
    "ApiPort": 5100,
    "AdminPort": 5001,
    "ApiExecutable": "..\\Api\\DormManage.Api.exe",          ← 相对路径
    "AdminExecutable": "..\\Admin\\DormManage.Admin.exe"    ← 相对路径
  }
}
```

**关键点**：TrayApp 启动时 `..\Admin\` 解析为 `release/latest/TrayApp/Admin/`，**不是** `release/latest/Admin/`！

## 4. 发布流程（v2.13.193 标准流程）

### 4.1 强制使用同步脚本

**❌ 禁止**：仅用 `dotnet publish -o release/latest/Admin/`

**✅ 必须**：使用 `scripts/sync_publish_to_trayapp.sh`

```bash
# 标准发布流程
cd /path/to/项目根目录

# 步骤 1：构建
dotnet build DormManage.sln -c Release

# 步骤 2：发布到 release/latest/
dotnet publish DormManage.Api/DormManage.Api.csproj -c Release -r win-x64 --self-contained true -o release/latest/Api
dotnet publish DormManage.Admin/DormManage.Admin.csproj -c Release -r win-x64 --self-contained true -o release/latest/Admin
dotnet publish DormManage.TrayApp/DormManage.TrayApp.csproj -c Release -r win-x64 --self-contained true -o release/latest/TrayApp

# 步骤 3：同步 DLL + Pages 到 TrayApp 兄弟目录（v2.13.193 关键步骤）
cp -f release/latest/Admin/DormManage.Admin.dll         release/latest/TrayApp/Admin/
cp -f release/latest/Admin/DormManage.Admin.pdb         release/latest/TrayApp/Admin/
cp -f release/latest/Admin/DormManage.Shared.dll        release/latest/TrayApp/Admin/
cp -rf release/latest/Admin/Pages                       release/latest/TrayApp/Admin/

cp -f release/latest/Api/DormManage.Api.dll             release/latest/TrayApp/Api/
cp -f release/latest/Api/DormManage.Api.pdb             release/latest/TrayApp/Api/
cp -f release/latest/Api/DormManage.Shared.dll          release/latest/TrayApp/Api/

# 步骤 4：打包为 ZIP
TS=$(date +%Y%m%d_%H%M%S)
ARCHIVE="release/_archive/DormManage-v{版本号}_${TS}.zip"
powershell -Command "Compress-Archive -Path 'release/latest/*' -DestinationPath '${ARCHIVE}' -Force"
```

### 4.2 同步脚本（v2.13.193 新增）

**文件**：`scripts/sync_publish_to_trayapp.sh`

```bash
#!/bin/bash
# sync_publish_to_trayapp.sh — 发布后必须执行
# 用法：./sync_publish_to_trayapp.sh [--skip-build]

SKIP_BUILD=false
for arg in "$@"; do
    if [ "$arg" == "--skip-build" ]; then SKIP_BUILD=true; fi
done

# Step 1: Build
if [ "$SKIP_BUILD" != "true" ]; then
    dotnet build DormManage.sln -c Release
fi

# Step 2: Publish
dotnet publish DormManage.Api/DormManage.Api.csproj -c Release -r win-x64 --self-contained true -o release/latest/Api
dotnet publish DormManage.Admin/DormManage.Admin.csproj -c Release -r win-x64 --self-contained true -o release/latest/Admin
dotnet publish DormManage.TrayApp/DormManage.TrayApp.csproj -c Release -r win-x64 --self-contained true -o release/latest/TrayApp

# Step 3: Sync DLLs + Pages to TrayApp sibling dirs (关键)
cp -f release/latest/Admin/DormManage.Admin.dll         release/latest/TrayApp/Admin/
cp -f release/latest/Admin/DormManage.Admin.pdb         release/latest/TrayApp/Admin/
cp -f release/latest/Admin/DormManage.Shared.dll        release/latest/TrayApp/Admin/
cp -rf release/latest/Admin/Pages                       release/latest/TrayApp/Admin/

cp -f release/latest/Api/DormManage.Api.dll             release/latest/TrayApp/Api/
cp -f release/latest/Api/DormManage.Api.pdb             release/latest/TrayApp/Api/
cp -f release/latest/Api/DormManage.Shared.dll          release/latest/TrayApp/Api/

# Step 4: Verify
echo "=== Sync verification ==="
grep -c "resident.Gender" release/latest/TrayApp/Admin/Pages/Dorms/Details.cshtml
# Should be >= 2
```

## 6. 常见错误排查表

| 错误 | 原因 | 解决 |
|------|------|------|
| TypeLoadException: RuntimeWindowGuard | Shared DLL 版本不一致 | 重新 sync Shared DLL |
| HTTP 500: Could not load type Xxx | Shared DLL 缺少类 | dotnet build 强制重新编译 |
| 浏览器仍显示旧版 | 浏览器缓存 | Ctrl+F5 强制刷新 |
| Admin 启动后立即退出 | 缺少类型 / 路径错误 | 检查 TrayApp 日志 |
| TrayApp 拉起子进程失败 | 注册码过期或 IPC 异常 | 检查注册表配置 |
| **修改无效（Bug#2 陷阱）** | **TrayApp 加载的是兄弟目录而非发布目录** | **使用 sync_publish_to_trayapp.sh** |
| test 用户仍看到隐私字段 | deny-by-default 未实施 | v2.13.193 已修复 PermissionService.cs |

## 7. 部署流程

### 7.1 标准部署步骤

```cmd
:: 步骤 1：解压 ZIP
Expand-Archive "DormManage-v{版本号}_{时间戳}.zip" -DestinationPath "D:\DormManage"

:: 步骤 2：启动 TrayApp（不要直接启动 Admin/Api）
cd "D:\DormManage\TrayApp"
.\DormManage.TrayApp.exe

:: 步骤 3：浏览器访问
:: http://localhost:5001（托盘自动启动 Admin）
```

### 7.2 重要警告

- **❌ 禁止**：直接双击 `DormManage.Admin.exe` 或 `DormManage.Api.exe`（强托管规则拒绝）
- **❌ 禁止**：在 IIS/Apache/Nginx 反向代理后部署 Admin（违反强托管）
- **❌ 禁止**：部署在 NAS/CIFS 共享目录（IPC 性能差+文件锁问题）

### 7.3 升级流程

1. 停止 TrayApp（托盘会自动停止子进程）
2. 备份当前版本（复制旧 release/ 到 backup/）
3. 解压新版到 release/
4. 检查 appsettings.json 中的端口配置
5. 启动 TrayApp

## 8. 永久教训

| # | 教训 | 强制规则 |
|---|------|---------|
| 1 | 发布路径 ≠ 运行路径 | 必须用 sync 脚本同步两个目录 |
| 2 | Shared DLL 必须全子目录同步 | cp -f 三处 |
| 3 | 文档与代码必须同步 | 不允许"v2.13.x 翻转"仅改文档 |
| 4 | 跨权限测试必须 2 角色 | admin + 未授权 |
| 5 | git 操作可能回滚修改 | Edit 后立即 git diff |
| 6 | StringEncoding 差异 | .NET DLL 用 UTF-16 LE 不是 ASCII |
| 7 | TypeLoadException 是 DLL 不一致 | 检查 Shared DLL 同步 |
| 8 | 备份残留陷阱 | cp -r 前先 rm -rf |
| 9 | 强制 deny-by-default 是安全选择 | 不勾选 → 隐藏 |
| 10 | 方法名必须反映语义 | `AllowDisplay` 比 `HasEnabled` 更清晰 |
