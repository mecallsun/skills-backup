## 九、永久教训

### 9.1 100% 1:1 对齐的检查方法

**逐项对比法**：对原型每个 DOM 节点、CSS 类、JS 逻辑点逐项 grep：

| 检查维度 | 工具 |
|---------|------|
| HTML 结构 | `grep -E "<element...>" file.html vs file.cshtml` |
| CSS 类 | `grep -E "class=\"form-card-header\""` |
| JS 函数 | `grep -E "function attendanceBadge\|function selectEmp"` |
| 数据流 | `grep -E "empSearchResults\.filter"` |

### 9.2 容易遗漏的差异类型

| 类型 | 示例 | 检测方法 |
|------|------|---------|
| **字段布局嵌套** | 性别嵌在姓名 span 内 | 对比独立 item-item 节点 |
| **图标缺失** | 性别 Badge 无 bi-gender | 原型 grep `bi-gender-` |
| **文案单/多字** | 早 vs 早班 | 对比 DOM textContent |
| **CSS 类名差异** | alert-warning vs 自定义 | 对比 class= 属性 |
| **value 回写** | 选中后 input.value 未设 | 对比 onselect 函数 |
| **图标库差异** | bi 图标 vs 自定义 SVG | 对比 `<i class="bi">` |

### 9.3 通用规则

> **100% 1:1 对齐不只是 UI 看起来一样，逻辑也要字节级匹配**：
> - 字段顺序、字段层级（独立/嵌套）
> - 文本内容（单词化/完整化）
> - 图标系统（bi-icons vs 自定义）
> - CSS 类（Bootstrap alert vs 自定义 class）
> - 数据流回写（input.value 更新）
> 任何被原型的"看起来一样"隐藏的差异都可能是 BUG 源头。
