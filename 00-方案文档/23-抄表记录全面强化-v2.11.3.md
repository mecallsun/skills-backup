## 2. 核心业务规则

### 2.1 每月每房号必须有一条记录（R-METER-NEW-01）

| 规则 | 说明 |
|------|------|
| R-METER-NEW-01 | **每月每间启用宿舍必须恰好有一条抄表记录**（无论是否已抄表） |
| R-METER-NEW-02 | 月末系统自动检查：若某启用宿舍当月无记录，自动生成 status=0（未抄表）占位记录 |
| R-METER-NEW-03 | 宿舍停用后不再为其生成占位记录 |
| R-METER-NEW-04 | 手动删除 status=0 占位记录后，系统在下一次检查时重新生成 |

**实现方式**：
- 前端原型：在 `mock-data.js` 的初始化阶段自动遍历所有启用宿舍 + 所有抄表月份，无记录则插入 status=0 占位记录（已在 v2.11.2 增补 n 中实现）
- 后端 API：新增定时任务或月末结账时调用的批处理接口，检查当月所有启用宿舍，缺失则自动创建 status=0 记录
- 数据库视图：`v_MeterRecordDetail` 需 LEFT JOIN Dorm 表，确保列出所有宿舍

### 2.2 状态机完整定义（5 状态，v2.11.3 最终版）

```
[未抄表(0)]    -- PDA 上传/后台补录/覆盖 --> [正常(1)]
[正常(1)]      -- 后台修正读数 --> [已修正(2)]
[正常(1)]      -- 重复/错误作废 --> [已作废(3)]
[未完成(4)]    -- 后台补全缺项 --> [正常(1)] 或 [已修正(2)]
[未抄表(0)]    -- PDA 上传/后台补录/覆盖 --> [正常(1)] 或 [未完成(4)]
```

| Status | 含义 | 数据完整性 | Badge 颜色 | 参与计费 | 可修正 | 可作废 | 可补录覆盖 |
|--------|------|----------|-----------|:---:|:---:|:---:|:---:|
| 0 | **未抄表** | 三表全 0 | 灰 `bg-light text-dark border` | ❌ | ❌ | ❌ | ✅ |
| 1 | **正常** | 三表完整且读数递增 | 绿 `bg-success` | ✅ | ✅ | ✅ | ❌（需先修正） |
| 2 | **已修正** | 三表完整（已修正过） | 黄 `bg-warning text-dark` | ✅ | ❌ | ❌ | ❌ |
| 3 | **已作废** | 不参与业务 | 深灰 `bg-secondary` | ❌ | ❌ | ❌ | ✅（覆盖后重建） |
| 4 | **未完成** | 部分表项=0（缺失） | 蓝 `bg-info text-dark` | ⚠️ 部分 | ❌ | ❌ | ✅（补全） |

**状态转换规则**：

| 来源状态 | 目标状态 | 触发条件 | 说明 |
|---------|---------|---------|------|
| 0 → 1 | 正常 | PDA 上传三表完整数据 / 后台手动补录三表完整 | 补录时旧数据追加到备注 |
| 0 → 4 | 未完成 | PDA 上传部分表项（1-2个表有值，其余为0） | 部分上传场景 |
| 0 → 1/4 | 正常/未完成 | 后台新增/导入覆盖 status=0 记录 | 覆盖旧数据追加到备注 |
| 1 → 2 | 已修正 | 后台修正读数（填写修正原因） | 已修正后不可再修正/作废 |
| 1 → 3 | 已作废 | 后台作废记录 | 作废后不参与计费 |
| 4 → 1 | 正常 | 后台补全未完成记录的缺失表项 | 补全后状态变正常 |
| 4 → 2 | 已修正 | 后台补全的同时修改已有读数 | 补全且有改动则变已修正 |
| 4 → 4 | 未完成 | 补全部分缺失项但仍有缺失 | 部分补全 |
| 3 → 0 | 未抄表 | 作废记录被删除/逆向恢复 | 极少场景，需权限控制 |

### 2.3 "未完成"状态明确定义（R-METER-NEW-05 ~ R-METER-NEW-08）

| 规则 | 说明 |
|------|------|
| R-METER-NEW-05 | **未完成判定**：三表中至少有一个表项读数=0 且至少一个表项读数>0 |
| R-METER-NEW-06 | 三表全 0 → status=0（未抄表），不是未完成 |
| R-METER-NEW-07 | 三表均>0 → status=1（正常）或 status=2（已修正），不是未完成 |
| R-METER-NEW-08 | 部分表项=0 且部分>0 → status=4（未完成） |

**未完成判定逻辑**：

```csharp
bool IsUnfinished(decimal cold, decimal hot, decimal electric)
{
    int nonZeroCount = 0;
    if (cold > 0) nonZeroCount++;
    if (hot > 0) nonZeroCount++;
    if (electric > 0) nonZeroCount++;
    
    // 至少一个有值，但至少一个为0
    return nonZeroCount > 0 && nonZeroCount < 3;
}
```

**各表项独立判断是否"未完成"**：

| 表项 | 未完成标志 | 用量计算 |
|------|----------|---------|
| coldMeter=0 | 冷水未完成 ⚠️ | max(0, 0 - 上月冷水读数) = **0**（永远为0） |
| hotMeter=0 | 热水未完成 ⚠️ | max(0, 0 - 上月热水读数) = **0**（永远为0） |
| electricMeter=0 | 电表未完成 ⚠️ | max(0, 0 - 上月电表读数) = **0**（永远为0） |

**用量计算统一公式（所有状态）**：

```
当月用量 = max(0, 本月读数 - 上月最近一条有效(非作废)读数)
```

**关键约束**：
- 当 status=4（未完成）时，缺失表项（读数=0）的用量强制为 0
- 即使上月读数 > 0，本月读数=0 时用量 = max(0, 0 - 上月) = 0，**永远不会出现负数**
- 正常状态（status=1/2）下，读数应 > 上月读数，用量为正数
- 异常情况（读数 < 上月）：用量强制为 0，并在备注中标注异常

### 2.4 数据覆盖与历史追加机制（R-METER-NEW-09 ~ R-METER-NEW-12）

| 规则 | 说明 |
|------|------|
| R-METER-NEW-09 | **新增/导入/补录时**：若同月份同房号已存在记录（status≠3 作废），则覆盖旧记录 |
| R-METER-NEW-10 | **旧数据快照追加到备注**：格式为 `[YYYY-MM-DD HH:mm 覆盖前数据] 字段快照` |
| R-METER-NEW-11 | **多次覆盖保留完整历史**：每次覆盖都在备注末尾追加新的历史条目 |
| R-METER-NEW-12 | **已修正(2)/已作废(3)记录不允许直接覆盖**：需先作废或走修正流程 |

**备注追加格式**：

```
[原始备注内容，如有]
[2026-07-11 14:30 覆盖前数据] cold=100.00, hot=50.00, electric=200.00, status=1, operator=陈师傅
[2026-07-12 09:15 覆盖前数据] cold=105.00, hot=55.00, electric=210.00, status=1, operator=刘师傅
```

**覆盖场景处理**：

| 场景 | 旧记录状态 | 处理方式 |
|------|----------|---------|
| PDA 上传 | status=0（未抄表） | 覆盖，旧数据追加备注 |
| PDA 上传 | status=4（未完成） | 覆盖，旧数据追加备注，标注"补全" |
| 后台手动补录 | status=0（未抄表） | 覆盖，旧数据追加备注 |
| 后台手动补录 | status=4（未完成） | 覆盖，旧数据追加备注，标注"补全" |
| 批量导入 | status=0/4 | 覆盖，旧数据追加备注 |
| 批量导入 | status=1/2 | 拦截，提示"该记录已有正常/已修正数据，请走修正流程" |
| 批量导入 | status=3 | 允许覆盖（作废记录可重建） |

public async Task<(int success, List<string> errors)> ImportAsync(
    List<MeterRecordImportDto> dtos, 
    string operatorName,
    bool allowOverwrite = false)
{
    var errors = new List<string>();
    int success = 0;
    var dormCodes = (await _db.Dorms.Where(d => d.IsActive).Select(d => d.DormCode).ToListAsync()).ToHashSet();
    var seenInFile = new HashSet<string>(); // 文件内查重

    foreach (var dto in dtos)
    {
        try
        {
            // ... 现有校验 ...
            
            // 文件内查重
            var fileKey = $"{dto.DormCode}|{dto.ReadMonth}";
            if (seenInFile.Contains(fileKey))
            {
                errors.Add($"宿舍 {dto.DormCode} 的 {dto.ReadMonth} 月份：文件内同月同房号重复");
                continue;
            }
            seenInFile.Add(fileKey);
            
            // 校验是否已有记录
            var existing = await _db.MeterRecords
                .FirstOrDefaultAsync(r => r.DormCode == dto.DormCode && r.ReadMonth == dto.ReadMonth);
            
            if (existing != null)
            {
                // 允许覆盖的场景
                if (existing.Status == 0 || existing.Status == 4 || existing.Status == 3)
                {
                    // 构建历史备注
                    var historyEntry = FormatHistoryEntry(existing);
                    dto.Remark = AppendHistory(dto.Remark, historyEntry);
                    
                    // 更新现有记录
                    existing.ColdMeter = dto.ColdMeter;
                    existing.HotMeter = dto.HotMeter;
                    existing.ElectricMeter = dto.ElectricMeter;
                    existing.Remark = dto.Remark;
                    existing.UpdatedAt = DateTime.Now;
                    
                    // 自动判定新状态
                    existing.Status = DetermineStatus(dto.ColdMeter, dto.HotMeter, dto.ElectricMeter);
                    
                    success++;
                    continue;
                }
                else
                {
                    errors.Add($"宿舍 {dto.DormCode} 的 {dto.ReadMonth} 月份：已有正常/已修正记录，无法导入");
                    continue;
                }
            }
            
            // 新建记录
            var record = new MeterRecord
            {
                DormCode = dto.DormCode,
                ReadMonth = dto.ReadMonth,
                ColdMeter = dto.ColdMeter,
                HotMeter = dto.HotMeter,
                ElectricMeter = dto.ElectricMeter,
                Operator = operatorName,
                ClientRecordId = $"import-{DateTime.Now:yyyyMMddHHmmss}-{success}",
                DeviceSn = "IMPORT",
                Remark = dto.Remark,
                Status = DetermineStatus(dto.ColdMeter, dto.HotMeter, dto.ElectricMeter),
                CreatedAt = DateTime.Now
            };
            _db.MeterRecords.Add(record);
            await _db.SaveChangesAsync();
            success++;
        }
        catch (Exception ex)
        {
            errors.Add($"导入失败：{ex.Message}");
        }
    }

    return (success, errors);
}

private byte DetermineStatus(decimal cold, decimal hot, decimal electric)
{
    int nonZeroCount = 0;
    if (cold > 0) nonZeroCount++;
    if (hot > 0) nonZeroCount++;
    if (electric > 0) nonZeroCount++;
    
    if (nonZeroCount == 0) return 0;  // 未抄表
    if (nonZeroCount == 3) return 1;  // 正常
    return 4;  // 未完成
}

## 11. 与现有模块的关系

- **宿舍档案**：MeterRecord.DormCode → Dorm；占用/停用影响占位记录生成
- **费用标准 / 宿舍账单**：仅 status=1/2 记录参与计费；status=4 部分参与；status=0/3 不参与
- **员工分摊**：基于宿舍账单分摊，受抄表状态间接影响
- **权限**：Meter:Edit（修正）、Meter:Void（作废）、Meter:Import（导入）、Meter:Add（新增/补录）、Meter:Export（导出）
