
## 1. 系统概述

### 1.1 业务定位

金戈宿舍管理系统数据采集**到**费用分摊核算**再到**人事宿舍管理**的全业务链。

**核心业务流**：
`
PDA 现场抄表 → 抄表记录(MeterRecord) → 费用标准(BillingStandard) 
    → 宿舍账单(DormBilling) → 员工分摊(EmployeeBilling) → Excel 报表 → HR 工资扣除
`

**辅助业务流**：
`
人事档案(Employee) → 办理记录(Booking) → 宿舍分配(Dorm) 
    → 入住率统计 → 费用分摊基数
`

### 1.2 系统组成

| 组件 | 技术栈 | 端口 | 职责 |
|------|--------|------|------|
| **Api 服务** | .NET 8 Minimal API | 5000 | PDA 数据上传、REST API |
| **Admin 后台** | .NET 8 MVC + Razor | 8080 | Web 管理界面 |
| **托盘程序** | .NET 8 WinForms | 桌面托盘 | 服务守护、配置管理 |
| **Bootstrapper** | .NET 8 Console | 命令行 | 一键启动所有服务 |
| **PDA App** | Android(Kotlin) | 移动端 | 现场抄表 |

### 1.3 数据库

- **引擎**: SQL Server 2017/2019（开发期可用 SQLite）
- **名称**: DormManageDB / DormManageDb
- **连接**: 192.168.1.237:1433, 账号 __DB_USER__
- **编码**: UTF-8 + Chinese_PRC_CI_AS

## 3. 业务领域模型

### 3.1 六大业务域

| 域 | 核心实体 | 业务描述 |
|----|---------|---------|
| **抄表管理** | MeterRecord, MeterImage | PDA/后台抄表、读数、用量计算 |
| **宿舍管理** | Dorm | 宿舍档案、容量、在住统计 |
| **办理记录** | DormBooking | 入住/退房/调宿全流程 |
| **人员管理** | Employee | 员工档案、考勤班次、在职状态 |
| **费用管理** | BillingStandard, DormBilling, EmployeeBilling | 费用标准、宿舍账单、员工分摊 |
| **系统设置** | SysUser, SysRole, SysPermission, SysConfig | 用户、角色、权限、配置 |

### 3.2 实体关系图（ER）

`
SysUser ──< SysUserRole >── SysRole ──< SysRolePermission >── SysPermission

Employee <─── DormBooking ───> Dorm
  │                                │
  ├──(DormCode)                    ├──(DormCode)
  │                                │
  └───< EmployeeBilling ── DormBilling ──< BillingStandard
                                    │
MeterRecord ──(DormCode)─────────────┘
  │
  └───< MeterImage
`

### 3.3 关键业务关系

1. **员工 ↔ 宿舍**: 多对多（通过 DormBooking 记录生命周期）
2. **员工类型 ↔ 费用标准**: 一对一（每种类型一个生效标准）
3. **宿舍 ↔ 账单**: 一对多（每月一条）
4. **宿舍账单 ↔ 员工账单**: 一对多（一个宿舍对应多个员工分摊）
5. **抄表记录 ↔ 账单**: 用量来源（账单用量 = 抄表读数差）

## 5. 核心业务规则

### 5.1 抄表规则

1. **唯一性**: 同一房号+月份只能有一条有效记录
2. **读数递增**: 本月读数必须 > 上月同表读数
3. **用量计算**: 用量 = 本月读数 - 上月读数（首次抄表用量为空）
4. **未完成处理**: status=4 时，缺失表项用量强制为 0
5. **覆盖历史**: 同月同房覆盖时，旧数据快照追加到 remark
6. **幂等**: PDA 上传通过 ClientRecordId 去重

### 5.2 费用标准规则

1. **单价 > 0**: 三种单价都必须大于 0
2. **一类型一标准**: 每种员工类型最多一个生效标准
3. **自动过期**: 启用新标准时，同类型旧标准自动 IsActive=false
4. **多类型共存**: 不同类型标准可同时生效

### 5.3 宿舍账单规则

1. **按月生成**: 每月每间启用宿舍一条记录
2. **用量来源**: 取该月抄表记录值
3. **覆盖生成**: 可选择覆盖已有账单
4. **发布控制**: 发布后可追踪、可撤销

### 5.4 员工分摊规则（v2.11.2 精确计算）

1. **精确公式**: 分摊 = (宿舍总费用 ÷ 当月天数) × 入住天数 ÷ ∑入住天数
2. **空床位处理**: 空床位不参与分摊
3. **调宿处理**: 跨宿舍调宿按入住段拆分多条记录
4. **类型匹配**: 按员工类型匹配费用标准，无标准则单价=0
5. **仅在职**: 仅向 Status=1（在职）员工分摊
6. **误差容限**: DECIMAL(12,2)，分摊误差允许 ±0.01 元

### 5.5 办理记录规则

1. **一进一出**: 同一员工记录按时间交替 入住→退房→入住→退房
2. **同日不重叠**: 同一天不能既有入住又有退房
3. **日期校验**: 入住日期 ≥ 入职日期；退房日期 ≤ 今天
4. **容量校验**: 入住时检查宿舍余量
5. **离职自动退宿**: 员工离职时自动创建退宿记录

### 5.6 人员筛选规则

1. **默认在职**: 列表默认仅显示 Status=1（在职）
2. **离职软删除**: 离职不物理删除，Status=2
3. **离职禁入住**: 办理入住时模糊查询仅返回在职员工
4. **住宿状态推断**: 基于最后一条办理记录动态计算

## 13. 代码优化建议

### 13.1 模型层

1. **统一字段命名**: DDL 与 Shared 模型的字段名需对齐
2. **添加 AttendanceType**: Employee 模型增加考勤班次字段
3. **创建 DormBooking 模型**: 办理记录完整 CRUD
4. **完善 MeterRecord 状态**: 增加 Status=0(未抄表)/4(未完成)
5. **EmployeeBilling 增加字段**: StayDays, StayStartDate, StayEndDate, SourceType

### 13.2 服务层

1. **精确分摊算法**: 重写 GenerateEmployeeBillingsAsync 使用天数加权
2. **办理记录校验**: 实现一进一出日期重叠校验
3. **容量校验**: 入住时检查宿舍余量
4. **调宿原子操作**: 旧记录退宿 + 新记录入住在同一事务中
5. **住宿状态推断**: 基于最后一条办理记录动态计算

### 13.3 控制器层

1. **统一错误处理**: 使用 ProblemDetails (RFC 9457)
2. **参数验证**: 使用 FluentValidation
3. **权限过滤**: 统一使用 [RequirePermission] 特性
4. **API 版本化**: 统一使用 /api/v1/ 前缀

### 13.4 视图层

1. **导航栏重构**: 按新设计实现双层导航
2. **数据看板**: 实现 6 KPI + 7 图表
3. **筛选优化**: 人员清单按 v2.11.2 规范调整
4. **分页组件**: 统一分页控件，支持 localStorage 持久化
