## 7. v2.11.2 增补 (b)：考勤班次 + 办理记录联动（2026-07-11）

### 7.1 变更背景

员工因倒班（早班/中班/晚班/夜班）作息时间差异大，混居同一宿舍时**相互影响休息**。为解决此问题，新增"**考勤班次**"字段，宿舍分配时**尽量**（非强制）安排相同考勤班次的员工同住。

### 7.2 字段定义

**表 `Personnel`** 新增 `AttendanceType` 字段：

| 取值 | 编码 | 时段 | 颜色 |
|------|------|------|------|
| 默认 | DEFAULT | 09:00-18:00 | 灰 `#6c757d` |
| 早班 | MORNING | 06:00-14:00 | 橙 `#fd7e14` |
| 中班 | MIDDLE | 14:00-22:00 | 黄 `#ffc107` |
| 晚班 | EVENING | 18:00-02:00 | 蓝 `#0d6efd` |
| 夜班 | NIGHT | 22:00-06:00 | 紫 `#6610f2` |
| 其他 | OTHER | 不定期 | 青 `#20c997` |

默认值：`DEFAULT`（早九晚五标准作息）

### 7.3 智能分配算法

按考勤班次一致性优先级：

1. **同考勤班次 + 有空位**（核心目标）
2. **任意有空位**（兜底，避免空床）

实际效果（演示数据）：

| 总宿舍数 | 完全一致（100%） | 主要一致（≥75%） |
|---------|----------------|------------------|
| 129 | **126 (97.7%)** | 126 (97.7%) |

## 9. v2.11.2 增补 (d)：住宿状态字段（2026-07-11）

### 9.1 业务背景

人员清单需要展示每位员工**当前是否在宿**的状态，但住宿状态是**派生属性**（无独立字段），需根据 BOOKINGS 表的最后一条记录动态推断。

### 9.2 住宿状态枚举

| 取值 | 编码 | 中文 | 来源（最后一条 BOOKINGS） | 颜色 Badge |
|------|------|------|-------------------------|----------|
| 在宿 | `LIVING` | 在宿 | `status=2 && type=1` | 绿 `bg-success` |
| 已退宿 | `LEFT` | 已退宿 | `status=3`（已退房） | 灰 `bg-secondary` |
| 预订中 | `BOOKED` | 预订中 | `status=1`（未入住） | 蓝 `bg-info text-dark` |
| 已取消 | `CANCELLED` | 已取消 | `status=4` | 黄 `bg-warning text-dark` |
| 无记录 | `NONE` | 无记录 | 无任何 BOOKINGS | 浅灰 `bg-light text-dark` |

### 9.3 推断算法

```javascript
function getLivingStatus(employeeId) {
    const records = BOOKINGS
        .filter(b => b.employeeId === employeeId)
        .sort((a, b) => b.bookingDate.localeCompare(a.bookingDate));
    if (records.length === 0) return 'NONE';
    const last = records[0];
    if (last.status === 4) return 'CANCELLED';
    if (last.status === 1) return 'BOOKED';
    if (last.status === 3) return 'LEFT';
    if (last.status === 2 && last.type === 1) return 'LIVING';
    return 'NONE';
}
```

### 9.6 后端 SQL 实现

```sql
SELECT
    p.*,
    COALESCE(b.LatestStatus, 'NONE') AS LivingStatus,
    b.LatestBookingDate
FROM Personnel p
LEFT JOIN (
    SELECT EmployeeId, Status AS LatestStatus, BookingDate AS LatestBookingDate,
           ROW_NUMBER() OVER (PARTITION BY EmployeeId ORDER BY BookingDate DESC) AS rn
    FROM Booking
) b ON b.EmployeeId = p.Id AND b.rn = 1
ORDER BY p.EmployeeCode;
```

## 12. v2.11.2 增补 (g)：宿舍费用 TOP10 canvas 按区域拉伸（2026-07-11）

### 12.1 问题

原 CSS `.viz-card canvas { max-height: 150px; }` 强制限制所有 canvas 最大高度 150px，导致宿舍费用 TOP10 即使位于 col-lg-6 大区域，仍只能渲染 150px 高度，未充分占用右侧区域。

### 12.2 解决方案

通过 CSS Flexbox 让 viz-card 容器能够完整填充父区域高度，再让 #chartDormCost canvas 拉伸至 100%：

```css
/* viz-card 改为 Flex 布局 */
.viz-card {
    display: flex;
    flex-direction: column;
}
.viz-card .card-header { flex-shrink: 0; }
.viz-card .card-body {
    flex: 1;
    min-height: 0;        /* 关键：允许 flex 子项收缩 */
    position: relative;
    display: flex;
    flex-direction: column;
}
/* 默认其他 canvas 仍受 max-height: 150px 限制 */
.viz-card canvas { max-height: 150px; }

/* 特殊：chartDormCost 完全填充父容器 */
#chartDormCost {
    max-height: none !important;
    width: 100% !important;
    height: 100% !important;
    flex: 1;
}
```

### 12.3 实现要点

1. **viz-card flex 布局**：`display: flex; flex-direction: column` 让卡片内容纵向排列
2. **card-body flex: 1**：占据 header 之外的剩余高度

## 16. v2.11.2 增补 (k)：员工分摊费用精确计算 + 宿舍房号筛选（2026-07-11）

### 16.1 变更背景

原 v2.11.1 员工分摊采用简化的"1/N 平均分摊"算法，存在以下问题：
1. 忽略入住天数差异（7月1日入住和7月31日入住分摊相同）
2. 未处理空床位
3. 未处理调宿（员工 7月15日调宿时分摊不正确）

本次需求修订算法，按"实际入住天数 × 日均费用 × 占比"精确计算。

### 16.2 计算公式

```
coldShare = (C_cold / T) × D_emp / S
hotShare  = (C_hot / T) × D_emp / S
elecShare = (C_elec / T) × D_emp / S

其中：
  T = 当月天数（31）
  C_cold = 该宿舍冷水表总费用
  C_hot = 该宿舍热水表总费用
  C_elec = 该宿舍电表总费用
  D_emp = 该员工在该宿舍的实际入住天数
  S = ∑(同宿舍所有员工的入住天数)
```

### 16.3 调宿处理

员工 2026-07-15 从 D-301 调到 D-302：
- **D-301 段**：7月1日-15日（15天）的费用分摊 → segmentType = `TRANSFER_OUT`
- **D-302 段**：7月16日-31日（16天）的费用分摊 → segmentType = `LIVING`

### 18.3 "入住率最低 TOP 10"算法

```sql
SELECT TOP 10 d.DormCode, d.Building, d.Capacity,
       COUNT(r.Id) AS CurrentResidents,
       CAST(COUNT(r.Id) AS DECIMAL) / d.Capacity AS OccupancyRate
FROM Dorm d
LEFT JOIN Residency r ON d.DormCode = r.DormCode AND r.Status = 1
WHERE d.IsActive = 1
GROUP BY d.DormCode, d.Building, d.Capacity
ORDER BY OccupancyRate ASC, d.DormCode ASC;
```

```javascript
function meterCoverage(readMonth) {
    const active = DORMS.filter(d => d.isActive);
    const read = new Set(METER_RECORDS.filter(m => 
        m.readMonth === readMonth && (m.status === 1 || m.status === 2)
```
