## 1. 变更背景

原 v2.11.1 员工分摊费用采用简化的"**1/N 平均分摊**"算法（同宿舍在住人员平均分摊该宿舍账单），存在以下问题：

1. **忽略入住天数差异**：7月1日入住和7月31日入住的员工分摊相同金额（不合理）
2. **未处理空床位**：4人间只有 2 人入住时，按 1/2 分摊（实际应按人天数分摊）
3. **未处理调宿**：员工 7月15日从 D-301 调到 D-302 时，原规则无法正确分摊两段入住天数
4. **缺少宿舍房号筛选**：无法快速查询某间宿舍的人员费用明细

本次需求修订算法，按**实际入住天数 × 日均费用**精确计算，并增加宿舍房号筛选。

## 3. 计算规则（核心）

### 3.1 基本公式

```
员工冷水分摊 = (当月冷水表总费用 ÷ 当月天数) × 员工入住天数 ÷ ∑(同宿舍员工入住天数)
员工热水/电分摊同理
```

### 3.2 变量定义

| 变量 | 含义 |
|------|------|
| `T` | 当月天数（30 或 31 天） |
| `C_cold` | 当月该宿舍冷水表总费用 |
| `C_hot` | 当月该宿舍热水表总费用 |
| `C_elec` | 当月该宿舍电表总费用 |
| `D_emp` | 员工在当月该宿舍的实际入住天数 |
| `S` | ∑(同宿舍所有员工的入住天数) |

### 3.3 完整公式

```
coldShare = (C_cold / T) × D_emp / S
hotShare  = (C_hot / T) × D_emp / S
elecShare = (C_elec / T) × D_emp / S
totalShare = coldShare + hotShare + elecShare
```

### 3.4 示例

**场景**：D-301 宿舍（4 人间，2026-07 月 30 天）

- 当月冷水表费用 C_cold = ¥40
- 当月热水表费用 C_hot = ¥100
- 当月电表费用 C_elec = ¥80

**入住情况**：
| 员工 | 入住起止 | 入住天数 |
|------|---------|---------|
| 张三 | 07-01 ~ 07-15 | 15 天 |
| 李四 | 07-16 ~ 07-31 | 16 天 |
| 王五 | 未入住 | 0 天 |
| 赵六 | 未入住 | 0 天 |

**总人天数 S = 15 + 16 = 31 人天**

**张三冷水分摊** = (40/30) × 15 / 31 = 1.333 × 15 / 31 ≈ **¥0.65**
**李四冷水分摊** = (40/30) × 16 / 31 = 1.333 × 16 / 31 ≈ **¥0.69**

> **对比旧算法**：旧 1/N 算法下，2 个未住满月的人按 1/4 = 0.25 平均分摊 ¥40 = ¥10/人
> **新算法按入住天数精确分摊**，避免了"住 1 天和住 30 天付同样钱"的不合理

## 4. 调宿人员处理

### 4.1 业务场景

员工张三 2026-07-15 从 D-301 调到 D-302，需要为张三生成分摊费用时：

- **D-301 段**：7月1日-15日（15天）的水/电/热费用分摊
- **D-302 段**：7月16日-31日（16天）的水/电/热费用分摊

**v2.11.2 计算规则**：调宿人员按每个房号入住记录的每段入住分别生成对应条数的记录，按房号汇总。

> 示例：张三 7月份从 D-301→D-302→D-303 调宿两次，则生成 3 条记录（D-301 入住段、D-302 入住段、D-303 入住段各 1 条）。

### 4.2 数据模型

**EmployeeBilling** 表需调整：

| 字段 | 调整 |
|------|------|
| `id` | 主键 |
| `employeeId` | 员工 ID |
| `employeeCode` / `employeeName` / `department` / `employeeType` | 员工基本信息 |
| `dormCode` | 该段入住的宿舍 |
| `billingMonth` | 计费月份 |
| `stayDays` | 该段入住天数 |
| `stayStartDate` / `stayEndDate` | 该段入住起止日期 |
| `coldShareAmount` / `hotShareAmount` / `electricityShareAmount` | 三表分摊金额 |
| `totalShareAmount` | 总分摊 |
| `isPublished` | 发布状态 |
| `sourceType` | `LIVING` 在宿 / `TRANSFER_OUT` 调出段 / `TRANSFER_IN` 调入段 |

### 4.3 示例：调宿员工分摊记录

```
| id | employeeId | employeeName | dormCode | stayDays | totalShare |
|----|-----------|--------------|----------|----------|-----------|
| 100 | 1         | 张三         | D-301    | 15       | ¥5.50      | (调出段)
| 101 | 1         | 张三         | D-302    | 16       | ¥7.20      | (调入段)
```

**算法**：
- D-301 段：基于 D-301 宿舍当月账单 + 张三在 D-301 的 15 天
- D-302 段：基于 D-302 宿舍当月账单 + 张三在 D-302 的 16 天

## 5. 空床位处理

### 5.1 业务场景

D-201 宿舍（8 人间）当月只有 3 人入住：
- 张三：全月（31天）
- 李四：全月（31天）
- 王五：半个月（15天）

### 5.2 算法验证

**总人天数 S = 31 + 31 + 15 = 77 人天**

**总床位天数**（理论最大值）= 8 × 31 = 248 床天

**冷水表费用 ¥50**：日均 ≈ ¥1.61/天
- 张三冷水分摊 = 1.61 × 31 / 77 ≈ ¥0.65
- 李四冷水分摊 = 1.61 × 31 / 77 ≈ ¥0.65
- 王五冷水分摊 = 1.61 × 15 / 77 ≈ ¥0.31

> **核心**：5 个空床位不参与分摊，按"实际入住人天数"加权

## 6. 后端 SQL 实现

```sql
-- 员工冷水分摊计算
SELECT
    e.EmployeeId,
    e.DormCode,
    e.StayDays,
    db.TotalColdAmount / :MonthDays AS DailyColdCost,
    e.StayDays * (db.TotalColdAmount / :MonthDays) AS EmpColdCost,
    SUM(e.StayDays * (db.TotalColdAmount / :MonthDays)) OVER (PARTITION BY e.DormCode) AS DormTotalCost,
    e.StayDays * (db.TotalColdAmount / :MonthDays) /
        SUM(e.StayDays * (db.TotalColdAmount / :MonthDays)) OVER (PARTITION BY e.DormCode) *
        db.TotalColdAmount AS ColdShare
FROM EmployeeBilling e
JOIN DormBilling db ON e.DormCode = db.DormCode AND e.BillingMonth = db.BillingMonth
WHERE e.BillingMonth = :Month;
```
