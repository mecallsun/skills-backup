### 1.2 启动机制的核心保证（v2.13.25 新增）

| 保证项 | 实现方式 | 触发时机 |
|--------|---------|---------|
| **数据库连通性** | `CanConnectAsync()` 探测 | Api/Admin 启动同步 |
| **关键表存在性** | EF 元数据 → `INFORMATION_SCHEMA.TABLES` 检测（SQL Server）/ `sqlite_master`（SQLite） | 启动同步 |
| **关键表自建** | SQLite：`EnsureCreatedAsync()` | 启动同步（仅 SQLite） |
| **基础字典种子** | 9 张字典表：Department/Building/Floor/EmployeeType/AttendanceType/MeterUnit/ResidenceStatus/EmploymentStatus/Team | 启动同步 |
| **默认管理员** | `admin / admin123`（SHA256(Salt+Pwd)） | 启动同步 |
| **AppVersion 登记** | 当前 DLL 版本写入 AppVersion 表（IsLatest=true） | 启动同步 |
| **FK 归一化** | `BatchNormalizeEmployeesAsync()` 后台执行 | 启动 + 5s 延迟 |
| **启动横幅** | ASCII 横幅 → LogInformation | 启动同步 |
| **优雅降级** | 任何步骤失败 → 仅记录警告，不阻塞应用 | 全流程 |

## 第二部分：DatabaseInitializer 启动校验服务

### 2.1 服务位置

`DormManage.Shared/Services/DatabaseInitializer.cs` — 新建文件，425 行

### 2.2 入口签名

```csharp
public static async Task<StartupReport> InitializeAsync(
    IServiceProvider services,
    ILogger logger,
    CancellationToken ct = default);
```

### 2.3 6 步执行流程

| # | 步骤 | 实现 | 输出 |
|---|------|------|------|
| 1 | 解析 DbContext | `services.CreateScope() + GetRequiredService<DormDbContext>()` | DbContext 实例 |
| 2 | 连通性探测 | `db.Database.CanConnectAsync(ct)` | `ConnectionOk=true/false` |
| 3 | 关键表检测 | `INFORMATION_SCHEMA.TABLES`（SQL Server）/ `sqlite_master`（SQLite） | `MissingTables=List<string>` |
| 4 | 字典种子 | 9 张字典表：Department×6/Building×3/Floor×3/EmployeeType×4/AttendanceType×3/MeterUnit×3/ResidenceStatus×3/EmploymentStatus×3/Team×5/Address×1 + BillingStandard×1 | `SeedCounts=Dictionary` |
| 5 | 默认管理员 | `SysUser{UserName=admin,PasswordHash=SHA256("WaterMeter2026"+"admin123")}` + SysRole=Admin + SysUserRole 关联 | `AdminSeeded=true/false` |
| 6 | AppVersion 登记 | `AppVersion{Version=当前DLL版本, IsLatest=true}` | `AppVersionSeeded=true/false` |

### 2.4 启动报告对象

```csharp
public class StartupReport
{
    public string Version { get; set; }             // DLL 版本号
    public string Provider { get; set; }            // SqlServer / Sqlite
    public bool ConnectionOk { get; set; }          // 连通性
    public List<string> MissingTables { get; set; } // 缺失关键表
    public bool TablesAutoCreated { get; set; }     // SQLite 自建成功
    public Dictionary<string, int> SeedCounts { get; set; }  // 字典种子计数
    public bool AdminSeeded { get; set; }           // 默认 admin 账户状态
    public bool AppVersionSeeded { get; set; }      // AppVersion 登记
    public long DurationMs { get; set; }            // 启动耗时
    public bool Healthy => ConnectionOk
                       && MissingTables.Count == 0
                       && Warnings.Count == 0;
    public string ToBanner() {...}                  // ASCII 横幅
}
```

### 4.4 修复的关键障碍

发布时遇到 NETSDK1152 错误：`ErrorOnDuplicatePublishOutputFiles: 找到多个 appsettings.json`。

**修复**：在 `DormManage.Admin/DormManage.Admin.csproj` 添加：

```xml
<ErrorOnDuplicatePublishOutputFiles>false</ErrorOnDuplicatePublishOutputFiles>
```

原因：Admin 通过 ProjectReference 引用 Api → Api 的 appsettings.json 与 Admin 自身的冲突。
此修复让 Api 的 appsettings.json 优先保留（不影响最终功能，因为 Admin 进程内托管的是 Api Controllers）。

## 第六部分：故障排查矩阵

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 启动横幅显示 "✗ FAIL" | DB 连通性失败 | 1) 检查 SQL Server 是否启动 2) 检查 db_setting.json 中的连接参数 3) 用 TrayApp 设置面板"测试连接" |

## v2.13.109 备注：SQLite Provider 彻底移除

自 v2.13.109 起，DormManage 运行时仅支持 SQL Server。SQLite 代码路径、EF Core SQLite Provider、SQLite 备份恢复逻辑均已移除。历史配置中的 SqlitePath 字段仅为旧配置反序列化兼容，不代表运行时继续支持 SQLite。生产数据库初始化以 init_schema.sql 和 SQL Server 运维脚本为准，不使用 EnsureCreated()。
