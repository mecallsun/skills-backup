## 二、实施方案

### 2.1 架构变更：表单提交从同步 POST → AJAX

**修复前**：
```html
<form method="post">
  <button type="submit">提交</button>  <!-- 同步 POST + RedirectToPage -->
</form>
```

**修复后**：
```html
<form id="entryForm">
  <input id="antiforgeryToken" value="@antiforgery.RequestToken">
  <button type="button" id="submitBtn" onclick="submitForm()">提交</button>  <!-- AJAX -->
</form>
```

**AJAX 流程**：
1. POST `/Meter/Entry?handler=SaveReadings` → JSON `{success, recordId, message}`
2. 对 3 个 `<input type="file">` 各 POST `/Meter/Entry?handler=UploadImage&recordId=X&meterType=cold|hot|electric` → JSON `{success, imageUrl}`
3. 全部成功 → `window.location.href = '/Meter'`

### 2.4 覆盖历史快照实现

```csharp
// v2.13.68 P0 修复：覆盖模式 — 旧数据追加到 Remark 历史
var snapshot = $"[{DateTime.Now:yyyy-MM-dd HH:mm} 覆盖前] " +
    $"cold={existing.ColdMeter:F2}, hot={existing.HotMeter:F2}, electric={existing.ElectricMeter:F2}, " +
    $"status={existing.Status}({existing.GetStatusName()}), operator={existing.Operator ?? "(空)"}";

    ? snapshot
    : $"{existing.Remark}\n{snapshot}";
```

### 2.5 DormDbContext 修复（副作用）

```csharp
entity.Property(e => e.Id).HasColumnName("RecordId").HasColumnType("int");
// v2.13.68：避免 EF int↔SQL BIGINT 读回类型转换异常
// （SQL 列类型 BIGINT，EF 因 C# 类型 int 会按 BIGINT 读取，再转 int cast 失败）
```

> ⚠️ **此修复只是 hint EF，治标不治本**。如生产 DB 的现有 `RecordId` 值大于 `int.MaxValue (2,147,483,647)`，EF 仍会失败。彻底解决需要把 `MeterRecord.Id` 从 `int` 改为 `long`（参见 §6 架构问题）。

## 五、教训

### 5.1 关键教训

1. **占位符首次留存 = 永久债务**：原型 `alert('原型演示...')` 看似无害，3 个月后无人记得必须补实现。CLAUDE.md 新增 P0 规则强制要求 0 命中。
2. **业务规则必须服务端实操化**：前端校验只能提建议；后端 Service 层必须独立校验（status 拦截、用量校验、读数≥上月）。
3. **表单提交优先选 AJAX**：原型设计常预设 AJAX，但 Razor Page 默认 POST + RedirectToPage。改造为 AJAX 后可分步（先保存 readings、再逐个上传照片），用户体验更好。
4. **覆盖必须保留历史**：业务场景下"覆盖"不等于"删除"。EF Core UPDATE 不会保存旧值，必须程序员主动序列化旧值到 Remark 等审计字段。

### 5.2 架构遗留问题

EF Core int↔BIGINT cast 异常：

| 项 | 现状 |
|----|------|
| **C# MeterRecord.Id** | `int`（来自 BaseEntity） |
| **SQL Server** | `BIGINT IDENTITY` |
| **冲突点** | EF SaveChangesAsync 读回 `SCOPE_IDENTITY()` → SQL 返回 BIGINT → EF 试图 cast 到 int → 失败 if value > int.MaxValue |
| **修复路径** | (a) 把 C# 改为 `long`；(b) 把 SQL 改为 `INT IDENTITY`（破坏现有数据迁移）；(c) DbContext.ValueGeneratedNever() |
| **影响范围** | 所有 `_db.MeterRecords.Add()` 路径（PdaController.Upload 也潜在） |
| **建议** | 单独 PR 修复，不要混入 v2.13.68 范围 |
