## 九、永久教训（7 条）

### 9.1 Obfuscar 实际从未自动跑 — 关键调研成果

v2.13.135 「默认未启用（避免 EF Core 反射）」实质是**机制层面未注入 MSBuild.Obfuscar NuGet**，而不是「安全考虑」。
**教训**：配置外部工具时，**「路径」和「触发」是两件事**——只设路径不触发，永远不会跑。

### 9.2 Obfuscar 白名单要「宁可多 Skip 不可漏 Skip」

EF Core / ASP.NET Core / DI 容器均强依赖完整元数据。漏 Skip 一个 Models 命名空间 → `OnModelCreating` 抛 `MissingMethodException: Cannot find property 'DormId'`。**白名单优先 + 用 SkipNamespace 整段保护 + 每次新增服务/PageModel 必须更新白名单**。

### 9.3 BitMono 仅适用单文件 EXE，ASP.NET Core 严禁使用

PE 级加壳破坏 IL 元数据，ASP.NET Core 路由 / EF 模型 / DI 构造 / Razor 绑定全依赖原始元数据，**加壳后几乎必崩**。**永久规则**：BitMono 只用于 EXE（TrayApp），ASP.NET Core 走 Obfuscar + R2R。

### 9.4 「三者同等强度」≠「三者工具相同」，分层匹配才是工程实现

不同形态（EXE vs Web）能用的工具不同。按 6 层（源码混淆 / PE 加壳 / R2R / 字符串加密 / Anti-Reflection / IL 优化）分层匹配，**让攻击难度一致**而非工具一致。

### 9.5 ConfuserEx 是「被低估的诱惑」

ConfuserEx 看起来是 BitMono ASP.NET 替代方案，但已多年未维护，**官方对 .NET 8 兼容性未验证**。工程上要**早放弃**短期诱惑。**改用 .NET 8 原生 PublishReadyToRun** 补强 Admin/Api，达到同等攻击成本。

### 9.6 反编译工具链 = 真实攻击链

验证必须用**攻击者同样的工具链**：
- **ildasm** 验 Anti-ILDasm 阻断
- **ilspycmd** 验字符串+类名可读性
- **de4dot** 验 Anti-De4dot 标签
- **strings** 验 HideStrings

每次交付自动探针存档（verify_protection.ps1 已实现）。

### 9.7 PublishReadyToRun 是「被低估」的 IL 级保护

混淆完反编译器仍能逐方法展示 IL。PublishReadyToRun=true 让 ASP.NET Core 预编译为 R2R 机器码，ILSpy 只能看到 R2R 包装层，**业务方法体几乎不可见**。与 Obfuscar 形成「重命名 + 字符串加密 + 预编译」三层防护。
