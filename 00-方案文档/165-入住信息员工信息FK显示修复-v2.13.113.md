# 入住信息员工信息 FK 显示修复 — v2.13.113

> **版本**：v2.13.113  
> **日期**：2026-07-22  
> **类型**：P0 数据展示一致性修复（v2.13.78 班组 FK + v2.13.91 班组列 + v2.13.97/111 班组列的三轮迭代遗漏：selectEmp 函数未升级到 FK 模式）

---

## 一、问题背景

### 1.1 用户原话

> "修复 入住信息录入 员工选择 张 工号:JG003032 姓名:张金文 部门: 类型: 班次: 中的 部门显示 员工 部门 id FK 的部门分列 名称；班次、班组，也同样显示；请修复这些 BUG，深度理解修复原型及程序"

### 1.2 现象

| # | 页面 | 字段 | 期望显示 | 实际显示 |
|---|------|------|----------|----------|
| 1 | 办理入住 CheckIn / 办理退房 CheckOut | 部门 | 「行政部」/「技术部」等基础资料名称 | **永远是 `-`**（默认 placeholder） |
| 2 | 办理入住 CheckIn / 办理退房 CheckOut | 类型 | 「合同工」/「临时工」等基础资料名称 | 部分显示 fallback 字符串字段 |
| 3 | 办理入住 CheckIn / 办理退房 CheckOut | 班次 | Badge「MORNING/早/中/晚/夜」 | 部分 OK，部分 fallback |
| 4 | 办理入住 CheckIn / 办理退房 CheckOut | **班组** | Badge「一班/二班/三班/...」 | **完全空白（未渲染）** |

### 1.3 根因

**v2.13.78（班组 FK 关联）** 和 **v2.13.91（宿舍详情班组列）** + **v2.13.97/111（人员清单/宿舍档案列表班组列）** 三轮迭代都在解决"班组显示"问题，但都集中在「列表页」场景。**「selectEmp 单个员工信息卡片」场景完全遗漏**：

1. **PERSONNEL mock-data 已升级到 FK 结构**：`departmentId/departmentName`、`employeeTypeId/employeeTypeName`、`attendanceTypeId/attendanceTypeName`，但**没有 `teamId/teamName` 字段**
2. **check-in.html selectEmp 函数仍读字符串字段**：
   ```javascript
   // ❌ 第 214 行 — 永远显示 '-'
   document.getElementById('empDept').textContent = emp.department || '-';
   // ❌ 第 216-218 行 — 类型 OK 但 employeeType 字符串字段 fallback 死代码
   var empTypeName = (emp.employeeTypeId != null)
       ? (EMPLOYEE_TYPES.find(...)).name
       : (emp.employeeType || '-');
   ```
3. **check-in.html emp-info-card 容器完全缺失「班组」span**（第 95-96 行只有部门/类型/班次）
4. **selectEmp 函数没有「班组」渲染逻辑**
5. **程序端 CheckIn.cshtml 第 310 行** `emp.department || '-'` —— 同样的 bug，访问的是 SysEmployee.Department 冗余字符串字段（实际生产中可能为空）

### 2.2 核心原则（FK 单一真源）

```javascript
// ❌ 之前：直接读字符串字段（mock-data 已 FK 化，字符串字段永远为空）
document.getElementById('empDept').textContent = emp.department || '-';

// ✅ v2.13.113：用 FK ID 查基础资料字典
var deptName = (emp.departmentId != null)
    ? ((DEPARTMENTS.find(function(d){return d.id === emp.departmentId;}) || {}).name || '-')
    : (emp.departmentName || emp.department || '-');
document.getElementById('empDept').textContent = deptName;

// ✅ v2.13.113：班组 Badge（新增）
var teamName = (emp.teamId != null)
    ? ((TEAMS.find(function(t){return t.id === emp.teamId;}) || {}).name || '-')
    : (emp.teamName || '-');
var teamBadge = teamName && teamName !== '-'
    ? '<span class="badge bg-primary">' + teamName + '</span>'
    : '<span class="text-muted">-</span>';
```

### 2.3 程序端 API 扩展

```csharp
// EmployeeSearchResult DTO 扩展
public int? DepartmentId { get; set; }
public string? DepartmentName { get; set; }
public int TeamId { get; set; }
public string? TeamName { get; set; }

// SearchEmployeeAsync LINQ 投影
.Select(x => new EmployeeSearchResult {
    ...
    DepartmentId = x.DepartmentId,
    DepartmentName = _db.Departments.Where(d => d.Id == x.DepartmentId).Select(d => d.Name).FirstOrDefault(),
    ...
    TeamId = x.TeamId,
    TeamName = x.Team != null ? x.Team.Name : null
})
```

## 六、核心教训

| # | 教训 |
|---|------|
| 1 | **同模式 BUG 必须全场景审计**：v2.13.78/91/97/111 都在解决「班组列显示」，但遗漏了「员工信息卡片」场景。下次任何 FK 字段升级，必须列出**所有渲染位置**逐一审计 |
| 2 | **字符串字段永远不能信任**：SysEmployee.Department 是冗余字符串字段，实际生产可能为 NULL。永远走 FK JOIN（DepartmentId → Department.Name）作为单一真源 |
| 3 | **mock-data.js 是测试用例的真相**：v2.13.78 后 PERSONNEL 应该有 teamId 字段，但实际未补。**FK 关联的所有字段必须在 mock-data 中一致**，否则前端永远 fallback 到 '-' |
| 4 | **selectEmp 是 4 字段同模式**：部门/类型/班次/班组都是「FK ID → Name」派生，必须**一次性全部升级**，避免反复打补丁 |
