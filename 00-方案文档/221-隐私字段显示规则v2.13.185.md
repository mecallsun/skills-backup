# 隐私字段显示规则（v2.13.185 系统级唯一权威源）

> **版本**：v2.13.185  
> **日期**：2026-07-27  
> **类型**：系统级字段权限规则定义  
> **用户原话**：「当 用户 所属的 角色 都没有 勾选「允许显示隐私字段」时，则 字段权限管理 的字段 对应的页面 中不显示 相应的字段；当用户所属的 角色 中有任一角色 有勾选「允许显示隐私字段」时，则 字段权限管理 清单中的 字段 对应 的页面 都显示 相应 的字段」

---

## ⚠️ 唯一权威规则（v2.13.185）

### 1. 核心规则（任一角色 OR 语义）

| 用户角色状态 | 隐私字段显示行为 |
|------------|---------------|
| 用户的**所有**角色都未勾选「允许显示隐私字段」 | **隐藏** 所有隐私字段（deny-by-default） |
| 用户的**任一**角色勾选了「允许显示隐私字段」 | **显示** 所有隐私字段（allow-by-any-role） |

### 2. 数据模型

| 表 | 关键字段 | 说明 |
|---|---------|------|
| `SysPermission` | `PermissionCode = "privacy:field:enable"` | 「允许显示隐私字段」权限码（Id=39, PermissionType=3 数据权限） |
| `SysRolePermission` | `(RoleId, PermissionId=39)` 行存在 | 该角色被授权 |
| `SysUserRole` | `UserId` ↔ `RoleId` 多对多关联 | 用户拥有的角色 |
| `SysFieldPermission` | `IsActive=true` | 字段被纳入"默认隐藏清单"（v2.13.176 deny-by-default 翻转后） |

### 3. 核心代码路径（实测已正确实现 OR-across-roles）

#### 3.1 `PermissionService.GetUserPermissionCodesAsync(userId)`
**位置**：`DormManage.Shared/Services/PermissionService.cs:57-68`

```csharp
public async Task<HashSet<string>> GetUserPermissionCodesAsync(int userId)
{
    var codes = await (
        from p in _db.SysPermissions
        join rp in _db.SysRolePermissions on p.Id equals rp.PermissionId
        join ur in _db.SysUserRoles on rp.RoleId equals ur.RoleId
        where ur.UserId == userId && p.IsActive
        select p.PermissionCode
    ).Distinct().ToListAsync();
    return new HashSet<string>(codes);
}
```

**关键设计**：三表 JOIN + `Distinct()` 天然实现 **OR-across-roles** 语义 —— 用户任一角色拥有 `privacy:field:enable` PermissionCode 即视为用户拥有该权限。

#### 3.2 `PermissionService.AllowDisplayPrivacyFieldsAsync(userId)`
**位置**：`DormManage.Shared/Services/PermissionService.cs:163-168`

```csharp
public async Task<bool> AllowDisplayPrivacyFieldsAsync(int userId)
{
    if (userId <= 0) return false;
    var codes = await GetUserPermissionCodesAsync(userId);
    return codes.Contains(PrivacyFieldPermissionCode);  // "privacy:field:enable"
}
```

#### 3.3 `PermissionService.GetHiddenFieldKeysAsync(userId)`
**位置**：`DormManage.Shared/Services/PermissionService.cs:174-188`

```csharp
public async Task<HashSet<string>> GetHiddenFieldKeysAsync(int userId)
{
    if (!await AllowDisplayPrivacyFieldsAsync(userId))
    {
        var allActiveKeys = await _db.SysFieldPermissions
            .Where(p => p.IsActive)
            .Select(p => p.FieldKey)
            .ToListAsync();
        return new HashSet<string>(allActiveKeys);  // 隐藏
    }
    return new HashSet<string>();  // 显示
}
```

## 二、关键事实

### 1. OR-across-roles 自然实现

`GetUserPermissionCodesAsync` 使用 `Distinct()` 在 `SysPermission × SysRolePermission × SysUserRole` JOIN 上 → 用户**任一**角色拥有 `privacy:field:enable` 即返回 true。

无需额外修改代码逻辑：**当前代码已正确实现用户最新需求**。

### 2. deny-by-default vs allow-by-any-role

- **deny-by-default**（v2.13.176 翻转后）：未授权 → 隐藏所有 IsActive=true 字段
- **allow-by-any-role**（v2.13.185 显式化）：任一角色授权 → 显示所有字段

### 3. 缓存机制

`HttpContext.Items["__FIELD_HIDDEN_KEYS__"]` 缓存每请求只查一次 DB。

### 4. 字段清单（v2.13.180 全量扩展，21 个）

按 Module 分组：
- **Personnel**（9）：`employee.realname/phone/employeecode/dormcode/remark/idnumber/hiredate/leavedate/employeetype`
- **Booking**（5）：`booking.realname/employeecode/dormcode/department/operator`
- **Dorms**（3）：`dorm.address/capacity/currentcount`
- **Meter**（1）：`meter.operator`
- **EmployeeBilling**（3）：`billing.realname/employeecode/dormcode`

## 四、v2.13.185 永久教训

1. **OR-across-roles 自然实现原理**：使用 `Distinct()` + 三表 JOIN 是最简单且性能最优的实现方式。如果未来规则改为"所有角色都需勾选"，只需将 `Distinct()` 改为聚合函数（如 `Count()`）即可。

2. **deny-by-default 是安全设计**：v2.13.176 翻转后从 allow 改 deny，避免新创建角色自动看到 PII 字段的安全漏洞。

3. **缓存键设计**：`HttpContext.Items["__FIELD_HIDDEN_KEYS__"]` 缓存 HashSet 是同一请求内多次 `IsFieldHiddenAsync` 调用的性能优化（避免每个列渲染都查 DB）。

4. **SysRolePermission 删除逻辑**：RolePanelPartial.cs 的 `OnPostRoleSavePermissionsAsync` 使用 `RemoveRange` 先全删后重建，确保 uncheck "允许显示隐私字段" 立即生效（依赖 step 1 已清空）。
