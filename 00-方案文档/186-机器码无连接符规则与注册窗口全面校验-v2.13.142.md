## 二、根因分析（4 个问题）

### 2.1 P0 机器码显示带连字符

**v2.13.138 引入错误**：`MachineCodeProvider.FormatDisplayStyle` 把 raw 24 hex 格式化为 28 字符 display 形式（5-5-5-5-4），并把 display 形式写入 machine.dat。

**v2.13.141 验证日志**：
```
[INFO] [LICENSE] 已初始化：BFEBF-BFF00-0A06A-4AA2E-3B0E   ← ❌ 带连字符，违反规则
```

**链路**：
1. `MachineCodeProvider.Initialize()` → `ComputeRawMachineCode()` → raw 24 hex
2. `FormatDisplayStyle(raw)` → 错误格式化 → display 28 字符
3. `RegisterSdk.WriteMachineSN(display)` → 写入 machine.dat + ENV
4. `LicenseForm.textSN.Text = reg.SN` → 显示 display

**用户预期链路**：
1. `MachineCodeProvider.Initialize()` → raw 24 hex ✅
2. **不再调用任何格式化** ✅
3. `RegisterSdk.WriteMachineSN(raw)` → 写入 raw ✅
4. `LicenseForm.textSN.Text = _rawSN` → 直接显示 raw ✅

### 2.2 P1 LicenseForm 二次格式化（错位）

`LicenseForm.cs` 之前保留的 `FormatMachineCodeDisplay` 把 28 字符 display 当 raw 处理（再分组），产生 35+ 字符错位。

### 2.3 P1 RegisterSdk.cs 残留过时注释 + 死代码

3 处遗留：
- Line 67-68：注释提到已删除的 `LicenseForm.FormatMachineCodeDisplay`
- Line 105-108：注释提到已删除的 `MachineCodeProvider.FormatDisplayStyle`
- Line 504：`FormatCDKeyStyle` 未使用死代码

### 2.4 P1 部署路径默认值错误

**AppConfig.cs 默认值**：
```csharp
public string ApiExecutable { get; set; } = "Api\\DormManage.Api.exe";        // ❌ 错误（相对自身）
public string AdminExecutable { get; set; } = "Admin\\DormManage.Admin.exe";  // ❌ 错误
```

## 四、注册码（CDKEY）校验规则一并确认

### 4.1 长度规则（与机器码区分）

| 类型 | 长度 | 说明 |
|------|------|------|
| **机器码（SN）** | 24 hex | CPUID(16) + VolumeSerialNumber(8) 拼接 + Substring(0, 24) |
| **注册码（CDKEY）** | 25 hex | 验证段(20) + 日期段(5)，MD5(SN+LTDName+SECRET_KEY) 前 20 位 + 过期日 Unix 时间戳前 5 hex |

### 4.2 CDKEY 校验 4 件套（v2.13.142 已具备）

`RegisterSdk.CheckRegCDKey` 校验链：
1. **长度**：`Replace("-", "").Length == 25`
2. **字符集**：`0-9 A-F` 大写 hex（`TryNormalizeCDKey` 自动 upper + 去连字符）
3. **MD5 验证**：`(SN + "|" + LTDName + "|" + SECRET_KEY)` MD5 前 20 位 == CDKEY[0:20]
4. **日期段**：CDKEY[20:25] hex → Unix timestamp → 过期日 < 今天 = 拒绝

### 4.3 输入 UX（v2.13.142 已具备）

`LicenseForm.Text_CDKEY_KeyPress`：每输入 5 个字符自动补 `-`：
- 用户输入 `ABCDE12345` → UI 显示 `ABCDE-12345`
- 业务校验前 `Replace("-", "")` → `ABCDE12345` 25 字符
- 同时支持「无连字符 raw 25 输入」与「带连字符 29 字符输入」

## 六、永久教训（4 条）

### 6.1 显示格式化必须由 UI 层唯一负责

v2.13.138 在 `MachineCodeProvider`（业务/存储层）错误地做了展示格式化。**业务/存储/IPC 层必须恒用 raw 24 hex**，展示格式化只能在 UI 层（且必须是可逆的，仅展示时格式化）。

**检验原则**：
- `Clipboard.SetText(_rawSN)` 而非 `_displaySN`
- `File.WriteAllText(MACHINE_FILE, raw)` 而非 `display`
- `Environment.SetEnvironmentVariable(ENV_MACHINE_SN, raw)` 而非 `display`

### 6.2 默认值必须与外部配置一致

`AppConfig.cs` 默认值与 `appsettings.json` 不一致 → ConfigService 首次启动写默认值会覆盖正确配置。**经验法则**：默认值应该与 appsettings.json 字节级一致（或根本不提供默认值让 JSON 必须存在）。

### 6.3 注释与死代码同步清理

`FormatCDKeyStyle` 与 `FormatMachineCodeDisplay` 已删除但注释还提到 → 误导后续开发者。**删除方法时**：
1. 全局 `grep` 该方法名
2. 删除方法 + 清理所有相关注释
3. 确认无调用点

### 6.4 用户规则必须按用户原话实现

用户原话「机器码显示没有连接符」+ 反例正例对照 → 必须严格按 raw 实现。**不可**自行添加「为了视觉效果」的格式化（如 5-5-5-5-4 分组）。

NPGS.Register 参考项目 `RegisterForm.cs:62` 的 `textSN.Text = SN` 正是无格式化直接显示，是工业界的成熟实践。
