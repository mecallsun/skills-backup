## 二、深度根因排查

### 2.1 BUG 1：启用勾选不保存

#### 2.1.1 旧代码 Edit.cshtml line 56-63

```html
<input type="hidden" asp-for="Input.IsActive" value="false" />
<input asp-for="Input.IsActive" type="checkbox" class="form-check-input" />
```

**根因**：`asp-for="Input.IsActive"` 在 hidden field 上会根据**当前 ModelState 值**渲染 `value` 属性。例如当 `Input.IsActive=false` 时，ASP.NET 渲染 `<input type="hidden" name="Input.IsActive" value="false" />`，**覆盖了静态 value="false"**。

当用户勾选后提交，表单字段顺序：
```
Input.IsActive=false  ← 来自 hidden
Input.IsActive=true   ← 来自 checkbox
```

ASP.NET ModelBinder 默认取**第一个**值（按 form 字段顺序），所以 `Input.IsActive=false` 被绑定，导致用户勾选无效。

#### 2.1.2 BillingStandard.cs 的 `new` 关键字冲突

```csharp
// 旧代码
public new bool IsActive { get; set; } = true;  // 隐藏 BaseEntity.IsActive
```

**根因**：`new` 关键字在 EF Core 物化时与 BaseEntity.IsActive 产生属性映射冲突。EF Core 反射时只跟踪其中一个属性，导致 `existing.IsActive = standard.IsActive` 写入与 BaseEntity.IsActive 不同步。

### 2.2 BUG 2：适用员工类型无 FK 关联

#### 2.2.1 旧代码 Create/Edit.cshtml line 44-54

```html
<input asp-for="Input.ApplicableType" class="form-control" list="applicableTypeList" />
<datalist id="applicableTypeList">
    <option value="合同工"></option>
    <option value="临时工"></option>
    ...
</datalist>
```

**根因**：
1. datalist 选项是**前端硬编码**的 5 种类型，不与后端 EmployeeType 字典同步
2. 保存的是 `ApplicableType` Name 字符串（"合同工"），不是 FK Id
3. 没有 FK 约束保证 EmployeeType 字典的存在性
4. 数据冗余：删除字典中的"实习生"后，旧的 BillingStandard.ApplicableType="实习生" 失去关联

#### 2.2.2 数据库现状（修复前）

```sql
SELECT Id, StandardName, ApplicableType, IsActive FROM BillingStandard ORDER BY Id
  Id=1, name='合同工水电气单价', ApplicableType='合同工', IsActive=False
  Id=2, name='临时工水电气单价', ApplicableType='临时工', IsActive=False
  Id=3, name='外包人员水电气单价', ApplicableType='外包', IsActive=False
```

## 三、修复方案

### 3.1 SQL 修复（P0 数据迁移）

#### 3.1.1 添加 ApplicableTypeId 列 + 数据迁移

```sql
-- 1. 添加 ApplicableTypeId 列
ALTER TABLE dbo.BillingStandard ADD ApplicableTypeId INT NOT NULL DEFAULT 0;

-- 2. 数据迁移：根据现有 ApplicableType 字符串匹配 EmployeeType.Name → EmployeeType.Id
UPDATE b SET b.ApplicableTypeId = e.Id
FROM dbo.BillingStandard b
INNER JOIN dbo.EmployeeType e ON b.ApplicableType = e.Name
WHERE b.ApplicableTypeId = 0;
-- Migrated rows: 3

-- 3. 添加 FK 约束
ALTER TABLE dbo.BillingStandard WITH CHECK
ADD CONSTRAINT FK_BillingStandard_EmployeeType
FOREIGN KEY (ApplicableTypeId) REFERENCES dbo.EmployeeType(Id)
ON DELETE NO ACTION ON UPDATE NO ACTION;
```

执行结果：
- ✅ ApplicableTypeId 列已添加
- ✅ 3 行数据迁移完成（Id=1→1, Id=2→2, Id=3→3）
- ✅ FK 约束 FK_BillingStandard_EmployeeType 创建成功

## 八、教训总结（v2.13.61）

### 8.1 三个核心失误

1. ❌ **`asp-for` 在 hidden field 上会被 ModelState 覆盖** — 启用勾选永远 false
2. ❌ **`new` 关键字在 EF Core 模型中与基类属性冲突** — 字段映射不可靠
3. ❌ **适用员工类型硬编码 datalist** — 不符合基础资料真源原则

### 8.2 后续强制检查清单（表单持久化）

- [ ] HTML hidden field 用于 checkbox fallback 时，**使用 `name` 属性而非 `asp-for`**
- [ ] EF 模型字段避免 `new` 关键字（直接继承基类即可）
- [ ] 字典类数据必须使用 FK 关联（Id），禁止冗余字符串字段

### 8.3 运维强制检查清单（生产数据库迁移）

- [ ] 添加 FK 列时同步建立 FK 约束（数据完整性）
- [ ] SQL 数据迁移用 INNER JOIN + WHERE 0 兜底（避免历史数据 NULL）
- [ ] 删除字典项时考虑 ON DELETE 策略（NO ACTION 保护历史数据）
