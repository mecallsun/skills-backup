## Hotfix #1：隐私字段语义翻转（核心逻辑修复）

### 用户报告

> 在隐私字段管理清单中已勾选的「宿舍档案」模块中，「容量」、「在住人数」字段对于未授权「允许显示隐私字段」的角色（如行政助理）仍然显示，存在 BUG。

### 调查路径（5 层深度排查）

| 层 | 验证项 | 结果 |
|----|--------|------|
| 1️⃣ | SysFieldPermission 表是否配置 dorm.capacity + dorm.currentcount | ✅ 配置正确 |
| 2️⃣ | Dorms/Index.cshtml 是否调用 IsFieldHiddenAsync | ✅ 调用了 6 处 |
| 3️⃣ | IsFieldHiddenAsync → PermissionService.GetHiddenFieldKeysAsync 调用链 | ✅ 调用链正确 |
| 4️⃣ | GetHiddenFieldKeysAsync → HasPrivacyFieldEnabledAsync → codes.Contains | ✅ 调用正确 |
| 5️⃣ | **核心问题**：`HasPrivacyFieldEnabledAsync` 语义**反向** | ❌ **BUG** |

### 根本原因（关键发现）

**v2.13.176 的 deny-by-default 设计仅存在于文档（216 文档），代码层从未实施！**

#### 文档预期（v2.13.176）

| 维度 | 文档预期（v2.13.176） |
|------|------------------------|
| 权限 PermissionName | 允许显示隐私字段 |
| 默认状态 | 不勾选 = 隐藏全部（deny） |
| 勾选后行为 | 看到所有字段 |
| 不勾选行为 | 看不到所有 IsActive=true 字段 |

#### 实际代码（v2.13.92 实现）——**语义相反！**

```csharp
// v2.13.92 原始实现（v2.13.176 翻转未实施）
public async Task<HashSet<string>> GetHiddenFieldKeysAsync(int userId)
{
    // 默认：用户无隐私权限 → 不隐藏任何字段 ← ❌ BUG：应为"隐藏所有"
    if (!await HasPrivacyFieldEnabledAsync(userId)) return new HashSet<string>();

    // 启用隐私权限 → 拉取所有 IsActive=true 的字段键 ← ❌ BUG：应为"不隐藏"
    var activeKeys = await _db.SysFieldPermissions
        .Where(p => p.IsActive)
        .Select(p => p.FieldKey)
        .ToListAsync();

    return new HashSet<string>(activeKeys);
}
```

**结果**：
- 用户未勾选「允许显示隐私字段」→ 实际**显示**所有字段 ← **反了！**
- 用户勾选了 → 实际**隐藏**所有字段 ← **反了！**

这解释了为什么 test 用户（行政助理角色，未勾选隐私权限）仍然能看到容量在住人数。

### 实施方案（v2.13.193）

#### 修复 1：核心代码翻转（PermissionService.cs）

```csharp
// v2.13.193 翻转：HasPrivacyFieldEnabledAsync → AllowDisplayPrivacyFieldsAsync（语义反转）

/// <summary>
/// v2.13.176 翻转：是否允许显示隐私字段（v2.13.92 是 HasPrivacyFieldEnabledAsync，语义相反）
/// 勾选 → 允许显示所有隐私字段
/// 不勾选 → 全部隐藏（deny-by-default）
/// </summary>
public async Task<bool> AllowDisplayPrivacyFieldsAsync(int userId)
{
    if (userId <= 0) return false;
    var codes = await GetUserPermissionCodesAsync(userId);
    return codes.Contains(PrivacyFieldPermissionCode);
}

/// <summary>
/// v2.13.176 翻转：获取应该隐藏的字段集合
/// v2.13.92 旧逻辑（有 BUG）：勾选权限 → 隐藏所有字段；不勾选 → 显示所有字段
/// v2.13.176 新逻辑（已修复）：不勾选 → 隐藏所有 IsActive 字段（deny-by-default）；勾选 → 不隐藏任何字段
/// </summary>
public async Task<HashSet<string>> GetHiddenFieldKeysAsync(int userId)
{
    // v2.13.176 deny-by-default：不勾选 → 隐藏所有 IsActive=true 的字段
    if (!await AllowDisplayPrivacyFieldsAsync(userId))
    {
        var allActiveKeys = await _db.SysFieldPermissions
            .Where(p => p.IsActive)
            .Select(p => p.FieldKey)
            .ToListAsync();
        return new HashSet<string>(allActiveKeys);
    }

    // 勾选了「允许显示隐私字段」 → 不隐藏任何字段
    return new HashSet<string>();
}
```

## Hotfix #2：发布目录双胞胎陷阱（部署架构修复）

### 用户报告

> 在宿舍详情/当前入住人员 页面，没有显示员工性别列，床号列也没去掉「床位」文字。

### 根本原因

**项目存在两套发布目录，但发布脚本只更新了一处！**

```
release/
└── latest/
    ├── Admin/         ← 开发者发布时更新
    │   └── DormManage.Admin.dll  (v2.13.192 16:01)
    └── TrayApp/
        └── Admin/     ← TrayApp 实际加载的子目录
            └── DormManage.Admin.dll  (旧版 09:50 ← 未更新！)
```

**TrayApp 使用相对路径 `..\Admin\`**，实际加载 `release/latest/TrayApp/Admin/` 而不是 `release/latest/Admin/`。

### 实施方案

#### 修复 1：新建同步脚本

**文件**：`scripts/sync_publish_to_trayapp.sh`

```bash
#!/bin/bash
# sync_publish_to_trayapp.sh — 发布后必须执行
# 用法：./sync_publish_to_trayapp.sh [--skip-build]

# Step 1: Build all projects
dotnet build DormManage.sln -c Release

# Step 2: Publish all projects
dotnet publish DormManage.Api/DormManage.Api.csproj -c Release -r win-x64 --self-contained true -o release/latest/Api
dotnet publish DormManage.Admin/DormManage.Admin.csproj -c Release -r win-x64 --self-contained true -o release/latest/Admin
dotnet publish DormManage.TrayApp/DormManage.TrayApp.csproj -c Release -r win-x64 --self-contained true -o release/latest/TrayApp

# Step 3: Sync DLLs + Pages to TrayApp's sibling dirs
cp -f release/latest/Admin/DormManage.Admin.dll         release/latest/TrayApp/Admin/
cp -f release/latest/Admin/DormManage.Admin.pdb         release/latest/TrayApp/Admin/
cp -f release/latest/Admin/DormManage.Shared.dll        release/latest/TrayApp/Admin/
cp -rf release/latest/Admin/Pages                       release/latest/TrayApp/Admin/

cp -f release/latest/Api/DormManage.Api.dll             release/latest/TrayApp/Api/
cp -f release/latest/Api/DormManage.Api.pdb             release/latest/TrayApp/Api/
cp -f release/latest/Api/DormManage.Shared.dll          release/latest/TrayApp/Api/

# Step 4: Verify sync
echo "=== Verify ==="
grep -c "resident.Gender" release/latest/TrayApp/Admin/Pages/Dorms/Details.cshtml
# Should be >= 2 (table header + data row)
```

## 永久教训

### 教训 1：文档与代码必须同步实施

v2.13.176 设计了 deny-by-default，但**代码层从未真正实现**。这是「文档先行于实现」的典型陷阱：
- 文档是「目标」
- 代码是「现实」
- 文档和代码不一致时，BUG 已经在生产中潜伏

**强制规则**：任何「v2.13.x 翻转」的文档必须在同一版本中包含代码改动 commit，不允许仅修改文档。

### 教训 2：发布目录双胞胎陷阱

v2.13.184 强托管规则规定 TrayApp 通过相对路径加载子目录，但发布脚本默认输出到 `release/latest/{项目名}/`，导致**两套发布目录不一致**。

**强制规则**：发布脚本必须同步到 TrayApp 兄弟目录，禁止单独 `dotnet publish`。

### 教训 3：方法命名必须反映语义

`HasPrivacyFieldEnabledAsync` → `AllowDisplayPrivacyFieldsAsync`：
- 旧名称"模糊不清"，可能让人误解语义
- 新名称"明确表达含义"——勾选 → 允许显示

**强制规则**：方法名必须明确表达行为，特别是涉及布尔返回的语义方法。

### 教训 4：跨权限测试才能发现 BUG

**为什么 admin 看不到 BUG**：admin 角色拥有所有权限，包括 `privacy:field:enable`，所以 `AllowDisplayPrivacyFieldsAsync` 返回 true → 字段不隐藏。

**为什么 test 用户能发现 BUG**：test 用户（行政助理）未勾选该权限 → 应该隐藏字段 → 但实际未隐藏。

**强制规则**：任何权限/隐私类修改必须用「未授权角色」做 E2E 测试，不能只看 admin 用户。
