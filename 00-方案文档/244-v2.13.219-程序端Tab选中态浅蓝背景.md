## 7. 永久教训（v2.13.219+ 强制沉淀）

### 7.1 **程序端 vs 原型端必须同步修改**

v2.13.217 我只改了 `_shared/layout-tab.css`（原型用），但程序端 `_Layout.cshtml:138-151` 仍是 v2.13.216 旧版。**任何 UI 修改必须同时改原型 + 程序两份文件**，否则用户实测会发现「程序没有一致界面效果」。

### 7.2 **DOM/JS 逻辑已正确，仅 CSS 缺失**

本次根因不是 DOM 结构问题（active class 应用正确），**也不是 JS 逻辑问题**（路径匹配正确），**仅是 CSS 未同步**。修复方案：只改 CSS 1 处，其他无需改。

### 7.3 **修改前先 grep 验证「全站一致」**

未来做 UI 调整时，应先 grep 查找所有包含 `.tab-item` 或 `.tab-bar` 的文件，确保「单点修改 + 跨文件同步」。本次修复前我应该 grep 看到 `_Layout.cshtml` 也有 `.tab-item` 才不至于遗漏。

### 7.4 **v2.13.217 交付报告「不在本次范围」要明确**

v2.13.217 交付报告（242 文档）明确写了「不在本次范围：v2.13.219 程序端同步」，并标注「先原型后程序：本次仅原型，程序端留待 v2.13.218/v2.13.219」。这种「阶段性发布」要主动追踪后续版本落地。

### 7.5 **保留兼容代码作为历史文档**

与 v2.13.217 一致，5 种模块分组配色的 CSS 规则**保留但标记「已不再生效」**，作为 v2.13.x 风格历史可追溯。
