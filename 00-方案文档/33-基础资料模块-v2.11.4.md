## 1. 概述

### 1.1 业务定位

基础资料是系统的基础数据配置模块，用于集中维护各功能页面中**固定下拉选项值**的数据字典。避免在多个页面中硬编码维护，提高数据一致性和可维护性。

### 1.2 功能范围

| 分类 | 包含项 | 用途页面 |
|------|--------|---------|
| **部门管理** | 部门列表（增删改） | 人员清单、办理登记、宿舍账单 |
| **楼栋管理** | 楼栋列表（增删改） | 宿舍列表、宿舍账单 |
| **楼层管理** | 楼层列表（增删改） | 宿舍列表 |
| **宿舍地址管理** | 地址列表（增删改） | 宿舍档案 |
| **员工类型管理** | 类型列表（增删改） | 人员清单、费用标准 |
| **考勤班次管理** | 类型列表（增删改） | 人员清单、宿舍详情 |
| **员工班组管理** | 班组列表（增删改） | 人员清单筛选与列表、新增/编辑员工表单 |
| **计量单位管理** | 单位列表（增删改） | 抄表记录（m³/度） |
| **住宿状态管理** | 状态列表（增删改） | 人员清单（住宿筛选）、宿舍详情 |
| **在职状态管理** | 状态列表（增删改） | 人员清单（状态筛选）、员工账单 |
| **设备档案管理**（v2.13.120 新增）| **设备档案列表（与 Dorm 1:1）** | **宿舍档案（房号 FK）** |
| **设备记录管理**（v2.13.130 新增）| **设备读数日志列表（CRUD + 批量删除）** | **智能抄表、设备档案（日志 ↔ 配置对账）** |

### 3.11 设备档案表 (DormMeter)（v2.13.120 新增 — 与 Dorm 1:1 关系）

| 字段 | 类型 | 说明 |
|------|------|------|
| DormMeterId | int IDENTITY | 主键（自增） |
| DormId | int FK NOT NULL | 房号 FK → Dorm.DormId（**UNIQUE 1:1 唯一约束**，`UX_DormMeter_DormId`）|
| ElectricMeterId | nvarchar(64) NULL | 电表 ID/编号（现场标识）|
| ColdWaterMeterId | nvarchar(64) NULL | 冷水表 ID/编号 |
| HotWaterMeterId | nvarchar(64) NULL | 热水表 ID/编号 |
| Remark | nvarchar(500) NULL | 备注 |
| IsActive | bit NOT NULL DEFAULT 1 | 是否启用 |
| CreatedAt | datetime NOT NULL DEFAULT GETDATE() | 创建时间 |
| UpdatedAt | datetime NULL DEFAULT GETDATE() | 更新时间 |

**关键约束**：
- **R1 1:1 唯一**：`UX_DormMeter_DormId UNIQUE (DormId)` —— 同一房号只能配置 1 条设备档案
- **R2 删除宿舍级联**：`FK ON DELETE CASCADE` —— 删除 Dorm 时 DormMeter 自动清理（无需应用层代码）
- **R3 房号下拉过滤**：列表/表单中所有 Dorm 自动标注「已配置」便于辨识
- **R4 字段全可选**：电/冷/热 3 表 ID 均可为空（不强求三表齐全）
- **R5 列表 JOIN Dorm 取 DormCode/BuildingName/FloorNo**（10 列：ID/房号/楼栋/楼层/电表ID/冷水ID/热水ID/备注/更新时间/操作）

**5 字段权限**：`device:view`/`device:create`/`device:edit`/`device:delete`/`device:export`（SysPermission Id 42-45）

### 3.12 设备读数日志表 (EquipmentReading)（v2.13.130 新增 — 三层数据模型日志层）

**业务定位**：设备读数日志（v2.13.130）是「设备数据」三层递进抽象的**日志层**：
- **配置层**（v2.13.120 DormMeter）：静态映射（房号 ↔ 表 ID 1:1）
- **日志层（本次 v2.13.130）**：动态流水（设备某时间点的一次读数）
- **聚合层**（v2.13.96 MeterRecord）：月度聚合统计（FK → DormId）

**关键设计原则**：**EquipmentReading 不 FK 到 DormMeter**。原因：
1. PDA 端离线模式抄表：可能 DormMeter 还未配置
2. PDA 自动入库：直接走 EquipmentReading 日志层
3. 手工补录：操作员直接录入日志，无需先建 DormMeter

**字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| ReadingId | INT IDENTITY | PK | 主键 |
| EquipmentId | NVARCHAR(64) | ✓ | 设备 ID（电表/冷水/热水表编号）|
| EquipmentType | TINYINT | ✓ | 1=电表 2=冷水 3=热水 |
| Reading | DECIMAL(12,2) | ✓ | 读数（精度 2 位小数）|
| ReadTime | DATETIME | ✓ | 读取时间（业务读取时刻）|
| Remark | NVARCHAR(500) | ✗ | 备注 |
| CreatedBy | NVARCHAR(64) | ✗ | 记录创建人（SysUser 名称，审计字段）|
| CreatedAt | DATETIME | ✓ | 创建时间（GETDATE 默认值）|
| UpdatedAt | DATETIME | ✗ | 更新时间 |

**索引策略**：
- `IX_EquipmentReading_EquipmentId`：查某设备最新读数
- `IX_EquipmentReading_ReadTime`：按时间段查询/批量删除
- `IX_EquipmentReading_Type_Time`：按类型 + 时间段聚合（复合索引）

**CHECK 约束**：`CK_EquipmentReading_Type` (`EquipmentType BETWEEN 1 AND 3`)

**5 字段权限**：`equipment-reading:view`/`equipment-reading:create`/`equipment-reading:edit`/`equipment-reading:delete`/`equipment-reading:batch-delete`（SysPermission Id 46-50）

**8 列表列**：序号 / 设备ID / 设备类型Badge / 读数 / 读取时间 / 备注 / 创建人 / 操作

## 10. v2.11.7.BUGFIX 关联关系错误更正（强制补充）

> **⚠️ 重要历史修正**：本节新增于 v2.11.7（2026-07-12），记录真实数据中发现的关联关系错误及修复方案。**强烈建议**本节作为后续所有基础资料模块相关功能开发的核心参考。

### 10.1 错误场景描述

工号 `EMP-2026-228`（员工姓名：马欣）的员工档案数据：
```javascript
{
    "id": 228,
    "employeeCode": "EMP-2026-228",
    "attendanceType": "MIDDLE"     // ← 只用旧字符串字段
    // ❌ 缺少 attendanceTypeId FK 字段
}
```

在 `dorm-bills.html` 宿舍账单明细弹窗中点击"详情"按钮，该员工的"考勤班次"列显示 `-`（而非"中班"）。

**根因**：
- `mock-data.js` PERSONNEL 数组存在**数据格式不一致**问题
- 619 条记录使用旧格式 `attendanceType: "MIDDLE"`（字符串代码）
- 仅 31 条记录使用新格式 `attendanceTypeId: 3`（FK）
- v2.11.7 引入的 FK 关联引用代码在 95% 员工记录上失效

| 2 | SysEmployee.员工类型字段 | 应为 `EmployeeTypeId` INT FK | 5 条使用旧字段，31 条使用 FK | 同上 |

### 10.3 修正方案

#### 10.3.1 mock-data.js 数据规范化 IIFE

**位置**：`mock-data.js` 文件末尾（`EMPLOYEE_BILLS_202607` 数组之后）

**实现**：

```javascript
(function normalizeData() {
    'use strict';
    if (typeof PERSONNEL === 'undefined') return;

    // 1. 考勤班次补全（旧字符串 → FK + Name）
    PERSONNEL.forEach(p => {
        if ((p.attendanceTypeId === undefined || p.attendanceTypeId === null) && p.attendanceType) {
            const t = ATTENDANCE_TYPES.find(x => x.code === p.attendanceType);
            if (t) { p.attendanceTypeId = t.id; p.attendanceTypeName = t.name; }
        }
    });

    // 2. 员工类型补全
    PERSONNEL.forEach(p => {
        if ((p.employeeTypeId === undefined || p.employeeTypeId === null) && p.employeeType) {
            const t = EMPLOYEE_TYPES.find(x => x.code === p.employeeType || x.name === p.employeeType);
            if (t) { p.employeeTypeId = t.id; p.employeeTypeName = t.name; }
        }
    });

    // 3. 部门补全
    PERSONNEL.forEach(p => {
        if ((p.departmentId === undefined || p.departmentId === null) && p.department) {
            const d = DEPARTMENTS.find(x => x.name === p.department || x.code === p.department);
            if (d) p.departmentId = d.id;
        }
    });

    // 4. 在职状态补全
    PERSONNEL.forEach(p => {
        if ((p.employmentStatusId === undefined || p.employmentStatusId === null) && p.status) {
            p.employmentStatusId = p.status;
            const s = EMPLOYMENT_STATUSES.find(x => x.id === p.status);
            if (s) p.employmentStatusName = s.name;
        }
    });

    // 5. EMPLOYEE_BILLS 规范化：移除冗余缓存
    if (typeof EMPLOYEE_BILLS_202607 !== 'undefined') {
        EMPLOYEE_BILLS_202607.forEach(b => {
            delete b.attendanceType;
            delete b.employeeType;
        });
    }
})();
```

#### 10.3.2 findEmployee 增强

function findEmployee(idOrCode) {
    if (idOrCode === null || idOrCode === undefined) return null;
    if (typeof idOrCode === 'number') {
        return PERSONNEL.find(p => p.id === idOrCode)
            || PERSONNEL.find(p => String(p.employeeCode) === String(idOrCode));

    const str = String(idOrCode);

### 10.4 强制规范（v2.11.7 起）

#### 10.4.1 数据存储原则

**所有基础资料关联字段遵循**：
- ✅ **存储**：业务表通过 FK 引用基础资料（`XxxTypeId INT`）
- ❌ **禁止**：业务表同时冗余存储字符串代码（如 `attendanceType: "MORNING"`）

#### 10.4.2 单一数据源原则

**任何 FK 字段只从一个数据源取**：
- ✅ 业务表现 FK ID，从基础资料表 JOIN 取 Name 显示
- ❌ 禁止多表并存（如 EMPLOYEE_BILLS 也缓存 attendanceType）

#### 10.4.3 EF Core 导航属性

**所有业务表 `XxxType` 外键必须添加 EF Core 导航属性**：

```csharp
[Table("SysEmployee")]
public class SysEmployee : BaseEntity
{
    [ForeignKey(nameof(AttendanceTypeId))]
    public AttendanceType? AttendanceType { get; set; }
    
    [ForeignKey(nameof(EmployeeTypeId))]
    public EmployeeType? EmployeeType { get; set; }
    
    [ForeignKey(nameof(DepartmentId))]
    public Department? Department { get; set; }
    
    [ForeignKey(nameof(EmploymentStatusId))]
    public EmploymentStatus? EmploymentStatus { get; set; }
}
```

## 11. v2.11.7.CORRECT 员工类型 FK 关联修正（强制）

> **日期**：2026-07-12
> **范围**：基础资料-员工类型列表 ↔ 人员清单列表

### 11.1 问题描述

**现象**：基础资料-员工类型列表只定义了 5 种类型（合同工/临时工/外包/实习生/驻场），但人员清单列表中部分员工的员工类型显示为"顾问""技师""保安"等不存在于基础资料的类型。

**根因**：
1. `34c-mock-data-人员清单FK补全-v2.11.7b.md` 将 `EMPLOYEE_TYPES` 字典从 5 种扩展至 10 种（新增顾问/技师/保安/司机/保洁）
2. `34d-mock-data-PERSONNEL-FK深度补全-v2.11.7d.md` 的 `DEPT_TO_TYPE` 映射将技术部员工分配给"技师"(ID=7)、仓储部分配给"保安"(ID=8)、其他分配给"顾问"(ID=6)
3. 导致 650 条 PERSONNEL 中有 197 条的 `employeeTypeId` 值为 6/7/8，但这些 ID 在 `EmployeeType` 表中不存在
4. `mock-data.js` 的 `EMPLOYEE_TYPES` 字典定义了 10 种，但数据库种子数据只有 5 种
5. 人员清单页面的筛选下拉（从 EmployeeType 表读取）只显示 5 种，但列表 Badge 渲染器支持 10 种

### 11.2 修正方案

**原则**：基础资料-员工类型列表是唯一数据源，所有引用必须与之保持一致。

| 修正项 | 修正前 | 修正后 |
|--------|--------|--------|
| `EmployeeType` 表种子数据 | 5 种（正确） | 保持不变 ✅ |
| `EmployeeTypeEnum` C# 类 | 5 种（正确） | 保持不变 ✅ |
| `mock-data.js` EMPLOYEE_TYPES | 10 种（错误扩展） | **回退至 5 种** |
| `mock-data.js` EMPLOYEE_TYPE_BADGE | 10 种颜色映射 | **回退至 5 种颜色映射** |
| PERSONNEL 记录 `employeeTypeId` | 197 条值为 6/7/8 | **运行时校正为 1-5 范围** |
| 人员清单 Badge 渲染 | 支持 10 种 | **仅支持 5 种** |

### 11.3 运行时校正逻辑

`mock-data.js` 的 `normalizeData()` IIFE 新增第 2b 步：

```javascript
// 2b. PERSONNEL 员工类型 FK 值校正（v2.11.7.CORRECT）
PERSONNEL.forEach(p => {
    if (p.employeeTypeId != null && p.employeeTypeId > 5) {
        // 按部门语义映射回有效的 1-5 范围
        var deptId = p.departmentId || 1;
        var validId = 1; // 默认合同工
        if (deptId === 1) { validId = 1; }       // 生产部 → 合同工
        else if (deptId === 2) { validId = 1; }  // 技术部 → 合同工
        else if (deptId === 3) { validId = 4; }  // 行政部 → 实习生
        else if (deptId === 4) { validId = 1; }  // 财务部 → 合同工
        else if (deptId === 5) { validId = 3; }  // 销售部 → 外包
        else if (deptId === 6) { validId = 2; }  // 后勤部 → 临时工
        else if (deptId === 7) { validId = 3; }  // 仓储部 → 外包
        else { validId = 1; }                     // 其他 → 合同工
        p.employeeTypeId = validId;
        // 同步修正 employeeTypeName
        var ct = EMPLOYEE_TYPES.find(function(x) { return x.id === validId; });
        if (ct) p.employeeTypeName = ct.name;
    }
});
```
