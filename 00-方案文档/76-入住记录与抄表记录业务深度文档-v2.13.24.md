## 第一部分：入住记录（DormBooking）

### 1.1 业务定位

**核心职责**：记录员工入住/退房的全生命周期事件，作为人员/宿舍/费用三大模块的连接器。

**与三层数据的关系**：
- 行政资料（SysEmployee）：单条 DormBooking 对应一名员工，通过 EmployeeId 关联
- 宿舍档案（Dorm）：单条 DormBooking 对应一间宿舍，通过 DormCode 关联
- 费用管理（DormBilling/EmployeeBilling）：入住天数为费用分摊依据

### 1.2 状态机

```
[预约(1)] --实际入住日到达--> [在宿(2)]
[在宿(2)]    --办理退房---------> [已退房(3)]（创建 Type=2 退房新记录）
[在宿(2)]    --今日撤销---------> [已取消(4)]（仅 BookingDate=今天，Type=1 入住 && Status=2 在宿）
[预约(1)] --取消-------------> [已取消(4)]
[预约退房(2+1)] --实际退房--------> [已退房(3)]
[预约退房(2+1)] --取消-------------> [已取消(4)]
```

**操作按钮规则**（操作列 6 按钮互斥显示）：
- 修改：仅 status=1 预约
- 撤销退房：BookingDate=今天 && status=3 已退房
- 入住：Type=1 && status=1 预约
- 退房：Type=2 && status=1 预约 或 Type=1 && status=2 在宿
- 撤销在宿：Type=1 && status=2 在宿 && BookingDate=今天
- 撤销预约：status=1 预约
- 删除：status=1 预约 或 status=4 已取消

## 第二部分：抄表记录（MeterRecord）

### 2.1 业务定位

**核心职责**：记录每个宿舍每月的冷水/热水/电表读数 + 用量数据，作为 PDA 抄表 + 费用生成的数据源。

**与三层数据的关系**：
- 宿舍档案（Dorm）：单条 MeterRecord 对应一间宿舍，通过 DormId/DormCode 关联
- 费用管理：用量数据（ColdUsage/HotUsage/ElectricUsage）驱动 DormBilling 生成
- PDA 设备：通过 DeviceSn + ClientRecordId 关联 PDA 上传记录

### 2.2 状态机（5 项枚举）

```
[未完成(0)]  -- PDA 上传/后台补录/覆盖 --> [正常(1)]
[正常(1)]    -- 后台修正读数 --> [已修正(2)]
[未完成(0)]  -- PDA 上传部分表项 --> [未完成(0)]
[未完成(3)]  -- PDA 占位上传未补录 --> [正常(1)] / [未完成(0)]
[任何状态]   -- 物理删除 --> [删除]（仅 status=0 可删）
[任何状态]   -- 人为作废 --> [已作废(4)]
```

| Status | 含义 | Badge | 参与计费 | 可修正 | 可删除 |
|--------|------|-------|---------|--------|--------|
| 0 | 未完成（占位，三表全 0） | 灰 | ❌ | ❌ | ✅ |
| 1 | 正常（三表完整且递增） | 绿 | ✅ | ✅ | ❌ |
| 2 | 已修正 | 黄 | ✅ | ❌ | ❌ |
| 3 | 未完成(PDA 占位) | 黄 | ❌ | ✅ | ✅ |
| 4 | 已作废 | 灰-删除线 | ❌ | ❌ | ❌ |

**CHECK 约束**：`Status IN (0, 1, 2, 3, 4)`

### 2.4 用量计算公式

```
当月用量 = 本次读数 - 上月读数（自动计算，保存时填入 ColdUsage/HotUsage/ElectricUsage）
```

**算法逻辑**（v2.13.24 P76 MeterController.SaveRecord 实现）：
```csharp
var previousRecord = await _db.MeterRecords
    .Where(r => r.DormCode == request.DormCode && r.ReadMonth.CompareTo(request.ReadMonth) < 0)
    .OrderByDescending(r => r.ReadMonth)
    .FirstOrDefaultAsync();

var prevCold = previousRecord?.ColdMeter ?? 0;
var coldUsage = Math.Max(0, request.ColdMeter - prevCold);
```

### 2.5 8 个核心业务规则

| # | 规则 | 说明 |
|---|------|------|
| R-METER-AUTO-01 | 每日 0 点定时任务 | 自动生成当月缺失宿舍的占位记录 |
| R-METER-AUTO-02 | 仅启用宿舍 | Dorm.IsActive=true 才生成 |
| R-METER-AUTO-03 | 占位记录 status=0 | 三表读数均为 0 |
| R-METER-OVERWRITE-01 | 统一覆盖模式 | PDA/补录/导入均更新覆盖，不新增 |
| R-METER-OVERWRITE-02 | 历史快照追加 | 旧数据追加到新记录 Remark |
| R-METER-OVERWRITE-03 | 已修正状态拦截 | Status=2 记录需走修正流程 |
| R-METER-DELETE-01 | 仅 status=0 可删除 | 物理删除，需 Meter:Delete 权限 |
| R-METER-DELETE-02 | 删除后重建占位 | 系统自动重建 status=0 占位 |

| 触发操作 | 联动到 Dorm |

## 第三部分：两张表的对照

| 维度 | DormBooking | MeterRecord |
|------|------------|------------|
| **业务类型** | 入住/退房流水事件 | 每月每房号读数快照 |
| **数据来源** | HR 人工办理 + 系统联动 | PDA 上传 / 人工补录 / 自动生成 |
| **频率** | 低频（每人每月 1-2 条） | 高频（每房号每月 1 条） |
| **总记录数** | ~750（v2.11.3 mock 数据） | ~370（57 个宿舍 × 6 月） |
| **核心 FK** | EmployeeId + DormCode | DormId + DormCode |
| **数据冗余** | EmployeeCode/Name/Phone/Department | DormCode |
| **状态机** | 4 状态（预约/在宿/已退房/已取消） | 5 状态（0/1/2/3/4） |
| **核心约束** | 一进一出顺序 + 房间余量 | 覆盖逻辑 + 历史快照 |
| **双向联动** | ↔ SysEmployee ↔ Dorm | → Dorm |
| **业务深度字段** | **8 项**（v2.13.24 P75） | **12 项**（v2.13.24 P76） |
| **SQL NOT NULL 缺失** | 0 | **3 项（用量字段）** 🔴 |
