## 六、关键决策与权衡

| # | 决策 | 理由 |
|---|------|------|
| 1 | **DB Schema 不动** | `MeterRecord` 表名 / `RecordId` 列名均为 SQL 真理源；改动会触发 EF migration + 历史数据迁移 |
| 2 | **Controller / API 路由不动** | `/api/meter/*` 已被 PDA 客户端、移动 App、Admin 端引用；改名破坏兼容性 |
| 3 | **SysPermission seed + 手动 UPDATE 双轨** | seed 只对新部署有效；生产库已有行需手工 UPDATE；脚本已提供 |
| 4 | **保留 KPI「抄表覆盖」/ 图表「抄表覆盖」** | 「抄表」是动词性短语，统计指标；"覆盖范围"专业术语不需要"智能"前缀 |
| 5 | **保留 `抄表员 / 抄表月份 / 抄表方式 / 抄表时间 / 抄表上传`** | 行业术语 + PDA 移动端业务流程耦合；改术语需同步 Android 客户端 |
| 6 | **保留 localStorage key 命名空间 `meter.*`** | 防止用户浏览器缓存的筛选条件丢失 |
| 7 | **Mock 数据内部变量 `MOCK_METER_RECORDS` 不动** | mock-data.js 内部标识符，无用户展示 |
| 8 | **Swagger 摘要大幅更新** | Swagger UI 是 API 文档的可视化；类注释同步升级利于运维 |
| 9 | **文档改名 = git mv** | 保留 git rename 检测 + 历史 commit 连续性 |

## 七、风险与回退

### 7.1 生产 DB 菜单名未自动同步

**风险**：SysPermission 的 PermissionName 是 seed 数据，已存在的生产 DB 行不会因代码升级自动改名。  
**解决**：`scripts/rename_v2.13.96_meter_label.ps1` 提供 UPDATE 脚本。

### 7.2 localStorage 缓存值失效

**风险**：用户筛选条件写在 `meter.*` localStorage key 中。  
**解决**：保留 key 名不变，仅改 value 中的中文文案（如 `meter.search_label` → UI 显示「智能抄表筛选」）。

### 7.3 历史文档 git history

**风险**：强制改名 v2.13.79/80/81/41 文档可能导致 git rename，破坏 commit history。  
**解决**：使用 `git mv` 保留 rename 检测；INDEX.md 链接同步更新；CLAUDE.md 标注保留。

### 7.4 Swagger UI 缓存

**风险**：浏览器访问 `/swagger` 缓存了旧 doc。  
**解决**：用户端 Cmd/Ctrl+Shift+R 强制刷新。
