## 1. 概述

### 1.1 业务定位

宿舍管理是宿舍档案的核心管理模块，用于维护宿舍的基本信息（楼栋、楼层、容量、性别等），并提供宿舍详情查看、人员入住情况追踪、历史记录查询等功能。

### 1.2 功能范围

| 子模块 | 功能 | 路径 |
|--------|------|------|
| **宿舍列表** | 列表筛选、分页、CRUD | `/Dorms` |
| **宿舍详情** | 基本信息、当前入住、历史记录 | `/Dorms/Details/{id}` |
| **新增宿舍** | 表单录入（v2.12.37 改为弹窗模式） | Modal（#modalDormCreate） |
| **编辑宿舍** | 表单编辑（v2.12.38 改为弹窗模式，宿舍编号锁定 readonly） | Modal（#modalDormEdit） |

### 1.3 菜单入口

**位置**：顶部导航栏 → "宿舍管理"

**图标**：`bi bi-building`

### 3.3 床位号自动生成规则（v2.12.34 新增 → v2.12.35 升级）

> **v2.12.35 变更**：新增容量变更约束规则——容量减少时检查已入住人数、自动重新分配超床位号员工；容量增加时不影响原床位号。

| 规则 | 说明 |
|------|------|
| **生成时机** | ① 新增宿舍时；② 编辑宿舍修改 Capacity 时 |
| **生成逻辑** | 从 1 起至 Capacity 上限，生成逗号分隔的字符串（如 Capacity=4 → `"1,2,3,4"`） |
| **容量增加时** | 仅追加新床位号，不影响原床位号分配（如 Capacity 4→6，原 4 人已分配床位号 1,2,3,4 保持不变，追加 5,6 → `"1,2,3,4,5,6"`） |
| **容量减少时** | 分两步：① 先检查已入住人数 ≥ 新容量 → 禁止更改，提示"**该宿舍当前有 X 人在宿，无法将容量减少至 Y 以下**"；② 已入住人数 < 新容量 → 检查原床位号 > 新容量 的员工，自动重新随机分配空余床位号（从新容量范围内的空闲床位中随机抽取） |
| **显示格式** | 宿舍详情页显示"容量：X 人 / Y 床"（Y = BedNumbers 逗号分隔后的数量） |
| **入住预分配** | 办理入住时按已分配人数 + 1 计算床位号（如已有 2 人入住，新分配床位号 = 3） |

**容量减少时床位号重新分配算法（v2.12.35 新增）**：

```
输入：原床位号列表 [1,2,3,4,5,6]，新容量 4，已入住员工床位号映射 {员工A:5, 员工B:6}
输出：新床位号列表 [1,2,3,4,4,3]（员工A→4, 员工B→3）

步骤：
1. 计算空闲床位号集合 = [1..新容量] - [已入住员工的床位号]
   例：空闲 = {1,2,3,4} - {5,6} = {1,2,3,4}
2. 找出需要重新分配的超容量员工列表 = 床位号 > 新容量的员工
   例：超量 = [员工A(5), 员工B(6)]
3. 对每个超量员工，从空闲床位中随机抽取一个分配，并从空闲集合中移除
   例：员工A → 随机抽 4，空闲 = {1,2,3}；员工B → 随机抽 3，空闲 = {1,2}
4. 更新 BedNumbers = 1..新容量 的逗号分隔字符串
   例：BedNumbers = "1,2,3,4"
```

**业务约束规则（v2.12.35 新增）**：

| 规则 | 条件 | 行为 |
|------|------|------|
| R-BED-001 | 新 Capacity < 当前在宿人数 | 禁止保存，提示"**该宿舍当前有 X 人在宿，无法将容量减少至 Y 以下**" |
| R-BED-002 | 新 Capacity ≥ 当前在宿人数 且 Capacity < 原 Capacity | 自动重新分配超床位号员工，从空闲床位中随机抽取 |
| R-BED-003 | 新 Capacity ≥ 原 Capacity | 仅追加新床位号，不影响原床位号分配 |
| R-BED-004 | 新 Capacity = 原 Capacity | 不触发床位号变更 |

### 3.6 班组列派生规则（v2.13.107 新增）

> **业务背景**：宿舍档案列表需要展示每个房号当前在宿员工的**班组构成**，便于宿管员快速识别某宿舍的班组结构（例如夜班班组集中住宿便于轮班管理、跨班组混住识别协调冲突）。

**数据关系真源链**：

```
Dorm (DormCode = "A101")
  └─ DormBooking (DormCode = "A101" AND Status = 2 在宿)
      └─ SysEmployee (EmployeeId = DormBooking.EmployeeId)
          └─ TeamId (FK → Team.Id)
              └─ Team (Code, Name, SortOrder, IsActive)
```

派生链路与现有「班次」列同模式（v2.13.95 已落地）：

| 步骤 | 数据源 | 转换 |
|------|--------|------|
| ① 取房号当前在宿 | `DormBooking` WHERE `DormCode = X AND Status = 2` | DormBooking 列表 |
| ② JOIN 员工档案 | `DormBooking.EmployeeId = SysEmployee.Id` | SysEmployee 列表 |
| ③ 取班组 ID | `SysEmployee.TeamId` | int[] |
| ④ 去重 + 排序 | `Team.SortOrder ASC` | List<Team> |
| ⑤ 渲染 Badge | `TeamBadgeHelper.GetCode(team.Code)` | HTML Badge 字符串 |

**聚合 SQL 示例**（伪 SQL，实际 EF LINQ）：

```sql
SELECT DISTINCT t.Id, t.Code, t.Name, t.SortOrder
FROM DormBooking b
INNER JOIN SysEmployee e ON e.Id = b.EmployeeId
INNER JOIN Team t ON t.Id = e.TeamId
WHERE b.DormCode = 'A101'
  AND b.Status = 2           -- 在宿
  AND b.IsDeleted = 0
  AND t.IsActive = 1
ORDER BY t.SortOrder ASC;
```

**去重 + 排序规则**：

| 规则 | 说明 |
|------|------|
| **去重** | 同一班组出现多次（如 3 名员工均属 A班）只显示一次 Badge |
| **排序** | 按 `Team.SortOrder ASC` 升序（与基础资料班组列表排序一致） |
| **空值处理** | 员工 `TeamId IS NULL` 或 `Team.IsActive = 0` → 不计入聚合（与人员清单班组列一致） |
| **空房处理** | `CurrentCount = 0` → 显示 **「-」**占位符（不显示「无班组」提示） |

**显示示例**：

| 房号 | 在宿员工 | 员工班组 | 班组列显示 |
|------|---------|---------|-----------|
| A101 | 张三（A班）、李四（B班）、王五（B班） | A班、B班、B班 | `一班` `三班` 两个 Badge（一班 = TEAM_A1，三班 = TEAM_B1） |
| A102 | 0 人 | — | `—`（占位符） |
| A103 | 赵六（A班） | A班 | `一班` 单个 Badge |
| A104 | 孙七（B班）、周八（C班） | B班、C班 | `三班` `四班` 两个 Badge |

**Badge 颜色规则**（沿用 v2.13.91 TeamBadgeHelper）：

| Team.Code 首字母 | Badge 样式 |
|----------------|----------|
| A（TEAM_A1 / A2） | `bg-primary` |
| B（TEAM_B1） | `bg-info text-dark` |
| C（TEAM_C1） | `bg-warning text-dark` |
| D（TEAM_D1） | `bg-success` |
| E（TEAM_E1） | `bg-danger` |
| 其他/默认 | `bg-secondary` |

**实现要点**：

| # | 要点 | 说明 |
|---|------|------|
| ① | 不修改 Dorm 表 | 纯派生列，无 schema 变更 |
| ② | 不修改 DormBooking 表 | 仅 `Status=2 在宿`过滤 |
| ③ | 不修改 SysEmployee 表 | 仅读取 `TeamId` FK |
| ④ | 一次性 JOIN 批量查询 | Web Admin + API 在 GetListAsync 中 `.Include(b => b.Employee).ThenInclude(e => e.Team)`；避免 N+1 |
| ⑤ | 1 个宿舍 ≤ 班组数 ≤ 10 | 实测最多 4-5 个班组/宿舍；Badge 自适应宽度 `min-width: 100px` |
| ⑥ | 与 v2.13.95 班次列同模式 | 复用 DormDto 派生列模式，新增 `TeamNames` (List<string>) + `TeamCodes` (List<string>) 两个字段 |
| ⑦ | 排序方向 | SortOrder ASC（与基础资料班组列表排序一致） |

**联动关系**：

- 人员档案修改员工 `TeamId` → 该员工所在宿舍的「班组」列自动联动（因为是派生而非缓存）
- 员工换宿（CheckIn/CheckOut）→ 旧宿舍班组列 -1 / 新宿舍班组列 +1
- 班组字典停用（`Team.IsActive = 0`）→ 该班组所有宿舍的「班组」列移除该 Badge（实时）

## 5. 业务规则

| 规则 | 说明 |
|------|------|
| R-DORM-001 | 宿舍号全表唯一，新增/编辑时校验 |
| R-DORM-002 | 删除前检查是否有在宿人员（status=2），有则提示"该宿舍有在宿人员，无法删除" |
| R-DORM-003 | 容量字段必填，范围 1-20 |
| R-DORM-004 | 性别字段必填，1=男 / 2=女 |
| R-DORM-005 | 楼栋、楼层、地址均使用基础资料模块字典 |
| R-DORM-006 | 当前入住数实时统计 DormBooking WHERE Status=2 |
| **R-DORM-007** 🆕 | **禁止创建重复房号：DormCode 全表唯一，新增/编辑时实时校验（前端 oninput + onblur 即时校验 + 后端再次校验）；校验失败时红字提示"✗ 房号 XXX 已存在，禁止创建重复房号" + 锁定提交按钮；校验通过时绿字提示"✓ 校验通过！这是新房号，请填写完整资料！" + 解锁提交按钮** |
| **R-DORM-008** 🆕 | **宿舍编号锁定（v2.12.38）：编辑宿舍弹窗中 DormCode 输入框设为 readonly 灰底禁止修改；前端提交时 DormCode 字段不参与 PUT 请求；后端 PUT 接口忽略 DormCode 字段或 400 报错；避免误改房号导致 DormBooking/DormBilling 等历史关联断裂** |
| **R-DORM-009** 🆕 | **删除按钮锁定（v2.12.38 → v2.12.41 升级）：当宿舍满足以下任一条件时，列表"删除"按钮**完全隐藏不显示**（v2.12.41 升级：仅文字无标识符，无 disabled 灰色状态）——① 当前有在宿员工（residents > 0）；② 有历史办理登记记录（存在 BOOKINGS.dormCode = 当前 dormCode，包括已退房/已取消/预约/在宿）；前端兜底校验 + 后端删除接口再次校验并返回 400 错误** |
| **R-BED-006** 🆕 | **床号同步（v2.12.39）：SysEmployee.BedNo 字段与 DormCode 联动维护——仅当 DormCode 不为空时 BedNo 有值；入住操作（CheckIn/ConfirmCheckIn）同步写入 BedNo = activeCount + 1；退房操作（CheckOut/ConfirmCheckOutCreate/UndoCheckOut）同步清空 BedNo = NULL；容量减少重新分配床位（R-BED-002）时同步更新 BedNo；人员清单"床号"列展示此字段** |
| **R-DORM-010** 🆕 | **班组列派生（v2.13.107）：宿舍档案列表新增「班组」列——数据真源链 `DormBooking.Status=2 在宿 → SysEmployee.TeamId → Team`；派生规则：① 同一房号下多个员工同班组只显示一次（去重）；② 按 `Team.SortOrder ASC` 升序排列；③ 员工 `TeamId IS NULL` 或 `Team.IsActive = 0` 不计入聚合；④ 空房显示「-」占位符；⑤ Badge 颜色沿用 v2.13.91 `TeamBadgeHelper.GetCode(Team.Code)`（按 Code 首字母派生 6 种 Badge 颜色）；⑥ 不修改 Dorm/DormBooking/SysEmployee/Team 任何表结构，纯派生列；⑦ Web Admin + API 在 GetListAsync 一次性 JOIN 批量查询避免 N+1；⑧ 人员换宿/班组字典停用 实时联动** |
| **R-BED-001** 🆕 | **容量减少约束：新 Capacity < 当前在宿人数 → 禁止保存，提示"该宿舍当前有 X 人在宿，无法将容量减少至 Y 以下"** |
| **R-BED-002** 🆕 | **容量减少分配：新 Capacity ≥ 当前在宿人数 且 Capacity < 原 Capacity → 自动重新分配超床位号员工（从空闲床位中随机抽取）** |
| **R-BED-003** 🆕 | **容量增加保护：新 Capacity ≥ 原 Capacity → 仅追加新床位号，不影响原床位号分配** |
| **R-BED-004** 🆕 | **容量不变：新 Capacity = 原 Capacity → 不触发床位号变更** |
| **R-BED-005** 🆕 | **床位数锁定同步：BedCount = Capacity（容量变化时自动同步床位数）；新增/编辑表单中 BedCount 输入框设为 readonly（灰底不可编辑），仅在 Capacity 变更时自动更新** |
