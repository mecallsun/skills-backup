## 一、用户需求

> 「对基础资料主菜单导航下的部门管理、设备档案、设备记录等全部同级的二级菜单，进行增加优化功能：对各二级菜单的列表默认显示10条记录，如果对应数据表的记录超出10条记录，则显示列表底部的翻页组件（同人员清单一致）……」

**核心要求**：
- 默认每页 10 条
- 记录数 > 10 时显示 `_PaginationPartial`（与 Personnel 完全一致）
- 12 个 tab 全部统一

## 二、架构升级背景

### 之前（v2.13.158 之前）
- Basics/Index 完全靠内联 `<script>` + AJAX `fetch('/api/basics/...')` + DOM 拼装表格
- 列表渲染依赖 JS 运行（v2.13.152-154 的 4 个 BUG 链都是这条路径引发的）
- **没有分页器** —— 数据全量塞一页（设备记录 3552 条全部加载导致页面卡顿）
- 翻页 / 筛选 / 排序全部缺失

### 现在（v2.13.158 服务端 Razor）
- **全部 12 tab 改 Razor 服务端渲染**（与 Personnel/Index 同架构）
- **统一 `PaginatedPageModel` 基类** —— 强制 PageIndex/PageSize 白名单（10/20/50/100）
- **统一 `_PaginationPartial`** —— 智能截断、统计、pageSize 下拉
- URL 携带 `?tab=dept&page=2&pageSize=20&kw=xxx` 可分享/书签
- 服务端筛选（kw）+ 总数 + 当前页数据一次加载完成

## 三、关键实现

### 3.1 共享分页基类继承（`IndexModel : PaginatedPageModel`）

```csharp
public class IndexModel : PaginatedPageModel
{
    private readonly IBasicsService _svc;
    public IndexModel(IBasicsService svc) { _svc = svc; }

    [BindProperty(SupportsGet = true)] public string? Tab { get; set; }
    [BindProperty(SupportsGet = true, Name = "kw")] public string? Keyword { get; set; }
    // 设备记录专用
    [BindProperty(SupportsGet = true, Name = "type")] public byte? EquipmentType { get; set; }
    [BindProperty(SupportsGet = true, Name = "start")] public DateTime? StartTime { get; set; }
    [BindProperty(SupportsGet = true, Name = "end")] public DateTime? EndTime { get; set; }

    public List<Department> Departments { get; set; } = new();
    public int DepartmentsCount { get; set; }
    // ... 12 个 tab 各一对 Items + Count
}
```

### 3.2 OnGetAsync 策略

1. **预加载所有 tab 总数**（`pageSize=int.MaxValue` 一次拿全）+ **当前 tab 分页数据** —— 切 tab 无空白闪烁
2. URL 不带 pageSize → 默认 10（`PaginatedPageModel.DefaultPageSize` + `EnsureValidPagination()`）
3. URL 带非法 pageSize → 自动 fallback 到 10（白名单校验）

### 3.3 _PaginationPartial 12 tab 接入

每个 tab 表格底部统一接入：
```cshtml
@await Html.PartialAsync("../Shared/_PaginationPartial", new PaginationModel {
    PageIndex = Model.PageIndex, PageSize = Model.PageSize,
    TotalCount = Model.DepartmentsCount  // 或对应的 tab total count
})
```

当 `TotalCount <= PageSize` 时（≤10 条），`_PaginationPartial` 自动不渲染翻页器 —— 满足用户"超出 10 条才显示"诉求。

### 3.4 左侧导航栏改用 `<a href>`（不再 JS setActiveTab）

```cshtml
<a class="nav-link text-start @(Model.ActiveTab == t ? "active" : "")"
   href="@UrlWithTab(t)">  ← 携带当前 pageSize + keyword + 时间区间等筛选条件
   <i class="bi @icons[t]"></i> @labels[t]
</a>
```

→ 浏览器后退/前进按钮自然支持，URL 可书签/分享。

## 六、永久教训

| # | 教训 |
|---|------|
| 1 | **「AJAX 内联渲染」是脆弱路径**。v2.13.152/153/154 一连串 BUG 都源于「依赖 JS fetch + DOM 拼装」。切到服务端 Razor 后这 4 个 BUG 全部根除，列表加载零失败。 |
| 2 | **「数据全部塞一页」是体验灾难**。设备记录 3552 条全加载 = 慢 + 卡 + 占内存；分页是基础可读性需求，不可妥协。 |
| 3 | **「统一基类 > 重复 BindProperty」**。`PaginatedPageModel.DefaultPageSize` + `EnsureValidPagination()` 集中兜底白名单 vs 在 12 个 tab 各自校验，可维护性 10 倍差距。 |
| 4 | **「智能显示翻页器」是必须的 UX 细节**。TotalCount ≤ PageSize 时不显示分页器（避免冗余 `1 1` 翻页）；`>PageSize` 时自动显示智能截断。`_PaginationPartial` 已内置此逻辑。 |
| 5 | **「12 个 tab 同一组分页 + 共享基类」= 设计上的「单源真相」**。避免每个 tab 自己写分页逻辑导致的实现漂移（参考 v2.13.155 TrayLaunchGuard 的教训）。 |
