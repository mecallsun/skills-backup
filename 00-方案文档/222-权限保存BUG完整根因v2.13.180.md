## 一、用户报告

> 权限分配中，对"允许显示隐私字段"的选项进行勾选后保存没有生效
> 另：有2个允许显示隐私字段的勾选对象，重复需修复

## 二、问题层级（三个 BUG 串联）

| 序号 | BUG 位置 | 现象 | 严重度 |
|------|---------|------|--------|
| 1 | 权限矩阵 UI | `privacy:field:enable` 出现 2 次（独立卡片 + PermissionGroups 遍历） | 中 |
| 2 | `LicenseGuard.IsReadOnly()` | Admin 进程内通过 IPC 调托盘，托盘未运行 → state=null → 默认只读 | 严重 |
| 3 | `SysRolePermission.Id` 列 | 不是 IDENTITY → EF MERGE INSERT 不发送 Id → SQL Server Error 515 | 严重 |

## 三、完整 BUG 链路（按执行顺序）

```
用户操作：
1. 浏览器打开 /Settings?tab=roles
2. 勾选"允许显示隐私字段" + 其他权限
3. 点击"保存"

请求流转：
4. POST /Settings?handler=RoleSavePermissions (含 antiforgery token)
5. 到达中间件 LicenseReadOnlyMiddleware.InvokeAsync
6. LicenseGuard.IsReadOnly() → GetCachedState() → IPC 调托盘 :5099
7. 托盘未运行 → state = null → IsReadOnly = true (默认安全)
8. 中间件拦截 → 302 重定向到 /Error?code=LICENSE_UNAVAILABLE
9. 浏览器跟随 → 看到"授权服务不可用（托盘未运行）"错误页
10. 用户认为"保存未生效"

实际错误（绕过中间件后才发现）：
11. handler 调用 _db.SysRolePermissions.Add(...)
12. _db.SaveChangesAsync() → EF 生成 MERGE 语法
13. MERGE INSERT ([CreatedAt], [PermissionId], [RoleId]) VALUES (...)
14. SQL Server: Error 515 "不能将值 NULL 插入列 'Id'"
15. 因为 SysRolePermission.Id 列不是 IDENTITY 自增 → 必须是 NOT NULL
16. EF 不发送 Id 值（假设是 IDENTITY）→ 失败
17. 抛 DbUpdateException → handler 抛 → Error page
```

### 4.3 BUG #3 — SysRolePermission.Id IDENTITY 修复

**文件**：`DormManage.Shared/Services/DatabaseInitializer.cs`

新增迁移方法 `MigrateSysRolePermissionIdentityAsync`：

```csharp
// 启动期检测 SysRolePermission.Id 是否是 IDENTITY
// 若不是 → 备份数据 → DROP TABLE → CREATE TABLE (带 IDENTITY) → IDENTITY_INSERT 恢复数据
const string migrateSql = @"
    BEGIN TRANSACTION;
    IF OBJECT_ID('tempdb..#SysRolePermissionBackup', 'U') IS NOT NULL DROP TABLE #SysRolePermissionBackup;
    SELECT * INTO #SysRolePermissionBackup FROM [dbo].[SysRolePermission];
    DROP TABLE [dbo].[SysRolePermission];
    CREATE TABLE [dbo].[SysRolePermission] (
        [Id]              INT IDENTITY(1,1) NOT NULL,
        [RoleId]          INT NOT NULL,
        [PermissionId]    INT NOT NULL,
        [CreatedAt]       DATETIME NOT NULL DEFAULT GETDATE(),
        CONSTRAINT [PK_SysRolePermission] PRIMARY KEY CLUSTERED ([Id] ASC)
    );
    SET IDENTITY_INSERT [dbo].[SysRolePermission] ON;
    INSERT INTO [dbo].[SysRolePermission] ([Id], [RoleId], [PermissionId], [CreatedAt])
    SELECT [Id], [RoleId], [PermissionId], [CreatedAt] FROM #SysRolePermissionBackup ORDER BY [Id];
    SET IDENTITY_INSERT [dbo].[SysRolePermission] OFF;
    COMMIT;";
```

## 七、永久教训

1. **EF Core MERGE INSERT 假设 Id 是 IDENTITY** — 真实生产 DB 列必须与之匹配，否则 SQL Error 515
2. **LicenseGuard 不应完全依赖 IPC** — IPC 失败时必须有 fallback 路径
3. **重复显示检查** — 同一数据源在多处渲染时，必须在数据层去重，不在 UI 层去重
4. **启动期迁移必须幂等** — 备份/恢复是核心防御
5. **错误可见性** — 部署模式隐藏异常详情，调试时切到 Development 模式才能看到
