## 二、需求规格

### 2.1 业务模型

| 维度 | 规格 |
|------|------|
| **位置** | 基础资料 (Basics) 二级菜单，与员工类型/班次/班组/计量单位等并列 |
| **实体关系** | **DormMeter ──1:1── Dorm**（每间宿舍只能配置 1 条设备档案） |
| **数据源** | 房号 DormId FK → Dorm 表（来自宿舍档案） |
| **输入项** | 房号（下拉） + 电表ID + 冷水ID + 热水ID + 备注 |
| **操作** | 新增 / 修改 / 删除（与员工类型一致）|

### 2.2 字段定义

| # | 字段 | 类型 | 必填 | 长度 | 说明 |
|---|------|------|------|------|------|
| 1 | DormMeterId | INT IDENTITY | ✓ | — | 主键（自增）|
| 2 | DormId | INT FK | ✓ | — | 房号 FK → Dorm.DormId（**UNIQUE 1:1**）|
| 3 | ElectricMeterId | NVARCHAR | ✗ | 64 | 电表 ID/编号（现场标识）|
| 4 | ColdWaterMeterId | NVARCHAR | ✗ | 64 | 冷水表 ID/编号 |
| 5 | HotWaterMeterId | NVARCHAR | ✗ | 64 | 热水表 ID/编号 |
| 6 | Remark | NVARCHAR | ✗ | 500 | 备注 |
| 7 | IsActive | BIT | ✓ | — | 启用标志（默认 1）|
| 8 | CreatedAt | DATETIME | ✓ | — | 创建时间 |
| 9 | UpdatedAt | DATETIME | ✗ | — | 更新时间 |

### 2.3 业务规则

| 规则 | 校验 |
|------|------|
| **R1 1:1 唯一约束** | DormId UNIQUE — 同一房号只能有 1 条设备档案 |
| **R2 删除宿舍级联** | 删除 Dorm 时 DormMeter 自动级联清理（FK ON DELETE CASCADE）|
| **R3 房号必须存在** | 创建/修改时校验 DormId 存在于 Dorm 表 |
| **R4 列表展示** | 列表 JOIN Dorm 取 DormCode/BuildingName/FloorNo |
| **R5 房号下拉过滤** | 房号下拉中已配置设备档案的 Dorm 标记「（已配置）」便于辨识 |

```sql
CREATE TABLE dbo.DormMeter (
    DormMeterId        INT            IDENTITY(1,1) NOT NULL,
    DormId             INT            NOT NULL,
    ElectricMeterId    NVARCHAR(64)   NULL,
    ColdWaterMeterId   NVARCHAR(64)   NULL,
    HotWaterMeterId    NVARCHAR(64)   NULL,
    Remark             NVARCHAR(500)  NULL,
    IsActive           BIT            NOT NULL DEFAULT 1,
    CreatedAt          DATETIME       NOT NULL DEFAULT GETDATE(),
    UpdatedAt          DATETIME       NULL DEFAULT GETDATE(),
    CONSTRAINT PK_DormMeter PRIMARY KEY CLUSTERED (DormMeterId),
    CONSTRAINT FK_DormMeter_Dorm FOREIGN KEY (DormId)
        REFERENCES dbo.Dorm(DormId) ON DELETE CASCADE,
    CONSTRAINT UX_DormMeter_DormId UNIQUE (DormId)
);
```

```csharp
[Table("DormMeter")]
public class DormMeter : BaseEntity
{
    [Column("DormMeterId")]

    public int DormId { get; set; }
    [StringLength(64)] [Column("ElectricMeterId")]

    [StringLength(64)] [Column("ColdWaterMeterId")]

    public Dorm? Dorm { get; set; }
}
```

### 4.2 DbContext 配置

```csharp
modelBuilder.Entity<DormMeter>(entity =>
{
    entity.ToTable("DormMeter");
    entity.HasKey(e => e.Id);
    entity.Property(e => e.Id).HasColumnName("DormMeterId");
    entity.Property(e => e.DormId).IsRequired();
    entity.HasIndex(e => e.DormId).IsUnique().HasDatabaseName("UX_DormMeter_DormId");
    entity.HasOne(e => e.Dorm).WithMany().HasForeignKey(e => e.DormId)
          .OnDelete(DeleteBehavior.Cascade);
    entity.Property(e => e.CreatedAt).HasColumnType("datetime").HasDefaultValueSql("GETDATE()");
    entity.Property(e => e.UpdatedAt).HasColumnType("datetime").HasDefaultValueSql("GETDATE()");
});
```

## 九、核心教训

### 9.1 用户原话歧义澄清

用户原话「**系统设置**的二级菜单中增加设备档案」+「**与员工类型、班次等并列**」存在矛盾：
- 系统设置 vs 基础资料 — 两个不同模块
- 员工类型/班次 在 基础资料

通过 AskUserQuestion 确认：放置于**基础资料**模块。**原则**：当用户原话存在歧义时，先澄清再实施。

### 9.2 Razor @await 在 JS 模板字符串中的坑

`@await Html.HasPermissionAsync("...") ? "true" : "false"` 直接在 JS 模板字符串中：
- Razor 解析器看到 `@await` 立即启动表达式解析
- 但 JS 模板字符串里的 `@await` 不是 Razor 表达式
- 解决方案：把权限值渲染到 hidden input 或 `window.__xxx` 全局变量，JS 读取全局变量

### 9.3 EF BaseEntity Id + 自定义主键名

`MeterRecord` / `SysRolePermission` 等用 `public new int Id { get; set; }` + `[Column("XxxId")]` 重写 BaseEntity.Id。**DormMeter 同样模式**：`DormMeterId` 主键 + FK 关联 `DormId`。

### 9.4 1:1 关系实现

`HasIndex(e => e.DormId).IsUnique()` + FK `OnDelete(DeleteBehavior.Cascade)`：
- UNIQUE 索引 → 数据库层强制 1:1
- CASCADE → Dorm 删除时 DormMeter 自动清理（无需应用层代码）
