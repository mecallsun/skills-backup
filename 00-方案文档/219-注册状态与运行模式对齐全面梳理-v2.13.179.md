## 一、需求概述

系统定义 **3 种注册状态** ↔ **3 种运行模式**，需保证每一对映射在：
- 托盘端 LicenseForm UI 表现
- 中间件 LicenseReadOnlyMiddleware 拦截行为
- 控制器层 CheckTrialRecordLimit 记录上限
- LicenseGuard 内部方法判断
- 前端 license-status-badge.js 徽章显示
- 系统设置字段权限面板的引导提示

**全部对齐，不得有任何分支冲突。**

## 二、状态矩阵（权威定义）

### 2.1 注册状态枚举 (RegStatus)

| 枚举值 | RegInt | 含义 | 触发条件 |
|--------|--------|------|---------|
| Unregistered=-1 | -1 | 无注册信息 | RegisterSdk.CheckReg() 读不到 CDKEY |
| Valid=1 | 1 | 已注册且有效 | CDKEY 校验通过 + RegDate ≥ Today |
| Expired=2 | 0 | 已过期 | CDKEY 校验通过 + RegDate < Today |
| Invalid=3 | 0 | 校验失败 | CDKEY 校验不通过（SN/LTDName 不匹配） |

> ⚠️ **历史遗留 RegInt==0 混淆 Expired + Invalid**：v2.13.169 引入 RegStatus 枚举拆分，但 RegInt 保留向后兼容。

### 2.2 运行模式映射

| 注册状态 | 运行模式 | IsReadOnly() | IsTrialMode() | 写操作 | UI 提示 |
|---------|---------|-------------|--------------|-------|--------|
| Unregistered | **试用模式** | false | true | ✅ 放行 + 记录数限制 | ❌ 尚未注册 / btn="注册" |
| Valid | **注册模式** | false | false | ✅ 全功能 | ✅ 此软件已注册 / btn="取消注册" |
| Expired | **只读模式** | true | false | ❌ 拦截 403 | ⚠️ 许可已过期 / btn="重新注册" |
| Invalid | **只读模式** | true | false | ❌ 拦截 403 | （见 §3 建议改进） |

### 2.3 试用模式分模块上限

| 模块 | 上限 |
|------|------|
| 住宿登记 (Booking) | 500 条 |
| 宿舍档案 (Dorms) | 5 条 |
| 人员清单 (Personnel) | 5 条 |
| 所有其他 POST/PUT/DELETE | 完全放行（不受限） |

// line 219: cdkey 为空 → Unregistered

✅ **正确**

### 3.3 子进程端 — LicenseGuard

#### IsReadOnly()

```csharp
state == null → true           (兜底安全)
Expired || Invalid → true      (直接只读)
Unregistered → false            (试用可写)
Valid → 额外防御检查 → false    (有效可写)
```

✅ **正确** — 逻辑与矩阵完全一致

#### IsTrialMode()

```csharp
state == null → false   (不放行)
Unregistered → true     (唯一触发条件)
其他 → false
```

✅ **正确** — 与 IsReadOnly 协作：只有 `!IsReadOnly()` 才到控制器，此时 `IsTrialMode=true` 仅对 Unregistered 成立

#### CheckTrialRecordLimit()

```csharp
!IsTrialMode() → 不放行任何限制
当前模块超限 → 拒绝并返回详细消息
```

✅ **正确**

#### GetLicenseBanner()

5 个 case：
- Valid → LICENSE_OK
- Unregistered → LICENSE_TRIAL
- Expired → LICENSE_EXPIRED
- Invalid → LICENSE_INVALID
- default(托盘不可用) → LICENSE_UNAVAILABLE

✅ **正确** — 包含 Invalid（此前 UI 不区分 Expired/Invalid 是已知问题，不影响核心逻辑）

### 3.4 Admin 端 — LicenseReadOnlyMiddleware

```
isReadOnly=false → 直接放行 ✓
GET/HEAD → 放行 ✓
白名单路径 → 放行 ✓
其他写请求 → 403 RejectWrite ✓
```

✅ **正确** — 中间件层只做 IsReadOnly() 一把刀判断，与模式无关

### 3.5 API 端 — LicenseReadOnlyMiddleware（Api）

逻辑与 Admin 端完全相同。✅

### 3.6 PDA 端 — PdaController

PDA Controller 本身不直接调用 IsReadOnly()（v2.13.169 删除了直接调用 RegisterSdk）。
通过 Api 端中间件统一拦截。✅

### 3.7 LicenseForm UI 分支审查

```csharp
switch (reg.RegInt):
    case 1 (Valid)     → ✅ / btn="取消注册" / 只读 / 显示 RegDate / 隐藏 trial
    case 0 (Expired OR Invalid) → ⚠️ / btn="重新注册" / 可编辑 / 显示 RegDate
    default (-1 Unregistered)     → ❌ / btn="注册" / 可编辑 / 不显示 RegDate / 显示 trial
```

⚠️ **问题发现**：`case 0` 同时覆盖 Expired(2) 和 Invalid(3)，但它们语义完全不同：
- Expired：合法注册但过期 → 应给用户续期机会
- Invalid：盗版/不匹配 → 应阻止输入（因为当前输入的可能是盗版的）

**但实际上用户要求"重新注册"** —— 两种情况都允许修改输入框并重新提交校验，所以当前行为从用户体验角度是可接受的。

❓ **建议改进**（可选，不影响核心功能）：在 case 0 中根据 `reg.Status` 显示不同文案。

## 五、修复内容

## 六、验证方法（端到端）

| 场景 | 手动测试步骤 | 预期结果 |
|------|-------------|---------|
| 全新安装 | 清空注册表→重启托盘→打开 LicenseForm→尝试新增数据 | ❌ 尚未注册，btn="注册"，数据可新增但受限 |

| IPC 断开 | 停止托盘→操作 Web 页面 | 只读模式，所有 POST 返回 403 |
