### 2.2 Api 端验证（v2.13.84+v2.13.112 依然生效）

### 2.3 前端 BUG 根因（v2.13.36 → v2.13.121 之间一直遗漏）

`Admin/Pages/Booking/CheckIn.cshtml` 行 275：

```javascript
// ❌ v2.13.36 错误实现（v2.13.38/v2.13.84/v2.13.88/v2.13.112 等都未修复）
empSearchResults = res.data.filter(e => e.realName && e.realName.includes(kw));
```

**问题链条**：
1. 用户在「员工选择」输入框输「JG000607」或「刘院飘」
2. `onEmpSearch` → fetch `/api/v1/bookings/employee-search?keyword=JG000607`
3. API 返回 1 条员工 `刘院飘 JG000607`（完整字段）
4. **前端二次过滤 `e.realName.includes('JG000607')` → false**（realName="刘院飘" 不含 "JG000607"）
5. `empSearchResults = []`，下拉列表不显示
6. 用户无法点击员工 → **`selectEmp` 从未调用**
7. `empInfo` 卡片保持 `display:none`，部门/类型/班次/班组字段全是 `-`（用户看到的"空")
8. `refreshDorms()` 也未被调用 → 房号下拉保持「请选择房间」空

**当用户按姓名「刘院飘」搜索时**：
- realName.includes("刘院飘") → true
- empSearchResults = [1 条]
- 用户点击 → selectEmp 调用 → 档案卡/班次 Badge/班组 Badge 正确显示 → refreshDorms 加载 16 间可分配房号
- **这个 BUG 仅在按工号搜时出现**

`Admin/Pages/Booking/CheckOut.cshtml` 行 161 也有完全相同的 BUG，外加 `e.dormCode` 非空筛选。

### 2.4 v2.13.121 修复方案

```javascript
// ✅ v2.13.121 修复：姓名 + 工号 双重匹配
empSearchResults = res.data.filter(e =>
    (e.realName && e.realName.includes(kw)) ||
    (e.employeeCode && e.employeeCode.includes(kw))
);
```

CheckOut 增加 `e.dormCode` 限制（仅保留在宿员工）：
```javascript
empSearchResults = res.data.filter(e =>
    e.dormCode && (
        (e.realName && e.realName.includes(kw)) ||
        (e.employeeCode && e.employeeCode.includes(kw))
    )
);
```

## 六、核心教训

### 6.1 BUG 复发原因

v2.13.36 重构办理入住页面 → 引入员工搜索 JS 逻辑 → 二次过滤只考虑姓名 → 13 个版本（v2.13.38-v2.13.120）一直遗漏。

**为什么 v2.13.113 / v2.13.116 没有发现？**
- v2.13.113 修复的是 `selectEmp` 函数（行 304+ 的渲染），**没有触发 selectEmp 就不会暴露字段问题**
- v2.13.116 文档汇总 R1-R5，但 BUG 不是 selectEmp 渲染错，是触发 selectEmp 之前的搜索过滤错
- 测试时用 **姓名** 搜索能通过（realName.includes("刘院飘") 命中）→ 隐藏 BUG

### 6.2 永久教训

**前端二次过滤必须按 API 实际支持的字段全部覆盖**：
- API `/bookings/employee-search` 用 `WHERE EmployeeCode LIKE @kw OR RealName LIKE @kw` 支持工号 + 姓名 双字段
- 前端 JS 二次过滤必须同步按 `(realName.includes(kw) || employeeCode.includes(kw))` 双重匹配
- **禁止仅按单一字段匹配**（极易因 dev 自测常用字段而漏掉另一字段）

### 6.3 通用规则

> 任何"前端二次过滤"必须以**后端 API 支持的搜索字段矩阵**为准，对称同步。  
> 后端 WHERE 子句 LIKE 哪些字段 → 前端 filter 就必须 includes 哪些字段。  
> 测试时**至少按每一个字段**都搜一遍冒烟测试。
