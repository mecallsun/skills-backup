## 二、核心设计哲学

| 层级 | 设计哲学 |
|------|----------|
| **Web 端** | 只读 + 显示状态，不参与注册验证 |
| **托盘端** | 注册验证的唯一入口（机器码显示 + CDKEY 输入 + 校验 + 写注册表）|
| **全局拦截** | 注册过期/失败时，**最高优先级**全局只读（POST/PUT/DELETE → 403）|

**关键洞察**：用户原话"全局所有页面的功能，只能读取，不可以修改或删除等变更类的操作"——明确锁定**修改类操作**，GET/HEAD/查看不受影响。这与"页面 503 黑屏"完全不同，必须精细控制 HTTP 方法。

## 六、关键代码骨架

### 6.1 LicenseGuard 共享逻辑

```csharp
// DormManage.Shared/Security/LicenseGuard.cs
public static class LicenseGuard
{
    private static int? _cachedRegInt;
    private static readonly object _lock = new();

    public static bool IsReadOnly()
    {
        lock (_lock)
        {
            if (!_cachedRegInt.HasValue)
            {
                try
                {
                    var reg = RegisterSdk.CheckReg();
                    _cachedRegInt = reg.RegInt;
                }
                catch
                {
                    _cachedRegInt = -1;  // 异常时按"未注册"处理（更安全）
                }
            }
            return _cachedRegInt != 1;
        }
    }

    public static void ResetCache()
    {
        lock (_lock) { _cachedRegInt = null; }
    }
}
```

### 6.2 Admin LicenseReadOnlyMiddleware 核心

```csharp
public async Task InvokeAsync(HttpContext context)
{
    var isReadOnly = LicenseGuard.IsReadOnly();
    context.Items["__LICENSE_READONLY__"] = isReadOnly;

    if (!isReadOnly) { await _next(context); return; }

    var method = context.Request.Method;
    if (method == "GET" || method == "HEAD") { await _next(context); return; }

    var path = context.Request.Path.Value ?? "";
    if (IsWhitelisted(path)) { await _next(context); return; }

    // 拒绝写入
    context.Response.StatusCode = 403;
    if (path.StartsWith("/api/") || IsAjax)
    {
        context.Response.ContentType = "application/json; charset=utf-8";
        await context.Response.WriteAsync(JsonSerializer.Serialize(new
        {
            success = false,
            code = "LICENSE_READONLY",
            message = "软件未注册或注册已过期，所有修改类操作已禁用。"
        }));
        return;
    }
    context.Response.Redirect("/Error?code=LICENSE_READONLY&msg=...");
}
```

## 九、永久教训

### 9.1 注册验证的唯一性原则

**Web 端是"被验证者"，不是"验证者"**。所有 CDKEY 输入/校验/写入逻辑都必须在托盘端，Web 端只读不写。

**违反原则的代价**：
- 攻击者可绕过 Web 端直接调 API 写注册表
- 普通用户能在 Web 端"乱试" CDKEY（暴力破解风险）
- 多个 Web 实例并发写注册表产生竞态

**本次重构清零 Web 端所有 RegisterSdk 写入调用**，符合"最小权限原则"。

### 9.2 全局拦截的颗粒度选择

| 层级 | 优点 | 缺点 |
|------|------|------|
| 中间件层（推荐）| 一处生效全栈保护；API + Razor Page 同时拦截 | 不能精细控制单个端点（需白名单）|
| ActionFilter 层 | 可精细到单个 Controller | 必须逐个 Controller 加 attribute；API 端点遗漏风险 |
| PageModel 层 | 最小侵入性（只改 PageModel）| 跨项目重复代码；新页面遗漏风险 |

**本次选择中间件层 + 白名单机制**，平衡"全局覆盖"与"业务例外"。

### 9.3 进程内缓存 + ResetCache 的协作

托盘端 `LicenseForm` 写入新 CDKEY 时，必须主动调用 `LicenseGuard.ResetCache()`，否则：
- 当前 Admin 进程的全局只读状态不会立即更新
- 用户必须重启 Admin 才能生效（用户体验极差）

**实现方式**：
- `LicenseForm.cs:BtnReg_Click` 成功路径加 `LicenseGuard.ResetCache()`
- 跨进程场景：通过环境变量 / 共享文件通知 Admin 进程重读（v2.13.32 数据源热加载模式可扩展）

### 9.4 「只读降级」与「暗桩」是两个独立机制

| 机制 | 触发条件 | 用户感知 | 拦截范围 |
|------|----------|----------|----------|
| **暗桩**（v2.13.135）| 系统日期 < 2026-06-01 或 > Min(暗桩截止, RegDate) | 全部 503（黑屏）| 所有页面（含 GET）|
| **注册降级**（v2.13.136）| `RegInt != 1` | POST 403，GET 仍可 | 仅写入操作 |

**两者可同时生效**（暗桩是更高优先级）。暗桩触发时，注册降级也被"屏蔽"（因为已 503）。

## 十、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 中间件拦截误杀合法写入 | 中 | 用户无法保存任何数据 | 完善白名单（登录页 + 静态资源 + PDA + 健康检查）|
| Web 端缓存导致状态不同步 | 中 | 托盘注册后 Web 仍 403 | ResetCache() 在 LicenseForm 写入路径调用 + 文档明确告知重启 |
| PDA 端点被拦截 | 低 | PDA 无法上传抄表 | `IsApiWhitelisted` 显式放行 `/api/v1/pda/*` |
| 登录页被拦截 | 低 | 用户无法登录 | 白名单 `/Account/*` |
| RegisterSdk 异常导致全局只读 | 低 | 误判为"未注册" | catch 块按 -1 处理（默认只读，更安全）|
| Web 端反注册攻击 | 低 | 攻击者绕过托盘直接调 API 写注册表 | v2.13.136 中间件拦截所有写注册表相关端点（如未来添加）+ 审计 |
