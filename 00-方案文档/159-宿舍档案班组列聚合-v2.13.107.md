## 二、数据关系真源链

```
Dorm (DormCode = "A101")
  └─ DormBooking (DormCode = "A101" AND Status = 2 在宿)
      └─ SysEmployee (EmployeeId = DormBooking.EmployeeId)
          └─ TeamId (FK → Team.Id)
              └─ Team (Code, Name, SortOrder, IsActive)
```

**关键决策**：

| # | 决策 | 理由 |
|---|------|------|
| ① | 数据真源用 `DormBooking.Status = 2`（在宿），不用 `SysEmployee.DormCode` | `SysEmployee.DormCode` 是冗余字段；`DormBooking` 是住宿事实表，状态变更可追溯（v2.13.33 起 BookingService 实时覆盖 DormCode） |
| ② | `SysEmployee.TeamId` 是 FK 到 `Team`，不是字符串 | v2.13.78 修复班组 FK 关联；不再用孤儿字符串 `Team` |
| ③ | 班组字典 `Team` 已有 Code/Name/SortOrder/IsActive | 与基础资料班组管理一致 |

---

## 三、聚合规则

| 规则 | 说明 | 示例 |
|------|------|------|
| **去重** | 同一房号下多个员工同班组只显示一次 Badge | 3 人同属 A班 → 显示 `一班` 单个 Badge |
| **排序** | 按 `Team.SortOrder ASC` 升序排列（与基础资料班组列表一致） | 一班/二班/三班/四班/五班 |
| **空值处理** | `SysEmployee.TeamId IS NULL` 或 `Team.IsActive = 0` → 不计入聚合 | — |
| **空房处理** | `CurrentCount = 0` → 显示 `—` 占位符 | 不显示「无班组」提示 |
| **Badge 颜色** | 沿用 v2.13.91 `TeamBadgeHelper.GetCode(Team.Code)`，按 Code 首字母派生 6 种 Badge 颜色 | A=primary, B=info, C=warning, D=success, E=danger, 默认=secondary |

## 五、原型变更

### 5.1 `mock-data.js` 新增 `currentTeams(dormCode)` 辅助函数

```javascript
// 辅助：v2.13.107 住宿档案列表「班组」列派生
function currentTeams(dormCode) {
    const staying = RESIDENCIES.filter(r => r.dormCode === dormCode && r.status === 1);
    const teams = staying
        .map(r => PERSONNEL.find(e => e.id === r.employeeId))
        .filter(e => e && e.teamId)
        .map(e => TEAMS.find(t => t.id === e.teamId))
        .filter(t => t); // 过滤掉 TEAMS 中不存在的孤儿 teamId
    if (teams.length === 0) return [];
    // 按 SortOrder 升序 + 去重（同 teamId 仅保留第一个）
    const seen = new Set();
    return teams
        .slice()
        .sort((a, b) => (a.sortOrder || 0) - (b.sortOrder || 0))
        .filter(t => { if (seen.has(t.id)) return false; seen.add(t.id); return true; });
}
```

    : teams.map(t => {

### 7.2 Service 层（`DormService.GetListAsync`）

```csharp
// 一次性 JOIN 批量查询（避免 N+1）
var query = _db.Dorms
    .Where(d => /* filter */)
    .GroupJoin(_db.DormBookings.Where(b => b.Status == BookingStatus.Staying), d => d.DormCode, b => b.DormCode, (d, bookings) => new { d, bookings })
    .SelectMany(x => x.bookings.DefaultIfEmpty(), (x, b) => new { x.d, b })
    .GroupJoin(_db.Employees, x => x.b.EmployeeId, e => e.Id, (x, emps) => new { x.d, x.b, emps })
    .SelectMany(x => x.emps.DefaultIfEmpty(), (x, e) => new { x.d, x.b, e })
    .GroupJoin(_db.Teams, x => x.e.TeamId, t => t.Id, (x, teams) => new { x.d, x.b, x.e, teams })
    .SelectMany(x => x.teams.DefaultIfEmpty(), (x, t) => new { x.d, x.b, x.e, t });

// 物化后聚合（去重 + 排序）
var dormGroups = query.ToList().GroupBy(x => x.d.DormCode);
foreach (var group in dormGroups)
{
    var teamIds = group.Where(x => x.t != null).Select(x => x.t.Id).Distinct().ToList();
    var teams = _db.Teams.Where(t => teamIds.Contains(t.Id)).OrderBy(t => t.SortOrder).ToList();
    // 填充 DormDto.TeamNames + TeamCodes
}
```

## 八、决策与权衡

| 决策 | 理由 |
|------|------|
| **复用 v2.13.91 TeamBadgeHelper 派生 Badge 颜色** | 项目统一班组 Badge 风格（人员清单/住宿登记/住宿详情） |
| **去重 + SortOrder 排序** | 聚合规则最简洁，符合用户"集合"语义；与基础资料班组列表排序一致 |
| **不修改 Dorm/DormBooking/SysEmployee/Team 表** | 纯派生列，无 schema 迁移；与 v2.13.95 班次列同模式 |
| **JOIN 批量查询避免 N+1** | 复用 v2.13.95 班次列的 GroupJoin + SelectMany 模式 |
| **空房显示 `-` 而非「无班组」** | 与 v2.13.95 班次列占位符风格一致 |
| **原型先于代码** | 用户原话明确"先完成原型的界面与功能"，后续 v2.13.108 实施代码端 |
