# v2.13.112 可分配房号「班组」列 + 智能排序

> **版本**：v2.13.112  
> **日期**：2026-07-22  
> **类型**：P1 派生字段 + 排序优化（参照 v2.13.95/97/111 EmployeeTeamMap 模式）

## 一、用户原话

> "入住信息录入 员工选择 后，根据 之前 约定的规则 ，筛选的出的 可分配 房号 信息中，同时再显示 已入住人员的 班组 名称（A/B/C），班组仅显示不参与筛选，但与 选择的员工 班组 优先相同的 已入住 房间 同性别或 空房号，且有空余床位号，同空房间或相同班组 优先（其次同班次优先）排序"

---

## 二、需求深度解读

### 2.1 触发场景

```
入住信息录入 → 选择员工 → 自动调 /api/v1/bookings/available-dorms?employeeId=X
  ↓
返回可分配房号列表（v2.13.84 三层过滤 + v2.13.112 新增班组 + 智能排序）
  ↓
下拉框显示：房号 | 楼栋 | 地址 | 班组 A/B/C | 余量 X/Y | 床位 N/M · 下一个 N号
```

### 2.2 排序规则（核心）

| 优先级 | 排序条件 | 说明 |
|--------|---------|------|
| 1st | **同员工班组**（TeamId 一致） | 最高优先：选择员工所属班组已在该房号入住 |
| 2nd | **空房号** > 同性别房号 | 空房号 CurrentCount==0 优先；同性别内有员工 |
| 3rd | **同班次**（AttendanceTypeId 一致）| 同一作息时间的员工优先 |
| 4th | 房号字典序 | 稳定排序兜底 |

### 2.3 显示规则

| 列 | 数据来源 | 渲染 |
|----|---------|------|
| 房号 | Dorm.DormCode | 主键 |
| 楼栋 | Dorm.BuildingName | — |
| 地址 | Dorm.AddressText | — |
| **班组**（v2.13.112 新增） | DormBooking Status=2 → SysEmployee.TeamId → Team.Name | `/` 拼接去重（按 SortOrder），无班组显示 `-` |
| 余量 | Capacity - CurrentCount - Reserved | X/Y |
| 床位 | Occupied / All | N/M · 下一个 N号 |

### 2.4 班组仅显示不参与筛选（明确边界）

- ❌ 班组列**不作为筛选条件**（用户已明确）
- ✅ 班组仅作为**显示信息** + **排序权重**
- ✅ 仍然按 v2.13.84 规则过滤：余量 > 0 + 同性别/空房号

## 三、数据关系（深度）

```
SysEmployee (员工)
  ├── Id
  ├── TeamId (FK) ─→ Team ─→ Name + SortOrder
  ├── AttendanceTypeId (FK) ─→ AttendanceType ─→ Name + SortOrder
  ├── DepartmentId (FK) ─→ Department ─→ Name
  └── Gender (1=男 2=女 0=未知)

Dorm (房号)
  ├── DormCode (PK)
  ├── BuildingId (FK)
  ├── Capacity (床位总数)
  ├── Gender (1=男 2=女)
  └── IsActive (启用)

DormBooking (住宿记录)
  ├── DormCode (FK) ─→ Dorm
  ├── EmployeeId (FK) ─→ SysEmployee
  ├── Status (2=在宿)
  └── BedNo (床位号)
```

### 派生链路（v2.13.112 新增）

```
Dorm.DormCode ─(FK)─→ DormBooking.DormCode WHERE Status=2 ─(FK)─→ SysEmployee
  ↓
SysEmployee.TeamId ─(FK)─→ Team.Id
  ↓
Team.Name (显示) + Team.SortOrder (排序)
```

## 六、核心代码逻辑

### 6.1 程序端 GetAvailableDormsAsync 新增查询

```csharp
// v2.13.112 员工 TeamId + AttendanceTypeId 查询（用于排序权重）
var empInfo = await _db.Employees.AsNoTracking()
    .Where(e => e.Id == employeeId)
    .Select(e => new { e.Gender, e.TeamId, e.AttendanceTypeId })
    .FirstOrDefaultAsync();
int empTeamId = empInfo?.TeamId ?? 0;
int? empAttId = empInfo?.AttendanceTypeId;

// v2.13.112 派生班组（与 v2.13.111 同 EmployeeTeamMap 模式）
var teamMap = await _db.DormBookings
    .Where(b => dormCodes.Contains(b.DormCode) && b.Status == BookingStatus.Staying)
    .Join(_db.Employees.AsNoTracking(),
          b => b.EmployeeId, e => e.Id,
          (b, e) => new { b.DormCode, e.TeamId })
    .Join(_db.Teams.AsNoTracking(),
          x => x.TeamId, t => t.Id,
          (x, t) => new { x.DormCode, TeamId = t.Id, TeamName = t.Name, SortOrder = t.SortOrder })
    .GroupBy(x => x.DormCode)
    .Select(g => new {
        DormCode = g.Key,
        TeamNames = g.OrderBy(x => x.SortOrder).ThenBy(x => x.TeamId)
                     .Select(x => x.TeamName).Distinct().ToList()
    })
    .ToDictionaryAsync(x => x.DormCode, x => x.TeamNames);
```

### 6.2 DormOption 新增字段

```csharp
public class DormOption
{
    // ... 已有字段
    /// <summary>v2.13.112 新增：该房号已入住员工的班组集合（按 SortOrder 升序 + 去重）。
    /// 数据关系：DormBooking Status=2 → SysEmployee.TeamId → Team.Name。</summary>
    public List<string> TeamNames { get; set; } = new();
    /// <summary>渲染为「一班/三班」格式字符串</summary>
    public string TeamNamesText => string.Join("/", TeamNames);
}
```

### 6.3 4 级智能排序

```csharp
// v2.13.112 4 级排序：同员工班组 > 空房/同性别 > 同班次 > 字典序
var sortedResult = result
    .OrderByDescending(d => teamMap.GetValueOrDefault(d.DormCode)?.Contains(empTeamId) ?? false ? 1 : 0)  // 1st: 同员工班组
    .ThenByDescending(d => d.CurrentCount == 0 ? 1 : 0)  // 2nd: 空房号
    .ThenBy(d => dormAttMap.GetValueOrDefault(d.DormCode) == empAttId ? 0 : 1)  // 3rd: 同班次
    .ThenBy(d => d.DormCode)  // 4th: 字典序
    .ToList();
```

## 八、与 v2.13.111「无人入住完全空白」规则的关系

| 场景 | v2.13.111 宿舍档案列表 | v2.13.112 可分配房号下拉框 |
|------|------------------------|---------------------------|
| 无人在宿 | `<td>` **完全空白** | `班组 -`（用户 v2.13.112 显示需求） |
| 理由 | 列表视图需简洁 | 下拉框信息密度更高，保留 `-` 视觉锚点 |

**为什么不统一？** v2.13.111 用户原话明确「无字符」针对**列表**；v2.13.112 用户原话「班组 A/B/C」针对**下拉框**。两种场景视觉要求不同。
