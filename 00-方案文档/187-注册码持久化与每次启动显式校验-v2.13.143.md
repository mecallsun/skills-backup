## 三、3 大修复策略

### 3.1 显式日期校验（防御深度）

**两层守卫独立校验 RegDate**，不再依赖内嵌规则：

**Layer 1 — TrayApp 启动守卫 `ProcessManager.IsLicenseValid()`**：
```csharp
if (reg.RegInt == 1)
{
    if (!reg.RegDate.HasValue)
    {
        _log.Warn("[LICENSE] RegInt=1 但 RegDate 缺失 → 拒绝启动");
        return false;
    }
    if (reg.RegDate.Value.Date < DateTime.Today)
    {
        _log.Warn($"[LICENSE] 注册已过期: RegDate={reg.RegDate:yyyy-MM-dd} < Today={DateTime.Today:yyyy-MM-dd} → 拒绝启动");
        return false;
    }
    _log.Info($"[LICENSE] 注册有效: LTD={reg.LTDName}, 至 {reg.RegDate:yyyy-MM-dd}");
    return true;
}
```

**Layer 2 — Web/Api 全局守卫 `LicenseGuard.IsReadOnly()`**：
```csharp
if (state.RegInt != 1) return true;   // 第一道
if (!state.RegDate.HasValue) return true;  // 第二道 a：缺失视为异常
if (state.RegDate.Value.Date < DateTime.Today) return true;  // 第二道 b：过期
return false;  // 通过
```

### 3.2 license 文件 DPAPI 加密

**为什么选 DPAPI**：
- Windows 原生最佳实践（`System.Security.Cryptography.ProtectedData`）
- LocalMachine scope 让同一台机器的任何进程（包括非管理员服务）都能解密
- 无需自己管理密钥（Windows 用户的登录凭证派生）
- `Obfuscar` 已 Skip `System.Security.Cryptography` 命名空间，混淆安全

**新文件格式**：
```
offset 0..3:  magic = "JLDL" (0x4A 0x4C 0x44 0x4C)
offset 4:     version = 0x01
offset 5..N:  DPAPI(LocalMachine) 加密的明文 NAME=VALUE\n...
```

**读取兼容性策略**：
```csharp
var isNewFormat = bytes[0..4] == "JLDL" && bytes[4] == 0x01;
if (isNewFormat) {
    // DPAPI 解密
} else {
    // 旧明文格式（v2.13.142 及之前），向后兼容
}
```

**写入永远是新格式**：v2.13.143 启动后，下次注册新 CDKEY 自动覆盖为加密格式。

   ├─ delay 1s
   └─ StartAdminAsync()
        ↓
6. Api/Admin 启动 → 第一次 HTTP 请求
   ↓
7. ┌─ LicenseReadOnlyMiddleware.InvokeAsync()
   │  ├─ LicenseGuard.IsReadOnly()
   │  │  ├─ GetCachedState()
   │  │  │  ├─ 缓存命中 → 直接返回
   │  │  │  └─ 缓存过期 → IpcClient.GetRegStateAsync(2000ms)
   │  │  │        ├─ TCP 127.0.0.1:5099 → TrayApp
   │  │  │        ├─ TrayApp HandleGetRegState
   │  │  │        │  ├─ RegisterSdk.CheckReg() → RegStateDto
   │  │  │        │  └─ 返回 JSON

   │  │  │        └─ 异常 → 返回 null

## 九、5 条永久教训

### 9.1 校验规则必须显式化

依赖"内嵌规则"是脆弱的：`RegisterSdk.CheckReg()` 内部 `if (regDate < Today) RegInt = 0` 是单一权威。如果该规则未来被改写或漏写，所有外部守卫全部失效。**守卫层必须独立判断核心条件**（RegInt != 1 + RegDate < today），即使底层实现变了也能正确执行。

### 9.2 存储保密 ≠ 仅靠文件系统 ACL

HKLM/HKCU 由 Windows ACL 保护是可靠的，但**文件 fallback** 必须额外加密（DPAPI 是 Windows 原生最佳方案）。**三层 fallback 必须分别处理保密强度**，每一层都不能假定上一层覆盖了。

### 9.3 持久化格式升级必须向前兼容

license.dat 加密格式升级时，旧明文格式必须能读取（否则升级导致用户数据丢失）。**用 magic + version 头标识格式**，读取时自动识别格式。这条规则同样适用于所有持久化格式升级。

### 9.4 启动校验失败兜底必须"安全"方向

如果 RegDate 缺失/异常，**不能默认"通过"**——必须进入只读模式。**拒绝写入比允许未授权写入安全得多**（前者的最坏后果是用户不能用，后者是数据被篡改）。

### 9.5 IPC 反转 + 显式校验形成完整闭环

v2.13.137 解决了「注册权威唯一收敛到 TrayApp」，v2.13.143 解决了「校验规则独立且显式」。**两者组合才能形成完整防御纵深**——单点权威 + 多点验证。
