## 1. 业务背景

原功能需求缺少「系统设置」模块。系统实际由 **.NET 8 自托管 EXE + 托盘守护** 运行，所有连接串、端口、路径均需可视化配置。

**双 UI 入口职责划分**：

| 入口 | 职责 | 权限控制 |
|------|------|---------|
| **托盘系统配置窗口**（SettingsForm） | 仅配置核心服务端参数（PDA/Web 端口、数据库连接、图片存储路径、服务器域名），**无角色权限项控制** | 仅运维/管理员本地维护 |
| **Web 后台系统设置**（`/Settings`） | 承载全部系统设置功能（服务管理、数据库、PDA版本、用户角色、备份恢复、系统集成、筛选缓存），**受角色权限管控** | 仅管理员可访问 |

> **设计原则**：托盘窗口仅保留系统启动所必需的核心服务端参数配置，其他所有业务配置功能均在 Web 端实现，统一由角色权限体系管控。

**仅「管理员」角色可访问 Web 端「系统设置」模块**（见权限矩阵）。

### 3.8 数据库参数本地加密存储（v2.11.8 初稿，v2.13.19 重大修订）

> **⚠️ 版本说明**：本节 v2.11.8 原建议使用 Windows DPAPI。v2.13.19 实现已改为 **AES-256-CBC 对称加密 + AppConfigManager 双 UI 同步机制**，并新增 `DbConfigController` 与 `SysParameter` 表持久化。本节保留 DPAPI 原文作为历史参考，**实际开发以 `00-方案文档/71-系统设置数据库连接双UI同步需求-v2.13.19.md` 为准**。

#### 3.8.1 技术澄清：为什么不用 MD5

> ⚠️ **关键纠偏**：MD5 / SHA-1 / SHA-256 等哈希算法**均为单向不可逆**——只有「加密」没有「解密」。原话「MD5 加密...自动解密」在技术层面不可能实现。

| 算法 | 类型 | 可逆性 | 适用场景 |
|------|------|--------|---------|
| **MD5** | 哈希 | ❌ **不可逆** | 文件指纹、密码哈希（不应再使用） |
| **SHA-256** | 哈希 | ❌ **不可逆** | 文件校验、SSL 证书指纹 |
| **AES-256** | 对称加密 | ✅ 可逆（需 Key） | 通用数据加密 |
| **RSA** | 非对称加密 | ✅ 可逆（需私钥） | 数字签名、TLS 握手 |
| **Windows DPAPI** | OS 托管加密 | ✅ 可逆（OS 派生 Key） | **本系统选用** |

**结论**：连接串包含数据库账号密码，必须以**可逆加密**方式保护，故排除 MD5 / SHA 系列哈希算法。

#### 3.8.2 选用 AES-256 对称加密（v2.13.19 修订）

> **⚠️ 版本说明**：v2.11.8 原建议使用 Windows DPAPI。v2.13.19 实现已改为 **AES-256-CBC 对称加密**，密钥硬编码于 `AesEncryptor`（生产环境建议改为外部注入）。

| 维度 | AES-256-CBC | Windows DPAPI |
|------|---------------|---------------|
| **密钥管理** | 硬编码 Key + IV（生产环境建议外部注入） | 操作系统自动派生（绑用户+机器） |
| **跨平台** | ✅ 支持 Linux/macOS/Windows | ❌ 仅 Windows |
| **额外依赖** | 0（System.Security.Cryptography 内置） | 0（Windows 10/11/Server 2016+ 原生） |
| **与现有体系一致** | ✅ §3.8.4 密码字段同样使用 AES-256 | ⚠️ DPAPI 仅适用于 Windows 环境 |

**最终方案**：**AES-256-CBC 对称加密**，支持跨平台部署（未来 Linux Docker 场景）以及服务端与托盘分离读取。

#### 3.8.3 字段与规则（v2.13.19 修订）

| 字段 | 存储介质 | 存储形态 | 写入时机 | 读取时机 |
|------|---------|---------|---------|---------|
| `Database.ConnectionString` | `db_setting.json` | **Base64(AES-256 密文)** | 用户在系统配置窗口点击「保存」并通过「测试连接」后 | 托盘程序启动时 / 重启服务时 |
| `SysParameter` 表 | SQL Server `SysParameter` | AES-256 加密后存储 | 保存配置时后台异步写入 | 启动时从文件优先读取 |

**约束**：
- 配置文件 `db_setting.json` 中**始终存储密文**，禁止明文落盘
- 内存中（托盘进程、Web/PDA 子进程）可短暂持有明文
- 托盘 → 子进程的传递通过**进程环境变量** `DormManage_DB_CONN`，子进程不写回磁盘
- 密码字段使用 `AppConfigManager` 的 AES-256 加密/解密

#### 3.8.4 完整生命周期（v2.13.19 修订）

```
阶段 1 - 首次部署
  └─ 使用默认值（192.168.1.237 / WaterMeterDB / __DB_USER__ / __DB_PASSWORD__）

阶段 2 - 用户填写并保存
  └─ 用户在 SettingsForm 或 Web Admin 输入：服务器/端口/库名/账号/密码
      └─ 点击「测试连接」→ AppConfigManager.TestDbConnectionAsync()
          └─ 测试通过 → 点击「保存」
              └─ AppConfigManager.SaveConfigurationAsync()
                  ├─ AES-256 加密密码
                  ├─ 原子写入 db_setting.json（temp → rename）
                  └─ 后台异步写入 SysParameter 表
                      └─ 触发 OnDatabaseConfigUpdated 事件

阶段 3 - 托盘启动（每次开机 / 手动重启）
  └─ TrayApp.exe 启动
      └─ AppConfigManager.LoadAsync() 读取 db_setting.json
          └─ AES-256 解密密码
              └─ ConfigService.UpdateDatabaseSection() 写回 appsettings.json
                  └─ 注入到 ProcessStartInfo.Environment["DormManage_DB_CONN"]

阶段 4 - 拉起 Web/PDA 子进程
  └─ ProcessManager.StartService("Admin" / "Api")
      └─ 构造 ProcessStartInfo 时注入环境变量 DormManage_DB_CONN
          └─ 子进程 Program.cs 读环境变量 → 覆盖 appsettings.json 中的 ConnectionString
              └─ EF Core / SqlClient 使用该连接串连接数据库

阶段 5 - Web Admin 读取配置
  └─ 用户访问 /Settings?tab=db
      └─ JS 调用 GET /api/v1/system/dbconfig
          └─ DbConfigController.GetConfig() → AppConfigManager.LoadAsync()
              └─ AES-256 解密密码 → 脱敏为 ****** → 返回前端
                  └─ 前端填充表单（密码显示 ******，其他字段显示真实值）

阶段 6 - Web Admin 保存配置
  └─ 用户修改配置 → 点击「保存」
      └─ JS 调用 POST /api/v1/system/dbconfig/save
          └─ DbConfigController.SaveConfig() → AppConfigManager.SaveConfigurationAsync()
              └─ 双擎持久化（db_setting.json + SysParameter 表）
                  └─ 触发 OnDatabaseConfigUpdated 事件
                      └─ 兜底通过 IPC 通知 TrayApp
```

## 6. UI 与交互要求

- 左侧竖向 pills 导航（宽度固定 200px）+ 右侧 tab 面板，**左右两侧上边严格水平对齐（flexbox 布局 `display: flex; align-items: flex-start; gap: 12px`）**，单页内切换，专业紧凑。
- 所有列表页筛选条件区域使用 `flex-nowrap` 一行排列，根据屏幕宽度自适应调整字段宽度。
- 服务状态用绿/红圆点 + 文字实时展示；启停即时联动。
- 数据库测试逐步反馈 8 步结果；全部通过时高亮成功。
- 危险操作（恢复数据库、停用用户）二次确认。
- 仅管理员可见「系统设置」导航入口。

## 7. 双 UI 职责划分

| 入口 | 职责范围 | 权限控制 |
|------|---------|---------|
| **托盘系统配置窗口**（SettingsForm） | 核心服务端参数：PDA/Web 端口、数据库连接、图片存储路径、服务器域名、服务启停、保存参数 | **无角色权限项控制**，任何本地用户均可打开和修改 |
| **Web 后台系统设置**（`/Settings`） | 全部系统设置功能：服务管理、数据库、PDA版本、用户角色、备份恢复、系统集成、筛选缓存 | **仅管理员可访问**，各子功能受角色权限矩阵管控 |

> **设计原则**：托盘窗口仅保留系统启动所必需的核心服务端参数配置，确保运维工程师在紧急情况下能够快速修改端口、数据库连接等关键参数；Web 端承载全部业务配置功能，统一由角色权限体系管控。
