## 1. 业务背景

原功能需求缺少「系统设置」模块。系统实际由 **.NET 8 自托管 EXE + 托盘守护** 运行，所有连接串、端口、路径均需可视化配置。

**双 UI 入口职责划分**：

| 入口 | 职责 | 权限控制 |
|------|------|---------|
| **托盘系统配置窗口**（SettingsForm） | 仅配置核心服务端参数（PDA/Web 端口、数据库连接、图片存储路径、服务器域名），**无角色权限项控制** | 仅运维/管理员本地维护 |
| **Web 后台系统设置**（`/Settings`） | 承载全部系统设置功能（服务管理、数据库、PDA版本、用户角色、备份恢复、系统集成、筛选缓存），**受角色权限管控** | 仅管理员可访问 |

> **设计原则**：托盘窗口仅保留系统启动所必需的核心服务端参数配置，其他所有业务配置功能均在 Web 端实现，统一由角色权限体系管控。

**仅「管理员」角色可访问 Web 端「系统设置」模块**（见权限矩阵）。

### 3.8 数据库参数本地加密存储（v2.11.8 初稿，v2.13.19 重大修订）

> **⚠️ 版本说明**：本节 v2.11.8 原建议使用 Windows DPAPI。v2.13.19 实现已改为 **AES-256-CBC 对称加密 + AppConfigManager 双 UI 同步机制**，并新增 `DbConfigController` 与 `SysParameter` 表持久化。本节保留 DPAPI 原文作为历史参考，**实际开发以 `00-方案文档/71-系统设置数据库连接双UI同步需求-v2.13.19.md` 为准**。

#### 3.8.1 技术澄清：为什么不用 MD5

> ⚠️ **关键纠偏**：MD5 / SHA-1 / SHA-256 等哈希算法**均为单向不可逆**——只有「加密」没有「解密」。原话「MD5 加密...自动解密」在技术层面不可能实现。

| 算法 | 类型 | 可逆性 | 适用场景 |
|------|------|--------|---------|
| **MD5** | 哈希 | ❌ **不可逆** | 文件指纹、密码哈希（不应再使用） |
| **SHA-256** | 哈希 | ❌ **不可逆** | 文件校验、SSL 证书指纹 |
| **AES-256** | 对称加密 | ✅ 可逆（需 Key） | 通用数据加密 |
| **RSA** | 非对称加密 | ✅ 可逆（需私钥） | 数字签名、TLS 握手 |
| **Windows DPAPI** | OS 托管加密 | ✅ 可逆（OS 派生 Key） | **本系统选用** |

**结论**：连接串包含数据库账号密码，必须以**可逆加密**方式保护，故排除 MD5 / SHA 系列哈希算法。

#### 3.8.2 选用 AES-256 对称加密（v2.13.19 修订）

> **⚠️ 版本说明**：v2.11.8 原建议使用 Windows DPAPI。v2.13.19 实现已改为 **AES-256-CBC 对称加密**，密钥硬编码于 `AesEncryptor`（生产环境建议改为外部注入）。

| 维度 | AES-256-CBC | Windows DPAPI |
|------|---------------|---------------|
| **密钥管理** | 硬编码 Key + IV（生产环境建议外部注入） | 操作系统自动派生（绑用户+机器） |
| **跨平台** | ✅ 支持 Linux/macOS/Windows | ❌ 仅 Windows |
| **额外依赖** | 0（System.Security.Cryptography 内置） | 0（Windows 10/11/Server 2016+ 原生） |
| **与现有体系一致** | ✅ §3.8.4 密码字段同样使用 AES-256 | ⚠️ DPAPI 仅适用于 Windows 环境 |

**最终方案**：**AES-256-CBC 对称加密**，支持跨平台部署（未来 Linux Docker 场景）以及服务端与托盘分离读取。

#### 3.8.3 字段与规则（v2.13.19 修订）

| 字段 | 存储介质 | 存储形态 | 写入时机 | 读取时机 |
|------|---------|---------|---------|---------|
| `Database.ConnectionString` | `db_setting.json` | **Base64(AES-256 密文)** | 用户在系统配置窗口点击「保存」并通过「测试连接」后 | 托盘程序启动时 / 重启服务时 |
| `SysParameter` 表 | SQL Server `SysParameter` | AES-256 加密后存储 | 保存配置时后台异步写入 | 启动时从文件优先读取 |

**约束**：
- 配置文件 `db_setting.json` 中**始终存储密文**，禁止明文落盘
- 内存中（托盘进程、Web/PDA 子进程）可短暂持有明文
- 托盘 → 子进程的传递通过**进程环境变量** `DormManage_DB_CONN`，子进程不写回磁盘
- 密码字段使用 `AppConfigManager` 的 AES-256 加密/解密

#### 3.8.4 完整生命周期（v2.13.19 修订）

```
阶段 1 - 首次部署
  └─ 使用默认值（192.168.1.237 / WaterMeterDB / __DB_USER__ / __DB_PASSWORD__）

阶段 2 - 用户填写并保存
  └─ 用户在 SettingsForm 或 Web Admin 输入：服务器/端口/库名/账号/密码
      └─ 点击「测试连接」→ AppConfigManager.TestDbConnectionAsync()
          └─ 测试通过 → 点击「保存」
              └─ AppConfigManager.SaveConfigurationAsync()
                  ├─ AES-256 加密密码
                  ├─ 原子写入 db_setting.json（temp → rename）
                  └─ 后台异步写入 SysParameter 表
                      └─ 触发 OnDatabaseConfigUpdated 事件

阶段 3 - 托盘启动（每次开机 / 手动重启）
  └─ TrayApp.exe 启动
      └─ AppConfigManager.LoadAsync() 读取 db_setting.json
          └─ AES-256 解密密码
              └─ ConfigService.UpdateDatabaseSection() 写回 appsettings.json
                  └─ 注入到 ProcessStartInfo.Environment["DormManage_DB_CONN"]

阶段 4 - 拉起 Web/PDA 子进程
  └─ ProcessManager.StartService("Admin" / "Api")
      └─ 构造 ProcessStartInfo 时注入环境变量 DormManage_DB_CONN
          └─ 子进程 Program.cs 读环境变量 → 覆盖 appsettings.json 中的 ConnectionString
              └─ EF Core / SqlClient 使用该连接串连接数据库

阶段 5 - Web Admin 读取配置
  └─ 用户访问 /Settings?tab=db
      └─ JS 调用 GET /api/v1/system/dbconfig
          └─ DbConfigController.GetConfig() → AppConfigManager.LoadAsync()
              └─ AES-256 解密密码 → 脱敏为 ****** → 返回前端
                  └─ 前端填充表单（密码显示 ******，其他字段显示真实值）

阶段 6 - Web Admin 保存配置
  └─ 用户修改配置 → 点击「保存」
      └─ JS 调用 POST /api/v1/system/dbconfig/save
          └─ DbConfigController.SaveConfig() → AppConfigManager.SaveConfigurationAsync()
              └─ 双擎持久化（db_setting.json + SysParameter 表）
                  └─ 触发 OnDatabaseConfigUpdated 事件
                      └─ 兜底通过 IPC 通知 TrayApp
```

## 8. v2.13.94 软件注册授权（追加章节）

### 8.1 业务背景

参考原 NPGS.Register WinForms 项目（.NET 4.8 + 闭源 Public.Core.SDK.dll），将软件注册授权功能整合到本项目并支持后续其他 .NET 项目复用。入口：

- **Web 端**：`系统设置 → 关于系统` Tab 顶部新增「软件注册授权」卡片
- **托盘端**：托盘右键菜单 → 「软件注册授权...」弹窗

### 8.2 字段定义（5 字段 + 4 按钮）

| # | 字段 | 类型 | 只读 | 说明 |
|---|------|------|------|------|
| 1 | 机器码 | readonly | 是 | 24 字符 hex（如 `BFEBFBFF000A06A4AA2E3B0E`），display 5-5-5-5-4 带连字符 |
| 2 | 公司名称 | readonly | 是 | 注册时填入，存入 License 文件 |
| 3 | 注册码 | readonly | 是（已注册）/ 否（未注册） | 29 位 5-5-5-5-5，前 20 位是验证段 + 后 5 位日期段 |
| 4 | 有效日期 | readonly | 是 | 从注册码末段 HEX 解码 YYYY-MM-DD |
| 5 | 试用次数 / 状态 | readonly | 是 | 「试用 N / 30 次」+ 「已注册 / 已过期 / 未注册」Badge |

| # | 按钮 | 触发 | 权限 |
|---|------|------|------|
| 1 | 复制机器码 | navigator.clipboard.writeText(SN) | 无 |
| 2 | 注册 | CheckRegCDKey + WriteRegItem | 管理员 |
| 3 | 取消注册 | DeleteRegItem（保留试用次数） | 管理员 |
| 4 | 清理 | DeleteRegAll（含试用次数） | 管理员 |

### 8.3 业务规则

- **机器码生成**：WMI `Win32_Processor.ProcessorId` (16 hex) + `Win32_LogicalDisk.VolumeSerialNumber` (8 hex) = 24 hex
- **CDKEY 生成**：20 位验证段 = `MD5(SN|LTDName|SECRET_KEY).前20hex` + 5 位日期段 = `HEX(YYYY-MM-DD)`
- **试用期**：未注册时启动 UseTimes +1，超过 30 次必须注册
- **注册验证失败**：错误消息精准化（机器码不匹配 / 公司名称不匹配 / 注册码无效 / 已过期）
- **存储**：HKLM → HKCU → `%ProgramData%\JINGE\DormManage\license.dat` 三层降级

### 8.4 跨平台兼容

- **TrayApp 端**（net8.0-windows）：用 System.Management 取真实 CPUID + VolumeSerialNumber，启动时写入共享文件 `machine.dat` + 设置环境变量 `DORM_MACHINE_SN`
- **Web 端**（跨平台 .NET 8）：三层降级读取（环境变量 → 共享文件 → MD5 fallback）
- **关键约束**：Shared 项目不能依赖 System.Management（Linux 不可用，CS0234 失败）

### 8.5 复用性要求

详见 `00-方案文档/147-软件注册授权-v2.13.94.md`（⭐⭐⭐⭐⭐ 独立可复用）：
- 4 文件最小迁移包：`RegItem.cs` + `RegisterSdk.cs` + `LicenseGenerator.cs` + `LicenseForm.cs`
- SECRET_KEY 必须替换为公司专属密钥
- 算法兼容原 NPGS.Register，可由我方"注册机"独立生成 CDKEY

### 8.6 原型与代码对照

- 原型：`00-方案文档/04-HTML原型/settings/about.html`（独立预览）+ `license-form-tray.html`（托盘弹窗）
- Web 实现：`DormManage.Admin/Pages/Settings/Index.cshtml?tab=about`（tab-about 区块顶部 + 嵌入主入口）

## 9. v2.13.95 账号有效期（追加章节）

### 9.1 业务背景

**用户原话**：在 用户管理 中，增加账号 的 有效期至，用于登记访问的日期大于有效期至设置的日期时，则拒绝登录系统。

**业务价值**：
- 临时人员（外部审计员、PDA 借调、外包）账号过期自动失效，无需人工停用
- 离职人员账号一次性设置过期日，不再需要手动停用
- 满足等保 / ISO27001「账号生命周期管理」合规要求

### 9.2 字段定义

| # | 字段 | 类型 | NULL 语义 | 说明 |
|---|------|------|----------|------|
| 1 | `SysUser.ExpiresAt` | `DateTime?` | **NULL = 永久有效** | 账号有效期截止日期（精确到日，存为 UTC+8 当天 00:00:00）|

### 9.3 业务规则

#### 9.3.1 登录校验（`AuthService.LoginAsync`）
```csharp
if (user.ExpiresAt.HasValue && DateTime.Today > user.ExpiresAt.Value.Date)
    return (false, "账号已过期，请联系管理员", null);
```
- 含当日（Today ≤ ExpiresAt.Date）→ 可登录
- 次日（Today > ExpiresAt.Date）→ 拒绝「账号已过期，请联系管理员」

#### 9.3.2 会话校验（`Program.cs::AddCookie::OnValidatePrincipal`）
每次请求时校验 ExpiresAt，已登录会话会自动踢出：
```csharp
options.Events.OnValidatePrincipal = async context => {
    var db = context.HttpContext.RequestServices.GetRequiredService<DormDbContext>();
    var userIdClaim = context.Principal?.FindFirst(ClaimTypes.NameIdentifier)?.Value;
    if (int.TryParse(userIdClaim, out var userId))
    {
        var user = await db.SysUsers.FindAsync(userId);
        if (user == null || !user.IsActive || user.IsLocked
            || (user.ExpiresAt.HasValue && DateTime.Today > user.ExpiresAt.Value.Date))
        {
            context.RejectPrincipal();
            await context.HttpContext.SignOutAsync(CookieAuthenticationDefaults.AuthenticationScheme);
        }
    }
};
```

#### 9.3.3 三层防御（必做）
| 层级 | 实现位置 | 拒绝逻辑 |
|------|---------|---------|
| ① 登录层 | `AuthService.LoginAsync` | 校验 ExpiresAt → 返回错误码 `EXPIRED` |
| ② 会话层 | `OnValidatePrincipal` 钩子 | 每次请求 FindAsync SysUser → 过期则 `RejectPrincipal` + `SignOutAsync` |
| ③ UI 层 | `_UserPanel.cshtml` 列表 Badge | 提示管理员即将过期 / 已过期，避免忘记设置 |

### 9.4 UI 字段（4 态 Badge）

#### 9.4.1 列表「有效期至」列（v2.13.95 新增）

| 状态 | 条件 | Badge 颜色 | 样式 |
|------|------|-----------|------|
| **永久** | `ExpiresAt IS NULL` | `bg-light text-dark border` + `<i class="bi bi-infinity">` | 灰底描边 + 无限符号 |
| **正常** | `Today ≤ ExpiresAt - 30 天` | 普通文本 | 显示日期 + title「X 天后到期」|
| **即将过期** | `ExpiresAt - 30 天 ≤ Today ≤ ExpiresAt` | `bg-warning text-dark` | 黄底 + title「剩 X 天过期」|
| **已过期** | `Today > ExpiresAt` | `bg-danger` | 红底 + title「已过期 X 天，下次登录将被拒绝」|
