# 办理入住 BUG 修复 + 工号姓名关联修正（v2.13.33）

> 实施日期：2026-07-20
> 关联 BUG：
> - **BUG #1**：办理入住（CheckIn）弹窗 — 筛选并选择员工后，没有返回员工信息，而是卡着界面，按钮失效
> - **BUG #2**：办理登记记录列表中的「工号显示姓名的关联存在 BUG」— 需要以人员清单的档案姓名的工号进行数据补充更正关联
> 关联版本：v2.13.32 → v2.13.33

## 一、BUG 复现与根因分析

### 1.1 BUG #1：办理入住弹窗卡死

**复现步骤**：
1. 进入 `/Booking` 页面
2. 点击「办理入住」打开弹窗
3. 在员工搜索框输入员工姓名/工号
4. 从下拉建议中选择一个员工
5. **现象**：员工信息展示区（工号/姓名/部门/手机）仍为空；「选择员工」校验提示仍显示「请先选择员工」；点击「确认入住」按钮无效，弹窗卡死

**根因**（`DormManage.Admin/Pages/Booking/Index.cshtml` L738-746）：

```javascript
async function selectCiEmp(empId) {
    document.getElementById('ciEmpSuggestions').style.display = 'none';
    try {
        const resp = await fetch(`/api/v1/bookings/employee-search?keyword=`);  // ❌ 空 keyword
        // 从搜索结果中找到匹配的员工（简化：通过 API 获取员工详情）
        // 这里先用搜索回调填充
        onCiEmpSearch();   // ❌ 只是再调一次搜索，没有填充任何员工字段
    } catch(e) {}
}
```

`empId` 参数虽然传入了，但函数体完全没用上：
1. 空 keyword 调 API → 后端返回空结果
2. `onCiEmpSearch()` 只是把员工列表重新渲染到下拉
3. **`dataset.empId` 永远没被设置** → `submitCheckIn()` 取 `document.getElementById('ciEmpKeyword').dataset.empId` 得到空 → `if (!employeeId) { alert('请选择员工'); return; }` 阻断提交

### 1.2 BUG #2：工号显示姓名与档案不一致

**复现步骤**：
1. 修改某员工档案（`SysEmployee.RealName` 从「张三」改为「张三丰」）
2. 进入 `/Booking` 页面
3. **现象**：历史登记记录中该员工的姓名仍显示「张三」（即 `DormBooking.EmployeeName` 列里写的旧值）

**根因**（`DormManage.Shared/Services/BookingService.cs` L160-227）：

`GetListAsync` 用 JOIN 取 `SysEmployee.AttendanceTypeId` 用于列表显示，但 **没有用 `SysEmployee.RealName` 覆盖 `DormBooking.EmployeeName`**。当员工档案改名后：
- `DormBooking.EmployeeName` 保留登记时的旧姓名（写入时快照）
- `SysEmployee.RealName` 已是新姓名
- 列表只读 `DormBooking.EmployeeName` → 显示错误

**历史原因**：`DormBooking.EmployeeName` 是 v2.11.x 引入的"反范式冗余字段"（避免每次 JOIN），但缺少与档案的同步机制。

#### 2.2.2 一次性数据修复（Repair API）

**新增方法**：`BookingService.RepairBookingEmployeeNamesAsync()`

```csharp
public async Task<ApiResponse<(int Updated, int Skipped, int NotFound)>> RepairBookingEmployeeNamesAsync()
{
    var allBookings = await _db.DormBookings
        .Where(b => !string.IsNullOrEmpty(b.EmployeeCode))
        .Select(b => new { b.Id, b.EmployeeId, b.EmployeeCode, b.EmployeeName })
        .ToListAsync();

    var empIds = allBookings.Where(b => b.EmployeeId > 0).Select(b => b.EmployeeId).Distinct().ToList();
    var empCodes = allBookings.Select(b => b.EmployeeCode).Distinct().ToList();

    var employees = await _db.Employees
        .Where(e => empIds.Contains(e.Id) || empCodes.Contains(e.EmployeeCode))
        .Select(e => new { e.Id, e.EmployeeCode, e.RealName })
        .ToListAsync();

    var byId = employees.ToDictionary(e => e.Id);
    var byCode = employees.ToDictionary(e => e.EmployeeCode);

    int updated = 0, skipped = 0, notFound = 0;
    var affected = new List<DormBooking>();
    foreach (var b in allBookings) {
        string? latest = null;
        if (b.EmployeeId > 0 && byId.TryGetValue(b.EmployeeId, out var byIdEmp))
            latest = byIdEmp.RealName;
        else if (byCode.TryGetValue(b.EmployeeCode, out var byCodeEmp))
            latest = byCodeEmp.RealName;

        if (latest is null) { notFound++; continue; }
        if (string.IsNullOrEmpty(latest)) { skipped++; continue; }
        if (string.Equals(latest, b.EmployeeName, StringComparison.Ordinal)) { skipped++; continue; }

        var entity = await _db.DormBookings.FindAsync(b.Id);
        if (entity is null) continue;
        entity.EmployeeName = latest;
        entity.UpdatedAt = DateTime.Now;
        affected.Add(entity);
        updated++;
    }

    if (affected.Count > 0) await _db.SaveChangesAsync();
    return ApiResponse<(int, int, int)>.Ok((updated, skipped, notFound));
}
```

**匹配优先级**：
1. **EmployeeId 优先**（v2.13.x 起 DormBooking.EmployeeId 必填，JOIN 关系稳定）
2. **EmployeeCode 次之**（兼容历史数据中 EmployeeId=0 的孤儿记录）

**新增 API 端点**：`POST /api/v1/bookings/repair-employee-names`

```csharp
[HttpPost("repair-employee-names")]
public async Task<ApiResponse<(int Updated, int Skipped, int NotFound)>> RepairEmployeeNames()
{
    return await _service.RepairBookingEmployeeNamesAsync();
}
```

**新增 UI 按钮**：在 `/Booking` 页面 PageHeader 加「修复姓名关联」按钮（橙色 `btn-warning`）

```javascript
async function repairEmployeeNames() {
    if (!confirm('将以「人员清单」档案中的最新姓名为准，修正办理登记列表中所有工号对应的姓名。\n\n仅修正 DormBooking.EmployeeName 与 SysEmployee.RealName 不一致的记录，已一致的会跳过。\n\n继续执行？')) return;
    try {
        const resp = await fetch('/api/v1/bookings/repair-employee-names', { method: 'POST' });
        const result = await resp.json();
        if (result.success) {
            const { updated, skipped, notFound } = result.data;
            alert(`✅ 修复完成\n\n修正：${updated} 条\n跳过（已一致）：${skipped} 条\n未找到档案：${notFound} 条\n\n3 秒后自动刷新页面...`);
            setTimeout(() => location.reload(), 3000);
        } else {
            alert('修复失败：' + (result.message || '未知错误'));
        }
    } catch (err) { console.error(err); alert('修复请求失败：' + err.message); }
}
```

**返回值语义**：
| 字段 | 含义 |
|------|------|
| `updated` | 实际修正的 DormBooking 行数 |
| `skipped` | 已一致（无需修正）或档案姓名为空的记录数 |
| `notFound` | 在 `SysEmployee` 表里找不到匹配档案的孤儿记录数 |

## 四、关联记录修复流程

```
用户进入 /Booking 页面（BUG 已自动修正，无需手动操作）
    ↓
GetListAsync (运行时实时修正)
    ├─ JOIN SysEmployee ON DormBooking.EmployeeId = SysEmployee.Id
    ├─ SELECT EmployeeName = COALESCE(emp.RealName, b.EmployeeName)
    └─ 列表显示"档案最新姓名"
    ↓
若用户希望"一次性写回数据库"（如导出前清理）
    ↓
点击「修复姓名关联」按钮（橙色）
    ↓
POST /api/v1/bookings/repair-employee-names
    ↓
BookingService.RepairBookingEmployeeNamesAsync()
    ├─ 拉取所有 DormBooking（EmployeeCode 非空）
    ├─ 拉取匹配 EmployeeId / EmployeeCode 的 SysEmployee
    ├─ 逐条对比 EmployeeName 与 RealName
    ├─ 不一致 → UPDATE DormBooking.EmployeeName + UpdatedAt
    └─ 返回 (updated, skipped, notFound) 计数
    ↓
alert 显示修复摘要 + 3 秒后刷新页面
```
