## 一、注册状态与运行模式映射

系统依据注册信息（CDKEY 校验结果、有效期、试用次数）进入三种运行模式之一，三种模式**互斥且完备**，覆盖所有可能的注册状态组合。

### 1.1 核心映射表

| 注册状态 (RegStatus) | RegInt | 运行模式 | IsReadOnly() | IsTrialMode() | 写操作权限 | UI 徽章 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **Unregistered**<br>（未注册）| -1 | **试用模式** | false | true | ✅ 放行 + 分模块记录限制 | 🟦 试用模式 |
| **Valid**<br>（已注册且有效）| 1 | **注册模式** | false | false | ✅ 全功能正常（无限制） | ✅ 已注册 |
| **Expired**<br>（已过期）| 0 | **只读模式** | true | false | ❌ 全部拦截 403 | ⚠️ 已过期 |
| **Invalid**<br>（校验失败）| 0 | **只读模式** | true | false | ❌ 全部拦截 403 | ⚠️ 校验失败 |

> **说明**：
> - `RegInt` 为向后兼容值：`Valid→1`，`Expired/Invalid→0`，`Unregistered→-1`
> - `IsReadOnly()` 返回 `true` 时，所有非 GET 请求被 LicenseReadOnlyMiddleware 拦截返回 403
> - `IsTrialMode()` 仅在 `Unregistered` 且试用次数未超限时返回 `true`，此时 API 中间件放行情由 Controller 层的 `CheckTrialRecordLimit` 做二次限制

### 1.2 试用模式分模块记录上限

试用模式下，为平衡业务可用性与防滥用，对以下三个高频模块设置记录数上限：

| 模块名（显示名）| 模块路径 | 上限条数 | 说明 |
|:---:|:---:|:---:|:---:|
| 住宿登记 | `/api/v1/bookings`、`/api/bookings` | 500 条 | 高频业务操作，上限较高 |
| 住宿档案 | `/api/dorms`、`/api/v1/dorms` | 5 条 | 基础资料，一次性录入 |
| 人员清单 | `/api/v1/personnel`、`/api/personnel` | 5 条 | 基础资料，一次性录入 |

> **业务规则**：
> - 超出上限时，返回 `TRIAL_LIMIT_EXCEEDED` 错误码，含详细提示
> - 其他模块（如智能抄表、账单、基础资料等）在试用模式下**不受记录数限制**
> - 正式注册后（`Valid` 模式），所有上限自动解除

## 二、只读模式行为定义

当注册进入 `Expired` 或 `Invalid` 状态时，系统进入**只读模式**，特征如下：

### 2.1 访问控制

- **GET / HEAD / OPTIONS 请求**：正常放行，用户可查看数据、执行筛选、统计查询
- **POST / PUT / PATCH / DELETE 请求**：全部拦截，返回 HTTP 403 Forbidden
  - API 端 → 返回 JSON：`{ "success": false, "code": "LICENSE_READONLY", "message": "..." }`
  - Admin Razor Page POST → 重定向到 `/Error?code=LICENSE_READONLY&msg=...`

### 2.2 前端反馈

- **注册状态徽章**（`wwwroot/js/license-status-badge.js`）显示 `⚠️ 已过期(只读)` 或 `⚠️ 校验失败(只读)`，badge 颜色为 warning/danger
- **写操作按钮**：前端通过 `license-status-badge.js` 自动禁用所有 `type="submit"`、`.btn-primary`、`.btn-danger.action-save` 按钮，置灰并提示"许可受限，写操作已禁用"
- **AJAX 请求错误处理**：`postPanelAction` 等统一拦截函数会捕获 403 响应，在表单上方显示红色错误提示框
- **Error 页面**：当通过重定向到达时，显示明确的注册过期友好提示，而非通用错误信息

### 2.3 例外白名单

只读模式下仍可访问以下路径（供用户进行注册操作或诊断）：

- `/Account/*`（登录页、退出页）
- `/Error`（错误显示页）
- `/api/v1/system/license-status`（注册状态查询端点）
- `/swagger/`（Swagger API 文档，运维诊断需要）
- `/api/v1/system/dbhealth/*`（健康检查，托盘轮询需要）

## 三、模式转换逻辑

### 3.1 从试用模式 → 注册模式

用户通过托盘 LicenseForm 完成注册后：

1. TrayApp 调用 `RegisterSdk.WriteRegItem()` 持久化注册信息
2. `LicenseMonitor()` 通过 IPC 向 Admin/Api 推送 `regstate.changed` 事件
3. Admin/Api 子进程在下次 30s 轮询时获取新状态，`IsReadOnly()` 和 `IsTrialMode()` 立即返回 `false`
4. 已存在的 Session 不受影响，新请求即生效（无需重启）

### 3.2 从注册模式 → 只读模式

注册码过期（RegDate < Today）时：

1. TrayApp 的 LicenseMonitor 在检测到过期时推送状态变化
2. Admin/Api 子进程 30s 内轮询到状态变更，`IsReadOnly()` 切换为 `true`
3. 所有未完成的 POST 请求在下一个请求中被拦截
4. 正在进行的读操作不受影响

### 3.3 从只读模式 → 注册模式（续期）

用户在过期后通过 LicenseForm 输入新的有效 CDKEY：

1. 新注册信息写入覆盖旧值
2. `LicenseGuard.ResetCache()` 清空子进程缓存
3. 子进程下次轮询获取新状态，恢复全功能
