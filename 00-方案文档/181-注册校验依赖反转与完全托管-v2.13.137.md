## 一、用户原话（2026-07-24 最新指示）

> "将 交付 程序，封装 成为 exe 文件在服务器主机运行，所有 web 服务及 pda 服务 程序的运行，必须 依附于 托盘程序 的运行及注册校验信息的结果的通过或失败（过期、未注册、超出使用次数）；禁止任务程序 或功能 托盘程序 的注册 信息的 校验！"

**关键洞察**：
1. 「封装成为 exe 文件」= 部署简化（仍是 3 EXE，但逻辑上统一由托盘托管）
2. 「必须依附于 托盘程序 的运行」= 进程生命周期从属
3. 「注册校验信息的通过或失败」= 校验决策权
4. 「过期、未注册、超出使用次数」= 三种拦截场景
5. **「禁止任何程序或功能 托盘程序 的注册信息的校验」= 反向依赖**——这是核心架构变更！

**反向依赖**：原本 Web/Api/PDA 各自调用 `RegisterSdk.CheckReg()`，v2.13.137 改为：
- **托盘** 唯一调用 `RegisterSdk.CheckReg()` / `WriteRegItem()` / `DeleteRegItem()`
- **Web/Api/PDA** 全部改为通过 IPC 查询托盘获取注册状态
- **禁止** Web/Api/PDA 独立读注册表 / 读注册表键值 / 调用 RegisterSdk 任何方法

```
└──────────────┬──────────────────────────────┘

        ┌──────┴──────┐
        ▼             ▼
   ┌─ Admin ─┐   ┌─ Api ──┐
   │ LicenseGuard│  │ LicenseGuard│
   │ IsReadOnly()│  │ IsReadOnly()│
   │ (IPC 查询) │  │ (IPC 查询) │
   └──────────┘  └──────────┘
   禁止独立启动！禁止自启注册表！
   禁止调用 RegisterSdk！
```

### 3.2 完全托管生命周期

| 阶段 | 操作 | 拦截 |
|------|------|------|
| **托盘启动** | 单实例 Mutex + 暗桩 + WMI 机器码初始化 | 进程级 |
| **注册校验** | `LicenseGuard.IsReadOnly()` → IPC `getregstate` | 业务级 |
| **子进程启动** | `ProcessManager.StartAllAsync()` 调用 `IsLicenseValid()` | **未注册 → 拒绝启动** |
| **运行期查询** | Web/Api 中间件 30s 轮询 IPC | HTTP 请求级 |
| **注册变更** | 托盘 `LicenseMonitor` 5s 探测 → 日志记录 | 日志+5s 内子进程轮询触发 |
| **托盘退出** | `ExitAsync` 调用 `StopAllAsync` | **强制停止 Admin/Api** |
| **开机自启** | 仅托盘可注册 `HKCU\...\Run\DormManage.TrayApp` | **Admin/Api 自动清理** |

### 3.3 三种拦截场景（与用户原话对齐）

| 场景 | RegInt | UseTimes | 行为 |
|------|--------|----------|------|
| **未注册 + 未超试用** | -1 | < 30 | ✅ 托盘启动子进程（试用模式）|
| **未注册 + 超试用** | -1 | ≥ 30 | ❌ 托盘拒绝启动 → 弹错误提示 |
| **已过期** | 0 | * | ❌ 托盘拒绝启动 → 弹错误提示 |
| **注册有效** | 1 | * | ✅ 托盘启动子进程（正常使用）|
| **托盘未运行** | * | * | ❌ 子进程不可达（无进程托管 → 无端口监听）|

### 5.2 TrayApp ProcessManager 启动守卫

```csharp
public async Task StartAllAsync()
{
    // v2.13.137 完全托管：启动前校验注册
    if (!IsLicenseValid())
    {
        _log.Error("[LICENSE] 注册校验未通过，拒绝启动 Api/Admin 子进程");
        throw new InvalidOperationException("注册校验未通过，禁止启动 Web 服务");

    await StartApiAsync();
    await Task.Delay(1000);
    await StartAdminAsync();

private bool IsLicenseValid()
{
    var reg = RegisterSdk.CheckReg();
    if (reg.RegInt == 1) return true;           // 注册有效
    if (reg.RegInt == -1 && reg.UseTimes < TRIAL_LIMIT) return true;  // 试用模式
    return false;  // 已过期 或 超试用次数
}
```

### 5.3 LicenseGuard 软拦截（Web/Api）

```csharp
public static bool IsReadOnly()
{
    var state = GetCachedState();
    if (state is null) return true;  // 托盘未运行 → 默认只读（最安全）
    return state.RegInt != 1;
}

public static ServiceIpc.RegStateDto? GetCachedState()
{
    lock (_lock)
    {
        EnsurePollingStarted();
        if (_cachedState != null && DateTime.UtcNow < _cacheExpiresAtUtc)
            return _cachedState;

        // 缓存过期 → IPC 查询托盘
        try
        {
            _ipcClient ??= new IpcClient();
            var state = _ipcClient.GetRegStateAsync(2000).GetAwaiter().GetResult();
            _cachedState = state;
            _cacheExpiresAtUtc = DateTime.UtcNow.AddSeconds(30);
            return state;
        }
        catch (IpcUnavailableException) { return _cachedState; }
    }
}
```

## 八、永久教训

### 8.1 反向依赖：Web 是被验证者，不是验证者

**架构反转原则**：任何「决策权威」必须唯一收敛到一个进程，其他进程通过 IPC 拉取决策。

**v2.13.137 反转前**：
- 3 个进程各自读注册表 → 多实例竞态 / 暴力破解面扩大 / 攻击者可绕过托盘
- 反转后：
- 1 个进程（托盘）独占注册表访问权 + 6 个 IPC 端点（getregstate）+ 集中审计
- Web/Api/PDA 永远不能直接读注册表 → 攻击面收敛到托盘 1 个进程

**未来扩展**：托盘端应增加 IPC 操作审计（每次 getregstate / 状态变更写 SysOpLog），便于追溯异常访问。

### 8.2 IPC 协议的「心跳 vs 轮询」取舍

| 模式 | 优点 | 缺点 | 选用 |
|------|------|------|------|
| **WebSocket 全双工** | 即时推送 + 心跳 | 实现复杂 + 需 NuGet + 反向连接管理 | 高频实时 |
| **子进程主动轮询**（30s）| 实现简单 + 协议稳定 + 天然兼容单向 TCP | 注册变更最多 30s 生效 | **本次选用** |
| **混合（轮询 + Push）** | 变更即时 + 心跳兜底 | 实现复杂 | 未来优化 |

**本次选 30s 轮询**：用户原话"注册过期或验证失败时...全局只读"——30s 内生效对人工操作完全可接受（用户注册 CDKEY 后等 30s 看到效果）。**未来可升级为 WebSocket 推送**，但需谨慎处理反向连接管理（防火墙 / NAT 场景）。

### 8.3 进程生命周期：从属必须显式声明

**架构原则**：「子进程从属于托盘」必须在以下 4 个层面显式约束：

| 层面 | 实现 |
|------|------|
| **启动权** | 仅托盘可启动子进程（自启注册表只允许托盘）|
| **运行依赖** | 托盘退出时必须显式终止子进程（StopAllAsync）|
| **业务权限** | 子进程注册校验必须通过 IPC（禁止独立读注册表）|
| **物理可达性** | 端口仅在托盘运行时监听（托盘未运行 → 端口不可达 → 服务不可用）|

**违反任一层 → 子进程可能脱离托盘独立运行，违反完全托管原则**。

### 8.4 默认只读策略

**安全默认**：托盘未运行 / IPC 失败 / 反序列化异常 → 子进程一律进入只读模式（拒绝所有写入操作）。

**理由**：
- 「拒绝写入」比「允许写入但可能绕过授权」安全得多
- 攻击者即使能杀掉托盘也不能让 Web 端进入「可写 + 假装有注册」状态
- 用户体验：托盘短暂重启（5s）期间 Web 短暂 403，可接受

## 九、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 托盘进程崩溃但子进程继续运行 | 低 | 子进程失去注册校验权威 | 子进程 30s 轮询检测托盘 → 自动进入只读 |
| IPC 端口被其他应用占用 | 低 | 托盘无法启动 IPC Server | 启动时检测 + 日志告警 + 子进程 fallback |
| Web 端通过环境变量伪造 IPC | 中 | 攻击者可绕过托盘校验 | IPC 仅监听 127.0.0.1（已实现）+ 未来加 HMAC 签名 |
| 30s 轮询期间用户注册新码后立即操作 | 中 | 用户看到 403（误以为是 BUG）| 文档明确告知 / 未来升级 WebSocket 推送 |
| PdaController 删除 CheckReg 导致安全降级 | 中 | 若托盘被绕过则 Api 裸奔 | 自启注册表清理 + 启动校验两道防线 |
| 跨域 IPC 被中间人攻击 | 低 | 攻击者篡改注册状态 | 仅监听 Loopback + 未来加密通信 |
