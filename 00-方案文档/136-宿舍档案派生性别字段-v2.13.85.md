# v2.13.85 住宿档案「派生性别」字段

## Context（背景）

**用户原话**：
> *"增加规则 约束：住宿档案中 当 入住的 人员 有女性时，则将 住宿档案显示 为女  当有入住的 人员性别为男时，则入住的住宿 档案 显示 为男，否则 为 无；当空房间时 住宿档案 显示 为无；请全面理解分析、补充更新到 相关的文档中"*

**业务问题**：
- 当前 `Dorm.Gender` 字段是**手工维护**字段（Dorms/Create/Edit 表单让用户选「男/女/不限」），存在**数据不一致风险**（员工已变更但 Dorm.Gender 未同步）。
- 用户原话：性别字段应**派生自当前在宿人员**，不允许手工设置。
- 与 v2.13.84（办理入住性别约束）配合：v2.13.84 负责写入侧保证，v2.13.85 负责读取侧派生展示。

**派生规则**（用户原话）：
| 当前在宿人员 | EffectiveGender | 显示 |
|-------------|-----------------|------|
| 无（空房） | 0 | 无 |
| 仅男员工 | 1 | 男 |
| 仅女员工 | 2 | 女 |
| 男 + 女（v2.13.84 后不会发生） | 取多数 | 男/女 |

### 4.4 公共方法 `LoadEffectiveGenderAsync`

```csharp
private async Task LoadEffectiveGenderAsync(string dormCode)
{
    var stats = await _db.DormBookings
        .Where(b => b.DormCode == dormCode && b.Status == BookingStatus.Staying)
        .Join(_db.Employees.AsNoTracking(),
              b => b.EmployeeId, e => e.Id,
              (b, e) => e.Gender)
        .GroupBy(g => 1)
        .Select(g => new { MaleCount = g.Count(x => x == 1), FemaleCount = g.Count(x => x == 2) })
        .FirstOrDefaultAsync();
    MaleCount = stats?.MaleCount ?? 0;
    FemaleCount = stats?.FemaleCount ?? 0;
    EffectiveGender = MaleCount > 0 ? 1 : (FemaleCount > 0 ? 2 : 0);
}
```

## 七、关键决策与权衡

| 决策 | 理由 |
|------|------|
| **派生而非写入** | 用户原话「显示为男/女/无」即派生；避免与实际入住人员不一致 |
| **保留 Dorm.Gender 字段** | DB schema 不变；API 仍接受 Gender（向后兼容）；Dorm.Gender 字段值不被 UI 使用 |
| **Edit 隐藏 input** | 保留 ModelBinder 接收原值；不影响 OnPost 写回逻辑 |
| **极端情况取多数** | v2.13.84 后理论上不会发生男女混住；取多数作为兜底 |
| **不修改 API 端点** | 本次只改 UI 层；API 用户暂时不感知；如需扩展后续版本 |

## 八、风险与回退

### 8.1 历史数据 Dorm.Gender 静态值

**风险**：DB 中 `Dorm.Gender` 可能是历史手工值（如标"女住宿"但住了男员工），本次改造后 UI 不再展示，可能误导。
**缓解**：v2.13.85 仅替换 UI 渲染逻辑，**不动 DB 字段**。后续如需要清理，运行 UPDATE Dorm SET Gender = 0（保留原值待用户确认）。

### 8.2 性能影响

**风险**：每次列表查询增加一次 JOIN + GROUP BY 聚合查询（O(N) 房间数）。
**缓解**：单次聚合查询，DormBookings 索引已存在；性能可接受。如未来房间数 > 1000，可考虑缓存。
