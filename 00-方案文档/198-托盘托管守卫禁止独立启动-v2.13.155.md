## 一、用户需求

> 「检查程序方案，所有程序必须由托盘程序启动，禁止独立使用，请全面深度理解，专业处理这个机制，核实测试可用，更新所有相关的需求文档，生成新版本」

**核心要求**：所有 Web/Api 服务程序（`DormManage.Admin.exe` / `DormManage.Api.exe`）必须由 `DormManage.TrayApp.exe` 拉起，**禁止双击独立运行**。

## 二、架构定位（在 v2.13.137 依赖反转基础上的强化）

| 版本 | 阶段 | 意义 |
|---|---|---|
| v2.13.137 | 注册校验依赖反转 | TrayApp 是唯一权威，Web/Api 通过 IPC 读注册状态；独立运行时变为「全局只读」但**仍可启动** |
| **v2.13.155** | 进程来源托管守卫 | 进一步收紧：Web/Api **必须由 TrayApp 拉起**，否则直接拒绝启动 |

需求层级：v2.13.137 解决了「注册码校验权威归托盘」，v2.13.155 解决了「进程本身必须由托盘拉起」——前者防止「伪造注册通过但脱离托盘」，后者防止「根本脱离托盘运行」。

## 三、机制设计（双层防御）

### 3.1 L1 — 签名握手令牌

托盘启动子进程前：
- 用内嵌 HMAC-SHA256 密钥对载荷 `childKey|托盘PID` 做签名
- 注入子进程环境变量 `DormManage_TRAY_HANDSHAKE`，格式 `childKey|托盘PID|HMAC`
- `childKey = "Admin"` 或 `"Api"`（防跨进程令牌复用）

子进程启动时：
- 读取该环境变量
- 重算 HMAC 比对（**FixedTimeEquals 抗时序攻击**）
- 任何不匹配 → 拒绝启动并输出去哪里应当启动

### 3.2 L2 — 父进程校验

- 子进程通过 `NtQueryInformationProcess`（Windows ntdll）取父进程 PID
- 校验父进程名必须为 `DormManage.TrayApp`
- 校验从令牌取的托盘 PID 必须等于实际父进程 PID（防令牌跨 PID 重放）
- 父进程已退出 / 平台不支持 / 权限不足 → 跳过 L2，依赖 L1 令牌（**抗腐败**而非完美）

### 3.3 仅 Release 强制

调试守卫用 `#if !DEBUG` 包裹：
- **Release（生产构建 / 发布包）**：强制守卫
- **Debug（`dotnet run` / IDE 调试）**：跳过守卫，开发体验零影响

密钥 `Jinge#Dorm@2026$Tray^Handshake&Key!v1` 在 Release 下经 Obfuscar HideStrings 加密，配合 L2 父进程校验满足「禁止独立使用」诉求。

### 3.4 失败反馈

```
[TRAY-GUARD] 本程序必须由「金戈宿舍管理系统托盘程序」启动，禁止独立运行。原因：缺少托盘启动握手令牌（未通过托盘程序启动）
[TRAY-GUARD] 请运行 DormManage.TrayApp.exe，由其统一拉起 Web/Api 服务。本次启动将在 2 秒后终止...
```
等 2 秒让用户看到信息后 `return`（早于 `WebApplication.CreateBuilder`，不占端口、不残留进程）。

## 六、对现有架构与运维的影响

1. **现有 `dotnet run` / IDE 调试不受影响**：Debug 构建跳过守卫。
2. **现有 TrayApp 启动流程不变**：唯一的变动是 `BuildStartInfo` 多注一个环境变量。
3. **子进程手动调试场景**：开发员如需单步调试 Admin/Api，用 Debug 模式即可（`dotnet run --project DormManage.Admin`）；Release 模式必须经过托盘。
4. **故障排查**：若 Admin/Api 意外退出且日志含 `[TRAY-GUARD]`，第一反应是确认 TrayApp 仍在运行（IPC 5069 是否可达、握手令牌是否被清空）。
5. **第三方集成**：v2.13.137 IPC 协议未受影响（仍独立），并不与守卫冲突。
6. **PE 加壳 / 混淆**：`HandshakeEnvVar` 字符串 / 密钥在 Release 下经 Obfuscar HideStrings 加密。

## 八、永久教训

| # | 教训 |
|---|------|
| 1 | **「依赖反转」不等于「进程来源管控」**。v2.13.137 解决了 IPC 拉取注册状态，但双击 `Admin.exe` 仍能独立运行（仅全局只读）。完整「托盘独占托管」必须补上 **进程来源校验**这一步。 |
| 2 | **信任链必须包含「启动源头」**。签名令牌 + 父进程校验 = 「防独立使用」+「防令牌跨进程重放」。两者互补：令牌防「完全独立」（无令牌 = 拒绝），父进程校验防「伪造令牌」（提取密钥伪造令牌但非托盘拉起 = 仍被拦截）。 |
| 3 | **密钥应当用业务常量不可猜且经 Obfuscar HideStrings 加密**。发布包的攻击成本 = 「还原 HideStrings 字符串」=「破坏 Obfuscar 混淆」=「逆向 .NET 8 DLL」3 层叠加，符合「防误用、不防深度逆向威胁」的合理边界。 |
| 4 | **生产守卫必须 `#if !DEBUG` 包裹**。否则开发者连「单步跟踪 Admin」都做不到，调试体验崩溃。Release 严格 / Debug 宽松是工程惯例。 |
| 5 | **失败反馈必须包含「该怎么做」**。守卫拒绝的提示语不仅说「不许」，还说「请运行 X，由其拉起」。这是软件可用性基本规则——错误消息不只是诊断，也是引导。 |
