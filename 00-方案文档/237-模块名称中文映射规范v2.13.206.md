## 一、Context（背景）

### 1.1 用户原话

> "字段权限管理 页面中 将 模块 的名称 全面使用 该模块的 中文名称，模块 为 Dorms 应该使用中文，界面UI 规范 是所有项目和功能的文档更新；全面理解 并更新 相关文档与规范"

### 1.2 业务问题

- 模块名（`SysFieldPermission.Module` 列、`PagePermissionFilter` 路由首段等）在代码中以**英文代码**（`Personnel`、`Booking`、`Dorms` 等）形式存储
- UI 渲染时直接显示英文 = 用户体验不佳，特别是字段权限管理页面需要中文友好显示
- 历史规范：`IndexModel.GetModuleDisplayName(string moduleCode)` 仅覆盖约 10 个核心模块名变体，对于扩展模块（如 `Bookings`/`Dorms`/`Personnels` 等带 s 后缀形式）显示不全

---

## 二、单一规范入口

**强制规则**：所有模块名 UI 显示**必须**通过以下单一入口方法，禁止硬编码中文字符串：

### 2.1 服务端入口（首选）

```csharp
// 文件：DormManage.Admin/Pages/Settings/Index.cshtml.cs:286
public string GetModuleDisplayName(string moduleCode)
```

**调用示例**：
```csharp
@Model.GetModuleDisplayName(f.Module)
```

### 2.2 应用场景

- ✅ 字段权限管理页面（`Settings/_FieldPermissionPanel.cshtml`）
- ✅ 所有需要把英文模块代码转为中文 UI 标签的位置

## 四、实施细节

### 4.1 核心代码位置

**方法实现**：`DormManage.Admin/Pages/Settings/Index.cshtml.cs` 第 286-330 行

```csharp
public string GetModuleDisplayName(string moduleCode)
{
    if (string.IsNullOrWhiteSpace(moduleCode))
        return "-";

    var moduleNames = new Dictionary<string, string>(StringComparer.OrdinalIgnoreCase)
    {
        ["Personnel"] = "人员清单",
        ["Booking"] = "办理登记",
        // ... 完整映射见源码
    };
    return moduleNames.TryGetValue(moduleCode, out var name) ? name : moduleCode;
}
```

### 4.2 数据库 Module 列值约定

**`SysFieldPermission.Module`** 字段应始终使用**单数无后缀**的英文（如 `Personnel`，非 `Personnels`/`PersonnelS`）：

- ✅ 推荐：`Personnel`、`Dorm`、`Booking`、`Meter`
- ❌ 不推荐：`Dorms`、`Personnels`、`MeterS`（虽然方法支持，但 seed 数据应统一）

这是**写入端规范**——数据库中的 Module 字段值应统一为单数无后缀形式，以避免映射字典无限膨胀。

### 4.3 字典扩展性

如果未来新增模块，只需在 `GetModuleDisplayName` 字典中追加一行映射，无需修改其他代码。这符合**单一入口** + **开闭原则**。

## 五、永久规则（CLAUDE.md 全局生效）

> **v2.13.206+ 强制规范**：任何项目、任何页面、任何模块名 UI 显示，**必须**通过 `GetModuleDisplayName()` 单一入口。禁止在以下位置硬编码中文字符串：
> - Razor 视图 (`*.cshtml`) 中写死 `"人员清单"`、`"办理登记"` 等
> - JavaScript 中写死模块名映射
> - API JSON 响应中返回中文模块名（除非显式格式化）
>
> 违反此规范将导致：未来新增模块需全代码库搜索替换、维护成本高、UI 不一致。

## 八、永久教训

1. **UI 标签规范必须文档化** — 任何字符串映射规则（模块名、错误码、状态码）都应在文档中固化，否则开发人员会随意硬编码
2. **多入口易导致不一致** — 单一入口方法（`GetModuleDisplayName`）是保证 UI 一致性的关键
3. **映射字典要预留扩展位** — 一次覆盖所有常见变体（单数/复数/驼峰），避免发布后频繁打补丁
4. **中英文档同步** — UI 规范变更必须同步更新 `CLAUDE.md` 与 `00-方案文档/`，不能让代码成为唯一信息源
