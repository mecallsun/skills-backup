## 一、用户原话

> "费用标准管理 新增标准 增加 权限分配 中的 权限项控制 显示/隐藏 新增标准 按钮"

---

## 二、问题背景

| # | 现状 | 影响 |
|---|------|------|
| 1 | 「新增标准」按钮 `PermissionCode = "billing:edit"` | 没有独立的「新增」权限，无法在权限矩阵单独勾选/取消 |
| 2 | 权限矩阵 Modal「费用标准」分组下 | 不显示独立「新增费用标准」复选框 |
| 3 | 财务专员（RoleId=2）已授权 `billing:edit` | 间接获得「新增标准」权限，但无法细粒度拆分 |
| 4 | API 层 `POST /api/v1/billing/standards` | 任何已登录用户均可调用，绕过 UI 控制 |

**结论**：「新增标准」按钮必须有独立权限码 `billingstandard:add`，否则：
- 财务专员无法单独控制「新增」能力（只要有 `billing:edit` 就有）
- 系统设置 → 权限分配 → 角色权限矩阵没有独立选项
- API 层缺少校验

### 3.2 PageModel 层

`DormManage.Admin/Pages/BillingStandard/Create.cshtml.cs`：

```csharp
public class CreateModel : PageModel
{
    public const string RequiredPermissionCode = "billingstandard:add";

    private readonly IBillingService _service;
    private readonly IPermissionService _perm;
    private readonly IHttpContextAccessor _http;

    public CreateModel(IBillingService service, IPermissionService perm, IHttpContextAccessor http) { ... }

    public async Task<IActionResult> OnGetAsync()
    {
        if (!_perm.CurrentUserHasCode(_http, RequiredPermissionCode))
        {
            TempData["Error"] = $"您没有「新增费用标准」权限（{RequiredPermissionCode}），无法访问该页面";
            return RedirectToPage("/BillingStandard/Index");
        }
        // ... 加载默认值 + EmployeeTypes
    }

    public async Task<IActionResult> OnPostAsync()
    {
        if (!_perm.CurrentUserHasCode(_http, RequiredPermissionCode))
        {
            TempData["Error"] = $"您没有「新增费用标准」权限（{RequiredPermissionCode}），无法提交数据";
            return RedirectToPage("/BillingStandard/Index");
        }
        // ... 保存
    }
}
```

### 3.3 API 层

`DormManage.Api/Controllers/Billing/BillingController.cs`：

```csharp
public class BillingController : ControllerBase
{
    public const string RequiredPermissionCode = "billingstandard:add";

    [HttpPost("standards")]
    public async Task<ApiResponse> SaveStandard([FromBody] BillingStandard standard)
    {
        if (!HasPermission(RequiredPermissionCode))
        {
            _logger.LogWarning("[v2.13.110 RBAC] 用户 {User} 尝试 POST /api/v1/billing/standards 但缺少 {Code} 权限",
                HttpContext.GetCurrentUserName(), RequiredPermissionCode);
            return ApiResponse.Fail("PERMISSION_DENIED", $"无 {RequiredPermissionCode} 权限，无法保存费用标准");
        }
        var (ok, msg) = await _service.SaveStandardAsync(standard);
        return ok ? ApiResponse.Ok(msg) : ApiResponse.Fail("SAVE_FAILED", msg);
    }

    private bool HasPermission(string code) { /* 同 PersonnelController */ }
}
```

## 四、权限码 ID 分配

| 实体 | ID | Code | Name | Type | Parent |
|------|----|------|------|------|--------|
| SysPermission | **41** | `billingstandard:add` | 新增费用标准 | 2 (操作权限) | 11 (billing:view) |
| SysRolePermission | **62** | — | admin→41 | — | — |

**序号延续原则**（v2.13.97 Id=40, v2.13.103 RP Id=61）：
- SysPermission Id=41 = v2.13.110 新增（personnel:add=40 后继）
- SysRolePermission Id=62 = v2.13.110 新增（admin→personnel:add=61 后继）

## 九、后续原则

任何「按钮级权限」需求必须遵循 **5 处同步**：

1. **EF Core HasData**：SysPermission seed + SysRolePermission admin 授权
2. **启动迁移**：DatabaseInitializer.MigrateFieldPermissionAsync 加 `SET IDENTITY_INSERT` 包裹的 INSERT
3. **UI 层**：PageHeader `PermissionCode = "..."` 字段
4. **PageModel 层**：Create/Edit OnGet + OnPost 顶部校验
5. **API 层**：Controller 端点顶部校验 + HasPermission 私有方法

**配套**：
- 手动 SQL 兜底脚本（无需重启服务即可修复生产 DB）
- UI 完整性 banner（`CheckSeedIntegrityAsync`）
- 启动日志完整性验证（`[v2.13.101 Verify]` 输出）
