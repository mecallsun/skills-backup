## 一、BUG 描述

### 现象
- 首页（Dashboard）数据为空或显示不真实
- 人员清单（Personnel）正常显示数据
- 同一应用、同一时间、同一数据库连接

### 用户诉求
> "请检查，为什么 首页 没有显示数据 而 人员清单 中有数据，这是数据源不统一的原因吗？必须所有页面的数据源连接是调用 同一个连接"

---

## 二、根因分析

### 2.1 双数据源架构问题

DashboardService 中存在 **真实数据源 + 演示数据源 混用**的严重问题：

```csharp
// ❌ v2.13.29 之前：KPI 6/7 + 图表 2/3/6 使用演示数据
private List<MockDormBill> BuildDormBillsForMonth(string monthStr)
{
    var dormCodes = _db.Dorms.Select(d => d.DormCode).ToList();
    if (dormCodes.Count == 0)
        dormCodes = new[] { "D-101", "D-055", ... };  // ← 测试数据兜底！

    var rng = new Random(GetMonthSeed(monthStr));    // ← 随机数生成！
    foreach (var code in dormCodes)
    {
        var cold = (decimal)(rng.NextDouble() * 80 + 100);
        var hot = (decimal)(rng.NextDouble() * 150 + 175);
        var elec = (decimal)(rng.NextDouble() * 200 + 280);
        bills.Add(new MockDormBill { ... });
    }
}
```

### 2.2 具体数据流

| 模块 | 数据源 | 表 | 状态 |
|------|--------|-----|------|
| Personnel Service | 真实 | `_db.Employees` | ✅ |
| Dorm Service | 真实 | `_db.Dorms` | ✅ |
| Booking Service | 真实 | `_db.DormBookings` | ✅ |
| Meter Service | 真实 | `_db.MeterRecords` | ✅ |
| **Dashboard KPI 1-5** | 真实 | `_db.Employees/Dorms/Bookings/MeterRecords` | ✅ |
| **Dashboard KPI 6**（人均费用） | **演示** | `BuildEmployeeBillsForMonth` 随机数 | ❌ |
| **Dashboard KPI 7**（费用合计） | **演示** | `BuildDormBillsForMonth` 随机数 | ❌ |
| **Dashboard 图表 2**（费用趋势） | **演示** | 随机数 + 测试数据 dormCodes | ❌ |
| **Dashboard 图表 3**（费用 TOP 10） | **混合** | 真实 dormCodes + 随机数金额 | ❌ |
| **Dashboard 图表 6**（费用类型占比） | **演示** | 随机数生成 | ❌ |

### 2.3 根本原因

`DormBilling` 和 `EmployeeBilling` 真实表**已存在**且**已注册到 DormDbContext**：
```csharp
public DbSet<DormBilling> DormBillings { get; set; } = null!;
public DbSet<EmployeeBilling> EmployeeBillings { get; set; } = null!;
```

但 DashboardService 编写时（v2.11.x 阶段）这两个表**尚未建立**，所以采用了 `MockDormBill/MockEmployeeBill` 临时方案。后来真源表建立后**忘了切换回真实表**，导致 DashboardService 长期使用演示数据。

### 2.4 单一数据源原则违反

CLAUDE.md 强制要求：
> "数据源统一：所有页面共享同一个 DormDbContext"

DashboardService 违反了这一原则 — 部分数据来自 `_db.DormBillings`，部分来自内部 `Random` 生成器。

## 三、修复方案

### 3.1 修复 KPI 1：入住人数双重统计

**问题**：原代码只查 `Employees.DormCode != null`，但人员导入时 DormCode 为 NULL → KPI 1 永远为 0

**修复**：双重统计，取较大值
```csharp
var residentFromBooking = await _db.DormBookings
    .Where(b => b.Status == BookingStatus.Staying)
    .Select(b => b.EmployeeId)
    .Distinct()
    .CountAsync();
var residentFromDormCode = await _db.Employees
    .CountAsync(e => e.DormCode != null && e.DormCode != "");
var residentCount = Math.Max(residentFromBooking, residentFromDormCode);
```

### 3.2 修复 KPI 6：人均费用

**修复前**（演示数据）：
```csharp
var employeeBills = BuildEmployeeBillsForMonth(monthStr);  // 随机数
var avgFee = employeeBills.Count > 0 ? employeeBills.Average(b => b.TotalShareAmount) : 0;
```

**修复后**（真实数据）：
```csharp
var employeeBills = await _db.EmployeeBillings
    .Where(b => b.BillingMonth == monthStr)
    .ToListAsync();
var avgFee = employeeBills.Count > 0
    ? Math.Round(employeeBills.Average(b => b.TotalShareAmount), 2)
    : 0;
```

### 3.3 修复 KPI 7：本月费用合计

**修复前**：演示数据
**修复后**：真实 `DormBilling` 表

### 3.4 修复图表 2（费用趋势曲线）

**修复后**：12 个月循环查询真实 `DormBilling.BillingMonth` 聚合

### 3.5 修复图表 3（费用 TOP 10）

**修复前**：硬编码 dormCodes + 随机数
**修复后**：
```csharp
var bills = await _db.DormBillings
    .Where(b => b.BillingMonth == monthStr)
    .GroupBy(b => b.DormCode)
    .Select(g => new DormCostRankDto {
        DormCode = g.Key,
        ColdAmount = g.Sum(b => b.ColdAmount),
        HotAmount = g.Sum(b => b.HotAmount),
        ElectricityAmount = g.Sum(b => b.ElectricityAmount)
    })
    .OrderByDescending(d => d.ColdAmount + d.HotAmount + d.ElectricityAmount)
    .Take(10)
    .ToListAsync();
```

### 3.6 修复图表 6（费用类型占比）

**修复后**：聚合 `DormBilling.ColdAmount/HotAmount/ElectricityAmount`

### 3.7 删除演示数据生成器

完全删除：
- `MockDormBill` 类
- `MockEmployeeBill` 类
- `BuildDormBillsForMonth` 方法
- `BuildEmployeeBillsForMonth` 方法
- `GetMonthSeed` 方法

## 四、修复后数据流（统一真源）

```
托盘程序启动
  ↓
ConfigService 加载数据库配置
  ↓
ProcessManager.BuildStartInfo() 注入环境变量 DormManage_DB_CONN
  ↓
Api/Admin Program.cs 中 effectiveProvider 从环境变量推断
  ↓
builder.Services.AddDbContext<DormDbContext>() ← 单一连接
  ↓
所有 Service 共用同一个 DormDbContext 实例：
  ├── IDashboardService → _db.DormBillings/EmployeeBillings/Employees/Dorms/DormBookings/MeterRecords
  ├── IPersonnelService → _db.Employees
  ├── IDormService → _db.Dorms
  ├── IBookingService → _db.DormBookings
  ├── IMeterService → _db.MeterRecords
  └── IBillingService → _db.DormBillings/EmployeeBillings

所有页面共享同一 SQL Server 连接（192.168.1.237/WaterMeterDB）
所有数据均来自真源数据库，无演示数据混入
```
