# 数据源热加载 + 统一 EF Interceptor 日志（v2.13.32）

> 实施日期：2026-07-20
> 关联需求：所有页面使用的数据源连接应统一且唯一，由"系统设置 → SQL Server 参数"配置，且修改后**无需重启服务**即可立即生效；同时提供运行时连接可观测性（日志 + 页头徽章）。
> 关联版本：v2.13.31 → v2.13.32

---

## 一、问题与目标

### 1.1 现状评估（Explore agent 实测）

| # | 现状 | 是否满足"统一唯一" |
|---|------|---------------------|
| 1 | 所有页面（DormBookings / Meter / BillingStandard / Profile 等）的 `DormDbContext` 通过 `AddDbContext` 注册 + Scoped DI 注入 | ✅ 物理上已经走同一连接 |
| 2 | 连接字符串在 `DormManage.Api/Program.cs:35-57` 与 `DormManage.Admin/Program.cs:73-98` **启动时硬绑定** | ❌ 运行中无法变更 |
| 3 | 「系统设置 → 数据库连接」保存后调用 `AppConfigManager.SaveConfigurationAsync` 写入双擎并触发 `OnDatabaseConfigUpdated` 事件；当前通过 IPC 让 TrayApp 弹窗确认是否 `RestartAllAsync()` 重启 Api/Admin | ❌ 切换需要重启服务，中断业务 |
| 4 | `AppConfigManager.Instance` 单例 + `OnDatabaseConfigUpdated` 事件机制已存在 | ✅ 基础设施完备 |
| 5 | `SysParameter` 表里持久化了 db.* 7 个参数（Category='Database'） | ⚠️ **但运行时未读取**，是孤儿备份 |
| 6 | 双 UI 入口（Web `/Settings` + 托盘 `SettingsForm`）+ IPC `dbconfig.updated` + TrayApp `ConfigService._current` 内存缓存 | ✅ 同步机制完备 |
| 7 | **没有任何运行时连接可观测性**（Interceptor / 日志 / 健康徽章均缺失） | ❌ 无法证明"所有页面真的走同一个连接" |

### 1.2 用户决策

1. **核心目标**：**热加载**（保存新连接后所有页面**立即**切换，**不重启服务**）
2. **可观测性**：添加**统一 EF Interceptor 日志**（证明所有操作走同一连接池）

### 1.3 预期成果

用户在「系统设置」改完 SQL Server 参数并保存 → 1 秒内所有打开的页面（住宿登记 / 抄表记录 / 首页等）刷新后自动从新数据库查询数据；连接切换过程通过 EF Interceptor 完整记录到日志；SysParameter 表从孤儿备份升级为运行时回退源。

### 2.2 关键技术决策

#### 决策 1：DI 注册方式重构

**原**：
```csharp
builder.Services.AddDbContext<DormDbContext>(options => {
    options.UseSqlServer(connectionString, ...);  // 启动时硬绑定
});
```

**新**：
```csharp
builder.Services.AddDbContextFactory<DormDbContext>((sp, options) => {
    var cfg = AppConfigRuntime.Instance.GetCurrent();  // 每次现读最新
    // v2.13.109: SQLite 已移除，仅 SQL Server 单 provider。
    options.UseSqlServer(cfg.BuildConnectionString(), ...);
    options.AddInterceptors(sp.GetService<DatabaseOperationInterceptor>());
});

// 保留 Scoped 注入（所有 Page / Controller / Service 零改动）
builder.Services.AddScoped<DormDbContext>(sp =>
    sp.GetRequiredService<IDbContextFactory<DormDbContext>>().CreateDbContext());
```

**关键点**：
- `AddDbContextFactory` 是 EF Core 8 标准 API；底层仍复用 SqlConnectionPool
- **每次切换连接**只需 `AppConfigRuntime.GetCurrent()` 返回新值
- **保留 Scoped DbContext**意味着调用方代码完全无需改动（30+ 页面 / 14+ Controller / 9+ Service）

#### 决策 2：运行时配置中心（AppConfigRuntime）

- 单例（与 AppConfigManager 配合）
- 数据源：4 级优先级回退（SysParameter → db_setting.json → appsettings.json → 默认）
- 线程安全：`volatile` + `lock` 双重保险（DateTime 字段用 long ticks 存）
- `event OnChanged` 供订阅（FileWatcher / Web UI / Interceptor）

#### 决策 3：FileSystemWatcher 跨进程同步

**新增**：`DormManage.Api/HostedServices/DatabaseConfigFileWatcher.cs`

- 监听 `db_setting.json` 变更（200ms 防抖）
- 当 Api/Admin 独立启动（无托盘）时也能感知新配置
- TrayApp 写文件后，所有 Api/Admin 进程自动收到变更

#### 决策 4：EF Interceptor 4 类事件

**新增**：`DormManage.Shared/Data/Interceptors/DatabaseOperationInterceptor.cs`

```csharp
public sealed class DatabaseOperationInterceptor : DbCommandInterceptor, IDbConnectionInterceptor
{
    // 继承 DbCommandInterceptor（override）
    public override void CommandFailed(...) { /* 错误全量记录 */ }
    public override DbDataReader ReaderExecuted(...) { /* 采样记录 */ return result; }
    public override object? ScalarExecuted(...) { /* 采样记录 */ return result; }
    public override int NonQueryExecuted(...) { /* 采样记录 */ return result; }

    // 显式实现 IDbConnectionInterceptor
    void IDbConnectionInterceptor.ConnectionOpened(...) { /* 100% 记录 */ }
    void IDbConnectionInterceptor.ConnectionClosed(...) { /* Debug 级别 */ }
    void IDbConnectionInterceptor.ConnectionFailed(...) { /* Error 级别 */ }
}
```

**输出格式**：
```
[DB-CONN] OPENED Server=192.168.1.237 Database=WaterMeterDB Duration=12ms
[DB-EXEC] Server=192.168.1.237 Database=WaterMeterDB Duration=35ms Sql=SELECT * FROM [DormBooking]...
[DB-EXEC-SLOW] Server=... Database=... Duration=1523ms Sql=...
[DB-CMD-FAIL] Server=... Database=... Duration=15ms Exception=...
```

**采样策略**：
- 普通 SELECT/UPDATE/INSERT：1/100 采样（默认）
- 慢查询（>1000ms）：100%
- 错误：100%
- 连接 OPENED：100%（切换时关键信息）

#### 决策 5：调用方代码零改动

由于保留 `AddScoped<DormDbContext>` 注册，所有现有 Service / Page / Controller 构造函数签名**完全无需改动**。

## 四、热加载数据流

### 4.1 Web 端保存新连接

```
用户: 在 /Settings → 数据库连接 修改 Server=10.0.0.1，点击保存
    ↓
浏览器: POST /api/v1/system/dbconfig/save
    ↓
DbConfigController.SaveConfig
    ↓
AppConfigManager.SaveConfigurationAsync(config)
    ├─ 1. 测试连通性（直连新库）
    ├─ 2. AES-256 加密密码
    ├─ 3. 写 db_setting.json (atomic rename)
    ├─ 4. _current = newConfig  ← 进程内缓存更新
    ├─ 5. 后台 Task → 写 SysParameter 表
    ├─ 6. OnDatabaseConfigUpdated?.Invoke (托盘 UI 订阅)
    └─ 7. AppConfigRuntime.ApplyExternalConfiguration(newConfig)  ← 热加载核心
            └─ _current = newConfig + OnChanged?.Invoke
    ↓
浏览器: 显示"✅ 已热加载，所有页面下次请求自动切换，无需重启服务"
    ↓
DbConfigController 兜底: IPC dbconfig.updated → TrayApp
    ↓
TrayApp TrayAppContext.HandleSetDbConfigAsync:
    ├─ SaveConfigurationAsync (已自动 Apply 到 Runtime)
    └─ 托盘 toast: "已热加载，无需重启"
    ↓
用户: F5 刷新 /Personnel
    ↓
Razor Page → Scoped DormDbContext (来自 factory.CreateDbContext)
    ↓
factory lambda: cfg = AppConfigRuntime.GetCurrent() = newConfig (10.0.0.1)
    ↓
UseSqlServer(cfg.BuildConnectionString())
    ↓
Interceptor: [DB-CONN] OPENED Server=10.0.0.1 Database=WaterMeterDB
    ↓
SELECT * FROM [SysEmployee] WHERE ...  ← 自动走新库
```

### 4.2 跨进程同步（托盘写 → Api/Admin 收）

```
TrayApp SettingsForm: 改数据库配置 + 保存
    ↓
ConfigService.Update (写 TrayApp appsettings.json)
    ↓
写 db_setting.json (File.Move overwrite)
    ↓
Api/Admin DatabaseConfigFileWatcher:
    ├─ Changed 事件触发
    ├─ 200ms 防抖
    └─ OnDebounceElapsed → 读取文件 → 反序列化 → 解密 → AppConfigManager.ApplyExternalConfiguration
            ↓
AppConfigRuntime.Apply → OnChanged → 下一请求自动用新连接
```

## 五、Plan agent 识别的 7 大技术风险

| 等级 | 风险 | 缓解措施 |
|------|------|---------|
| 🔴 高 | IDbContextFactory.Dispose 语义 | `AddScoped<DormDbContext>(sp => factory.CreateDbContext())` 让容器 Dispose |
| 🔴 高 | SaveConfigurationAsync 写 SysParameter 循环依赖 | WriteToDatabaseAsync 用**本次传入的 config**（不依赖 _current） |
| 🟡 中 | 跨进程同步（Api 独立启动） | FileSystemWatcher on db_setting.json |
| 🟡 中 | SqlClient 连接池旧连接占用 | 不调用 `ClearAllPools()`（会断开 in-flight 连接）；接受 4 分钟 idle |
| 🟡 中 | 首次访问 Current 阻塞 IO | 启动时同步预热 `AppConfigRuntime.Instance.GetCurrent()` |
| 🟢 低 | EF Interceptor 性能开销 | 采样 1/100 + 慢查询/错误全量 |
| 🟢 低 | 调用方代码改动 | 保留 Scoped 注入签名，**零改动** |

## v2.13.109 备注：SQLite Provider 彻底移除

自 v2.13.109 起，DormManage 运行时仅支持 SQL Server。SQLite 代码路径、EF Core SQLite Provider、SQLite 备份恢复逻辑均已移除。历史配置中的 SqlitePath 字段仅为旧配置反序列化兼容，不代表运行时继续支持 SQLite。生产数据库初始化以 init_schema.sql 和 SQL Server 运维脚本为准，不使用 EnsureCreated()。
