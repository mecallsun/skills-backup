## 一、项目类型与业务定位

**金智住宿管理系统（JINGE Dormitory Management System）** 是面向制造业工厂的住宿/人员/计费一体化管理平台。

### 1.1 业务范围

| 业务域 | 内容 |
|--------|------|
| 住宿档案 | 楼栋/楼层/房号管理、容量、当前在宿人数、设备档案（电表/水表 ID）|
| 人员管理 | 员工档案（人员清单）、班组/班次、部门、状态（在职/离职/请假）|
| 住宿登记 | 入住/退房办理、智能分配房号、历史住宿记录 |
| 智能抄表 | 月度电表/冷水/热水表读数、抄表进度、PDA 离线补录 |
| 费用管理 | 费用标准（住宿/水电）、月度账单、员工账单拆分 |
| 基础资料 | 12 个二级菜单（部门/楼栋/楼层/员工类型/考勤班次/班组/设备档案/设备记录 等）|
| 系统设置 | 用户/角色/权限、数据库连接双 UI、PDA 版本、系统集成、日志/备份 |

### 1.2 典型用户角色

- **管理员**（信息科）：系统配置、用户管理、备份恢复
- **HR**：人员清单、住宿登记、费用账单
- **后勤**：住宿档案、设备档案、智能抄表
- **普通员工**：查询个人住宿/账单（个人中心）
- **PDA 操作员**：移动抄表上传

## 三、解决方案结构（4 项目 + 1 Tray）

```
DormManage.sln
├── DormManage.Shared   →  EF Core entities + DbContext + business services + DTOs + Register SDK + Security utilities
├── DormManage.Api      →  REST API (Kestrel, port 5100) + Swagger
├── DormManage.Admin    →  Razor Pages UI (Kestrel, port 5001) + Cookie auth + embedded API (in-process ApplicationPart)
└── DormManage.TrayApp  →  WinForms tray daemon (process management + health check + IPC server + license auto-validation)
```

### 3.1 各项目核心职责

| 项目 | 核心职责 | 不应包含 |
|------|----------|---------|
| `DormManage.Shared` | 实体（62 DbSet）、服务（11 个 Service）、DTO、SDK、安全工具、注册机 | Razor Pages、WinForms、ASP.NET HTTP 引用 |
| `DormManage.Api` | REST 端点、Swagger、跨域中间件、文件上传、迁移动力 | Razor Pages 视图 |
| `DormManage.Admin` | Razor Pages UI、Cookie 认证、Filter 管道、自托管 API 控制器 | WinForms 引用 |
| `DormManage.TrayApp` | 进程托管、配置管理、IPC Server、托盘菜单、LicenseForm、SettingsForm | ASP.NET HTTP 引用（仅 Stub 共享服务）|

### 3.2 跨项目引用图

```
DormManage.Shared ←  DormManage.Api
                ←  DormManage.Admin
                ←  DormManage.TrayApp

DormManage.Api   ←  DormManage.Admin (通过 ApplicationPart 进程内自托管)
```

## 四、5 条核心设计原则（贯穿全部章节）

### 原则 1：**程序永远启动，只决定运行模式**
- 反例：v2.13.137 `ProcessManager.IsLicenseValid()` 硬阻断 → 用户看到「启动失败」
- 正例：5 状态全部能启动 → 按状态降级（试用/正常/只读-过期/只读-盗版/只读-授权不可用）
- 适用：所有业务硬约束（授权、试用、版本、安全）都应降级而非阻断
- **新项目复用**：默认「降级而非阻断」，仅在**业务不可降级**（如数据完整性）场景才允许硬阻断

### 原则 2：**分层防御 + 单一真源**
- 三层防御：
  - **UI 层**：用户感知（提示、弹窗、按钮 disabled）
  - **Service 层**：业务校验（主约束收口）
  - **DB 层**：唯一索引/约束（兜底）
- 单一真源：跨层共享的字段/状态/规则在 Shared 项目
- **新项目复用**：每加一个业务硬约束，必须先想「三层防御」+「跨层共享」

### 原则 3：**依赖反转 + 进程托管**
- 授权/进程决策集中在托盘（`DormManage.TrayApp`），Web/Api 通过 IPC 拉取
- v2.13.155 `TrayLaunchGuard`：HMAC-SHA256 握手令牌 + NtQueryInformationProcess 父进程校验
- **新项目复用**：需要「进程托管 + 授权决策集中」时，参考 TrayApp ↔ Api/Admin 模式

### 原则 4：**Obfuscar + R2R + 自包含 + 跳过反射密集区**
- 默认启用 `Obfuscar`（全栈混淆）+ `PublishReadyToRun`（R2R 预编译）+ `SelfContained`（自包含运行时）
- 必须 skip 反射密集区命名空间（Models/Data/Register/Security/Services/Pages/Controllers/Middleware）
- **新项目复用**：需要保护知识产权时，参考 `Obfuscar.xml` + `Directory.Build.props` 配置

### 原则 5：**文档与代码必须同步，禁止「演示版」遗留**
- 任何功能必须真实实现（1:1 落地），禁止 `alert('原型演示...')` 等占位符
- 每次改动必须同步文档（CLAUDE.md / 00-方案文档 / 01-Database 迁移脚本）
- DEPRECATED 文档加 banner 指向新文档，禁止删除历史文档
- **新项目复用**：建立 `CLAUDE.md` 用户规则（7 项强制）+ 文档同步流程（详见 `10-设计规范`）

## 六、与本项目类似的项目类型

- **住宿管理系统**（本项目）
- **物业管理系统**（房屋档案、租赁合同、物业费）
- **仓储管理系统**（库位、物品、盘点）
- **资产管理系统**（设备档案、折旧、盘点）
- **会员管理系统**（会员档案、积分、消费）
- **工单系统**（设备报修、流程审批）
- **计费系统**（用量表、月度账单、拆分）

**共性**：都需要「对象档案 + 流程审批 + 计费/计量」三元组。复用本知识库时，**只需替换 07 章「核心业务模块」的具体业务逻辑**，其余全部可直接复用。
