### 3.2.1 "员工类型"列数据源（v2.11.6 强化）

**强制规则**：宿舍详情页"当前入住人员"列表中"员工类型"列的**值必须**关联引用该人员档案（`SysEmployee`）对应的"员工类型"，不得使用任何冗余、缓存或硬编码数据。

**数据链路**：

```
┌──────────────────┐    ┌────────────────────┐    ┌──────────────────────┐
│  入住记录（RESIDENCIES）   │ → │  人员档案（SysEmployee）    │ → │  员工类型（EmployeeType）   │
│  employeeId（外键）         │    │  EmployeeTypeId（外键）       │    │  Code（编码）              │
│  dormCode = 当前宿舍房号  │    │  ← 人员档案就是"数据源"    │    │  Name（中文名）            │
└──────────────────┘    │  RealName / EmployeeCode  │    └──────────────────────┘
                          └────────────────────┘
```

**字段映射**：

| 显示层 | 取值字段 | 数据源 | 说明 |
|--------|---------|--------|------|
| 当前入住人员列表"员工类型"列 | `EmployeeType.Name`（中文名） | `SysEmployee → EmployeeTypeId → EmployeeType` | 通过 FK 关联引用人员档案 |
| 存储层（`SysEmployee`） | `EmployeeTypeId`（int） | 外键关联到 `EmployeeType.Id` | 单一数据源 |
| 字典层（`EmployeeType`） | `Code` + `Name` | 基础资料表 | 全局共享 |

**强制要求**：

| # | 要求 | 原因 |
|---|------|------|
| 1 | **"员工类型"列的值只能从 `SysEmployee.EmployeeTypeId` → `EmployeeType.Name` 链路获取** | 单一数据源，避免多个数据副本不同步 |
| 2 | **不得在 `RESIDENCIES` 表中冗余存储"员工类型"** | 一旦人员调岗/转类型，宿舍详情页必须实时反映 |
| 3 | **`SysEmployee` 必须添加 EF Core 导航属性 `EmployeeType EmployeeType`**（v2.11.6 推荐） | 简化查询：`emp.EmployeeType.Name` 即可获取中文名 |
| 4 | **删除人员档案时禁止级联删除对应的 `EmployeeType` 字典** | 否则会影响其他人员的历史记录 |
| 5 | **当人员档案的"员工类型"发生变更时**，宿舍详情页不需任何额外操作即可看到新值 | FK 关联 + 实时查询保证数据一致性 |

**真实模型字段定义**（来源 `DormManage.Shared/Models/SysEmployee.cs`）：

```csharp
[Table("SysEmployee")]
public class SysEmployee : BaseEntity
{
    // ... 其他字段 ...

    /// <summary>
    /// 员工类型ID
    /// </summary>
    public int EmployeeTypeId { get; set; }

    // v2.11.6 推荐：EF Core 导航属性（可选）
    // [ForeignKey(nameof(EmployeeTypeId))]
    // public EmployeeType? EmployeeType { get; set; }
}
```

**典型查询代码（Entity Framework Core）**：

```csharp
// 查询某宿舍当前所有入住人员（包含员工类型中文名）
var residents = await _dbContext.Residencies
    .Where(r => r.DormCode == code && r.Status == 1)
    .Join(_dbContext.SysEmployees,
          r => r.EmployeeId,
          e => e.Id,
          (r, e) => new { Residency = r, Employee = e })
    .Join(_dbContext.EmployeeTypes,
          x => x.Employee.EmployeeTypeId,
          et => et.Id,
          (x, et) => new
          {
              x.Employee.EmployeeCode,
              x.Employee.RealName,
              x.Employee.Department,
              EmployeeTypeName = et.Name,           // ← v2.11.6 关键：通过 FK 取 Name
              x.Residency.CheckInDate,
              x.Employee.AttendanceType
          })
    .ToListAsync();
```

```javascript
// v2.11.6 修订：员工类型名称按 FK 关联引用解析
// 入参: emp.employeeTypeId (int 外键，对应 SysEmployee.EmployeeTypeId)
// 输出: EmployeeType.Name（中文名，如"合同工"）
const empTypeNameByFk = (employeeTypeId) => {
    const t = EMPLOYEE_TYPES.find(x => x.id === employeeTypeId);
    return t ? t.name : '-';
};

// 员工类型 Badge 颜色（保持不变）
const empTypeBadge = (employeeTypeId) => {
    const t = EMPLOYEE_TYPES.find(x => x.id === employeeTypeId);
    if (!t) return 'bg-secondary';
    // 不同员工类型对应不同 Badge 风格（保持原有视觉层次）
    const map = {
        'CONTRACT': 'bg-secondary',       // 合同工-灰
        'TEMPORARY': 'bg-warning text-dark',  // 临时工-橙
        'OUTSOURCE': 'bg-info text-dark',    // 外包-青
        'INTERN': 'bg-success',             // 实习生-绿
        'ONSITE': 'bg-dark'                 // 驻场-紫
    };
    return map[t.code] || 'bg-secondary';
};

// 修改后（v2.11.6）
`<tr>
    <td>${emp.employeeCode}</td>
    <td>${emp.realName}</td>
    <td>${emp.department}</td>
    <!-- v2.11.6：员工类型 - 关联引用 SysEmployee → EmployeeType (FK) -->
    <td><span class="badge ${empTypeBadge(emp.employeeTypeId)}">${empTypeNameByFk(emp.employeeTypeId)}</span></td>
    <td><span class="badge ${ATTENDANCE_BADGE[emp.attendanceType]}">${ATTENDANCE_NAME[emp.attendanceType]}</span></td>  <!-- 考勤班次 -->
```

| # | 变更点 | v2.11.4 旧实现 | v2.11.6 新实现 |
