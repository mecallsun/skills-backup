# 4 页面 500 错误修复报告（v2.13.31）

> 修复日期：2026-07-20
> 关联 BUG：住宿登记 / 费用标准 / 抄表记录 / 个人中心 显示 "An error occurred while processing your request"
> 影响版本：v2.13.30

---

## 一、问题描述

### 1.1 用户反馈

进入以下 4 个菜单时，全部显示 ASP.NET Core 默认错误页：

```
Error.
An error occurred while processing your request.
Request ID: 00-cf09386d8cc9ea520c9b381a416be19d-4b874fdfcde2540c-00
Development Mode
```

受影响页面：
- `/Booking`（住宿登记）
- `/BillingStandard`（费用标准）
- `/Meter`（抄表记录）
- `/Account/Profile`（个人中心）

### 1.2 根因分析

经过三轮排查定位，最终确认 4 个根因：

| # | 根因 | 涉及对象 |
|---|------|---------|
| 1 | **SQL Server 缺失 8 张业务表** | SysUserSecurityQuestion、DormBilling、EmployeeBilling、SysUserFilterCache、AppVersion、SysIntegration、SysParameter、SysSystemIntegration |
| 2 | **EF 实体列名与 SQL 列名不匹配** | SysUser（缺 WeChatOpenId 等 6 列）、AppVersion（缺 Version 等 9 列）、DormBooking（缺 BookingType 列）、DormBilling、EmployeeBilling、MeterRecord 等多个表 |
| 3 | **DateOnly/DATE 映射 BUG（EF Core 8.0.0）** | DormBooking.BookingDate/ActualCheckInDate、BillingStandard.EffectiveFrom/EffectiveTo、MeterRecord.ReadDate |
| 4 | **历史数据 NULL 但 EF 实体 IsRequired** | DormBooking.Phone/Department（多处 NULL）、BillingStandard.EffectiveTo（全部 NULL） |

---

## 二、修复方案

### 2.1 数据库侧（v2.13.31 SQL 迁移）

#### 2.1.1 创建 8 张缺失业务表
- 文件：`01-Database/05_Migration_v2.13.31_AddMissingTables.sql`
- 工具：`01-Database/05_RunMigration.cs`（Microsoft.Data.SqlClient 5.2.0）
- 结果：8/8 表创建成功

#### 2.1.2 补充 EF 实体期望的所有列
- 文件：`01-Database/06_SyncColumns.cs` ~ `13_DropWithConstraints.cs`
- 主要工作：
  - SysUser：补 WeChatOpenId、PasswordResetToken 等 6 列
  - AppVersion：重建表（DELETE + CREATE）以匹配 EF 实体列
  - DormBooking：补 BookingType、AttendanceTypeId、BedNo 等 8 列
  - MeterRecord：补 PreviousColdReading、Operator 等 18 列
  - BillingStandard：删除多余 ColdWaterUnitPrice 列
  - 删除冗余约束后再 DROP COLUMN（解决默认约束依赖）

#### 2.1.3 重建 BillingStandard 表
- 删除冗余的 ColdWaterUnitPrice/HotWaterUnitPrice/ElectricUnitPrice
- 保留 EF 期望的 ColdWaterPrice/HotWaterPrice/ElectricityPrice

### 2.2 应用程序侧

#### 2.2.1 升级 EF Core 8.0.0 → 8.0.10
- 文件：`DormManage.Shared/DormManage.Shared.csproj`、`DormManage.Api/DormManage.Api.csproj`、`DormManage.Admin/DormManage.Admin.csproj`
- 原因：EF Core 8.0.0 的 `RelationalTypeMappingSource.FindCollectionMapping` 在 DateOnly 字段上有 NRE BUG
- 同步升级：`Microsoft.EntityFrameworkCore.Design`、`Microsoft.EntityFrameworkCore.Sqlite`、`Microsoft.EntityFrameworkCore.SqlServer`

#### 2.2.2 修复 EF 实体字段类型
- `DormManage.Shared/Models/BillingStandard.cs`：
  - `EffectiveTo`：`DateOnly` → `DateOnly?`（允许永久有效）
- `DormManage.Shared/Models/DormBooking.cs`：
  - 注释更新：`Phone`、`Department` 允许 NULL

#### 2.2.3 修正 DbContext 映射
- `DormManage.Shared/Data/DormDbContext.cs`：
  - `entity.Property(e => e.Phone).HasMaxLength(32)`（去掉 `.IsRequired()`）
  - `entity.Property(e => e.Department).HasMaxLength(128)`（去掉 `.IsRequired()`）
  - 移除自定义 `ValueConverter<DateOnly?, string?>`（EF 8.0.10 自动处理）

#### 2.2.4 修正 Razor 页面 null 处理
- `DormManage.Admin/Pages/BillingStandard/Index.cshtml`：
  - `EffectiveTo?.ToString("yyyy-MM-dd") ?? "—"`
  - 顶部 ActiveStandard 显示：`EffectiveTo?.ToString() ?? "永久"`

### 2.3 版本号同步
- `DormManage.Admin/Pages/Account/Login.cshtml`：v2.13.30 → v2.13.31
- `DormManage.Admin/Pages/Shared/_Layout.cshtml`：v2.13.30 → v2.13.31
- `DormManage.TrayApp/NotifyIconManager.cs`：v2.13.30 → v2.13.31（两处）

## 六、风险与回退

### 6.1 风险评估
- ✅ 低风险：所有迁移脚本均为 ALTER TABLE / CREATE TABLE，不影响现有数据
- ✅ 历史 NULL 数据：因 EF 实体调整为 nullable，不会引发完整性错误
- ✅ EF Core 升级：8.0.0 → 8.0.10 为补丁版本，无破坏性变更

### 6.2 回退方案
如出现新问题，可回退到 v2.13.30：

## v2.13.109 备注：SQLite Provider 彻底移除

自 v2.13.109 起，DormManage 运行时仅支持 SQL Server。SQLite 代码路径、EF Core SQLite Provider、SQLite 备份恢复逻辑均已移除。历史配置中的 SqlitePath 字段仅为旧配置反序列化兼容，不代表运行时继续支持 SQLite。
