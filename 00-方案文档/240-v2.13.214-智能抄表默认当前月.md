## 1. 用户原话与诉求

**用户原话**：「智能抄表 界面的 列表中，在 点击 智能抄表 时，则默认 筛选区 的抄表月份 和 对应 列表的 数据记录 为当前主机 的日期的月份，而不是妆前默认的「全部」抄表月份」

**核心诉求**：
- 进入 `/Meter` 页面时
- 默认选中**当前主机日期的月份**（如 `2026-07`）
- 列表数据**仅显示当前月记录**
- 而不是当前的「全部月份」

## 2. 当前 BUG 分析

### 2.1 现状代码（修复前）

**`Meter/Index.cshtml.cs:84-87`**：
```csharp
var query = _db.MeterRecords.AsQueryable();

if (!string.IsNullOrWhiteSpace(ReadMonth))
    query = query.Where(r => r.ReadMonth == ReadMonth);
```

**问题**：仅当 URL 显式传 `ReadMonth` 时才筛选；URL 未传时（首次进入页面）→ 返回所有月份数据。

**`Meter/Index.cshtml:42-46`**：
```html
<select name="ReadMonth" class="form-select">
    <option value="">全部</option>
    @foreach (var month in Model.Months)
    {
        <option value="@month" selected="@(Model.ReadMonth == month)">@month</option>
    }
</select>
```

**问题**：URL 未传 ReadMonth → `Model.ReadMonth == null` → 无 option 被选中 → 默认显示「全部」。

### 2.2 CoverageDto 已正确处理（无需修改）

`Index.cshtml.cs:182`：
```csharp
var targetMonth = !string.IsNullOrWhiteSpace(ReadMonth) ? ReadMonth : DateTime.Now.ToString("yyyy-MM");
```

**这部分 v2.13.209 已正确实现「ReadMonth 为空时 fallback 当前月」**，PageHeader 副标题「抄表进度」正确显示当前月。本次修复**让列表数据查询与 CoverageDto 行为对齐**。

## 3. v2.13.214 修复方案

### 3.1 用户确认的设计选择

1. **前端默认选中当前月**（保留「全部」option）+ URL 未传时 fallback 当前月
2. **保留过滤缓存**（FilterPersistence 优先级：URL → localStorage → 当前月）

### 3.2 后端修复（`Index.cshtml.cs`）

```csharp
// 修复前
var query = _db.MeterRecords.AsQueryable();
if (!string.IsNullOrWhiteSpace(ReadMonth))
    query = query.Where(r => r.ReadMonth == ReadMonth);

// 修复后
var query = _db.MeterRecords.AsQueryable();

// v2.13.214：默认筛选当前主机月份（避免「全部」返回大量历史数据）
// URL 优先 → ReadMonth 不为空 → 尊重用户选择
// URL 未传 → ReadMonth 为空 → 默认当前月份
var effectiveMonth = !string.IsNullOrWhiteSpace(ReadMonth)
    ? ReadMonth
    : DateTime.Now.ToString("yyyy-MM");
query = query.Where(r => r.ReadMonth == effectiveMonth);
```

### 3.3 前端修复（`Index.cshtml`）

```html
<!-- 修复前 -->
<select name="ReadMonth" class="form-select">
    <option value="">全部</option>
    @foreach (var month in Model.Months)
    {
        <option value="@month" selected="@(Model.ReadMonth == month)">@month</option>
    }
</select>

<!-- 修复后 -->
<select name="ReadMonth" class="form-select">
    @{
        // v2.13.214：默认选中当前主机月份（ReadMonth 为空时）
        var defaultMonth = DateTime.Now.ToString("yyyy-MM");
    }
    <option value="">全部</option>
    @foreach (var month in Model.Months)
    {
        // 默认选中逻辑：URL 传 ReadMonth → 选中对应月份；URL 未传 → 选中当前月
        var isSelected = !string.IsNullOrWhiteSpace(Model.ReadMonth)
            ? Model.ReadMonth == month
            : month == defaultMonth;
        <option value="@month" selected="@isSelected">@month</option>
    }
</select>
```

### 3.4 FilterPersistence 兼容性

**优先级链**：
```
1. URL 显式传 ReadMonth → 选中对应月份（如 ?ReadMonth=2026-06）
2. localStorage 有缓存 → 通过 filter-persistence.js 自动恢复表单值
3. 两者都无 → 默认选中当前月（v2.13.214 新增）
4. 用户点「查询」 → 表单提交 URL + 存 localStorage
5. 用户点「重置」 → FilterPersistence.resetFilters('meter') → 清空表单 → 重新 OnGet → 仍默认当前月
```

**与现有 FilterPersistence 完全兼容**，不破坏既有行为。

## 7. 永久教训（v2.13.214+ 强制沉淀）

### 7.1 默认值 = 用户第一眼体验

进入页面时**默认值**决定了用户第一眼看到的数据。如果默认「全部」会让用户感到困惑（140 间宿舍 × 12 个月 = 1680 条记录翻好几页）。**默认值必须 = 当前最相关的数据**（智能抄表 = 当前月）。

### 7.2 前后端默认值必须对齐

本次修复前：后端 CoverageDto L182 已 fallback 当前月（v2.13.209），但**后端列表查询 L86 与前端下拉框 L42 都未对齐**。这种「前后端默认值不一致」会让用户看到「副标题说当月 140 间但列表显示 1680 条」的诡异场景。**前后端默认值必须统一管理**。

### 7.3 「全部」选项 = 显式覆盖默认

保留「全部」option（value=""）让用户可以**显式选择查看所有月份**，但**默认不选中**。这种「默认值 ≠ 全部」的设计避免给用户造成「列表数据怎么这么多」的困惑。

### 7.4 FilterPersistence 必须支持「回退到默认值」

`FilterPersistence.resetFilters('meter')` 清空表单后 → OnGet 重新执行 → 此时 ReadMonth 仍为 null → **新默认值生效**（v2.13.214 默认当前月）。这是「重置按钮回到默认」的正确行为。

### 7.5 用户原话中的「妆前」是「当前」之误

用户原话「**妆前**默认的『全部』」应为「**当前**默认的『全部』」。修复时不能直接按字面意思改「去掉全部选项」，而要理解用户**真实意图 = 当前月默认**。
