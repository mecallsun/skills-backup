## 一、用户原话

> 默认隐私字段保护权限项清单的字段为不显示（隐藏）；将"启用隐私字段保护"修改为："允许显示隐私字段"，以此理解为与之前的定义相反，即：所有角色默认不勾选此允许显示隐私字段权限项，则不显示；当角色勾选后，则允许显示隐私字段清单的字段。

## 二、语义对照

| 维度 | v2.13.92 - v2.13.175（旧） | v2.13.176 起（新） |
|------|---------------------------|---------------------|
| 权限 PermissionName | 启用隐私字段保护 | **允许显示隐私字段** |
| 默认状态 | 不勾选 = 显示全部（默认 allow） | **不勾选 = 隐藏全部（默认 deny）** |
| 勾选后行为 | 看不到所有 IsActive=true 字段 | 看到所有字段 |
| 不勾选行为 | 看到所有字段 | 看不到所有 IsActive=true 字段 |

**核心原则**：deny-by-default。默认所有角色均看不到隐私字段清单中的字段，只有显式勾选「允许显示隐私字段」后才能查看。

## 三、核心实现反转

### 3.1 IPermissionService.GetHiddenFieldKeysAsync（PermissionService.cs）

**旧逻辑（v2.13.92）：**
```csharp
public async Task<HashSet<string>> GetHiddenFieldKeysAsync(int userId)
{
    if (!await HasPrivacyFieldEnabledAsync(userId)) return new HashSet<string>();  // 不勾选 → 不隐藏
    var activeKeys = await _db.SysFieldPermissions.Where(p => p.IsActive).Select(p => p.FieldKey).ToListAsync();
    return new HashSet<string>(activeKeys);  // 勾选 → 隐藏所有
}
```

**新逻辑（v2.13.176）：**
```csharp
public async Task<HashSet<string>> GetHiddenFieldKeysAsync(int userId)
{
    if (!await AllowDisplayPrivacyFieldsAsync(userId))  // 不勾选 → 隐藏
    {
        var allActiveKeys = await _db.SysFieldPermissions.Where(p => p.IsActive).Select(p => p.FieldKey).ToListAsync();
        return new HashSet<string>(allActiveKeys);
    }
    return new HashSet<string>();  // 勾选 → 不隐藏
}
```

### 3.2 接口改名

```csharp
// v2.13.92 旧名称：HasPrivacyFieldEnabledAsync（已重命名）
// v2.13.176 新名称：AllowDisplayPrivacyFieldsAsync（语义清晰，allow = true 时显示）
public Task<bool> AllowDisplayPrivacyFieldsAsync(int userId);
```

权限码常量 `PrivacyFieldPermissionCode = "privacy:field:enable"` **保持不变**（DB 兼容）。

## 五、用户操作流程（变更后）

### 5.1 默认行为（deny-by-default）

1. 新创建任意角色 → 默认无 privacy:field:enable 授权
2. 该角色登录 → 所有 SysFieldPermission.IsActive=true 的字段（姓名、手机号、工号等）**均不显示**
3. 这意味着即使是 admin 角色以外的任何角色，**默认都看不到 PII 字段**

### 5.2 允许显示

1. 打开「系统设置 → 角色与权限」→ 编辑目标角色权限矩阵
2. 勾选「**允许显示隐私字段**」→ 提交
3. 该角色的用户重新登录 → 所有 PII 字段正常显示

### 5.3 系统管理员（admin）默认授权

> ⚠️ 注意：admin 角色默认**无**该权限授权。需要手动勾选才能显示隐私字段。

但生产 DB 中 `SysRolePermission` 表已 seed 了 admin → privacy:field:enable 授权（v2.13.92 起一直如此），所以 admin 用户**仍能**看到隐私字段。语义翻转**不影响**已 seed 的 admin 授权。

## 六、启动兜底 UPDATE

为防止生产 DB 中旧 PermissionName 显示，新版启动期会执行：

```sql
UPDATE [dbo].[SysPermission]
SET [PermissionName] = N'允许显示隐私字段',
    [Description] = N'勾选此权限的角色可看到 SysFieldPermission 清单中的字段；不勾选（默认）则所有字段全部隐藏'
WHERE [PermissionCode] = N'privacy:field:enable'
  AND [PermissionName] <> N'允许显示隐私字段';
```

日志标识：`[v2.13.176 Privacy Flip] SysPermission.PermissionName 已 UPDATE N 行`

## 七、永久教训

1. **「保护」与「显示」是两个相反的语义**——同样一个字段，控制「看不见」和「看得见」需要明确语义，避免「双负」表达。
2. **默认 deny vs 默认 allow 是安全设计的根本差异**——v2.13.92 默认 allow 容易让新创建的角色"自动看到 PII 字段"，属于安全漏洞。v2.13.176 改为 deny-by-default，新角色默认安全。
3. **权限命名反映意图**——"启用隐私字段保护"和"允许显示隐私字段"看起来相似但语义相反，必须保持单一清晰。
4. **DB schema 与权限命名解耦**——PermissionCode（`privacy:field:enable`）不变，只改 PermissionName + 业务逻辑，确保数据库迁移零成本。
5. **行为变更需要重启兜底**——已 seed 的 PermissionName 必须 UPDATE 同步，否则 UI 显示和 DB 不一致。
