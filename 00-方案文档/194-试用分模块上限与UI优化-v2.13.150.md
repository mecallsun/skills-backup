## 三、试用模式分模块上限（核心变更）

### 3.1 上限规则对照表

| 模块 | v2.13.149 上限 | v2.13.150 上限 | 提示语 |
|------|----------------|----------------|--------|
| 住宿登记（Booking） | 5 条 | **500 条** | 试用功能受限请联系信息科！ |
| 住宿档案（Dorms） | 5 条 | **5 条**（不变） | 同上 |
| 人员清单（Personnel） | 5 条 | **5 条**（不变） | 同上 |

### 3.2 设计决策依据（v2.13.150 用户原话）

> 「分别限制 住宿登记 最多记录为 500条、住宿档案 最多记录为5条、人员清单 最多记录为5条」

住宿登记记录包含 住宿/退房 流水，业务上是高频操作（每天多次），需要更高上限保证基本业务可用；住宿档案和人员清单是基础资料，一次性录入，上限较低防止大量无效数据。

### 3.3 LicenseGuard.cs 关键改动

**新增字典 + 错误码 + 提示**：

```csharp
/// <summary>v2.13.150：试用受限标准提示（用户原话）</summary>
public const string TrialLimitMessage = "试用功能受限请联系信息科！";

/// <summary>v2.13.150：试用模式下各模块最大记录数（住宿登记/住宿档案/人员清单）</summary>
public static readonly IReadOnlyDictionary<string, int> TrialMaxRecordsByModule = new Dictionary<string, int>
{
    ["住宿登记"] = 500,
    ["住宿档案"] = 5,
    ["人员清单"] = 5
};

/// <summary>v2.13.149 旧版常量（保留兼容，已 Obsolete）</summary>
[Obsolete("v2.13.149 单一 5 条上限已被 v2.13.150 分模块上限取代，请使用 TrialMaxRecordsByModule")]
public const int TrialMaxRecords = 5;
```

**CheckTrialRecordLimit 改造为分模块查询**：

```csharp
public static (bool IsAllowed, string Message) CheckTrialRecordLimit(string moduleName, int currentCount)
{
    if (!IsTrialMode())
    {
        return (true, "");  // 已注册 → 不限制
    }

    // v2.13.150：分模块上限查询
    if (!TrialMaxRecordsByModule.TryGetValue(moduleName, out var maxRecords))
    {
        maxRecords = 5;  // 未知模块保守默认
    }

    if (currentCount >= maxRecords)
    {
        // v2.13.150 用户原话新提示
        return (false, $"试用功能受限请联系信息科！\n\n当前『{moduleName}』已有 {currentCount} 条记录，超出试用上限 {maxRecords} 条。\n\n请联系信息科进行正式注册后即可继续使用。");
    }

    return (true, $"试用模式：当前『{moduleName}』{currentCount}/{maxRecords} 条");
}
```

## 七、永久教训（3 条新增）

### 教训 #1：业务场景决定上限数量级
v2.13.149 一刀切 5 条上限忽略了「住宿登记」是高频操作（每天多次），v2.13.150 用户原话给出业务分级（500/5/5）。
**结论**：试用上限必须按业务场景分级，不能为简化逻辑强求统一。住宿登记高频 → 500；基础资料低频 → 5。

### 教训 #2：字典映射取代 if/else
v2.13.149 用 `TrialMaxRecords` 单常量 + if/else（"住宿登记"→5/else→5），v2.13.150 改 `TrialMaxRecordsByModule` 字典，新增模块只需在字典加一行。
**结论**：当未来模块可能增加时，**字典模式更可扩展**（O(1) 查询 + 新模块零代码改动）。

### 教训 #3：旧版常量 [Obsolete] 过渡
`[Obsolete("v2.13.149 单一 5 条上限已被 v2.13.150 分模块上限取代")]` 让旧调用方编译失败或收到警告，确保未来不会误用。
**结论**：常量重命名或语义变更必须用 `[Obsolete]` 标记，避免代码静默回退。
