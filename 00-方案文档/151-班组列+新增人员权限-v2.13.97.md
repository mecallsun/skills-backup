## 一、问题根因

### 1.1 班组列缺失 P0

`BookingService.GetListAsync()` 已 JOIN `SysEmployee`（v2.13.32-hotfix 姓名 / v2.13.47 工号 / v2.13.66 部门 / v2.13.86 性别 / v2.13.89 登记人），**唯独缺少 JOIN `Team`**。

**根本原则遗漏**：住宿相关业务以 SysEmployee（人员清单）为唯一真源，但「班组」字段未参与这个同步策略。模式 BUG 必须全字段审计 —— RealName/EmployeeCode/Department/Team 是同一类（冗余字段同步），缺一不可。

### 1.2 新增人员权限缺失 P0

`SysPermission` seed 当前 personnel 子权限 4 个（import/edit/markleft/delete），**缺少 `personnel:add`**。

而 `Personnel/Index.cshtml:22` 的「新增」按钮原错误绑定到 `PermissionCode = "personnel:import"`（笔误，应该是新增人员专属权限）。同时导致 `_UserPanel` / `Settings` 角色权限矩阵 personnel 区块的复选框列表缺少「新增」项。

## 二、修复实施（5 阶段）

### 2.1 数据层 — DormBooking 派生字段 + SysPermission seed

#### 2.1.1 `DormBooking.TeamName` 派生字段（NotMapped）

```csharp
/// <summary>
/// 班组名（v2.13.97 JOIN 派生：SysEmployee.TeamId → Team.Name，运行时计算不存库）
/// 人员清单为唯一真源 — 班组改后住宿登记列表自动同步显示最新班组
/// </summary>
[NotMapped]
public string? TeamName { get; set; }
```

#### 2.1.2 SysPermission seed — `personnel:add` (Id=40)

```csharp
// ========== v2.13.97 P0 BUG：personnel 子权限补全（用户反馈：缺少「新增」按钮权限） ==========
new SysPermission { Id = 40, PermissionCode = "personnel:add", PermissionName = "新增人员",
                    PermissionType = 2, ParentId = 9, Route = "/Personnel/Create",
                    Icon = "bi-plus-lg", SortOrder = 7, IsActive = true,
                    CreatedAt = DateTime.Parse("2026-07-22") }

// SysRolePermission — admin 默认拥有新增人员权限
new SysRolePermission { Id = 61, RoleId = 1, PermissionId = 40, CreatedAt = DateTime.Parse("2026-07-22") }
```

### 2.2 Service 层 — BookingService JOIN Team

```csharp
var query =
    from b in _db.DormBookings.AsNoTracking()
    join emp in _db.Employees.AsNoTracking() on b.EmployeeId equals emp.Id into empGroup
    from emp in empGroup.DefaultIfEmpty()
    join team in _db.Set<Team>().AsNoTracking() on (emp != null ? (int?)emp.TeamId : null) equals team.Id into teamGroup
    from team in teamGroup.DefaultIfEmpty()
    select new {
        ...
        TeamName = team != null ? team.Name : null
    };

// 物化覆盖（与姓名/工号/部门同模式）：
if (!string.IsNullOrEmpty(item.Dto.TeamName))
    item.Entity.TeamName = item.Dto.TeamName;
```

## 四、关键决策与权衡

| 决策 | 理由 |
|------|------|
| **TeamName 派生字段 NotMapped** | 与 v2.13.89 DisplayName 一致 — 运行时计算，不污染 DB schema |
| **保留 SysPermission.SortOrder=7** | 与 `personnel:import` 平级（v2.13.88 列表内按钮权限独立），但排在 import 之前（更具优先级） |
| **SysPermission 用 `personnel:add` 而非 `personnel:create`** | 与现有 `meter:entry`/`meter:import` 等按钮权限命名规则保持动词化（import 已经存在） |
| **JOIN 用 LeftJoin (DefaultIfEmpty) 风格** | 与 EmployeeId FK LEFT JOIN 风格一致 — 即使档案被删除，Booking 记录仍能展示（部门/班组显示 NULL/「-」） |
