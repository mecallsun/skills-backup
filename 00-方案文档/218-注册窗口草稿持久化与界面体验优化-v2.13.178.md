# v2.13.178 — LicenseForm 注册窗口草稿持久化 + 界面体验优化

**日期**：2026-07-26
**核心变更**：注册窗口输入框（CDKEY + 公司名称）支持草稿持久化，即使校验失败或取消注册，下次打开窗口仍能自动预填

---

## 一、用户原话

> 对托盘程序中的注册窗口中，当点击"取消注册"时，则清除注册信息和注册状态（每次启动程序或点击"注册"时，都触发注册码校验，注册状态为：注册校验通过或注册有效期超时、或试用状态、或无注册信息），但在注册窗口中的输入框中仍临时保存注册码与公司名称，并可用于下次启动程序时，当未校验成功的信息，则将输入框的注册码、公司名称等信息允许保存至注册表或本地临时文件中，用于下次打开注册窗口时，不必手工输入。

## 二、需求分析

### 2.1 现状（v2.13.94 - v2.13.177）

- 「取消注册」调用 `RegisterSdk.DeleteRegItem()` → 清掉 CDKEY/LTDName/RegDate/SN 全部字段
- LicenseForm 重新加载后，输入框被清空 → 用户必须重新输入 CDKEY 和公司名称
- 即使用户输入了 CDKEY 但校验失败（机器码不符 / 过期），下次启动窗口**不会保留**之前的输入 → 用户体验差

### 2.2 新需求（v2.13.178）

1. **「取消注册」只清正式注册信息，不清用户已输入的草稿**
2. **每次输入 CDKEY 或公司名称时自动保存草稿**（去抖 350ms）
3. **每次打开 LicenseForm 时自动加载草稿预填输入框**
4. **注册成功（通过校验）后清掉草稿**（已升级为正式注册，无需保留草稿）
5. **校验失败的输入仍保留草稿**（便于再次尝试或重新生成 CDKEY）

## 三、设计方案

### 3.1 核心思想：双层存储分离

```
HKLM\Software\JINGE\DormManage\License\
├── CDKEY         ← 正式注册码（删除=取消注册）
├── LTDName       ← 正式公司名称（删除=取消注册）
├── RegDate       ← 正式注册日期
├── SN            ← 机器码
├── DraftCDKEY    ← v2.13.178 新增：草稿注册码（输入变化时自动保存）
└── DraftLTDName  ← v2.13.178 新增：草稿公司名称（输入变化时自动保存）
```

### 3.2 状态机矩阵

| 操作场景 | 正式注册 | 草稿 | 输入框状态 |
|---------|---------|------|------------|
| 打开 LicenseForm（已注册 RegInt=1） | ✅ 保留 | ❌ 不显示 | 显示正式 CDKEY/LTDName，**只读** |
| 打开 LicenseForm（未注册/过期） | ❌ 无 | ✅ 保留（如有） | 优先用草稿预填，无草稿则空 |
| 用户输入 CDKEY | ❌ 不变 | ✅ 实时更新 | 350ms 后自动持久化草稿 |
| 用户输入公司名 | ❌ 不变 | ✅ 实时更新 | 350ms 后自动持久化草稿 |
| 点击「注册」（校验失败） | ❌ 不变 | ✅ 保留 | 保留，方便再次尝试 |
| 点击「注册」（校验成功） | ✅ 写入 | ❌ 清掉 | 升级为正式注册，草稿清空 |
| 点击「取消注册」 | ❌ 删除 | ✅ **保留** | 草稿保留，**输入框不变**，便于重输 |
| 程序关闭重启 | （不变） | （不变） | 下次打开自动预填 |

### 3.3 草稿保存策略

- **去抖 350ms**：CDKEY/LTDName 文本框 TextChanged 事件触发 → 启动 350ms 定时器 → 定时器到点才写一次
- 避免高频 IO：连续输入「ABCDE」5 个字符不会触发 5 次写入，只触发 1 次
- **字符集过滤**：仅保存 [0-9A-Z-] 字符（与 NPGS 算法 A 一致）；非法字符静默忽略
- **长度限制**：LTDName 最大 100 字符（与正式注册一致）

## 四、核心改动

### 4.1 `DormManage.Shared/Register/RegisterSdk.cs`

新增 3 个公开 API + 2 个常量：

```csharp
public const string DraftCDKEYKey = "DraftCDKEY";
public const string DraftLTDNameKey = "DraftLTDName";

/// <summary>保存草稿（输入变化时自动调用）</summary>
public static void SaveRegistrationDraft(string? cdkey, string? ltdName);

/// <summary>读取草稿（LicenseForm 打开时调用）</summary>
public static (string CDKEY, string LTDName) LoadRegistrationDraft();

/// <summary>清除草稿（注册成功后调用）</summary>
public static void ClearRegistrationDraft();
```

实现要点：
- 复用现有 `WriteRegValue` / `ReadRegValue` / `DeleteRegValue` 三层降级机制（HKLM → HKCU → license.dat DPAPI 加密文件）
- 写入路径与正式注册同一节点 `License\`，仅 key 名区分（`CDKEY` vs `DraftCDKEY`）

### 4.2 `DormManage.TrayApp/Forms/LicenseForm.cs`

#### 4.2.1 `LoadRegState()` 增加草稿预填逻辑

```csharp
// v2.13.178 草稿预填：仅当「无正式注册」分支才用草稿覆盖输入框
bool useDraft = reg.RegInt != 1;  // RegInt=1（已注册）→ 不覆盖
if (useDraft)
{
    var (draftCd, draftLtd) = RegisterSdk.LoadRegistrationDraft();
    text_CDKEY.Text = !string.IsNullOrEmpty(draftCd) ? draftCd : reg.CDKEY;
    textLTD.Text = !string.IsNullOrEmpty(draftLtd) ? draftLtd : reg.LTDName;
}
```

#### 4.2.2 新增 `ScheduleDraftSave()` 去抖保存

```csharp
private System.Windows.Forms.Timer? _draftTimer;
private void ScheduleDraftSave()
{
    if (_draftTimer == null)
    {
        _draftTimer = new System.Windows.Forms.Timer { Interval = 350 };
        _draftTimer.Tick += (_, _) =>
        {
            _draftTimer?.Stop();
            RegisterSdk.SaveRegistrationDraft(text_CDKEY.Text, textLTD.Text);
        };
    }
    _draftTimer.Stop();
    _draftTimer.Start();
}
```

#### 4.2.3 TextChanged 事件绑定

```csharp
text_CDKEY.TextChanged += (_, _) => ScheduleDraftSave();
textLTD.TextChanged += (_, _) => ScheduleDraftSave();
```

#### 4.2.4 `BtnReg_Click` 关键变更

**「注册」按钮（校验通过分支）：**
```csharp
if (RegisterSdk.WriteRegItem(reg))
{
    RegisterSdk.ClearRegistrationDraft();  // v2.13.178：升级为正式注册后清草稿
    LicenseGuard.ResetCache();
    MessageBox.Show($"🎉 注册成功！...");
}
```

**「取消注册」分支（保留草稿）：**
```csharp
if (RegisterSdk.DeleteRegItem())
{
    LicenseGuard.ResetCache();
    // 注意：此处**不**调用 ClearRegistrationDraft() —— 草稿保留以便下次重新输入
    MessageBox.Show("注册信息已取消！\n\n您之前输入的注册码和公司名称已作为临时草稿保留。");
}
```

## 五、用户体验流程（端到端）

### 5.1 用户首次安装（未注册）

1. 打开 LicenseForm → 「❌ 此软件尚未注册」+ 输入框空
2. 用户输入 CDKEY `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` → 350ms 后草稿自动保存
3. 用户输入公司名 `广东金戈新材料股份有限公司` → 350ms 后草稿自动保存
4. 点击「注册」→ **校验失败**（机器码不符）→ 错误提示 → 输入框不变
5. **关闭 LicenseForm**（不点注册，直接关）
6. **重启托盘** → 打开 LicenseForm → 输入框**自动预填**上次输入的 CDKEY 和公司名 ✅

### 5.2 用户取消注册

1. 已注册状态打开 LicenseForm → 「✅ 此软件已注册」+ 输入框只读显示正式信息
2. 点击「取消注册」→ 确认弹窗（明确告知"草稿保留"）
3. 取消成功 → LicenseForm 状态变为「❌ 此软件尚未注册」
4. **输入框保持上次内容**（已注册的 CDKEY/LTDName 同步作为草稿）
5. 用户修改 CDKEY 后再点击「注册」→ 校验通过 → **草稿清掉** → 升级为正式注册

### 5.3 注册过期

1. 已过期状态打开 LicenseForm → 「⚠️ 许可已过期」+ 输入框显示旧的过期 CDKEY（来自草稿）
2. 用户修改为新 CDKEY → 350ms 后草稿更新
3. 点击「重新注册」→ 校验通过 → 草稿清掉，新 CDKEY 写入正式注册

## 六、安全考虑

1. **草稿不加密敏感数据**——但只有**本机**用户能访问 HKLM/HKCU/license.dat（DPAPI LocalMachine 加密）
2. **草稿不进入 IPC 广播**——LicenseMonitor 只推送 `RegInt/RegStatus/RegDate`，草稿字段不会泄漏
3. **草稿不参与注册校验逻辑**——`CheckReg()` / `CheckRegCDKey()` 完全不读 DraftCDKEY
4. **草稿字符集过滤**——防止恶意输入污染注册表

## 九、永久教训

1. **「清空」≠「重置」**——取消注册只清正式注册，草稿必须保留以提供连续体验
2. **频繁写入必须去抖**——TextChanged 高频触发，350ms 去抖避免磁盘 IO 抖动
3. **draft 与正式数据分层**——草稿字段独立于正式字段，存储、读取、清除三套独立 API
4. **UI 输入体验与持久化解耦**——输入框 = UI 控件；持久化 = 业务逻辑；通过 TextChanged 事件桥接
5. **错误提示必须含「下一步」**——取消注册时明确告知「草稿保留」，避免用户疑惑「为什么输入框还在」
