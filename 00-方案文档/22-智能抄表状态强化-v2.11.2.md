## 1. 变更背景

v2.11.2 增补 (n) 引入"未抄表"状态（status=0）、增补 (o) 引入"未完成"状态（status=4）和备注历史追加机制。本次需求进一步强化：

1. **用量计算规则**：未完成记录中"未上传表项"对应的当月用量强制为 **0**（**不可为负数**）
2. **筛选选项简化**：删除"正常+已修正"等复合逻辑选项，"全部" = 含所有 5 个状态

## 2. 详细变更

### 2.1 状态机保持不变（5 状态）

| Status | 含义 | 数据完整性 | Badge | 参与计费 |
|--------|------|----------|-------|---------|
| 0 | 未抄表 | 三表全 0 | 灰 | ❌ |
| 1 | 正常 | 三表完整 | 绿 | ✅ |
| 2 | 已修正 | 三表完整已修正 | 黄 | ✅ |
| 3 | 已作废 | — | 灰 | ❌ |
| 4 | **未完成** | **部分表项 0** | 蓝 | ⚠️ 部分 |

### 2.2 用量计算规则强化（v2.11.2 增补 p）

**核心规则**：

```
当月用量 = max(0, 本月读数 - 上月读数)
```

**当 status=4（未完成）时**：

- 该表项本月读数 = 0
- 上月读数存在时，本月用量 = max(0, 0 - 上月读数) = **0**
- 上月读数不存在时，本月用量 = **0**
- **关键：本月用量绝对不会是负数**

**示例**：

| 宿舍 | 表项 | 上月读数 | 本月读数 | 用量 | 状态 |
|------|------|---------|---------|------|------|
| D-005 | 冷水 | 100 | 110 | 10 | 正常 |
| D-005 | 热水 | 50 | 0 | **0** | 未完成（热水未上传） |
| D-005 | 电表 | 200 | 210 | 10 | 正常 |

### 2.3 状态筛选选项简化（v2.11.2 增补 p）

**修改前（v2.11.2 增补 o）**：

```html
<option value="">全部（含所有状态）</option>
<option value="valid" selected>正常+已修正</option>      ← 复合选项，删除
<option value="0">未抄表</option>
<option value="4">未完成</option>
<option value="1">正常</option>
<option value="2">已修正</option>
<option value="3">已作废</option>
```

**修改后（v2.11.2 增补 p）**：

```html
<option value="" selected>全部（含所有状态）</option>  ← 默认
<option value="0">未抄表</option>
<option value="4">未完成</option>
<option value="1">正常</option>
<option value="2">已修正</option>
<option value="3">已作废</option>
```

**变更要点**：

- 删除"全部（排除未抄表）"和"全部（含未抄表）"重复定义
- 删除"正常+已修正"复合选项（合并到单独按状态筛选）
- 默认选项 = "全部"，含全部 5 个状态

### 2.4 getFiltered 逻辑

**修改前**：

```javascript
if (st === 'valid') { if (m.status !== 1 && m.status !== 2) return false; }
else if (st && m.status != st) return false;
else if (!st) { if (m.status === 0 || m.status === 3) return false; }
```

**修改后**：

```javascript
// 默认（st=""）= 全部，包含所有 5 个状态
if (st && m.status != st) return false;
```

## 3. 后端 SQL 实现

### 3.1 用量计算（强制 0）

```sql
SELECT
    MeterRecordId, DormCode, ReadMonth,
    ColdMeter, HotMeter, ElectricMeter, Status,
    -- 用量强制 max(0, 本月-上月)
    CASE 
        WHEN ColdMeter IS NULL OR PrevColdMeter IS NULL THEN 0
        WHEN ColdMeter < PrevColdMeter THEN 0  -- 异常强制 0
        ELSE ColdMeter - PrevColdMeter
    END AS ColdUsage,
    -- 同理 HotUsage / ElecUsage
    -- 当 Status = 4（未完成）时，对应缺失表项用量 = 0
    CASE 
        WHEN Status = 4 AND ColdMeter = 0 THEN 0  -- 未上传的表项用量强制 0
        WHEN ColdMeter IS NULL OR PrevColdMeter IS NULL THEN 0
        WHEN ColdMeter < PrevColdMeter THEN 0
        ELSE ColdMeter - PrevColdMeter
    END AS ColdUsageAdjusted
FROM MeterRecord
LEFT JOIN PrevMeter ON ...;
```

### 3.2 状态筛选 SQL

```sql
-- 全部（含所有状态）
SELECT * FROM MeterRecord WHERE ReadMonth = @Month;

-- 仅未完成
SELECT * FROM MeterRecord WHERE ReadMonth = @Month AND Status = 4;

-- 仅未抄表
SELECT * FROM MeterRecord WHERE ReadMonth = @Month AND Status = 0;
```
