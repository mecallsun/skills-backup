## 二、修改详情

### 2.1 有效期右移 50px

```diff
- label_DateValue = new Label { Text = "—", Location = new Point(x + 60, y + 3), ... };
+ label_DateValue = new Label { Text = "—", Location = new Point(x + 110, y + 3), ... };  // v2.13.167 右移 50px
```

`x` 是布局基准列（70px 标签宽 + 5px 间隔），原 `x+60` 仅距「有效期：」标签 5px 紧贴，**日期数字（"2026年07月26日"，共 12 个字符）**会被部分遮挡。`x+110` 给日期 12 字符（~108px 宽）留足空间。

### 2.2 试用次数条件显示

**v2.13.166 旧逻辑**（无脑全显）：
```csharp
label_Trial.Text = $"试用次数：{reg.UseTimes} / {RegisterSdk.TRIAL_LIMIT}";
// case 1: label_Trial.Text += $"（剩 {(reg.RegDate.Value.Date - DateTime.Today).Days} 天）";  // 已注册还追加
```

问题：
1. 已注册（RegInt=1）却显示"试用次数" → 误导用户以为还在试用
2. 已过期（RegInt=0）也显示 → 误导以为可继续试用
3. 「已注册」还显示「剩 X 天」 → 与已注册状态矛盾

**v2.13.167 新逻辑**（条件显示）：
```csharp
// 默认空 — case 1/0 不写即不显示
label_Trial.Text = "";

switch (reg.RegInt) {
    case 1:  // 已注册 — 仅显示有效期
        labRegInfo.Text = "✅ 此软件已注册";
        // 不写 label_Trial
        break;
    case 0:  // 已过期 — 仅显示状态
        labRegInfo.Text = "⚠️ 许可已过期";
        // 不写 label_Trial
        break;
    default: // 未注册（RegInt=-1）— 才显示试用次数
        labRegInfo.Text = "❌ 此软件尚未注册";
        label_Trial.Text = $"试用次数：{reg.UseTimes} / {RegisterSdk.TRIAL_LIMIT}";
        break;
}
```

**3 状态 UI 矩阵**（v2.13.167）：

| 状态 | labRegInfo | label_Trial | label_DateValue |
|---|---|---|---|
| 已注册 (RegInt=1) | "✅ 此软件已注册"（绿）| **不显示** | 注册到期日（绿）|
| 已过期 (RegInt=0) | "⚠️ 许可已过期"（橙红）| **不显示** | 原始到期日（绿）|
| 未注册 (RegInt=-1) | "❌ 此软件尚未注册"（红）| "试用次数：X/30"（灰）| "—" |

## 五、永久教训

| # | 教训 |
|---|------|
| 1 | **「条件显示」必须在初始化时显式清空**。如果只在某些 case 分支设置 Text，初始默认值会影响初始显示——本次通过 `label_Trial.Text = ""` 显式清空，确保所有分支初始一致。 |
| 2 | **「5px 间隔」对 12 字符中文日期不够**。`x + 60` 看似合理（标签 70 + 间隔 5 - 标签宽补偿），但中文日期「2026年07月26日」实际宽度 ~108px 远超 60px 起点。**UI 布局测试必须实际渲染验证，不能凭数学推算**。 |
| 3 | **「同 Label 多 Text 来源」需要明确状态机**。label_Trial 既被 `默认赋值` 又被 `case 1 追加`——这种「初始化 + 分支修改」模式容易产生状态不一致（v2.13.166 bug）。**v2.13.167 改为「默认空 + 仅 default 分支赋值」，状态机更清晰**。 |
| 4 | **「需求一致性检查」应跨多文档同步**。同一规则（试用次数条件显示）需在 147（注册机制）+ 09（系统设置需求）+ LicenseForm 注释 三处一致——任一处遗漏都会导致 UI 与文档脱节。 |
