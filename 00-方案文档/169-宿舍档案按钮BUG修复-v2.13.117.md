## 二、根因排查

### 2.1 现状（修复前）

`Dorms/Index.cshtml` 第 21-22 行同时定义 2 个按钮：

```csharp
primaryAction = new PageAction { Label = "新增宿舍", OnClick = "openDormModal(0)", Icon = "bi-plus-lg", Style = "success", PermissionCode = "dorm:create" },
actions = new List<PageAction> { new() { Label = "新窗口新增", Icon = "bi-box-arrow-up-right", Url = "/Dorms/Create", Style = "secondary", PermissionCode = "dorm:create" } }
```

### 2.2 现象

| 按钮 | 行为 | 用户感知 |
|------|------|---------|
| 「新增宿舍」 | `OnClick="openDormModal(0)"` → 打开 `#dormModal` 弹窗，iframe 加载 `/Dorms/Create?inModal=1` | ❌ 无功能（实际 iframe 提交后 `parent.location.reload()` 闪一下又恢复原状） |
| 「新窗口新增」 | `Url = "/Dorms/Create"` → 直接跳转独立页面 | ✅ 可用 |

### 2.3 真正根因

**v2.13.11 OPT-1 优化引入的 Modal iframe 模式有 3 个问题**：

1. **`Create.cshtml.cs:90` 提交后执行 `parent.location.reload()`** —— 在 iframe 中刷新整个父页（含弹窗），用户感知为「闪一下又恢复原状」
2. **`Create.cshtml:5-13` `Layout = null`** —— iframe 内页面极简（无顶栏/侧边栏），用户看不到提交反馈
3. **页面成功路径走 `RedirectToPage("/Dorms/Details")`** —— 即使弹窗刷新成功，也会跳到 Details 页而非列表，与「新增后回到列表」预期不符

### 2.4 一致性原则

参考其他 4 个模块的「新增」按钮实现：

| 模块 | 按钮模式 |
|------|---------|
| Personnel/Index | `Url = "/Personnel/Create"`（独立跳转） |
| Booking/Index | `Url = "/Booking/CheckIn"`（独立跳转） |
| BillingStandard/Index | `Url = "/BillingStandard/Create"`（独立跳转） |
| Meter/Index | `OnClick = "showAddModal()"`（弹窗独占模式，v2.13.81 引入） |

**Dorms/Index 是唯一异类**（同时存在 2 个按钮且 1 个不可用），本次统一为独立跳转模式。

## 六、核心教训

### 6.1 Modal iframe 模式的局限性

**触发条件**：用户报告「弹窗按钮无功能 / 提交后没反应」时，**优先排查 iframe 提交后的回调**：
- `parent.location.reload()` 看起来正确，但**弹窗自身也在被刷新**，用户看到的是「闪一下又恢复原状」
- iframe 内页面 `Layout = null` 会丢失顶栏/侧边栏/全局 JS，用户感知不到提交反馈
- 提交成功路径如果跳转到独立页面（如 Details），iframe 刷新后父页也跟着跳 —— 不是「弹窗关闭」而是「弹窗和父页一起跳转」

### 6.2 一致性原则

**业务相同 + 模块相同 → 必须使用相同模式**。本次修复前 Dorms 模块存在 2 个「新增」按钮且 1 个不可用，明显违反一致性原则：
- 4 个兄弟模块全部用 `Url = "/Xxx/Create"` 独立跳转
- Dorms 异类：2 个按钮 1 个 Modal iframe + 1 个 Url

**Code Review 必驳回**：
- ❌ 同一页面 2 个按钮做同样的事（即使命名不同）
- ❌ Modal iframe 模式与兄弟模块不一致
- ✅ 同一页面只保留 1 个「新增」按钮，模式与兄弟模块对齐

### 6.3 「弹窗 vs 独立页面」识别规则（v2.13.81 用户明确指令）

```
原型 <button data-bs-toggle="modal" data-bs-target="#xxx">  → 弹窗独占模式
原型 <a href="xxx.html">                                      → 独立页面跳转
实际实施可工作模式优先                                        → 模式必须用户可感知到功能
```

**本次案例**：原型 dorms/list.html 第 39 行 `<button data-bs-toggle="modal" data-bs-target="#modalDormCreate">`（弹窗模式），但用户实际反馈「弹窗按钮无功能，独立跳转可用」。**优先采用稳定可用的独立页面跳转**，保留 Modal 容器给其他入口（行内编辑）使用。
