### 3.2 PageModel 层（v2.13.106 新增）

**文件**：`DormManage.Admin/Pages/Personnel/Create.cshtml.cs`

```csharp
public const string RequiredPermissionCode = "personnel:add";

public CreateModel(IPersonnelService svc, DormDbContext db, IPermissionService perm, IHttpContextAccessor http) { ... }

public async Task<IActionResult> OnGetAsync()
{
    // v2.13.106 三层防御（PageModel 层）：无 personnel:add 权限 → 重定向
    if (!_perm.CurrentUserHasCode(_http, RequiredPermissionCode))
    {
        TempData["Error"] = $"您没有「新增人员」权限（{RequiredPermissionCode}），无法访问该页面";
        return RedirectToPage("/Personnel/Index");
    }
    await LoadDropdownsAsync();
    return Page();
}

public async Task<IActionResult> OnPostAsync()
{
    // v2.13.106 三层防御（PageModel 层）：POST 也必须校验
    if (!_perm.CurrentUserHasCode(_http, RequiredPermissionCode))
    {
        TempData["Error"] = $"您没有「新增人员」权限（{RequiredPermissionCode}），无法提交数据";
        return RedirectToPage("/Personnel/Index");
    }
    // ... 原有逻辑 ...
}
```

**PageModel 守卫目的**：
- PagePermissionFilter 只检查模块级 `personnel:view`（进入 /Personnel/*）
- PageModel 检查按钮级 `personnel:add`（进入 /Personnel/Create 提交）
- 防止**已知 URL 直接访问**绕过 UI 按钮隐藏

### 3.3 API 层（v2.13.106 新增）

**文件**：`DormManage.Api/Controllers/Personnel/PersonnelController.cs`

```csharp
public const string RequiredPermissionCode = "personnel:add";

public PersonnelController(IPersonnelService service, IPermissionService perm, ILogger<PersonnelController> logger) { ... }

[HttpPost]
public async Task<ApiResponse<int>> Create([FromBody] PersonnelEditDto dto)
{
    // v2.13.106 三层防御（API 层）：无 personnel:add 权限 → 403 拒绝
    if (!HasPermission(RequiredPermissionCode))
    {
        _logger.LogWarning("[v2.13.106 RBAC] 用户 {User} 尝试 POST /api/v1/personnel 但缺少 {Code} 权限",
            HttpContext.GetCurrentUserName(), RequiredPermissionCode);
        return ApiResponse<int>.Fail("PERMISSION_DENIED", $"无 {RequiredPermissionCode} 权限，无法新增人员");
    }
    var (ok, msg, id) = await _service.CreateAsync(dto);
    return ok ? ApiResponse<int>.Ok(id, msg) : ApiResponse<int>.Fail("CREATE_FAILED", msg);
}

[HttpPost("import")]
public async Task<ApiResponse<PersonnelImportResult>> Import(IFormFile file)
{
    // 导入批量新增同样需要 personnel:add 权限
    if (!HasPermission(RequiredPermissionCode))
    {
        _logger.LogWarning("[v2.13.106 RBAC] 用户 {User} 尝试 POST /api/v1/personnel/import 但缺少 {Code} 权限",
            HttpContext.GetCurrentUserName(), RequiredPermissionCode);
        return ApiResponse<PersonnelImportResult>.Fail("PERMISSION_DENIED", $"无 {RequiredPermissionCode} 权限，无法导入人员");
    }
    // ... 原有逻辑 ...
}

private bool HasPermission(string code)
{
    if (string.IsNullOrEmpty(code)) return true;
    var userId = HttpContext.GetCurrentUserId();
    if (userId <= 0) return false;
    var accessor = HttpContext.RequestServices.GetService<IHttpContextAccessor>()
                   ?? new HttpContextAccessor { HttpContext = HttpContext };
    return _perm.CurrentUserHasCode(accessor, code);
}
```

**API 守卫目的**：
- API 网络层信任（trusted local network），但**作为防御性深度**（defense in depth）必须校验
- 防止**外部脚本/Postman/curl**直接 POST 绕过 Razor UI
- 复用 `HttpContextExtensions.GetCurrentUserId` 兼容 X-User-Id header（v2.13.89）

## 七、决策与权衡

| 决策 | 理由 |
|------|------|
| **三层防御（UI + PageModel + API）** | v2.13.82 用户明确指令：业务硬约束必须三层都实现；UI 防误操作，PageModel 防 URL 绕过，API 防脚本绕过 |
| **PagePermissionFilter 只做模块级校验** | 模块级 `personnel:view` 控制整个 /Personnel/* 路由访问；按钮级 `personnel:add` 由 PageModel 处理。职责分离清晰 |
| **PageModel 重定向到列表 + TempData Error** | 比抛 403 页面更友好；用户立即看到列表 + 错误提示 |
| **API 返回 ApiResponse.Fail 而非 403 status** | 与项目其他端点风格一致；前端可统一处理 success=false 分支 |
| **API 同时校验 import 端点** | 批量导入同样创建员工，必须同等权限控制 |
| **API 用 X-User-Id Header 识别用户** | 与 v2.13.89 HttpContextExtensions 兼容，trusted local network 模式 |
| **RequiredPermissionCode 常量化** | 与 PageHeader primaryAction.PermissionCode 字符串保持一致，便于统一维护 |
| **复用 IPermissionService.CurrentUserHasCode** | 每请求 Items 缓存，避免重复查询 DB |
| **不删除 PagePermissionFilter 模块级校验** | 不影响现有逻辑；PagePermissionFilter 负责路由级，PageModel 负责按钮级 |

## 八、风险与回退

| 风险 | 缓解 |
|------|------|
| PageModel 校验增加 ~10ms（首次访问 Items 缓存命中后 ~0ms） | 复用 IPermissionService 已有的 Items 缓存机制 |
| API 校验增加 ~10ms（同上） | 同上 |
| IHttpContextAccessor 注册冲突（Admin 早已注册，Api 新增） | DI 容器按项目隔离，无冲突 |
| 已部署生产环境的非 admin 角色需要新增 personnel:add 才能用 | 这是权限升级，符合 v2.13.97 后 admin 默认行为；其他角色按业务需要授权 |
| admin 角色误取消 personnel:add 导致全系统无法新增人员 | 权限矩阵 UI banner（v2.13.102）+ 一键修复可恢复 |

## 九、教训（v2.13.106）

1. **「UI 隐藏按钮」≠「权限闭环」**：仅靠 PageHeader PermissionCode 隐藏按钮是 UX，不是安全。用户知道 URL 就能绕过，必须 PageModel + API 同样校验
2. **业务硬约束三层防御已成项目铁律**（v2.13.82）：任何按钮权限（不只是数据约束）都应三层落地
3. **API 复用 IPermissionService 0 成本**：X-User-Id Header + Items 缓存已有基础设施（v2.13.89/76），新增加密点只是几行 if
4. **PagePermissionFilter 职责单一**：路由级守卫不应混入按钮级权限校验，否则职责混乱且难维护
5. **RequiredPermissionCode 常量化便于审计**：PageHeader PermissionCode、CreateModel 常量、PersonnelController 常量三处统一字符串，一改全改
