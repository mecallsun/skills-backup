# 每页条数 dropdown BUG 修复（v2.13.74）

> **版本**：v2.13.74
> **日期**：2026-07-21
> **类型**：P0 BUG 修复（8 个 PageModel × 1 个 partial）
> **触发需求**：用户反馈"对列表底部的每页 N 条操作变更，但连接的参数正确，页面列表没有按此条数翻页"
> **结论**：✅ **根因：8 个 PageModel 的 `PageSize` 全部缺失 `[BindProperty(SupportsGet = true)]`（3 个甚至 `{ get; }` 只读）。`_PaginationPartial` 的 `changePageSize()` JS 设置 `?pageSize=N&pageIndex=1` 跳转，但 PageModel 不读此参数 → 列表永远硬编码 20。修复后 5 个有数据页面 100% 通过端到端验证。**

---

## 一、需求（用户原话）

> 对列表底部的 每页 N 条 操作变更，每页 显示记录 N 条 时列表的记录数量没有变化，存在 BUG，但连接的参数正确，为何页面列表没有按此条数翻页呢？请查明修复，补充到相关文档中

**业务影响**：
- `/Personnel`、`/Booking`、`/Dorms`、`/Meter`、`/DormBilling`、`/EmployeeBilling`、`/BillingStandard`、`/Settings?tab=users` 共 **8 个列表页**
- 用户改 dropdown → URL 跳转 `?pageSize=50&pageIndex=1` → 列表仍按硬编码 20 显示
- 「分页器」原本是 v2.13.71 P0 重点交付，但 **PageModel 未读取 URL 参数**导致 BUG

---

## 二、根因调查

### 2.1 `_PaginationPartial` 行为审计

`_PaginationPartial.cshtml`（v2.13.71 新增）`changePageSize()` JS：

```javascript
window.changePageSize = function (newSize) {
    localStorage.setItem(pageSizeKey, newSize);
    var url = new URL(location.href);
    url.searchParams.set('pageSize', newSize);   // ← URL 添加 ?pageSize=N
    url.searchParams.set('pageIndex', '1');
    location.href = url.toString();              // ← 跳转
};
```

✅ JS 行为完全正确：URL 带 `?pageSize=N&pageIndex=1` + `location.href` 跳转。

### 2.2 PageModel 行为审计

| # | 页面 | PageSize 声明 | 是否支持 GET 绑定 | BUG |
|---|------|-------------|------------------|-----|
| 1 | Personnel | `public int PageSize { get; } = 20;` | ❌ **无 setter** | 🔴 |
| 2 | Booking | `public int PageSize { get; } = 20;` | ❌ **无 setter** | 🔴 |
| 3 | Dorms | `public int PageSize { get; set; } = 20;` | ❌ **无 BindProperty 标签** | 🔴 |
| 4 | Meter | `public int PageSize { get; set; } = 20;` | ❌ **无 BindProperty 标签** | 🔴 |
| 5 | DormBilling | `public int PageSize { get; } = 20;` | ❌ **无 setter** | 🔴 |
| 6 | EmployeeBilling | `public int PageSize { get; set; } = 20;` | ❌ **无 BindProperty 标签** | 🔴 |
| 7 | BillingStandard | **完全 hardcoded `20`** in `OnGetAsync` | ❌ **未声明 PageSize 属性** | 🔴 |
| 8 | Settings?tab=users (UserPanel) | `[BindProperty(Name="uSize")]` 自定义 query 名 | ⚠️ partial 用 `pageSize`，PageModel 用 `uSize`，**名称不匹配** | 🔴 |

**核心问题**：

1. **Razor Pages 框架不会自动从 query string 绑定到属性**——必须显式声明 `[BindProperty(SupportsGet = true)]`
2. **3 个 `{ get; }` 只读属性** 即使加 BindProperty 也无法写入（编译错误或运行时静默失败）
3. **BillingStandard 完全硬编码 `20`**，根本没有 `PageSize` 属性
4. **UserPanel 用 `uSize`/`uPage` 自定义 query 名**，与 `_PaginationPartial` 的 `pageSize`/`pageIndex` 不一致

### 2.3 三层审计路径

| 层 | 检查项 | 结果 |
|----|------|------|
| **L1 partial** | `_PaginationPartial.cshtml` `changePageSize()` | ✅ 正确 |
| **L2 PageModel** | `PageSize` 属性 + `[BindProperty(SupportsGet = true)]` | ❌ **8 个全部缺失** |
| **L3 query 名称映射** | partial 用 `pageSize`，UserPanel 用 `uSize` | ❌ **不一致** |

## 三、修复方案

### 3.1 7 个主 PageModel：标准修复

统一为：

```csharp
[BindProperty(SupportsGet = true)]
public int PageIndex { get; set; } = 1;

/// <summary>v2.13.74 BUG 修复：必须可写 + BindProperty 才能从 ?pageSize=N URL 绑定</summary>
[BindProperty(SupportsGet = true)]
public int PageSize { get; set; } = 20;
```

**修改清单**：

| 文件 | 行 | 旧 | 新 |
|------|---|-----|-----|
| `Personnel/Index.cshtml.cs` | 114 | `public int PageSize { get; } = 20;` | `[BindProperty(SupportsGet = true)] public int PageSize { get; set; } = 20;` |
| `Booking/Index.cshtml.cs` | 46 | 同上 | 同上 |
| `Dorms/Index.cshtml.cs` | 34 | `public int PageSize { get; set; } = 20;` | 加 `[BindProperty(SupportsGet = true)]` 在 PageSize 上 |
| `Meter/Index.cshtml.cs` | 33 | 同上 | 同上 |
| `DormBilling/Index.cshtml.cs` | 59 | `public int PageSize { get; } = 20;` | 改为 `{ get; set; }` + 加 BindProperty |
| `EmployeeBilling/Index.cshtml.cs` | 57 | `public int PageSize { get; set; } = 20;` | 加 `[BindProperty(SupportsGet = true)]` |
| `BillingStandard/Index.cshtml.cs` | — | 无 PageSize 属性 + OnGetAsync 硬编码 `20` | 新增 `[BindProperty(SupportsGet = true)] public int PageSize { get; set; } = 20;` + 替换硬编码为 `PageSize` |

### 3.2 UserPanel：query 名称映射

`_PaginationPartial` 用 `pageSize`/`pageIndex` 标准名，但 UserPanel 既有 `uSize`/`uPage` 又有 form filter。修复方案：**双 BindProperty 别名**——保留旧的 `uSize`/`uPage`（form 提交保留），同时新增 `pageSize`/`pageIndex` 别名（partial 跳转兼容）。

```csharp
/// <summary>v2.13.74 BUG 修复：使用标准 pageIndex / pageSize（与 _PaginationPartial 一致）</summary>
[BindProperty(SupportsGet = true, Name = "uPage")]
public int UserPageIndex { get; set; } = 1;

[BindProperty(SupportsGet = true, Name = "pageIndex")]
public int? PageIndexAlias
{
    get => UserPageIndex;
    set { if (value.HasValue) UserPageIndex = value.Value; }
}

[BindProperty(SupportsGet = true, Name = "uSize")]
public int UserPageSize { get; set; } = 20;

[BindProperty(SupportsGet = true, Name = "pageSize")]
public int? PageSizeAlias
{
    get => UserPageSize;
    set { if (value.HasValue && value.Value > 0) UserPageSize = value.Value; }
}
```

### 3.3 BillingStandard Index.cshtml partial 传参修复

旧：
```cshtml
@await Html.PartialAsync("_PaginationPartial", new ... {
    PageIndex = Model.Result.PageIndex,
    PageSize = Model.Result.PageSize,   // ← 从 Result 取（间接）
    TotalCount = Model.Result.TotalCount
})
```

新：
```cshtml
@await Html.PartialAsync("_PaginationPartial", new ... {
    PageIndex = Model.PageIndex,         // ← 直接从 PageModel 属性
    PageSize = Model.PageSize,
    TotalCount = Model.Result.TotalCount
})
```

## 六、教训

### 6.1 关键教训

1. **Razor Pages 不会自动从 query string 绑定属性**：必须显式声明 `[BindProperty(SupportsGet = true)]`。其他字段（DepartmentId、Status、Keyword 等）都有 BindProperty，唯独 PageSize 漏掉了——这是 v2.13.71 partial 设计时的疏忽。
2. **`{ get; }` 只读属性 + BindProperty 是矛盾**：3 个 PageModel 把 PageSize 声明为只读（可能是为了"防止意外修改"），但这导致即使有 BindProperty 也无法写入。**生产代码中 `PageSize` 必须 `{ get; set; }`**。
3. **Query 参数名一致性**：`_PaginationPartial` 用 `pageSize`/`pageIndex`，但 UserPanel 用 `uSize`/`uPage`——partial 是 8 页共享，query 名必须统一。**修复方案：双 BindProperty 别名**，保留向后兼容。
4. **审计必须端到端**：v2.13.71 partial 上线时只审计了「partial 渲染 + URL 生成」，**没有审计 PageModel 是否从 URL 读取 pageSize**——这是典型的「代码层正确 ≠ 数据层正确」。

### 6.2 防御性编程

建议添加 **`_PaginationPartial` 使用审计脚本**：

```bash
# 任何包含 _PaginationPartial 的页面，PageModel 必须有 [BindProperty(SupportsGet=true)] int PageSize
for f in $(grep -rl '_PaginationPartial' DormManage.Admin/Pages/); do
    cshtml="${f%.cshtml}.cshtml.cs"
    grep -q '\[BindProperty(.*SupportsGet.*true.*)\].*\n.*public int PageSize' "$cshtml" || echo "MISSING: $cshtml"
done
```

### 6.3 强制检查清单（PR Review 自检）

任何修改列表页 PageModel 的 PR，必须确认：

- [ ] `PageIndex` 属性前有 `[BindProperty(SupportsGet = true)]`
- [ ] `PageSize` 属性前有 `[BindProperty(SupportsGet = true)]`（**本次 BUG 修复点**）
- [ ] `PageSize` 属性必须是 `{ get; set; }`（非 `{ get; }` 只读）
- [ ] `OnGetAsync` 中调用 service 时传 `PageSize`（非硬编码 `20`）
- [ ] `_PaginationPartial` 传参用 `Model.PageIndex/Model.PageSize`（非 `Model.Result.PageSize`）

违规 grep：
```bash
# 找出所有 PageSize 属性声明，缺少 BindProperty 的即 BUG
grep -rEn 'public int PageSize \{ get' DormManage.Admin/Pages/  # 应为 0 命中
grep -rEn 'public int PageSize \{ get; set;' DormManage.Admin/Pages/ | grep -v 'BindProperty'  # 应为 0 命中
```
