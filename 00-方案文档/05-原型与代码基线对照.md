## 8.3 v2.11.4 首页 KPI 卡片横向布局 (2026-07-11)

> **问题**：首页 7 个 KPI 统计卡片使用 Bootstrap Grid (`col-6 col-lg-2`)，在大屏幕上第 7 个卡片会换行，无法在一行显示。

**修复方案**：
- 使用 `flex` 横向布局替代 Grid 布局
- 使用 `flex: 1 1 auto` 让卡片自动拉伸占满宽度
- 设置 `min-width` 和 `max-width` 限制卡片宽度范围
- 支持横向滚动（当卡片总宽度超出屏幕时）

**修复前**：
```html
<div class="row g-3 mb-3">
    <div class="col-6 col-lg-2"><!-- KPI 1 --></div>
    <!-- ... 7 个卡片，第 7 个会换行 -->
</div>
```

**修复后**：
```html
<div class="kpi-row mb-3">
    <div class="kpi-card"><!-- KPI 1 --></div>
    <!-- ... 7 个卡片横向排列，自动拉伸占满宽度 -->
</div>
```

**CSS 样式**：
```css
.kpi-row {
    display: flex;
    flex-wrap: nowrap;
    gap: 12px;
    overflow-x: auto;
}
.kpi-card {
    flex: 1 1 auto;  /* 允许拉伸 */
    min-width: 140px;
    max-width: 220px;
}
```

**响应式断点**：
| 屏幕宽度 | 卡片行为 |
|---------|---------|
| < 768px | 宽度 120-160px，保持滚动 |
| 768-1400px | 宽度 140-220px，自动拉伸 |
| 1400-1600px | 宽度 180-280px，字号增大 |
| > 1600px | 等宽分布，宽度自动调整 |

**修复状态**：✅ 完成

**入住率排名数据计算逻辑**：
```javascript
// 数据来源：DORMS (宿舍表) + PERSONNEL (人员表)
// 过滤条件：只统计 isActive=true (已启用) 的宿舍
// 计算公式：入住率 = (当前入住人数 / 宿舍容量) × 100%
// 入住人数 = PERSONNEL 中 dormCode 等于该宿舍代码 且 status=1(在职) 的人数
// 排序：由小到大排序，取前20条

occData = DORMS
    .filter(d => d.isActive && d.capacity > 0)  // 只统计已启用的宿舍
    .map(d => {
        const currentResidents = PERSONNEL.filter(
            p => p.status === 1 && p.dormCode === d.dormCode
        ).length;
        const rate = Math.round((currentResidents / d.capacity) * 100);
        return { code: d.dormCode, rate: rate };
    })
    .sort((a, b) => a.rate - b.rate)  // 由小到大排序
    .slice(0, 20);
```

### 13.2 数据流

```
[BOOKINGS 表]
  │
  │  type=1 入住 + status=2 在宿    → 已住宿（LODGED） + dormCode 更新
  │  type=2 退房 + status=3 已退房  → 未住宿（NOT_LODGED） + dormCode 清空
  │  status=4 已取消                → 忽略（无效记录）
  │  status=1 预约                  → 忽略（未生效）
  ↓
[getLatestValidBooking(empId)]
  │  按 registrationDate 倒序，取最近一条有效记录
  ↓
[getResideStatusCode(p)]    → 'LODGED' | 'NOT_LODGED' | 'PENDING'  (ResidenceStatus.code)
[getResideStatus(p)]        → '已住宿' | '未住宿' | '待入住'    (ResidenceStatus.name)
[getLatestDormCode(p)]      → dormCode | null
```

### 13.4.1 v2.11.6 办理登记→人员清单联动更新规则（完整）

> **核心原则**：办理登记（BOOKINGS）所有操作必须在事务内同步更新对应人员的 `DormCode` 和 `住宿状态`。

| 办理登记操作 | BOOKINGS 变更 | PERSONNEL DormCode 变更 | PERSONNEL 住宿状态变更 | 异常处理 |
|---|---|---|---|---|
| **入住登记** | 新增 type=1, status=2 | 设为新房号 | 已住宿（LODGED） | 更新失败→提示"入住登记失败，宿舍房号同步异常"，回滚事务 |
| **退房登记** | 更新 type=2, status=3 | 清空（null） | 未住宿（NOT_LODGED） | 更新失败→提示"退房办理失败，宿舍房号同步异常"，回滚事务 |
| **预约** | 新增 type=1, status=1 | 不变 | 不变（待入住 PENDING） | 仅 BOOKINGS 写入，不涉及 DormCode |
| **撤销退房** | 恢复 status=3→2 | 恢复原房号 | 已住宿（LODGED） | 更新失败→提示"撤销退房失败，宿舍房号同步异常"，回滚事务 |
| **撤销入住** | 变更 status=2→4 | 清空（null） | 未住宿（NOT_LODGED） | 更新失败→提示"撤销入住失败，宿舍房号同步异常"，回滚事务 |
| **取消预约** | 变更 status=1→4 | 不变 | 不变（无效） | 仅 BOOKINGS 写入，不涉及 DormCode |

> **v2.11.6 新增**：所有涉及 DormCode 同步的操作，必须使用事务包裹（`Database.BeginTransactionAsync()`）。若 `SaveChangesAsync()` 抛出异常，需捕获并返回用户友好的错误提示，不直接暴露原始异常。

### 13.5 v2.12.8 概念区分（关键深度统一）

> ⚠️ **v2.12.8 深度理解**：项目里涉及"住宿/在宿"概念的有 3 类，**必须严格区分**：

| 概念 | 数据源 | 选项值 | 用途 |
|------|--------|--------|------|
| **住宿状态** | 基础资料 `RESIDENCE_STATUS` 字典 | LODGED=已住宿 / NOT_LODGED=未住宿 / PENDING=待入住 | 人员维度的派生属性（人员清单等） |
| **办理登记流水状态** | BOOKINGS.Status 字段 | 1=预约 / 2=在宿 / 3=已退房 / 4=已取消 | 单条办理记录的状态（办理登记模块） |
| **住宿记录状态** | RESIDENCIES.Status 字段（旧版） | 1=在宿 / 2=已退宿 / 3=调宿中 | 旧版住宿记录表（v2.10 已弃用，由 BOOKINGS 替代） |

### 13.6 v2.12.6 字典映射表（基础资料 RESIDENCE_STATUS）

### 13.7 住宿状态取值规则（单一数据源）

```
住宿状态 (基础资料 RESIDENCE_STATUS)
  ↑ 单一数据源：getResidenceStatusCode(p) 函数
  │
  │ 根据 BOOKINGS 最后有效记录派生：
  │
  ├─ BOOKINGS 无记录          → NOT_LODGED（未住宿）
  ├─ BOOKINGS.Status=4 已取消 → NOT_LODGED（未住宿）
  ├─ BOOKINGS.Status=1 预约   → PENDING（待入住）
  ├─ BOOKINGS.Status=2 在宿   → LODGED（已住宿）
  └─ BOOKINGS.Status=3 已退房 → NOT_LODGED（未住宿）
```
