# v2.13.180 — 字段权限清单全量扩展（5 → 15 字段）

**日期**：2026-07-26
**核心变更**：将所有主菜单导航列表中涉及的 PII 字段全部纳入字段权限管理

---

## 一、需求背景

用户原话：
> 字段权限管理 增加 所有 主菜单导航 列表的字段 都 成为 字段权限管理 的被选项

### 原状（v2.13.92 - v2.13.179）
- 仅 **5 个** SysFieldPermission 种子字段（employee.realname/phone/employeecode/dormcode/remark）
- 只覆盖 Personnel 模块的 5 个核心字段
- 其他主菜单（Booking/Dorms/Meter/EmployeeBilling）的 PII 字段无字段级权限保护

### 新版（v2.13.180）
- 扩展到 **15 个** PII 字段
- 覆盖全部 5 个主菜单列表：Personnel / Booking / Dorms / Meter / EmployeeBilling
- 与 v2.13.176 deny-by-default 联动：未勾选「允许显示隐私字段」的角色看不到所有 15 个字段

## 三、核心改动

### 3.1 DormDbContext.cs（HasData seed）

**5 字段 → 15 字段**：按 FieldKey 唯一性判断（v2.13.131 模式）+ 不指定 Id（IDENTITY 自动分配）

```csharp
// Personnel 5 字段
new SysFieldPermission { Id = 1, FieldKey = "employee.realname", ... }
new SysFieldPermission { Id = 2, FieldKey = "employee.phone", ... }
new SysFieldPermission { Id = 3, FieldKey = "employee.employeecode", ... }
new SysFieldPermission { Id = 4, FieldKey = "employee.dormcode", ... }
new SysFieldPermission { Id = 5, FieldKey = "employee.remark", ... }
// Booking 5 字段
new SysFieldPermission { Id = 6,  FieldKey = "booking.realname", ... }
... (Id 7-10)
// Dorms 1 字段
new SysFieldPermission { Id = 11, FieldKey = "dorm.address", ... }
// Meter 1 字段
new SysFieldPermission { Id = 12, FieldKey = "meter.operator", ... }
// EmployeeBilling 3 字段
new SysFieldPermission { Id = 13, FieldKey = "billing.realname", ... }
new SysFieldPermission { Id = 14, FieldKey = "billing.employeecode", ... }
new SysFieldPermission { Id = 15, FieldKey = "billing.dormcode", ... }
```

### 3.2 DatabaseInitializer.cs（启动迁移 SQL）

```csharp
// v2.13.180：扩展到 15 字段（IF NOT EXISTS + FieldKey 唯一性）
var fieldsSql = @"-- Personnel 5 字段
                   IF NOT EXISTS (SELECT 1 FROM [dbo].[SysFieldPermission] WHERE FieldKey = N'employee.realname')
                       INSERT INTO [dbo].[SysFieldPermission] ...
                   ...
                   -- Booking 5 字段 + Dorms 1 字段 + Meter 1 字段 + EmployeeBilling 3 字段
                   ...";

// 期望数量 5 → 15
const int expectedFieldPermCount = 15;
```

## 六、部署后行为

### 全新安装
- 启动 → `DatabaseInitializer.MigrateFieldPermissionAsync` → 检测到表不存在 → 创建 + 插入 15 条 seed
- `Settings → 字段权限` 页面：显示 15 行可勾选字段

### 升级部署（v2.13.179 → v2.13.180）
- 启动 → `MigrateFieldPermissionAsync` 检测 → 表已存在
- 走 `IF NOT EXISTS (WHERE FieldKey = '...')` 幂等模式
- 已存在的 5 字段 → 跳过；不存在的 10 字段 → 自动补齐
- `Settings → 字段权限` 页面：显示 15 行（5 原有 + 10 新增）

### 启用规则（v2.13.176 deny-by-default 联动）
- 默认 admin 已勾选「允许显示隐私字段」权限 → 看得到全部 15 字段
- 其他角色（财务/访客/操作员）：未勾选 → 全部 15 字段被隐藏（`d-none` 整列 + 值显示 `***`）

## 七、永久教训

1. **种子数据必须随需求演进**——v2.13.92 起步 5 字段是够用，v2.13.180 业务扩展到 5 个模块后才需要 15 字段
2. **按 FieldKey 唯一性判断比硬编码 Id 更安全**（v2.13.131 经验复用）——新字段插入不依赖 IDENTITY 顺序
3. **种子数据同步 UI 提示文本**——「5 → 15 字段」文案必须随种子数同步更新
4. **完整性检查 expectedFieldPermCount 必须同步**——否则 banner 会显示「预期 X/实际 X 但 X 不对」的提示
5. **deny-by-default 与字段全量扩展协同**——v2.13.176 deny-by-default 是 v2.13.180 全量扩展的前提；没有 deny-by-default，扩展 15 字段无意义（用户全能看到）
