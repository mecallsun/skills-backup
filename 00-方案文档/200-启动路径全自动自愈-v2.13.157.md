# 启动路径全自动自愈（用户零操作自愈）— v2.13.157

> **日期**：2026-07-25
> **类型**：用户体验改进（自动自愈机制）
> **前置**：[199 启动路径解析修复 v2.13.156](../方案文档/199-启动路径解析修复-v2.13.156.md)（提供了 fallback，但用户仍需手动运行 `reset-tray-config.ps1`）
> **改动文件**：`DormManage.TrayApp/Services/ConfigService.cs`（`AutoHealPathsIfInvalid` 47 行 + `TryFindExeUnderBase` 共享探测）+ `DormManage.TrayApp/Services/ProcessManager.cs`（`TryResolveExePath` 改用共享探测 + `HandleCrashAsync` 加 reload 触发自愈）

## 一、用户需求

> 「请设计一个方法让程序自动处理这些问题，不需要人工处理~！」

**目标**：v2.13.156 已经支持运行时 fallback，但 `appsettings.json` 中的失效路径**永远不会被自动修正**——下次启动还得重新探测。用户期望「**全自动、零操作自愈**」：程序启动时若检测到路径失效，自动修正配置 + 反哺持久化，下次启动直接正确启动，**整个过程用户无感**。

## 二、自动自愈架构

```
用户复制 publish-final/ 到新机器
                ↓
     启动 TrayApp.exe
                ↓
     ConfigService.Load()
                ├── 文件不存在 → 写出默认
                ├── JSON 损坏 → 备份 + 默认
                └── JSON 合法 + 路径失效 ↓
                      AutoHealPathsIfInvalid()
                          ├── 探测 9 候选路径
                          ├── 找到 → 反哺写入 appsettings.json
                          └── 找不到 → ERROR 日志（指明缺哪个 exe）
                ↓
       Api/Admin 正常启动 ✅
                ↓
       下次启动：AUTO-HEAL 不再触发（路径已正确）
```

## 三、实现细节

### 3.1 `ConfigService.AutoHealPathsIfInvalid()`

每次 `Load()` 成功后**自动调用**：
1. 检查 `ApiExecutable` / `AdminExecutable` 路径是否存在（用 `Path.Exists`）
2. 若失效，调用共享候选探测 `TryFindExeUnderBase(exeName)` 找正确路径
3. **找到了 → 直接 `_current` 修改 + `SaveUnlocked()` 写回**（反哺持久化）
4. 找不到 → `[ERROR]` 日志提示用户「请确认 Api/ 或 Admin/ 子目录存在」

### 3.2 `ConfigService.TryFindExeUnderBase(exeName)` 单源真相

与 `ProcessManager.TryResolveExePath` 共用同一组候选路径，**避免双份实现漂移**。按优先级探测 9 路径：自身目录 / Api 子目录 / Admin 子目录 / 兼容旧 `..\Api\` / 父目录 dev 模式 / 工作目录兜底。

### 3.3 `ProcessManager.HandleCrashAsync()` 自动 reload

每次子进程崩溃自动重启前，**手动调用 `ConfigService.Load()`** 触发一次自愈检查——确保路径被外部改动后下次重启能立即纠正。

### 3.4 用户反馈机制

`[WARN] [AUTO-HEAL] ApiExecutable='Z:/NonExistent/...' 路径失效 → 自动修复为 '...\publish-final\Api\DormManage.Api.exe'（无需用户操作）`

## 六、永久教训

| # | 教训 |
|---|------|
| 1 | **「运行时 fallback」≠「配置自愈」**。v2.13.156 让启动成功，但下次还得重探测；v2.13.157 把探测结果反哺到配置文件，一劳永逸。 |
| 2 | **「自动检测 + 自动修复 + 持久化」是用户体验闭环三件套**。仅检测不修复 → 用户要操作；仅修复不持久化 → 每次都得修。缺一不可。 |
| 3 | **「单源真相原则」消除实现漂移**。`ProcessManager.TryResolveExePath` 与 `ConfigService.TryFindExeUnderBase` 必须共用同一份候选路径列表——否则两处逻辑漂移，自愈与启动对不上。 |
| 4 | **「用户可见的日志」是用户信任的来源**。`[WARN] [AUTO-HEAL] xxx（无需用户操作）` 把「我在做什么」告诉用户，即使他什么都不用做也能安心。 |
| 5 | **「容错机制必须可降级」**。即使自愈失败也要 ERROR 日志告知用户怎么修，而不是静默失败——「找不到 Api/ 或 Admin/ 子目录」明确指引排查方向。 |
