## 1. 并发竞态修复（选床/入住超容）— 已修复并验证

### 1.1 根因
`BookingService.CheckInAsync/ConfirmCheckInAsync/UndoCheckOutAsync` 均为 **check-then-act**：先 COUNT 在宿/预约数算余量，再插入/改状态，**无事务、无锁、无隔离**。两管理员同秒办理可双双读到余量>0 并同时写入 → 超容。

### 1.2 修复
新增 `InSerializableTxAsync` 助手：经**执行策略**包裹（兼容 `EnableRetryOnFailure`，死锁 1205 自动重试）→ `IsolationLevel.Serializable` 事务 → `ChangeTracker.Clear()` 保证重试干净 → 成功提交/失败自动回滚。三处容量敏感方法全部包裹。SQL Server 下 SERIALIZABLE 的范围锁阻止幻读插入，实现真正串行化。

### 1.3 附带发现并修复的真实缺陷
并发测试触发 `不能将 NULL 插入 DormBooking.UpdatedAt`：真实多表 `UpdatedAt NOT NULL DEFAULT(GETDATE())`，但 EF 对新实体的 `UpdatedAt=null` **显式写 NULL** → **任何入住插入在 SQL Server 都会失败**（此前 SQLite 下 UpdatedAt 可空未暴露）。修复：DbContext 重写 `SaveChanges/SaveChangesAsync`，对 `BaseEntity` 新增补 `CreatedAt/UpdatedAt`、修改刷新 `UpdatedAt`。

### 1.4 验证（真实 SQL Server + 并发测试工具 tests/RaceTest）
