## 1. 系统架构总览

### 1.1 解决方案结构（4 个项目）

```
DormManage.sln (.NET 8 SDK)
│
├── DormManage.Shared        ← 类库（EF Core 实体 + DbContext + 业务服务 + DTO + IPC）
├── DormManage.Api           ← REST API（Kestrel: 5100）+ Swagger
├── DormManage.Admin         ← Razor Pages UI（Kestrel: 5001）+ Cookie Auth + 嵌入式 API 客户端
└── DormManage.TrayApp       ← WinForms 托盘守护（进程管理 + 健康检查 + IPC 服务端 + 自动启停）
```

**辅助项目**：`DormManage.Tools.GenderBackfill`（一次性数据修复工具）

### 1.2 端口分配

| 服务 | 端口 | 协议 | 用途 |
|------|------|------|------|
| **DormManage.TrayApp** | **5099**（IPC） | TCP（JSON-over-lines） | 托盘进程 ↔ Admin/Api 子进程 |
| **DormManage.Api** | **5100** | HTTP（REST + Swagger） | PDA 终端、外部系统集成、Web Api 调用方 |
| **DormManage.Admin** | **5001** | HTTP（Razor Pages + 内嵌 API 调用） | 浏览器访问、Web 管理界面 |

**端口来源**：
- IPC 端口 `5099`：硬编码于 `DormManage.Shared/Services/ServiceIpc.cs:32` `public const int DefaultPort = 5099`
- Api 端口 `5100`：托盘 `appsettings.json` `Tray.ApiPort` + Api `appsettings.json` `Urls: http://0.0.0.0:5100`
- Admin 端口 `5001`：托盘 `appsettings.json` `Tray.AdminPort` + Admin `appsettings.json` `Urls: http://0.0.0.0:5001`

### 1.3 进程模型（v2.13.155 托盘托管守卫 + v2.13.72 进程唯一锁）

```
┌─────────────────────────────────────────────────┐
│ DormManage.TrayApp.exe                          │ ← 唯一入口
│ ┌──────────────────────────────────────────┐    │
│ │ TrayAppContext                           │    │
│ │ ├─ ProcessManager（启动/停止子进程）      │    │
│ │ ├─ HealthChecker（10s 心跳）             │    │
│ │ ├─ ConfigService（动态加载 appsettings）│    │
│ │ ├─ AutoStartManager（清理自启项）        │    │
│ │ ├─ ServiceIpc（127.0.0.1:5099 服务端）  │    │
│ │ └─ TrayLaunchGuard（HMAC 签名握手）     │    │
│ │     ↓                                     │    │
│ │     ├─→ DormManage.Admin.exe :5001      │    │ ← 浏览器（Web 端）
│ │     │   携带 DormManage_TRAY_HANDSHAKE  │    │
│ │     └─→ DormManage.Api.exe :5100        │    │ ← PDA + 集成
│ │         携带 DormManage_TRAY_HANDSHAKE  │    │
│ └──────────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
```

**v2.13.72 进程唯一性保护**：
- `Global\DormManage.TrayApp.SingleInstance.v2`
- `Global\DormManage.Admin.SingleInstance.v1`
- `Global\DormManage.Api.SingleInstance.v1`

**v2.13.155 托盘托管守卫**：Admin/Api 必须由托盘拉起（HMAC-SHA256 签名 + NtQueryInformationProcess 父进程校验），否则 `[TRAY-GUARD]` 拒绝启动。

### 1.4 IPC 通信（v2.13.137 注册校验依赖反转）

**协议**：TCP `127.0.0.1:5099` JSON-over-lines（一行一个 JSON 命令）

**核心命令**（ServiceIpc.cs）：
- `getregstate` — 注册状态查询（Admin/Api 子进程 → 托盘，30s 轮询）
- `getconfig` — 动态配置查询（热加载 DB 配置）
- `restart` — 重启子进程
- `stop` — 停止服务

**托盘唯一权威**：注册校验/配置/运行状态由托盘决定，子进程通过 IPC 拉取，不直接调用底层 API。

### 3.3 终端 2：PDA 设备（Api :5100）

**PDA 控制器**（`DormManage.Api/Controllers/Pda/`）：

| 控制器 | Route | 主要端点 |
|--------|-------|---------|
| **PdaController** | `api/v1/pda` | `POST upload`（抄表上传）/ `GET image/*`（图片下载）/ `GET coverage`（覆盖率） |
| **AppVersionController** | `api/v1/appversion` | `GET list` / `GET latest` / `GET {id}` / `POST` / `POST {id}/enable` / `GET {id}/download` / `POST generate-placeholder` |

**PDA 端点清单**（关键）：

```
POST /api/v1/pda/upload            # 抄表上传（图片 + 读数 + 房号 + 抄表员 + 设备 SN）
GET  /api/v1/pda/image/{path}     # 图片下载（透明转发到文件系统）

GET  /api/v1/appversion/list      # 版本列表
GET  /api/v1/appversion/latest    # 最新版本
POST /api/v1/appversion           # 新增版本（管理端）
POST /api/v1/appversion/{id}/enable  # 启用版本
GET  /api/v1/appversion/{id}/download  # 下载 APK 包
POST /api/v1/appversion/generate-placeholder  # 生成占位版本（开发用）
```

**认证方式**：PDA 鉴权 = `RegisterSdk.CheckReg()`（v2.13.137 依赖反转后由托盘权威 + `X-Machine-SN` header 标识）

**存储位置**：
- 图片：`%ProgramData%\JINGE\DormManage\images\`（v2.13.180 路径前缀 + dormCode 子目录）
- 路径通过 `DormManage_IMAGE_ROOT` 环境变量可覆盖（托盘注入）

**支持的设备类型**：Android PDA（采集抄表数据）+ Web PDA（备用）

**入口**：`http://localhost:5100/swagger/index.html`

**启用配置**：所有环境启用（**不**仅 `IsDevelopment()`）

### 3.7 终端 6：Windows 服务（**未实现**）

当前架构下：
- 托盘 + Admin + Api 都是**桌面进程**（Kestrel 自托管）
- **不支持** Windows Service 注册
- 服务注册功能（`/System/Services/Register`）只清理第三方自启项，**不安装为 Windows 服务**

**未来扩展点**：如需改为 Windows Service，需重构 `Program.cs`（top-level statements）支持 `UseWindowsService` 扩展。

## 4. 中间件与安全

### 4.1 关键中间件

| 中间件 | 位置 | 职责 |
|--------|------|------|

### 5.2 启动流程

```

5. 浏览器访问 Admin → Cookie 登录 → 调用内嵌 Api 客户端 → 访问 Api :5100
```
