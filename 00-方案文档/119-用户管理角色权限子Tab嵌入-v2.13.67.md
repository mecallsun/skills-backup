## 八、教训总结

### 8.1 关键教训

1. **「嵌入 vs 跳转」的用户体验** — 引导卡跳独立页面是技术债务解决方式（独立 PageModel 实现 CRUD 更简单），但用户体验割裂。当用户期望「点 Tab 看到内容」时，必须**嵌入而不是引导**。partial view + partial class 是 Razor Pages 的标准嵌入模式。
2. **Handler 命名空间隔离** — 多 panel 共享 IndexModel 时，handler 命名必须带前缀（UserCreate / RoleCreate）避免冲突。这是 Razor Pages `OnPost{Name}Async` 模式的硬约束。
3. **Antiforgery token 共享** — partial view 不能重复注入 antiforgery token，必须由父页面（Index.cshtml）一次性注入，partial view 中的 form 通过 `data-bs-toggle="modal"` 触发的 JS 读取同一份 token。
4. **partial view 不能定义 @section Scripts** — partial view 中的 JS 必须由父页面的 @section Scripts 统一管理，或通过 `<script>` 内联。本方案中 User + Role 的 JS 都放在 Index.cshtml 的 Scripts section。

### 8.2 强制检查清单（菜单重组自检）

- [ ] 旧独立路由物理删除（`/Settings/User` + `/Settings/Role` 返回 404）
- [ ] 「独立页面」「进入 X」等引导文案全局 grep = 0 命中
