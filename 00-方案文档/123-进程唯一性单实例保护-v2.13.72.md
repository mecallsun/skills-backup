## 三、实施方案

### 3.1 核心机制（Win32 全局命名 Mutex）

使用 .NET 标准 `System.Threading.Mutex` + 全局命名（`Global\` 前缀）：

```csharp
using var _singleInstanceMutex = new System.Threading.Mutex(
    initiallyOwned: true,
    name: @"Global\DormManage.XXX.SingleInstance.v1",
    createdNew: out bool createdNew);

if (!createdNew)
{
    // Mutex 已被其他进程占用 → 自动终止
    Console.Error.WriteLine("[SINGLE-INSTANCE] XXX 已在运行中...");
    Thread.Sleep(2000); // 让用户看到提示
    return; // top-level return 退出 Main
}
```

**关键设计点**：

| 点 | 解释 |
|----|------|
| **`using var`** | Mutex 在 Main 方法退出时自动 Dispose（进程生命周期 = Main 生命周期，因为 `app.Run()` 阻塞至主机停止）|
| **`Global\` 前缀** | 全局命名空间，跨 Windows 用户会话唯一（避免 session 0 / session 1 隔离） |
| **`initiallyOwned: true`** | 创建时立即尝试获取锁；`createdNew` 参数返回 Mutex 是否为本进程新建 |
| **top-level `return`** | Mutex 检查失败时直接退出 Main，跳过 `WebApplication.CreateBuilder` 与 `app.Run()` — 比 `IHostedService` 守卫更早拦截，避免其他 hosted service（如 DB 清理）在守卫检测冲突时已经启动 |
| **2 秒延迟 + `Console.Error`** | 让用户在控制台或日志中清晰看到冲突信息（窗口模式用户能看到） |

### 3.2 为何不采用 `IHostedService` 守卫？

`.NET 8 BackgroundService.StartAsync` 立即返回（实际工作 `ExecuteAsync` 在后台 Task 跑），意味着：
- `IHostedService` 守卫触发 `StopApplication()` 后，**后续 hosted service（如 `DataCleanupHostedService`）仍会启动并执行**
- 若 DB 清理等服务正在跑，突然停止会留下半成品状态

**top-level statements 同步检查** → 在 `WebApplication.CreateBuilder` 之前完成 mutex 检测 → 失败立即 `return`，host 完全不构建 → 100% 阻止多实例副作用。

### 3.3 命名规范

```
Global\DormManage.{AssemblyName}.SingleInstance.v{MajorVersion}
```

| 项目 | Mutex 名称 |
|------|----------|
| DormManage.TrayApp | `Global\DormManage.TrayApp.SingleInstance.v2` |
| DormManage.Admin | `Global\DormManage.Admin.SingleInstance.v1` |
| DormManage.Api | `Global\DormManage.Api.SingleInstance.v1` |

`v1` / `v2` 后缀用于在破坏性升级时强制清理旧版本残留 mutex（升级前可手动执行 `taskkill /F /IM DormManage.*.exe` 清理）。

## 九、教训

### 9.1 关键教训

1. **`using var` 在 top-level 语句中横跨整个进程生命周期**：`app.Run()` 阻塞 Main，Main 退出时 `_singleInstanceMutex` 才 Dispose，完美覆盖 mutex 持有需求。
2. **`IHostedService` 守卫 ≠ 早期拦截**：BackgroundService.StartAsync 立即返回，其他 hosted service 仍会启动；top-level 同步检查是更可靠的早期拦截方式。
3. **`Global\` 前缀不可省略**：跨 Windows 用户会话（Terminal Services / RDP）必须用 `Global\` 才能跨用户检测到同一 mutex；否则不同 session 各自认为自己是唯一。
4. **Mutex 名称带版本号**：未来 v2.13.x → v3.0.0 时如 mutex 机制破坏性变更，可用版本号区分（如 `v1` → `v2`），强制清理旧版本残留。

### 9.2 防御性编程

- ✅ 失败时 `Thread.Sleep(2000)`：用户能看到控制台输出（否则进程瞬时退出，看不到提示）
- ✅ 失败时输出**残留进程清理指引**（"任务管理器结束 DormManage.X 进程"）：降低用户困惑
- ✅ 成功时 stdout 输出 `[SINGLE-INSTANCE] 进程唯一锁已获取`：运维可通过日志确认守卫生效
