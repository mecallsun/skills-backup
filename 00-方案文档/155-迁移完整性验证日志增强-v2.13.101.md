## 一、问题

**用户反馈**：
> 在权限矩阵中，角色定义时人员清单权限清单没有显示"新建"按钮的权限项？为什么勾选的权限控制项没有生效？

**根因分析结论**：
- v2.13.100 已修复 `DatabaseInitializer.MigrateFieldPermissionAsync` 中 SysPermission Id=40 (`personnel:add`) + SysRolePermission Id=61 seed 缺失问题
- **代码层无缺陷**，`_RolePanel.cshtml` + `RolePanelPartial.LoadRolePanelAsync` 能正确遍历并渲染 Id=40
- 但 MigrateFieldPermissionAsync 整体被 try/catch 包裹，失败仅 `LogError` 不抛出
- 用户部署后若迁移失败，无任何可见提示

---

## 二、根本原因（部署态）

| # | 可能原因 | 概率 |
|---|---------|------|
| 1 | Admin 未重启 → `DatabaseInitializer.InitializeAsync` 未执行 | 高 |
| 2 | 数据库文件不一致：Admin 连接了一份 DB，TrayApp 连接了另一份 | 高 |
| 3 | `ExecuteSqlRawAsync` 静默失败（如外键约束、列缺失）但 try/catch 吞错 | 中 |
| 4 | 浏览器缓存未硬刷 | 中 |
| 5 | SysPermission.Id=40 的 ParentId 被手工 SQL 误改为非 9 | 低 |

**共性**：所有失败场景下，运维/用户**无任何启动日志可见**。

## 三、修复（v2.13.101）

### 3.1 `DatabaseInitializer.MigrateFieldPermissionAsync` 末尾增加「迁移完整性验证段」

迁移完成后主动 SELECT 关键 Id 的实际状态，缺失项输出 WARNING 日志，让运维启动时立即看到迁移完整性。

```csharp
// v2.13.101 新增：验证迁移完整性
var requiredPermIds = new[] { 37, 38, 39, 40 };
var requiredRpIds   = new[] { 58, 59, 60, 61 };

var presentPerms = await db.Database.SqlQueryRaw<int>(
    "SELECT Id FROM SysPermission WHERE Id IN (37,38,39,40)").ToListAsync(ct);
var presentRps = await db.Database.SqlQueryRaw<int>(
    "SELECT Id FROM SysRolePermission WHERE Id IN (58,59,60,61)").ToListAsync(ct);
var fieldPermCount = await db.SysFieldPermissions.CountAsync(ct);

var missingPerms = requiredPermIds.Except(presentPerms).ToList();
var missingRps   = requiredRpIds.Except(presentRps).ToList();

if (missingPerms.Count == 0 && missingRps.Count == 0 && fieldPermCount >= 5)
{
    logger.LogInformation("[v2.13.101 Verify] 隐私字段权限迁移完整性检查通过：SysPermission 4/4、SysRolePermission 4/4、SysFieldPermission {N}/5", fieldPermCount);
}
else
{
    if (missingPerms.Count > 0)
        logger.LogWarning("[v2.13.101 Verify] SysPermission 缺失 {Ids}（personnel:add=40 / privacy:field:enable=39 等）", string.Join(",", missingPerms));
    if (missingRps.Count > 0)
        logger.LogWarning("[v2.13.101 Verify] SysRolePermission 缺失 {Ids}（admin→personnel:add=61 等）", string.Join(",", missingRps));
    if (fieldPermCount < 5)
        logger.LogWarning("[v2.13.101 Verify] SysFieldPermission 仅 {N}/5 行，字段权限清单不完整", fieldPermCount);
    logger.LogWarning("[v2.13.101 Verify] ⚠ 迁移不完整！请检查：(1) Admin 是否已重启触发 DatabaseInitializer.InitializeAsync；(2) 数据库连接字符串是否指向预期文件；(3) 启动日志是否有错误");
}
```

## 六、用户侧排查清单

### 6.1 启动后查看日志（v2.13.101 部署）

1. **看到「Verify 检查通过」日志** → 迁移完整，问题不在 DB
2. **看到「Verify ⚠ 迁移不完整」日志** → DB 确实有缺失
   - 检查 Admin 是否真的重启过
   - 检查数据库连接字符串（Settings → 数据库连接）
   - 检查 TrayApp 与 Admin 是否连接相同 DB 文件

### 6.2 UI 侧确认

```sql
-- 在用户 DB 上执行
SELECT COUNT(*) FROM SysPermission;       -- 期望 40
SELECT COUNT(*) FROM SysRolePermission;  -- 期望 ≥32
SELECT COUNT(*) FROM SysFieldPermission; -- 期望 5
SELECT Id FROM SysPermission WHERE Id = 40;        -- 期望 1 行 personnel:add
SELECT Id FROM SysRolePermission WHERE Id = 61;    -- 期望 1 行 admin→40
```

如果 Id=40 不存在 → 重启 Admin（不是 TrayApp）触发迁移。

## 七、决策日志

| # | 决策 | 理由 |
|---|------|------|
| 1 | 在 Migrate 末尾添加验证段而非单独方法 | 复用同一 DbContext，避免重复连接 |
| 2 | 检查关键 Id 而非全表 Count | Count 不区分"内容是否正确"；Id 检查更精准 |
| 3 | 失败时输出 WARNING 而非 ERROR | 迁移不完整是部署态问题，不阻塞应用启动 |
| 4 | 给出排查建议（3 项） | 用户曾多次反馈不知如何修复，必须给明确诊断路径 |

## 八、教训（v2.13.101）

1. **静默失败是最危险的失败**：try/catch + LogError 是 90% 项目标配，但对运维/用户不可见。涉及数据迁移/补偿逻辑必须额外加完整性验证 + 明确日志。
2. **"看起来 OK"≠"实际 OK"**：v2.13.99/100 的 migrate 方法代码逻辑正确，但用户实际部署可能根本没跑（DB 文件不一致 / Admin 未重启）。必须主动 dump 验证报告。
3. **失败要给排查路径**：仅仅日志"WARNING 失败"对运维无帮助；必须列出可能原因 + 验证 SQL。
