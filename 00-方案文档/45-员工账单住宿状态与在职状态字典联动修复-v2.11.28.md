## 1. 修复背景

### 1.1 数据/逻辑关联现状

员工账单列表同时涉及两个相互独立的字典：

| 字典 | 来源字段 | 取值 |
|------|---------|------|
| `EMPLOYMENT_STATUSES`（基础资料-在职状态） | `PERSONNEL.employmentStatusId` | 1=在职 / 2=待入职 / 3=已离职 |
| `RESIDENCE_STATUS`（基础资料-住宿状态） | `BOOKINGS` 推导（`getResidenceStatusCode`） | LODGED / NOT_LODGED / PENDING |

交叉分布（v2.11.28 实测）：

| 在职状态 \ 住宿状态 | LODGED | NOT_LODGED | PENDING | 合计 |
|--------------------|--------|------------|---------|------|
| 在职（1）          | 467    | 0          | 1       | 468  |
| 待入职（2）        | 1      | 16         | 6       | 23   |
| 已离职（3）        | 0      | 1          | 0       | 1    |
| **合计**           | **468** | **17**    | **7**   | **492** |

### 1.2 问题诊断

| # | 文件 | 问题 | 严重程度 |
|---|------|------|---------|
| 1 | `employee-bills.html` | 缺少"在职状态"筛选下拉，无法按员工在职状态过滤账单 | 高 |

| 4 | `employee-bills.html` | `resetFilter()` 缺少新字段清理 | 低 |

## 2. 修复方案

### 2.1 新增"在职状态"筛选下拉（v2.11.28 新增）

**HTML 新增**（位置：员工类型与住宿状态之间）：
```html
<!-- ⑤ 在职状态：v2.11.28 新增（关联引用基础资料 EMPLOYMENT_STATUSES 字典）-->
<div class="filter-item">
    <label>在职状态</label>
    <select id="fEmpStatus" class="form-select">
        <option value="">全部</option>
    </select>
</div>
```

**JS 初始化（字典关联引用）**：
```javascript
// 5) 在职状态下拉（v2.11.28 新增）— 关联引用基础资料 EMPLOYMENT_STATUSES 字典
const fEmpStatus = document.getElementById('fEmpStatus');
if (fEmpStatus && typeof EMPLOYMENT_STATUSES !== 'undefined') {
    EMPLOYMENT_STATUSES.forEach(s => {
        const opt = document.createElement('option');
        opt.value = s.id;
        opt.textContent = s.name;
        fEmpStatus.appendChild(opt);
    });
}
```

### 2.2 部门下拉 value 改用 FK id（v2.11.28 修订）

**修复前**：
```javascript
DEPARTMENTS.forEach(d => {
    const opt = document.createElement('option');
    opt.value = d.name;  // ← 字符串（与 PERSONNEL.departmentId 不匹配）
    opt.textContent = d.name;
    fDept.appendChild(opt);
});
```

**修复后**：
```javascript
DEPARTMENTS.forEach(d => {
    const opt = document.createElement('option');
    opt.value = d.id;  // v2.11.28: 改为 FK 主键
    opt.textContent = d.name;
    fDept.appendChild(opt);
});
```

### 2.3 currentData() 同步更新筛选逻辑

**修复前**：
```javascript
const deptName = document.getElementById('fDept').value;
// ...
if (deptName) {
    data = data.filter(b => (b.department || '') === deptName);
}
```

**修复后**：
```javascript
// v2.11.28 修订：fDept.value 现为 DEPARTMENTS.id（FK），通过 getDepartmentName(id) 还原 name
const deptId = parseInt(document.getElementById('fDept').value) || null;
const deptName = deptId ? (typeof getDepartmentName === 'function' ? getDepartmentName(deptId) : null) : null;
// ...
if (deptName) {
    data = data.filter(b => (b.department || '') === deptName);
}

// v2.11.28 新增：在职状态筛选
const empStatusId = parseInt(document.getElementById('fEmpStatus').value) || null;
if (empStatusId) {
    data = data.filter(function (b) {
        var sid = getEmployeeEmploymentStatusId(b.employeeId);
        return sid === empStatusId;
    });
}
```

## 3. 字典联动规则（v2.11.28 强化）

### 3.1 员工账单字典联动矩阵

| 维度 | 数据源 | 关联方式 | 字典引用 |
|------|-------|---------|---------|
| 计费月份 | `EMPLOYEE_BILLS_202607.billingMonth` | 直接匹配字符串 | — |
| 部门 | `EMPLOYEE_BILLS.department` | 通过 `getDepartmentName(PERSONNEL.departmentId)` 还原 | `DEPARTMENTS` |
| 员工类型 | `PERSONNEL.employeeTypeId` | 通过 employeeId 关联 | `EMPLOYEE_TYPES` |
| 在职状态 | `PERSONNEL.employmentStatusId` | 通过 employeeId 关联 | `EMPLOYMENT_STATUSES` |
| 住宿状态 | `BOOKINGS` 最后有效记录 | 通过 employeeId 关联 PERSONNEL → getResidenceStatusCode | `RESIDENCE_STATUS` |
| 住宿房号 | `EMPLOYEE_BILLS.dormCode` | 直接匹配 | — |

### 3.2 历史账单在职状态筛选的语义选择（重要决策）

**问题**：员工已离职（status=3）后，历史月份的账单（2026-07）仍存在。按"账单生成时该员工的在职状态"还是"当前在职状态"筛选？

**规范选择**（v2.11.28 决策）：**按"当前在职状态"**（关联引用 PERSONNEL 实时状态）

**理由**：
1. 与住宿状态（`getResidenceStatusCode`）基于 BOOKINGS 最后记录保持一致（实时）
2. 避免引入"账单时点状态"复杂字段（如 `billGeneratedAtEmploymentStatus`）
3. HR 视角：已离职员工的账单归入"已离职"分组便于催收/清理

**应用结果**：v2.11.28 实测 1 条"已离职"员工的 2026-07 历史账单可在"在职状态=已离职"筛选下检索到。

### 3.3 字典关联引用规范（v2.11.28 强化版）

| 规则 | 说明 |
|------|------|
| R-DICT-01 | 字典访问必须使用 `typeof X !== 'undefined'` 守卫 |
| R-DICT-02 | 字典渲染必须遍历字典数组，禁止硬编码映射 |
| R-DICT-03 | 字典字段使用 `.find()` 提取，禁止直接索引 |
| R-DICT-04 | 字典修改必须同步所有引用页面 |
| R-DICT-05 | 新增字典项必须同步更新所有引用页面的初始化逻辑 |
| **R-DICT-06**（v2.11.28 新增）| **所有下拉筛选 value 一律使用 FK 主键（id），不混用字符串 name** |
| **R-DICT-07**（v2.11.28 新增）| **跨字典关联场景（如在职状态 ↔ 住宿状态）必须在文档中明确数据来源与联动规则** |
