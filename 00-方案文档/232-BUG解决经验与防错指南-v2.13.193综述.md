## 二、BUG 案例库（按发现顺序）

### BUG #1：隐私字段权限失效（v2.13.187）

**症状**：用户报告
> 在隐私字段管理清单中勾选了「宿舍档案」的「容量」「在住人数」字段；未授权角色仍能看到这些字段。

**调查路径**：
1. ✅ SysFieldPermission 表配置正确
2. ❌ Dorms/Index.cshtml 没有 `IsFieldHiddenAsync()` 调用
3. ❌ 没有隐私字段接线

**根因**：v2.13.180 扩展隐私字段到 21 个，但**只 seed 了 DB 数据，没有接线到 UI 页面**。

**教训**：
- ❌ **数据先行 ≠ UI 就绪**：seed 数据库 ≠ 隐私保护生效
- ✅ **强制规则**：每增加一个 `SysFieldPermission` 字段，必须 24h 内完成所有引用页面的接线

### BUG #2：发布目录双胞胎陷阱（v2.13.193）

**症状**：用户报告
> 在 /Dorms/Details 页面没有性别列，床位「床位 1」也没去掉。

**调查路径**（5 层深度）：
1. ✅ 源码有 Gender 修改（7 处）
2. ✅ DLL 时间戳是最新（16:01）
3. ❌ **真正运行的进程是从 `release/latest/TrayApp/Admin/` 加载的 DLL（09:50 旧版）**
4. ❌ 而我发布的是 `release/latest/Admin/`（16:01 最新）
5. **两套目录不一致**！

**根因**：TrayApp 用相对路径 `..\Admin\` 加载子目录，但发布脚本只更新 `release/latest/Admin/`，**没有同步到兄弟目录**。

**教训**：
- ❌ 发布路径 ≠ 运行路径
- ✅ **强制规则**：发布后必须使用 `sync_publish_to_trayapp.sh` 同步两个目录

### BUG #3：隐私字段语义反向（v2.13.193 核心修复）

**症状**：用户报告
> 行政助理角色（test）登录后，/Dorms 页面仍显示「容量」「在住人数」列。

**调查路径**（关键发现）：
1. ✅ `IsFieldHiddenAsync()` 调用链正确
2. ❌ **`HasPrivacyFieldEnabledAsync` 返回 true 给 test 用户**
3. ❌ **方向反了！** 用户应"deny-by-default"，但代码是"allow-by-default"

**根因**（v2.13.176 文档 vs 代码）：
- **文档说**：「不勾选 → 隐藏」deny-by-default
- **代码实现**：「不勾选 → 显示」allow-by-default

**v2.13.176 翻转从未实施**：文档先于代码，文档说"应该这样"，代码还是旧逻辑。

**修复**：
```csharp
// v2.13.193 修复
public async Task<bool> AllowDisplayPrivacyFieldsAsync(int userId)
{
    var codes = await GetUserPermissionCodesAsync(userId);
    return codes.Contains(PrivacyFieldPermissionCode);  // 勾选 → 返回 true
}

public async Task<HashSet<string>> GetHiddenFieldKeysAsync(int userId)
{
    // v2.13.176 deny-by-default：不勾选 → 隐藏所有
    if (!await AllowDisplayPrivacyFieldsAsync(userId))
    {
        var allActiveKeys = await _db.SysFieldPermissions
            .Where(p => p.IsActive)
            .Select(p => p.FieldKey)
            .ToListAsync();
        return new HashSet<string>(allActiveKeys);
    }
    // 勾选 → 不隐藏
    return new HashSet<string>();
}
```

**教训**：
- ❌ **文档先行于代码**导致 17+ 版本 BUG 潜伏
- ❌ **方法名模糊**（`HasPrivacyFieldEnabledAsync`）误导理解
- ✅ **强制规则**：任何「v2.13.x 翻转」必须同时改文档 + 代码 commit，不允许仅修改文档

### BUG #4：DLL 缺失类错误（v2.13.191 发现）

**症状**：Admin 启动后立即退出
```
System.TypeLoadException: Could not load type 'DormManage.Shared.Security.RuntimeWindowGuard'
```

**根因**：`DormManage.Shared.dll` 是旧版（09:50），缺少 `RuntimeWindowGuard` 类（v2.13.135 引入）。

**修复**：同步 Shared DLL 到所有子目录：
```bash
cp release/latest/Admin/DormManage.Shared.dll release/latest/TrayApp/Admin/
cp release/latest/Admin/DormManage.Shared.dll release/latest/TrayApp/Api/
```

**教训**：
- ❌ Shared DLL 不同步会导致 TypeLoadException
- ✅ **强制规则**：Shared DLL 必须所有子目录同步

### BUG #5：编辑回滚偷偷发生

**症状**：用户报告 BUG#3 时，发现源码中 `IsFieldHiddenAsync` 调用数为 0（git HEAD 也是 0）。

**根因**：之前 v2.13.187 的修复虽然做了 Edit 调用，但 git stash pop / git checkout 等操作可能**静默回滚修改**。

**教训**：
- ❌ **git 操作可能回滚工作**
- ✅ **强制规则**：每次修改后用 `git diff` 确认修改已保存

## 三、排查方法论（5 步法）

遇到"修改无效"类 BUG 时，按以下步骤排查：

### 步骤 1：源码层确认
```bash
# 检查源码是否包含修改
grep -c "新增字段" source.cs
# 应该是非零
```

### 步骤 2：编译层确认
```bash
# 编译并检查错误
dotnet build -c Release
# 必须 0 错误
```

### 步骤 3：发布时间戳确认
```bash
# 检查发布包 DLL 时间戳
stat -c '%y  %n' release/latest/TrayApp/Admin/DormManage.Admin.dll
# 应该是刚刚发布的最新时间
```

### 步骤 4：DLL 内容确认
```bash
# 检查 DLL 中是否包含特定字符串（注意 UTF-16 LE 编码）
python3 -c "
with open('path/to/dll', 'rb') as f:
    data = f.read()
import codecs
target = codecs.encode('性别', 'utf-16-le')
print(f'性别 UTF-16 LE count: {data.count(target)}')
"
```

### 步骤 5：运行环境确认
```bash
# 关键！检查运行进程加载的 DLL 路径
Get-Process DormManage.Admin | ForEach-Object { 
    $_.Modules | Where-Object { $_.FileName -like "*DormManage*" } | Select-Object FileName
}
```

## 六、永久教训（10 条核心）

1. **文档与代码必须同步 commit**：不允许"v2.13.x 翻转"仅修改文档
2. **发布双胞胎必须同步**：TrayApp 加载路径 ≠ 发布路径
3. **Shared DLL 必须全子目录同步**：TypeLoadException 是漏同步的标志
4. **deny-by-default 是默认安全选择**：allow-by-default 容易导致 BUG
5. **方法名必须反映语义**：`AllowDisplay` 比 `HasEnabled` 更清晰
6. **跨权限测试必须 2 种角色**：admin + 未授权角色
7. **git 操作可能回滚**：Edit 后立即 git diff 确认
8. **StringEncoding 差异**：.NET DLL 中中文是 UTF-16 LE 不是 ASCII
9. **TypeLoadException 是 DLL 版本不一致**：检查 Shared DLL 同步
10. **备份残留陷阱**：`cp -r` 有时跳过目录，需 `rm -rf` 后再 `cp -r`
