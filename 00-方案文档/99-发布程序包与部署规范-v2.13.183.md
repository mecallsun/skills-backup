## 一、发布包结构

### 1.1 统一目录结构

所有发布程序（含 `dotnet publish` 产物、Release zip 包、exe/dll 等可执行文件）**必须**遵守以下目录结构：

```
<项目根目录>\
├── release\                          ← 项目专用发布根目录（必备）
│   ├── latest\                       ← 当前最新可发布的二进制（已解压的可部署目录）
│   │   ├── Admin-v2.13.XXX\          ← Web 管理后台（Razor Pages UI，端口 5001）
│   │   ├── Api-v2.13.XXX\            ← REST API 服务端（Kestrel，端口 5100）
│   │   └── TrayApp-v2.13.XXX\        ← 托盘守护进程（WinForms，负责启动 + 进程管理）
│   └── _archive\                     ← 历史发布 zip 包归档
│       ├── DormManage-v2.13.183_20260727_035651.zip
│       ├── DormManageApi-v2.13.183_20260727_035812.zip
│       └── DormManageTrayApp-v2.13.183_20260727_035812.zip
└── <其他源码目录>\
```

### 1.2 严禁行为

| ❌ 禁止 | 原因 |
|---------|------|
| 根目录放 `*.zip`、`*.dll`、`*.exe` | 污染工作区，git diff 无法区分源码和产物 |
| 使用 `publish-final/` / `dist/` / `out/` / `bin/` 作为发布根目录 | 与 .NET 内置编译产物 `bin/obj/` 混淆，且不符合规范要求 |
| 把 zip 包放在源码目录下 | 增加仓库体积，git clone 极慢 |
| 未命名版本号直接覆盖 `release/latest/` | 无法回滚到旧版本 |

## 二、发布包内容规范

### 2.1 单一压缩包原则

**每次发版必须生成一个整合的单一 zip 压缩包**，包含全部三个组件（Admin + Api + TrayApp），解压即可直接运行，无需手动复制多个文件夹。

**命名规则**：`DormManage-v{主版本}.{次版本}.{修订版本}_{YYYYMMDD_HHMMSS}.zip`

| 要素 | 说明 | 示例 |
|------|------|------|
| `DormManage` | 项目名称 | 固定 |
| `v2.13.183` | 版本号 | 与 CLAUDE.md 中的版本一致 |
| `20260727_035651` | 时间戳 | 发布时的当地日期 + 时间（精确到秒） |

### 2.2 压缩包内部结构

单一压缩包内部必须包含完整的可执行结构和引导脚本：

```
DormManage-v2.13.183_20260727_035651.zip
├── 📁 Admin-v2.13.183\              ← Web 管理后台（~160 MB, 831 文件）
│   ├── appsettings.json
│   ├── web.config
│   ├── wwwroot\...
│   ├── Pages\...
│   └── [全部 .dll / .exe / .js / .css]
├── 📁 Api-v2.13.183\                 ← REST API 服务端（~123 MB, 376 文件）
│   ├── appsettings.json
│   ├── web.config
│   ├── wwwroot\swagger\...
│   └── [全部 .dll / .exe]
├── 📁 TrayApp-v2.13.183\             ← 托盘守护进程（~209 MB, 644 文件）
│   ├── DormManage.TrayApp.exe
│   ├── appsettings.json
│   └── [全部 .dll / .exe]
├── 📄 README.md                      ← 快速部署指南
├── 📄 启动程序.bat                   ← 一键启动所有服务（托盘+API+后台）
├── 📄 停止程序.bat                   ← 一键停止所有服务
└── 📄 安装为服务.bat                 ← 将 TrayApp 注册为 Windows 服务（开机自启）
```

> **注意**：以上目录和文件为打包后的标准结构。实际发布时，`Admin-v2.13.XXX/`、`Api-v2.13.XXX/`、`TrayApp-v2.13.XXX/` 内的内容由 `dotnet publish` 自动产生；`README.md`、`*.bat` 引导脚本需随源码一起打包进 zip。

### 2.3 启动脚本规范

#### 2.3.1 `启动程序.bat`

```batch
@echo off
chcp 65001 >nul
echo ========================================
echo   金智住宿管理系统 v%VERSION%
echo ========================================
echo.
echo [1/3] 正在启动托盘守护进程...
start "" "%~dp0TrayApp-v2.13.XXX\DormManage.TrayApp.exe"
timeout /t 3 /nobreak >nul
echo [2/3] 托盘进程已启动（等待初始化）...
timeout /t 2 /nobreak >nul
echo [3/3] 启动完成！托盘图标已在系统托盘中显示。
echo.
echo - 右键托盘图标可查看状态 / 注册 / 退出
echo - 管理后台地址: http://localhost:5001
echo - API 接口地址: http://localhost:5100
echo.
pause
```

#### 2.3.2 `停止程序.bat`

```batch
@echo off
chcp 65001 >nul
echo 正在停止金智住宿管理系统...
taskkill /IM "DormManage.Admin.exe" /F 2>nul
taskkill /IM "DormManage.Api.exe" /F 2>nul
taskkill /IM "DormManage.TrayApp.exe" /F 2>nul
echo 已停止所有服务。
timeout /t 2 /nobreak >nul
```

### 2.4 `README.md` 内容规范

每个发布包必须包含 `README.md`，内容包括：

| 章节 | 内容 |
|------|------|
| **概述** | 系统名称、版本、发布日期 |
| **系统要求** | Windows 11+/Server 2016+、.NET 8 Desktop Runtime |
| **快速启动** | 双击 `启动程序.bat` |
| **默认端口** | 托盘(:5099) / Admin(:5001) / Api(:5100) |
| **登录信息** | 用户名: `admin` / 密码: `admin123` |
| **数据库配置** | 默认连接串在 `TrayApp/appsettings.json` 中配置 |
| **故障排查** | 常见问题（端口占用、数据库连接失败、注册码错误） |

## 三、发布流程

### 3.1 完整发布步骤

```powershell
# === Step 1: Release 构建 ===
dotnet build DormManage.sln -c Release --no-restore

# === Step 2: Publish 三个组件 ===
dotnet publish DormManage.Admin/DormManage.Admin.csproj -c Release -r win-x64 --self-contained true -o release/latest/Admin
dotnet publish DormManage.Api/DormManage.Api.csproj -c Release -r win-x64 --self-contained true -o release/latest/Api
dotnet publish DormManage.TrayApp/DormManage.TrayApp.csproj -c Release -r win-x64 --self-contained true -o release/latest/TrayApp

# === Step 3: 版本号处理 ===
# 3a. 将 release/latest/{Admin,Api,TrayApp} 重命名为带版本的目录
Move-Item "release\latest\Admin" "release\latest\Admin-v2.13.183"
Move-Item "release\latest\Api" "release\latest\Api-v2.13.183"
Move-Item "release\latest\TrayApp" "release\latest\TrayApp-v2.13.183"

# 3b. 创建整合包（三合一 zip）
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
Compress-Archive -Path "release\latest\Admin-v2.13.183\*" `
    -DestinationPath "release\_archive\DormManage-v2.13.183_$ts.zip" -Force

# === Step 4: 验证 ===
Get-ChildItem "release\_archive" | Where-Object { $_.Name -match "v2.13.183" } | Select-Object Name, @{N='SizeMB';E={[math]::Round($_.Length/1MB,2)}}
```

### 3.2 验证清单

| # | 检查项 | 通过条件 |
|---|--------|---------|
| 1 | `dotnet build -c Release` | 0 error |
| 2 | `dotnet publish` 三个组件 | 输出到 `release/latest/{Admin|Api|TrayApp}` |
| 3 | zip 包体积合理 | Admin ~60-70 MB / Api ~50-60 MB / TrayApp ~80-90 MB |
| 4 | zip 内结构正确 | 解压后含 `Admin-vX.Y.Z/` + `Api-vX.Y.Z/` + `TrayApp-vX.Y.Z/` |
| 5 | 启动脚本存在 | `启动程序.bat` + `停止程序.bat` 在 zip 顶层 |
| 6 | README.md 存在 | zip 顶层有 `README.md` |

## 四、版本编号规则

| 规则 | 说明 |
|------|------|
| **格式** | `v{主}.{次}.{修订}`（如 v2.13.183） |
| **主版本** | 重大架构变更递增（如 .NET Framework → .NET 8） |
| **次版本** | 新功能模块（如新增 PDA APP） |
| **修订号** | BUG 修复、UI 优化、文档同步 |
| **一致性** | 版本号在以下位置必须同步一致：`CLAUDE.md` 版本头 / 文档文件名 / zip 包文件名 / `_archive/` 目录 |

## 五、发布历史管理

### 5.1 `_archive/` 目录

- 所有历史 zip 包永久保留，按时间戳排序
- 不要手动删除旧版 zip（除非存储空间不足并经团队确认）
- 归档命名格式：`{组件名}-v{版本}_{YYYYMMDD_HHMMSS}.zip`

### 5.2 回滚方法

如需回滚到上一个版本：
1. 从 `release/_archive/` 解压指定版本的 zip
2. 将解压后的 `{组件}-v{版本}/` 目录复制回 `release/latest/{组件}/`
3. 重启托盘进程：运行 `停止程序.bat` → 再运行 `启动程序.bat`
