## 9. v2.11.20 增补：住宿状态字段（与基础资料 ResidenceStatus 字典一致）

### 9.1 业务背景

人员清单需要展示每位员工**当前住宿情况**的状态，住宿状态是**派生属性**（无独立字段），需根据 BOOKINGS（办理登记）表的最后一条记录动态推断，并关联引用**基础资料-住宿状态表 ResidenceStatus**。

> **v2.11.20 重要修订**：原 §9 草案（v2.11.2 增补 d）使用 5 项状态枚举（`LIVING`/`LEFT`/`BOOKED`/`CANCELLED`/`NONE`），与基础资料 ResidenceStatus 字典的 3 项不一致。v2.11.20 起统一为 3 项字典定义，删除冗余/冲突定义。

### 9.2 住宿状态枚举（v2.11.20 规范：与基础资料 ResidenceStatus 字典一致）

| 取值 | 编码 (Code) | 中文 (Name) | 来源（最后一条 BOOKINGS） | 颜色 Badge |
|------|------|------|-------------------------|----------|
| **已住宿** | `LODGED` | 已住宿 | `status=2 && type=1`（入住登记生效中） | 蓝 `bg-primary` |
| **未住宿** | `NOT_LODGED` | 未住宿 | `status=3`（含 type=2 已退房）/ `status=4`（已取消）/ 无 BOOKINGS | 浅灰 `bg-light text-dark` |
| **待入住** | `PENDING` | 待入住 | `status=1`（预约未入住） | 黄 `bg-warning text-dark` |

> **v2.11.20 强制规范**：
> - 上述 3 项与基础资料-住宿状态表（ResidenceStatus）完全一致
> - 禁止使用历史 5 项枚举：`LIVING`/`LEFT`/`BOOKED`/`CANCELLED`/`NONE`
> - 单一数据源：基础资料 ResidenceStatus 字典
> - 详见 `39-住宿状态字典一致性规范-v2.11.20.md`

### 9.3 推断算法（v2.11.20 修订）

```javascript
// v2.11.20 修订：返回值与基础资料 ResidenceStatus.code 一致
function getResidenceStatusCode(p) {
    if (!p) return 'NOT_LODGED';
    var b = (typeof getLatestValidBooking === 'function') ? getLatestValidBooking(p.id) : null;
    if (!b) return 'NOT_LODGED';
    if (b.type === 1 && b.status === 2) return 'LODGED';      // 入住登记生效中
    if (b.type === 1 && b.status === 1) return 'PENDING';     // 预约未入住
    if (b.type === 2 && b.status === 3) return 'NOT_LODGED'; // 退房后清空
    if (b.status === 4) return 'NOT_LODGED';                  // 已取消
    return 'NOT_LODGED';  // 兜底
}

// 通过 Code 获取名称（关联引用基础资料字典）
function getResidenceStatusName(p) {
    var code = getResidenceStatusCode(p);
    var rs = (typeof getResidenceStatusByCode === 'function') ? getResidenceStatusByCode(code) : null;
    return rs ? rs.name : '未住宿';
}
```

### 9.4 字段定义

**表 `Personnel`** 无独立字段，住宿状态为**派生字段**，由查询时根据 BOOKINGS 实时计算。

**后端实现（SQL）**：

```sql
SELECT
    p.*,
    COALESCE(b.LatestStatus, 'NONE') AS LivingStatus,
    b.LatestBookingDate
FROM Personnel p
LEFT JOIN (
    SELECT EmployeeId, Status AS LatestStatus, BookingDate AS LatestBookingDate,
           ROW_NUMBER() OVER (PARTITION BY EmployeeId ORDER BY BookingDate DESC) AS rn
    FROM Booking
) b ON b.EmployeeId = p.Id AND b.rn = 1
ORDER BY p.EmployeeCode;
```

**性能**：建议在 `Booking(EmployeeId, BookingDate DESC)` 建立复合索引。

## 3. 详细变更

### 3.1 删除：显示离职人员（复选框）

| 属性 | 内容 |
|------|------|
| **原字段** | `<input type="checkbox" id="showLeft">` |
| **原功能** | 勾选时显示已离职员工（employmentStatusId=3） |
| **删除原因** | 与"在职状态"下拉功能重叠（选择"已离职"即可显示已离职员工） |
| **影响 JS** | `getFiltered()` 中移除 `showLeft` 变量和 `showLeft || ...` 判断 |

**业务说明**：
- 默认（不勾选）：仅显示在职员工（employmentStatusId=1）
- 勾选：显示所有员工（含待入职/已离职）
- 等价操作：选择"在职状态"下拉为"已离职"

> **v2.11.19 规范**：在职状态枚举值与基础资料-在职状态表（EmploymentStatus）保持完全一致：
> - `employmentStatusId=1` → "在职"（ACTIVE）
> - `employmentStatusId=2` → "待入职"（ONBOARDING）
> - `employmentStatusId=3` → "已离职"（LEFT）
> - 不得使用历史遗留的 `status=2 离职`、`status=3 停薪留职` 等错误定义

### 3.2 新增：姓名（文本输入框）

| 属性 | 内容 |
|------|------|
| **新字段** | `<input type="text" id="nameKeyword">` |
| **占位符** | `姓名/工号/手机` |
| **宽度** | 200px |
| **匹配规则** | 大小写不敏感的子串匹配 |
| **匹配字段** | `realName`（姓名）+ `employeeCode`（工号）+ `phone`（手机号） |

**匹配逻辑（伪代码）**：

```javascript
const kw = document.getElementById('nameKeyword').value.trim().toLowerCase();
if (kw) {
    const hit = p.realName.toLowerCase().includes(kw)
              || p.employeeCode.toLowerCase().includes(kw)
              || (p.phone || '').includes(kw);
    if (!hit) return false;
}
```

**示例**：

| 输入 | 匹配结果 |
|------|---------|
| `张` | 匹配所有姓名含"张"的员工（如"张三"、"张伟"） |
| `EMP-2026-001` | 精确匹配工号 EMP-2026-001 |
| `001` | 匹配工号含"001"的所有员工 |
| `1380000` | 匹配手机号前 7 位为 `1380000` 的所有员工 |
| ` `（空格） | 不应用筛选条件 |

function render() {

        // seqNo = 1, 2, 3, ... 在当前筛选条件下递增
    });
}

## 11. v2.12.39 增补：床号列（2026-07-13）

### 11.1 业务背景

人员清单需要展示每位员工当前在住宿的**床位号**，便于：
1. 快速识别员工的具体床位（如 D-088 房间的 3 号床）
2. 配合宿管员查房、床位调整、抄表定位等业务场景
3. 与 v2.12.34 新增的 Dorm.BedNumbers（床位号列表）形成完整链路：住宿有床位列表 → 员工分配床位 → 人员清单展示床位

### 11.2 数据模型

**表 `SysEmployee`** 新增字段 `BedNo INT NULL`（v2.12.39）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `BedNo` | INT | 否 | 当前床位号（如 1、2、3）；仅当 DormCode 不为空时有值 |

**单一数据源**：`SysEmployee.BedNo` 字段（与 `DormCode` 同步维护）

**维护规则（v2.12.39 强制）**：

| 触发场景 | 行为 |
|---------|------|
| 办理入住（CheckIn） | 同步写入 BedNo = 已分配床位号（= activeCount + 1） |
| 快速确认入住（ConfirmCheckIn） | 同步写入 BedNo |
| 撤销在宿（CancelToday） | 不变更 BedNo（保留入住记录） |
| 办理退房（CheckOut/ConfirmCheckOutCreate/UndoCheckOut） | 同步清空 BedNo = NULL |
| 撤销预约（CancelReservation） | 不变更 BedNo（从未入住） |
| 容量减少重新分配床位（R-BED-002） | 同步更新对应员工的 BedNo |
| 容量增加追加床位（R-BED-003） | 不影响原 BedNo |
| DormCode 变化 | BedNo 必须同步变化（联动） |

function bedNoCellHtml(p) {
