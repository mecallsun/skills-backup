## 二、核心设计哲学（贯穿全部章节）

### 哲学 1：**程序永远启动，只决定运行模式**
- 反例（v2.13.137 `ProcessManager.IsLicenseValid()` 硬阻断）：未注册/过期 → throw 拒绝启动 → "启动失败"错误
- 正例（v2.13.169 改造）：5 状态全部能启动（Unregistered/Valid/Expired/Invalid/Unavailable）→ 按状态降级（试用/正常/只读-过期/只读-盗版/只读-授权不可用）
- 适用：所有业务硬约束（授权、试用、版本、安全）都应降级而非阻断

### 哲学 2：**分层防御 + 单一真源**
- 三层防御：UI 提示反馈（**用户体验层**）+ Service 业务校验（**主约束收口**）+ DB 唯一索引/约束（**兜底层**）
- 单一真源：跨层共享的字段定义/状态/规则在 Shared 项目（`DormManage.Shared/Models`、`Security`、`Services`）

### 哲学 3：**依赖反转 + 进程托管**
- 授权/进程决策集中在托盘（`DormManage.TrayApp`），Web/Api 通过 IPC 拉取 → 决策权威唯一
- v2.13.155 进程来源守卫（TrayLaunchGuard）：HMAC-SHA256 握手令牌 + 父进程名校验 → 防 Web/Api 独立双击运行

### 哲学 4：**Obfuscar + R2R + 自包含 + 跳过反射密集区**
- 默认启用 `Obfuscar`（全栈混淆）+ `PublishReadyToRun`（R2R 预编译）+ `SelfContained`（自包含运行时）
- 必须 skip 反射密集区命名空间：Models / Data / Register / Security / Services / Pages / Controllers / Middleware
- 详见 `知识库/11-构建发布与受保护包.md`

### 哲学 5：**文档与代码必须同步，禁止「演示版」遗留**
- 任何功能必须真实实现（1:1 落地），禁止 `alert('原型演示...')` 等占位符
- 每次改动必须同步文档（CLAUDE.md / 00-方案文档 / 01-Database 迁移脚本）
- DEPRECATED 文档加 banner 指向新文档，禁止删除历史文档

## 四、如何使用本知识库

### 场景 A：**快速启动一个相似新项目**（推荐 1-2 天完成架构骨架）
1. 阅读 `01-项目总览` + `02-系统架构` → 理解整体设计
2. 拷贝 `02-系统架构.md` 中的 4 项目 csproj 结构 + Obfuscar/R2R/Directory.Build.props 配置
3. 拷贝 `10-设计规范` 中的 7 项强制规则（写入新项目 CLAUDE.md）
4. 拷贝 `03-注册许可` 中的 RegisterSdk + LicenseGuard + 中间件 → 修改 LTDName 等业务字段即可
5. 按 `14-复用模板` 决策树选择业务模块替换方案

### 场景 B：**深度理解某个具体模块**
1. 在目录中定位章节
2. 阅读「核心思路 + 代码位置 + 关键参数」
3. 查 `15-代码片段库` 找具体实现
4. 查 `13-永久教训` 看避坑指南

### 场景 C：**排查现有项目问题**
1. 查 `13-永久教训` 20+ 条 → 匹配症状
2. 查 `12-端到端测试` 学 MockTrayIpc / SpawnApi 模式
3. 查 `11-构建发布` 学 Obfuscar / 部署包诊断
