## 1. 业务背景

### 1.1 名称变更

| 旧名（导航） | 新名 |
|------|------|
| 记录 | **抄表** |

### 1.2 功能定位

系统业务闭环的**数据源头**：

```
PDA 现场抄表 → MeterRecord（本模块）→ 费用标准 → 宿舍账单 → 员工分摊 → Excel
```

- PDA 端由抄表员扫码宿舍、录入冷水/热水/电三表读数并拍照留证，Multipart 上传服务端。
- 本模块为 **Web 后台**，面向管理员，提供：抄表记录的查询、详情（含照片预览）、**手动补录**（PDA 漏抄时）、**批量导入**（Excel 整月导入）、**修正**、**作废**。
- 每间宿舍每月产生一条记录；**本月用量 = 本月读数 − 上月读数**，是宿舍账单的唯一计费依据。

## 2. 业务规则

### 2.1 唯一性与幂等

| 规则 | 说明 |
|------|------|
| R-METER-01 | **同一房号 + 同一抄表月份（DormCode + ReadMonth）唯一**，不可重复（`UX_MeterRecord_DormMonth`） |
| R-METER-02 | PDA 上传通过 `ClientRecordId`（UUID+时间戳）实现幂等，重复提交返回已存在记录，不产生重复数据 |
| R-METER-03 | 后台"手动补录"命中已存在（同房同月且非作废）时，禁止提交，提示改用"修正" |
| R-METER-09 | **批量导入**逐行校验同房同月唯一：命中数据库已有记录（非作废）→ 该行拦截 |
| R-METER-10 | **批量导入**文件内自查重：同一房号+月份出现多行，仅首行有效，其余按"文件内重复"拦截 |
| R-METER-11 | 批量导入为**部分成功**语义：仅写入校验通过的行，逐行返回拦截原因，不因个别错误整体回滚 |

### 2.2 读数与用量

| 规则 | 说明 |
|------|------|
| R-METER-04 | 三表读数均 **≥ 0**（DECIMAL(10,2)） |
| R-METER-05 | 每种表本月读数必须 **> 上月同表读数**（表盘只增不减；否则判为异常） |
| R-METER-06 | 用量 = 本月读数 − 上月最近一条**有效**（非作废）读数 |
| R-METER-07 | 无上月记录时为"首次抄表"，用量不参与计费 |
| R-METER-08 | 账单取"该月抄表记录值"；同宿同月多版本时取首条（见 R-BILL-08） |

### 2.3 状态机（v2.11.2 增补 n + o）

```
[未抄表(0)]    -- PDA 上传/后台补录 --> [正常(1)]
[正常(1)]      -- 后台修正读数 --> [已修正(2)]
[正常(1)]      -- 重复/错误作废 --> [已作废(3)]
[未完成(4)]    -- 后台修正（补全缺项）--> [正常(1)] 或 [已修正(2)]
[正常(1)]      -- 部分表项缺失（PDA 部分上传）--> [未完成(4)]
[已修正(2)]    已定稿，不可再修正/作废
[已作废(3)]    已排除，不参与用量与账单
[未完成(4)]    -- 补全后 --> [正常(1)] / [已修正(2)]
```

| Status | 含义 | 三表数据完整性 | 参与计费 | 可修正 | 可作废 | 可补录 |
|--------|------|--------------|:---:|:---:|:---:|:---:|
| 0 | **未抄表** | 三表全 0 | ❌ | ❌ | ❌ | ✅ |
| 1 | 正常 | 三表完整 | ✅ | ✅ | ✅ | — |
| 2 | 已修正 | 三表完整（已修正） | ✅ | ❌ | ❌ | — |
| 3 | 已作废 | — | ❌ | ❌ | ❌ | — |
| **4** | **未完成** | **部分表项 0** | ⚠️ 部分 | ❌ | ❌ | ✅ 补全 |

**关键业务规则（v2.11.2 增补 o）**：

1. **每月每房号必须有一条记录**（每条记录最多含 3 个表项数据）
2. **整条记录无数据 → status=0（未抄表）**
3. **部分表项有数据 / 部分表项为 0 → status=4（未完成）**
4. **三表完整 → status=1（正常）或 status=2（已修正）**
5. **每个表项独立判断是否"未完成"**：coldMeter=0 → 冷水未完成；hotMeter=0 → 热水未完成；electricMeter=0 → 电未完成
6. **状态筛选"全部"= 含所有状态**（status=0/1/2/3/4），不再区分"全部（含未抄表）"和"全部（排除未抄表）"

### 2.4 备注历史追加机制（v2.11.2 增补 o）

新增或导入数据时，若同月份同房号已存在记录：

1. **旧记录覆盖**：原记录被新记录替换
2. **旧数据快照追加到备注**：将原记录的所有字段快照追加到新记录的 `remark` 字段，格式：

```
[2026-07-08 10:30 覆盖] dormCode=D-001, month=2026-07, cold=100, hot=50, electric=200, status=1, operator=陈师傅
```

3. **历史追溯**：通过备注可还原任意时刻的抄表状态
4. **备注追加**：多次覆盖时，新旧数据依次追加，保留完整历史

**实现示例**：

```javascript
// 旧记录
{ id: 100, dormCode: 'D-001', readMonth: '2026-07', coldMeter: 100, hotMeter: 50, electricMeter: 200, status: 1, remark: '' }

// 新导入数据
{ dormCode: 'D-001', readMonth: '2026-07', coldMeter: 105, hotMeter: 55, electricMeter: 210 }

// 覆盖后
{
    id: 200, dormCode: 'D-001', readMonth: '2026-07',
    coldMeter: 105, hotMeter: 55, electricMeter: 210, status: 1,
    remark: '[2026-07-08 10:30 覆盖前数据] cold=100, hot=50, electric=200, status=1, operator=陈师傅'
}
```

## 3. 数据模型（依据方案 §4.3.2 / §4.3.3）

### 3.1 MeterRecord 抄表主表（核心）

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| Id | BIGINT IDENTITY | PK | 自增主键 |
| DormCode | NVARCHAR(20) | 是 | FK→Dorm.DormCode |
| ReadMonth | CHAR(7) | 是 | 抄表月份 YYYY-MM |
| ColdMeter | DECIMAL(10,2) | 是 | 冷水表读数（m³），CHECK ≥ 0 |
| HotMeter | DECIMAL(10,2) | 是 | 热水表读数（m³），CHECK ≥ 0 |
| ElectricMeter | DECIMAL(10,2) | 是 | 电表读数（度），CHECK ≥ 0 |
| ClientRecordId | NVARCHAR(50) | 是 | PDA 端 UUID+时间戳，UNIQUE（幂等） |
| Operator | NVARCHAR(50) | 是 | 抄表员（SysUser.Username） |
| DeviceSn | NVARCHAR(50) | 是 | PDA 设备序列号 |
| Remark | NVARCHAR(500) | 否 | 备注 / 异常说明 / 修正原因 |
| Status | TINYINT | 是 | 1=正常 2=已修正 3=已作废（默认 1） |
| CreatedAt | DATETIME | 是 | 上传时间（默认 now） |
| UpdatedAt | DATETIME | 否 | 修改时间 |

**关键索引**：
- `UX_MeterRecord_DormMonth` UNIQUE (DormCode, ReadMonth) — 防重复
- `UX_MeterRecord_ClientRecordId` UNIQUE (ClientRecordId) — 幂等
- `IX_MeterRecord_CreatedAt` (CreatedAt DESC) INCLUDE(读数,Operator) — 列表覆盖索引
- `IX_MeterRecord_Operator` (Operator, ReadMonth) — 抄表员维度

### 3.2 MeterImage 图片附件表

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| Id | BIGINT IDENTITY | PK | 主键 |
| RecordId | BIGINT | 是 | FK→MeterRecord.Id，ON DELETE CASCADE（**v2.13.79 起 MeterRecord.Id 类型为 long**）|
| ImageType | VARCHAR(20) | 是 | cold / hot / electric |
| RelativePath | NVARCHAR(500) | 是 | 如 202607/D-301/20260708_103055_cold.jpg |
| AbsolutePath | NVARCHAR(500) | 是 | 如 D:\MeterImages\202607\D-301\... |
| FileSize / Width / Height | — | 是 | 文件元数据 |
| UploadedAt | DATETIME | 是 | 上传时间 |

- 每条抄表记录关联 **3 张**照片（冷/热/电），PDA 拍摄后压缩并加"房号 | 表种 | 时间"水印。
- 物理存储 `D:\MeterImages\YYYYMM\房号\`，Kestrel `UseStaticFiles` 映射 `/uploads/*` 供 Web 在线预览。

## 6. 交互流程

### 6.1 列表查询

```
[筛选区]
  ├─ 抄表月份（默认最新月）
  ├─ 楼栋 / 抄表员 / 状态（全部/正常+已修正/正常/已修正/已作废，**默认=正常+已修正**，即排除已作废）
  ├─ 房号/地址 模糊查询
  └─ [查询] [重置] [手动补录] [导出 Excel]

[覆盖进度条]  某月 已抄 X / Y 间 · 未抄：D-XXX...

[列表区]
  房号 | 月份 | 冷水读数 | 热水读数 | 电表读数 | 本月用量(冷/热/电) | 抄表员 | 设备 | 抄表时间 | 状态 | 操作
  操作列：详情 | 修正（仅正常）
  作废记录整行置灰、用量显示"—"
```

> **本月用量展示优化**：用量是核心计费依据，须清晰可读——放弃小号徽标，改为**较大字号（≈1rem，加粗、tabular-nums 对齐）**，每项配**表种色图标**（冷水💧蓝 `#2a78d6` / 热水🔥红 `#e34948` / 电⚡黄 `#eda100`）+ 带正负号数值 + 单位（m³ / 度），三项横向对齐。

### 6.2 手动补录（v2.12.36 改为弹窗模式）

> **v2.12.36 变更**：从独立页面 `/Meter/Entry` 改为 Bootstrap Modal 独占弹窗（#manualEntryModal），弹窗宽度 xl（1140px），背景半透明遮罩；紧凑一屏布局，去掉规范信息（v2.12.26 规范：删除顶部信息提示卡片、表单标题旁副标题、字段下方 form-hint 提示、底部"数据将保存至 XXX 表"等规范文件内容）；行间距减小；抄表月份默认为服务端当前日期。

```
┌─────────────────────────────────────────────────────────────────────┐
│  手动补录抄表                                                         │
├─────────────────────────────────────────────────────────────────────┤
│  [宿舍 *] [抄表月份 *] [抄表员（只读）]                                │
│  [冷水读数] [热水读数] [电表读数]                                       │
│  （三表读数卡片，各含用量提示 + 照片上传占位）                           │
│  [备注 textarea]                                                      │
│  ─────────────────────────────────────────────────────────────────  │
│  [用量预览卡片（右侧）]                                               │
│  冷水用量：X m³  |  热水用量：Y m³  |  电表用量：Z 度                  │
│  ─────────────────────────────────────────────────────────────────  │
│                    [取消]  [提交]                                      │
└─────────────────────────────────────────────────────────────────────┘
```

**交互流程**：

```
[步骤 1] 选择宿舍（仅启用）+ 抄表月份（默认 = 服务端当前月份）
   ├─ 命中同宿同月正常/已修正记录 → 红色告警，禁止提交，提示改用"修正"
   ├─ 命中同宿同月未完成记录 → 提示将覆盖占位记录
   └─ 自动带出上月读数作为参考

[步骤 2] 录入三表读数（冷水/热水/电）
   ├─ 实时计算用量
   ├─ 读数 ≤ 上月 → 标红拦截
   └─ 每表上传现场照片（自动加水印）

[步骤 3] 填写备注（异常说明）

[步骤 4] 提交 → POST /api/meter/records
```

### 6.3 修正 / 作废

```
修正：列表/详情 → 修正 → 改读数 + 填修正原因（必填）→ 状态置"已修正" → 重算用量与账单
作废：详情 → 作废 → 确认 → 状态置"已作废" → 该月用量不再参与账单
```

### 6.4 批量导入（整月）

```
[1] 下载模板  抄表导入模板.xlsx
     列：房号 | 抄表月份(YYYY-MM) | 冷水读数 | 热水读数 | 电表读数 | 抄表员 | 备注
[2] 上传文件 → 系统逐行校验，进入「预览」而非直接入库
[3] 预览表：每行标记「可导入 / 拦截+原因」，可导入行绿底、拦截行红底
     汇总：总行数 / 可导入 / 拦截
[4] 点击「导入通过校验的行」→ 仅写入有效行（部分成功），返回逐行结果
```

**逐行校验顺序（命中即拦截，不再继续）**：

```
1. 房号、抄表月份非空
2. 三表读数必填且为数字、≥ 0
3. 房号必须存在且为「启用」
4. 同房同月唯一（库）：数据库已有非作废记录 → 拦截「同月同房号已存在（数据库）」
5. 同房同月唯一（文件内）：本次文件中该 房号+月份 已出现有效行 → 拦截「文件内同月同房号重复」
6. 读数递增：若有上月有效读数，三表均需 > 上月同表读数
```

## 7. 校验规则详解

### 7.1 补录 / 修正提交校验

```
1. 宿舍、月份必填
2. 补录：同宿同月（非作废）不得已存在 → 否则拦截，提示改用"修正"
3. 三表读数必填且 ≥ 0
4. 若存在上月有效读数：本月每表读数必须 > 上月同表读数
5. 修正必须填写修正原因
6. 提交后自动：用量 = 本月 − 上月；关联宿舍账单需重算
```

### 7.2 用量计算

```
prev = 该宿舍 ReadMonth < 本月 且 Status ≠ 作废 的最近一条
用量.cold = 本月.ColdMeter − prev.ColdMeter （热/电同理）
prev 不存在 → 首次抄表，用量为空、不计费
```

## 9. 与现有模块的关系

- **宿舍档案**：MeterRecord.DormCode → Dorm；补录宿舍下拉仅取"启用"宿舍。
- **费用标准 / 宿舍账单**：DormBilling 的用量取该月抄表用量（R-BILL-08 多版本取首条），修正/作废会触发账单重算。
- **权限**：PDA 操作员仅"抄表"（上传），无费用/人员权限；后台补录/修正/作废归管理员。
