## 1. 业务背景



### 1.1 现状问题



- **住宿档案**：现有 Dorm 表只有基本字段（楼栋/楼层/地址），缺少房间容量、当前在住人数、最近抄表日期等运维字段，管理员无法快速了解住宿使用情况

- **住宿记录缺失**：员工与住宿是多对多关系（员工可换房、离职退宿），但当前只在 SysEmployee 表有一个 DormCode 字段，无法追溯历史：

  - 张三何时入住 D-301、何时换到 D-401？

  - 某住宿过去 1 年住过哪些员工？

  - 离职员工的退宿记录是否完整？



### 1.2 本次目标



- **住宿档案增强**：增加容量 / 当前在住 / 累计抄表次数等统计字段

- **新建住宿记录表**：完整记录「员工-住宿」关系生命周期（入住 → 在宿 → 退宿/换房）

## 3. 业务规则



### 3.1 住宿档案规则



| 规则 | 说明 |

|------|------|

| R-DORM-01 | 房号（DormCode）全局唯一 |

| R-DORM-02 | 默认房间数=1（单人间）；支持多户合租 |

| R-DORM-03 | 容量 = 房间数 × 每户标准人数（默认 4 人/户） |

| R-DORM-04 | 当前在住人数 = Status=Active 的住宿记录数 |

| R-DORM-05 | 启用 IsActive=0 后不能再分配员工入住 |

| R-DORM-06 | 删除前必须没有在宿员工和未完成的智能抄表记录 |



### 3.2 住宿记录规则



| 规则 | 说明 |

|------|------|

| R-RES-01 | 同一员工同一时间只能有 1 条在宿（Status=Active）记录 |

| R-RES-02 | 同一住宿在住人数 ≤ 容量上限 |

| R-RES-03 | 退宿 = 设置 LeaveDate + Status=Left（非物理删除） |

| R-RES-04 | 调宿 = 旧记录退宿 + 新记录入住（保证历史连续） |

| R-RES-05 | 离职员工 = 自动退宿（LeaveDate = 离职日期） |

| R-RES-06 | 入住日期不能早于员工入职日期 |

| R-RES-07 | 退宿日期不能晚于今天 |

### 6.1.1 住宿列表「班次」列派生规则（v2.13.95 新增）

**业务规则**：住宿档案列表的「班次」列显示该房号**当前在宿员工**（`DormBooking.Status = 2`）的**考勤班次去重集合**，按 `AttendanceType.Id` 升序排列，用 Badge 渲染（`<span class="badge bg-info text-dark me-1">`）。

**数据关系链**：
```
Dorm (DormCode)
  ↓ JOIN
DormBooking (DormCode=Dorm.DormCode AND Status=2)
  ↓ JOIN
SysEmployee (EmployeeId=SysEmployee.Id)
  ↓ JOIN
AttendanceType (AttendanceTypeId=AttendanceType.Id)
  ↓ 输出
List<string> = [Name1, Name2, ...] DISTINCT BY Id ASC
```

**示例**：
| 房号 | 在宿员工 | 员工考勤班次 | 显示 |
|------|---------|-------------|------|
| A101 | 3 人 | 早班/中班/中班 | `[Badge 早班] [Badge 中班]` |
| A102 | 0 人 | - | `<small class="text-muted">-</small>` |
| A103 | 2 人 | 默认/早班 | `[Badge 默认] [Badge 早班]` |

**实现要点**：
- 一次 JOIN 批量取全部页内住宿的班次集合（避免 N+1）
- 排序用 `AttendanceType.Id` 升序（AttendanceType 模型无 SortOrder 字段；与 Department 等其他基础资料实体不同）
- Badge 风格与人员清单考勤班次 Badge 一致（`bg-info text-dark`）
- 空房间（CurrentCount=0）显示 `-`（muted）而非空字符串
- 不修改 Dorm/DormBooking/SysEmployee/AttendanceType 任何表结构；纯派生列

## 8. 业务计算公式



### 8.1 住宿在住人数



```

CurrentResidentCount = COUNT(DormResidency WHERE DormCode = X AND Status = 1 AND LeaveDate IS NULL)

```



### 8.2 容量校验（入住时）

```

允许入住 IF CurrentResidentCount < Capacity
拒绝入住 IF CurrentResidentCount >= Capacity
```

### 8.3 调宿（原子事务）



```sql

BEGIN TRANSACTION;

  -- 1. 旧记录退宿

  UPDATE DormResidency SET LeaveDate = @TransferDate, Status = 2, Reason = '调宿' WHERE Id = @OldId;

  -- 2. 新记录入住

  INSERT INTO DormResidency (EmployeeId, DormCode, CheckInDate, Status, Reason) VALUES (@EmpId, @NewDorm, @TransferDate, 1, '调宿');

COMMIT;

```

## v2.13.111 备注：住宿档案列表新增「班组」列

**用户原话**：在原型中的住宿档案列表中，增加列「班组」，记录对应显示为该住宿房号已在宿人员的员工档案中员工的班组ID的集合，如 A101 住宿入住 3 人（班组分别是 A班、B班、B班），则班组列表中根据在宿员工班组显示该房号的班组为：A/B。

**追加要求**：房号无人入住则班组对应记录显示空白无字符（不渲染 `-` 或任何字符）。

### 数据关系

```
Dorm (房号) ─1:N─→ DormBooking (Status=2 在宿) ─N:1─→ SysEmployee (TeamId FK) ─N:1─→ Team (Name + SortOrder)
```

派生查询起点为 `DormBooking.Status = 2`（已入住），无 schema 迁移。

### 显示规则

| 场景 | 在宿员工班组 | 显示 |
|------|-------------|------|
| 3 人 A班/B班/B班 | TeamId=1, 2, 2 | `一班/三班` 两个 Badge（去重 + 按 SortOrder 升序）|
| 4 人 A班/A班/B班/C班 | 1, 1, 2, 3 | `一班/二班/四班` 三个 Badge |
| 单人 A班 | 1 | `一班` 单个 Badge |
| 无人入住 | — | `<td>` 完全空白 |
| 员工无班组 | TeamId 异常 | 不计入 |

### 实现要点

- **批量 JOIN 避免 N+1**：`WHERE DormCode IN (当前页 dormCodes) AND Status=2` 一次查询，GROUP BY + Dictionary 填充
- **Badge 单色 `bg-primary`**：与 v2.13.97 Booking 列表班组列对齐
- **删除 null 占位**：原型 v2.13.107 用 `-`，v2.13.111 程序改为完全空白
- **TeamId 是 int 非可空**：无需 null 过滤
