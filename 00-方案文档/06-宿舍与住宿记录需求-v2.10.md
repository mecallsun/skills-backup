## 1. 业务背景

### 1.1 现状问题

- **宿舍档案**：现有 Dorm 表只有基本字段（楼栋/楼层/地址），缺少房间容量、当前在住人数、最近抄表日期等运维字段，管理员无法快速了解宿舍使用情况
- **住宿记录缺失**：员工与宿舍是多对多关系（员工可换房、离职退宿），但当前只在 SysEmployee 表有一个 DormCode 字段，无法追溯历史：
  - 张三何时入住 D-301、何时换到 D-401？
  - 某宿舍过去 1 年住过哪些员工？
  - 离职员工的退宿记录是否完整？

### 1.2 本次目标

- **宿舍档案增强**：增加容量 / 当前在住 / 累计抄表次数等统计字段
- **新建住宿记录表**：完整记录「员工-宿舍」关系生命周期（入住 → 在宿 → 退宿/换房）

## 3. 业务规则

### 3.1 宿舍档案规则

| 规则 | 说明 |
|------|------|
| R-DORM-01 | 房号（DormCode）全局唯一 |
| R-DORM-02 | 默认房间数=1（单人间）；支持多户合租 |
| R-DORM-03 | 容量 = 房间数 × 每户标准人数（默认 4 人/户） |
| R-DORM-04 | 当前在住人数 = Status=Active 的住宿记录数 |
| R-DORM-05 | 启用 IsActive=0 后不能再分配员工入住 |
| R-DORM-06 | 删除前必须没有在宿员工和未完成的抄表记录 |

### 3.2 住宿记录规则

| 规则 | 说明 |
|------|------|
| R-RES-01 | 同一员工同一时间只能有 1 条在宿（Status=Active）记录 |
| R-RES-02 | 同一宿舍在住人数 ≤ 容量上限 |
| R-RES-03 | 退宿 = 设置 LeaveDate + Status=Left（非物理删除） |
| R-RES-04 | 调宿 = 旧记录退宿 + 新记录入住（保证历史连续） |
| R-RES-05 | 离职员工 = 自动退宿（LeaveDate = 离职日期） |
| R-RES-06 | 入住日期不能早于员工入职日期 |
| R-RES-07 | 退宿日期不能晚于今天 |

## 4. 数据模型

### 4.1 Dorm 宿舍档案表（增强）

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| Id | INT | PK | — | 主键自增 |
| DormCode | NVARCHAR(20) | 是 | — | 房号（UNIQUE） |
| Address | NVARCHAR(100) | 否 | — | 详细地址 |
| Building | NVARCHAR(50) | 否 | — | 楼栋 |
| Floor | INT | 否 | — | 楼层 |
| RoomCount | INT | 是 | 1 | 房间数（合租数） |
| Capacity | INT | 是 | RoomCount×4 | 容量上限（人） |
| BedNumbers 🆕 | NVARCHAR(500) | 否 | 自动生成 | **床位号（v2.12.34 新增）：按宿舍房间容量自动生成，从 1 起至 Capacity 上限为床位号；存储格式 `1,2,3,4`（逗号分隔）；当 Capacity 变更时自动重新生成** |
| BedCount | INT | 是 | Capacity | 床位数 |
| Remark | NVARCHAR(200) | 否 | — | 备注 |
| IsActive | BIT | 是 | 1 | 是否启用 |
| CreatedAt | DATETIME | 是 | — | 创建时间 |
| UpdatedAt | DATETIME | 否 | — | 更新时间 |

**索引**：`UX_Dorm_DormCode` UNIQUE / `IX_Dorm_BuildingFloor`

**冗余统计字段（运行时计算，不入库）**：
- CurrentResidentCount：在住人数
- LastReadMonth：最近抄表月份

### 4.2 DormResidency 住宿记录表（新建）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Id | INT | PK | 主键自增 |
| EmployeeId | INT | 是 | FK→SysEmployee.Id |
| DormCode | NVARCHAR(20) | 是 | FK→Dorm.DormCode |
| CheckInDate | DATE | 是 | 入住日期 |
| LeaveDate | DATE | 否 | 退宿日期（NULL=在宿） |
| Status | TINYINT | 是 | 1=在宿 2=已退宿 3=调宿中 |
| Reason | NVARCHAR(200) | 否 | 入住/退宿原因（入职、调岗、离职等） |
| Remark | NVARCHAR(500) | 否 | 备注 |
| OperatorId | INT | 否 | 经办人（SysUser.Id） |
| CreatedAt | DATETIME | 是 | 创建时间 |
| UpdatedAt | DATETIME | 否 | 更新时间 |

**索引**：
- `UX_DormResidency_Active` UNIQUE (EmployeeId) WHERE Status=1 — 同一员工只能有一条在宿
- `IX_DormResidency_DormActive` (DormCode, Status) WHERE Status=1 — 按宿舍查在宿
- `IX_DormResidency_DormHistory` (DormCode, CheckInDate DESC) — 按宿舍查历史
- `IX_DormResidency_EmployeeHistory` (EmployeeId, CheckInDate DESC) — 按员工查历史

**ER 关系**：
```
Dorm ||--o{ DormResidency : "1 宿舍 → N 住宿记录"
SysEmployee ||--o{ DormResidency : "1 员工 → N 住宿记录"
```

## 8. 业务计算公式

### 8.1 宿舍在住人数

```
CurrentResidentCount = COUNT(DormResidency WHERE DormCode = X AND Status = 1 AND LeaveDate IS NULL)
```

### 8.2 容量校验（入住时）

```
允许入住 IF CurrentResidentCount < Capacity
拒绝入住 IF CurrentResidentCount >= Capacity
```

### 8.3 调宿（原子事务）

```sql
BEGIN TRANSACTION;
  -- 1. 旧记录退宿
  UPDATE DormResidency SET LeaveDate = @TransferDate, Status = 2, Reason = '调宿' WHERE Id = @OldId;
  -- 2. 新记录入住
  INSERT INTO DormResidency (EmployeeId, DormCode, CheckInDate, Status, Reason) VALUES (@EmpId, @NewDorm, @TransferDate, 1, '调宿');
COMMIT;
```
