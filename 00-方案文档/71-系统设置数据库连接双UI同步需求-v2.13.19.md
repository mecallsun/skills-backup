## 1. 业务背景

系统由 **.NET 8 自托管 EXE + 托盘守护程序（TrayApp）** 运行，数据库连接参数是启动 Web（Admin）与 API（Api）两个子进程的前提条件。随着 v2.13.13 系统设置重构为 8 个嵌入式 Tab，「数据库连接」需要在两个入口之间保持一致：

| 入口 | 说明 |
|------|------|
| **托盘系统配置窗口**（`DormManage.TrayApp/Forms/SettingsForm.cs`） | 本地运维入口，无角色权限控制，仅保留核心服务端参数 |
| **Web 后台系统设置**（`/Settings` → 数据库连接 Tab） | 管理员入口，受角色权限管控，提供完整的 8 步深度验证 |

> **双 UI 职责划分原则**：托盘仅保留服务启动必需的端口/数据库/路径参数；Web 端承载全部系统设置功能，包括数据库连接的完整管理。

---

## 2. 功能目标

1. **单一事实来源**：数据库连接配置统一由 `AppConfigManager` 管理，避免托盘与 Web 端各写各的配置文件。
2. **双 UI 可读写**：托盘保存的配置，Web 端可读取；Web 端保存的配置，托盘下次启动可读取。
3. **安全持久化**：密码字段使用 **AES-256-CBC** 加密后存储于本地 `db_setting.json`，并同步写入 SQL Server `SysParameter` 表。
4. **变更广播**：配置保存成功后触发 `OnDatabaseConfigUpdated` 事件，订阅者（TrayApp UI Dispatcher、未来 SignalR Hub）可即时感知。
5. **连通性卡口**：保存前必须执行数据库连通性测试，测试失败禁止保存。

## 3. 数据模型

### 3.1 配置 DTO（`DatabaseConfigDto`）

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `DbServer` | string | `192.168.1.237` | 数据库服务器 IP / 主机名 |
| `DbPort` | int | `1433` | 端口号；非 1433 时连接字符串自动追加 `,port` |
| `DbName` | string | `WaterMeterDB` | 数据库名称 |
| `DbUser` | string | `__DB_USER__` | 登录账号 |
| `DbPassword` | string? | `__DB_PASSWORD__` | 密码；API 返回时脱敏为 `******` |
| `Provider` | string | `SqlServer` | 提供程序：`SqlServer` / `Sqlite` |
| `SqlitePath` | string? | — | SQLite 文件绝对路径（Provider=Sqlite 时必填） |

### 3.2 系统参数表（`SysParameter`）

| 字段 | 说明 |
|------|------|
| `Id` | 主键 |
| `ParamKey` | 全局唯一参数键，如 `db.server`、`db.password` |
| `ParamValue` | 参数值；密码字段 AES 加密后存储 |
| `Category` | 分类，固定为 `Database` |
| `Description` | 参数描述 |
| `IsEncrypted` | 是否已加密 |
| `CreatedAt` / `UpdatedAt` | 审计时间 |

## 4. API 端点（`DbConfigController`）

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/api/v1/system/dbconfig` | 读取当前数据库配置（密码脱敏） | 管理员 |
| `POST` | `/api/v1/system/dbconfig/test` | 测试数据库连接（不写入） | 管理员 |
| `POST` | `/api/v1/system/dbconfig/save` | 保存配置（先测试 → 再写入） | 管理员 |
| `POST` | `/api/v1/system/dbconfig/deep-test` | 8 步深度验证（同 DashboardService） | 管理员 |

### 4.1 保存流程

```
1. 接收 DatabaseConfigDto（前端明文密码或 "unchanged" 哨兵）
2. 若 DbPassword == "unchanged"，从 db_setting.json 读取旧配置替换真实密码
3. 调用 TestDbConnectionAsync 测试连通性
   ├─ SqlServer：SqlConnectionStringBuilder + OpenAsync
   └─ Sqlite：SqliteConnectionStringBuilder + OpenAsync
4. 测试失败 → 返回 CONN_FAILED，不写入任何介质
5. 测试通过 → AES-256 加密密码
6. 原子写入本地 db_setting.json（temp → move）
7. 后台任务写入 SysParameter 表
8. 触发 OnDatabaseConfigUpdated 事件
9. 返回 SAVE_SUCCESS
```

### 4.2 读取流程

```
1. 优先读取 db_setting.json
2. 解密密码字段（失败返回空，兼容老版本明文）
3. 文件不存在 → 使用 fallback（默认 appsettings.json）
4. 返回前将密码替换为 ******
```

## 5. 加密方案

### 5.1 算法选择

| 算法 | 用途 | 说明 |
|------|------|------|
| **AES-256-CBC** | 数据库密码加密 | 对称可逆；密钥硬编码于 `AesEncryptor`（生产环境建议改为外部注入） |

> **与 v2.11.8 DPAPI 方案的关系**：v2.11.8 文档曾建议使用 Windows DPAPI。v2.13.19 为支持跨平台部署（未来 Linux Docker 场景）以及服务端与托盘分离读取，改为 **AES-256** 对称加密。本文档以最新实现为准。

## 6. Web 端交互（`/Settings` 数据库连接 Tab）

### 6.1 页面字段

与 `DatabaseConfigDto` 一一对应：
- 数据库服务器
- 端口号
- 数据库名称
- 账号
- 密码（掩码输入，加载时显示 `******`）
- 提供程序（SqlServer / Sqlite）
- SQLite 路径（Provider=Sqlite 时显示）

### 6.2 操作按钮

| 按钮 | 行为 |
|------|------|
| 测试连接 | 调用 `POST /api/v1/system/dbconfig/test`，显示结果 |
| 8 步深度验证 | 调用 `POST /api/v1/system/dbconfig/deep-test`，逐步显示 8 步结果 |
| 保存 | 调用 `POST /api/v1/system/dbconfig/save`，成功后可选择通知托盘重启 |

### 6.3 与托盘联动

保存成功后，前端通过 `window.fetchTrayIpc` 发送 `dbconfig.updated` 命令；`fetchTrayIpc` 内部调用后端 API `/api/v1/system/ipc/tray` 转发到托盘 IPC 端口 5099：

```javascript
async function fetchTrayIpc(command, payload) {
    const res = await fetch('/api/v1/system/ipc/tray', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ command, payload })
    });
    return await res.json();
}

// 保存成功后调用
fetchTrayIpc('dbconfig.updated', payload);
```

同时 `DbConfigController.SaveConfig` 保存成功后主动通过 `IpcClient` 向 `127.0.0.1:5099` 发送 `dbconfig.updated`，作为前端通知不可靠时的兜底同步通道。

## 7. 托盘端交互（`SettingsForm` / `TrayAppContext`）

### 7.1 读取

- `SettingsForm` 加载时通过 `AppConfigManager.Instance.LoadAsync()` 读取 `db_setting.json`，将字段式配置映射到 UI 字段（密码框置空）。
- `Program.cs` 启动时同样调用 `LoadAsync`，将字段式配置同步为 `ConnectionString` 并写回 `appsettings.json`，保证 Web 保存的配置在 Tray 重启后生效。

### 7.2 保存

- 托盘构造 `DatabaseConfigDto`；密码框为空时 `DbPassword = "unchanged"`。
- 调用 `AppConfigManager.Instance.SaveConfigurationAsync(config)` 保存。
- 保存成功后，调用 `ConfigService.UpdateDatabaseSection(config)` 同步写回 `appsettings.json`。
- Web 端下次调用 `GET /api/v1/system/dbconfig` 即可读取到最新配置。

### 7.3 事件订阅

- `TrayAppContext` 订阅 `AppConfigManager.Instance.OnDatabaseConfigUpdated`；事件触发时刷新 `ConfigService` 中的数据库段并写回 `appsettings.json`。

### 7.4 IPC 命令处理

`TrayAppContext.HandleIpcCommand` 新增：

- `getdbconfig`：返回当前 `DatabaseConfigDto`（密码脱敏）。
- `setdbconfig` / `dbconfig.updated`：解析 payload 为 `DatabaseConfigDto`，调用 `SaveConfigurationAsync` 保存，成功后刷新 `appsettings.json` 并记录日志。

## 8. 错误码与提示

| 错误码 | 场景 | 前端提示 |
|--------|------|---------|
| `CONN_FAILED` | 测试连接失败 | 显示具体失败原因（如 SQL Server 连接失败、SQLite 路径为空） |
| `SAVE_FAILED` | 写入文件或数据库失败 | 显示异常信息 |
| `DEEP_TEST_FAILED` | 8 步深度验证异常 | 显示异常信息 |
| `NOT_FOUND` | 配置文件不存在 | 提示使用默认配置 |
