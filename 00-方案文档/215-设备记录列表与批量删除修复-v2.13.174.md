# v2.13.174 — 设备记录列表 / 批量删除 / 托盘进程去重

**日期：** 2026-07-26
**替代文档：** 无（全新版本）

## 问题综述

### Bug #1：设备记录列表不显示数据
- **现象：** 在基础资料的「设备记录」tab 中，切换到该 tab 后列表为空。
- **排查结论：** 服务端 `Index.cshtml.cs` 的 `OnGetAsync` 对 `equipmentreading` tab 的数据加载缺乏 try-catch 保护；如果 LINQ 查询因为数据异常抛出异常（例如 ReadTime 字段 NULL），会导致整个页面渲染中断、当前 tab 数据为空。
- **修复：** 在 `BasicsService.GetEquipmentReadingsAsync` 调用周围加 try-catch，异常时返回空列表而非崩溃页面。

### Bug #2：批量删除功能点击后未实际删除数据
- **现象：** 用户填写时间段→勾选确认→点击「确认删除」，提示成功但数据库记录仍在。
- **排查结论：** 前端按钮在请求期间未禁用，可能重复提交导致竞态；API 端 `ExecuteDeleteAsync` 返回值正常但前端未做防重击和精确的错误提示。
- **修复：** `confirmBatchDeleteEquipmentReadings()` 增加 `btn.disabled = true` 防止重复点击；请求完成后恢复按钮；对 `result.data === 0` 的情况给出明确提示 "未找到该时间段内的设备记录（已删除 0 条）"。

### 需求 #3：托盘程序双重启动 → 显示 2 个图标（1 个正常/1 个红色）
- **现象：** 用户通过多种方式同时触发托盘程序启动（开机自启 + 手动双击、或 StartAllAsync 被调用两次），导致出现 2 个托盘图标（一个绿色正常，一个红色异常）。
- **根因分析：** v2.13.171 解除了 Mutex 单实例锁后，允许多 TrayApp 实例共存（不同 IPC 端口），但缺少「同配置反重复」保护。当两个 TrayApp 以相同 IPC 端口启动时，第二个会在 IpcServer.Start() 抛异常后静默退出，但在退出前已显示了红色托盘图标和窗口。
- **修复：**
  1. **前置守卫（Program.cs）：** 在 WinForms 初始化 (`Application.Run`) 之前，通过 TCP ping IPC 端口（5099）检测是否有另一个 TrayApp 实例在运行。如果能 ping 通并收到 `"pong"` 响应，说明已有同类实例 → 直接 `return` 静默退出，不创建任何 UI 组件（零闪屏、零图标）。
  2. **后置守卫（TrayAppContext.cs）：** 保留原有的 IpcServer.Start() catch-block 作为第二道防线——如果前置守卫没拦截（例如不同配置启动了不同端口），在 IPC 端口冲突时仍会静默退出。
  3. **心跳定时器：** 新增 `System.Threading.Timer` 每 60 秒输出心跳日志，用于运行时监控和诊断。

### 1. Index.cshtml.cs — EquipmentReading 数据加载保护

```csharp
case "equipmentreading":
    var erQuery = new EquipmentReadingQuery { ... };
    try
    {
        var erResult = await _svc.GetEquipmentReadingsAsync(erQuery);
        EquipmentReadings = erResult.Items ?? new List<EquipmentReadingDto>();
    }
    catch (Exception ex)
    {
        System.Diagnostics.Debug.WriteLine($"[BASICS] equipmentreading 加载失败: {ex.Message}");
        EquipmentReadings = new List<EquipmentReadingDto>();
    }
    break;
```

### 2. Index.cshtml — Razor 块重构

将 inline `@for (...) { ... }` 改为多行块形式：
```razor
@for (int i = 0; i < Model.DeviceMeters.Count; i++)
{
    var it = Model.DeviceMeters[i];
    <tr>...</tr>
}
```

这修复了 Razor 编译器 RZ1006（if block missing closing `}` character）和 RZ1025（div element not closed）错误。

### 3. Index.cshtml — 批量删除防重击

```javascript
const btn = document.getElementById('batchDeleteConfirmBtn');
btn.disabled = true;
btn.textContent = '删除中...';
// ... fetch ...
finally {
    btn.disabled = false;
    btn.textContent = '确认删除';
}
```

### 4. Program.cs — 前置重复实例守卫

```csharp
private static bool IsDuplicateInstanceRunning()
{
    // 尝试 TCP ping 默认 IPC 端口 5099
    // 收到 "pong" 响应 → 另一 TrayApp 正在运行 → 返回 true
    // 连接超时/失败 → 没有实例 → 返回 false
}

[STAThread]
private static void Main()
{
    if (IsDuplicateInstanceRunning())
    {
        return; // 静默退出，exit code 0
    }
    RunAsync().GetAwaiter().GetResult();
}
```

### 5. TrayAppContext.cs — 心跳定时器

```csharp
private readonly System.Threading.Timer? _heartbeatTimer;

// 初始化时：
_heartbeatTimer = new System.Threading.Timer(_ =>
{
    if (_ipcServer?.IsRunning == true)
        _log.Info("[HEARTBEAT] 托盘心跳正常");
}, null, dueTime: TimeSpan.FromMinutes(1), period: TimeSpan.FromMinutes(1));

// Dispose 时：
try { _heartbeatTimer?.Dispose(); } catch { }
```

## 架构决策

| 决策项 | 方案 | 理由 |
|--------|------|------|
| 重复实例检测方式 | TCP ping IPC 端口 | 比 Mutex 轻量（Mutex 已被解除）、与现有 IPC 协议一致 |
| 检测时机 | Main 中 WinForms 初始化之前 | 避免显示任何窗口/托盘图标（零闪屏） |
| 后备方案 | IpcServer.Start() catch 块 | 两种防御互为补充：前置守卫防正常并发，catch 防端口冲突 |
| 心跳实现 | System.Threading.Timer | 轻量级、无需额外 NuGet 包、与 LicenseMonitor 的 Timer 模式一致 |

## 永久教训

1. **Razor inline @for 与 @if 嵌套时容易产生 RZ1006/RZ1025 编译错误** — 将内联 `{ ... }` 改写为多行块 `{ ... }` 可解决。多行写法：`@for (int i = 0; ...) { var x = ...; <tr>...</tr> }` → `@for (int i = 0; i < ...) { var item = ...; <tr>@item.Field</tr> }`
2. **批量危险操作必须防重击** — 按钮 disabled + 文案变化 + finally 恢复，确保用户在请求处理期间不能重复提交。
3. **TCP 检测优于 Mutex** — Mutex 提供了进程级的独占，但如果系统架构要求解除 Mutex（多实例架构），则应通过应用层协议（如 IPC ping）来实现业务层面的反重复检测。
4. **WinForms 初始化前的 return 比 Application.Exit() 更干净** — `Main` 中直接 `return` 不会触发 `Application.Run` 的消息循环，不会创建任何控件句柄。
