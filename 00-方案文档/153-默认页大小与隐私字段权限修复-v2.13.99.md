## 二、BUG #1 默认页大小 10 条

### 2.1 根因链

```
┌──────────────────────────────────────────────────────────────┐
│ 1. PageModel.PageSize 默认值 = 20（✅ 8 处全部正确）           │
│ 2. _PaginationPartial.cshtml 启动时 JS 读 localStorage        │
│    'pager_pageSize_{module}'                                  │
│ 3. 若 stored (e.g. '10') ≠ currentPageSize ('20')             │
│ 4. → location.replace('?pageSize=10&pageIndex=1')             │
│ 5. PageModel 这次收到 ?pageSize=10 → PageSize = 10            │
│ 6. 用户看到 10 条 ❌                                            │
└──────────────────────────────────────────────────────────────┘
```

**触发条件**：用户/测试曾在 v2.13.74 修复**前**手动选过 `10`，localStorage 永久保留。v2.13.74 修复让 PageModel 真正读 URL 后，旧 localStorage 中的 `'10'` 反而兑现生效。

### 2.2 修复

**文件**：`DormManage.Admin\Pages\Shared\_PaginationPartial.cshtml`

删除 JS 启动回退逻辑（行 133-140），保留 `changePageSize` 让用户主动选择：

```javascript
// 修复前（v2.13.71 引入）：
var stored = localStorage.getItem(pageSizeKey);
if (stored && stored !== currentPageSize && !location.search.match(/[?&]pageSize=/)) {
    var url = new URL(location.href);
    url.searchParams.set('pageSize', stored);
    url.searchParams.set('pageIndex', '1');
    location.replace(url.toString());   // ← BUG 源头
}

// 修复后（v2.13.99）：
// 移除整段回退逻辑。URL 不带 pageSize → 严格使用 PageModel 默认值 20。
// 用户主动选择 pageSize 时仍写入 localStorage（仅供记忆，不自动应用）。
```

### 2.3 行为变化

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 首次访问 URL 无 `?pageSize=` | 显示 localStorage 中旧值（如 10）❌ | **严格 20 条** ✅ |
| URL 含 `?pageSize=50` | 50 条 ✅ | 50 条 ✅ |
| 用户点击 dropdown 选 50 | URL 跳 `?pageSize=50&pageIndex=1` ✅ | 同上 ✅ |
| localStorage 已有 '10'，新 URL 不带参数 | 强制重定向到 `?pageSize=10` ❌ | **不再重定向**，使用默认 20 ✅ |
| 期望"下次自动恢复上次选择" | ✅ | ❌（用户需显式传参或重新选择） |

### 2.4 影响范围

## 三、BUG #2 隐私字段权限失效

### 3.1 根因链

```
┌──────────────────────────────────────────────────────────────┐
│ v2.13.92: DormDbContext.cs 新增                                │
│   · SysFieldPermission 表定义 + 5 字段种子                      │
│   · SysPermission seed Id=37/38/39 (privacy:field:enable)      │
│   · SysRolePermission seed admin 关联 37/38/39                 │
│                                                                 │
│ 当前 dorm.db 状态:                                               │
│   · SysPermission 表 18 行（max Id=18）→ 无 Id=39              │
│   · SysFieldPermission 表不存在 ❌                              │
│   · SysRolePermission 表 29 行 → 无 admin 关联 Id=39           │
│                                                                 │
│ 原因: EF EnsureCreated() 仅对空 DB 完整建表                    │
│       对既有 DB 不追加任何 schema（项目无 EF Migrations）        │
│                                                                 │
│ 运行链路:                                                        │
│   IsFieldHiddenAsync → GetHiddenFieldKeysAsync                  │
│   → HasPrivacyFieldEnabledAsync → 查询 SysPermission            │
│   → 找不到 'privacy:field:enable' Id=39 → 返回 false           │
│   → 返回空 HashSet → 所有字段视为可见 ❌                         │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 修复（双层防御）

**层 1 — `DatabaseInitializer` 启动迁移（自动）**

`DormManage.Shared\Services\DatabaseInitializer.cs`：
1. 新增 `CriticalTables` 白名单条目：`SysPermission` / `SysRolePermission` / `SysFieldPermission`
2. 新增私有方法 `MigrateFieldPermissionAsync(db, logger, ct)`：
   - 检测 `SysFieldPermission` 表是否存在（SQLite: `sqlite_master` / SQL Server: `INFORMATION_SCHEMA.TABLES`）
   - 缺失时按 Provider 分支执行 DDL 补建
   - 5 字段种子 + 3 权限码 + 3 角色关联全部用 `IF NOT EXISTS` / `WHERE NOT EXISTS` 守卫（幂等）
3. 在 `InitializeAsync` 第 6 步调用迁移方法
4. `StartupReport` 新增 `FieldPermissionMigrated` 字段

**层 2 — `init_schema.sql` SQL Server 真相源同步（手工）**

`init_schema.sql` 末尾追加：
- 34. SysFieldPermission 表 DDL（带 `IF NOT EXISTS` 守卫）
- 35. v2.13.92 3 个权限码种子
- 36. v2.13.92 admin 角色关联 3 条
- 37. v2.13.92 SysFieldPermission 5 字段种子

### 3.3 修复后行为

| 角色 | `privacy:field:enable` 权限 | 期望 |
|------|---------------------------|------|
| admin | ❌ 未勾选（v2.13.92 设计默认） | 所有字段都显示（admin 默认全权限） |
| 其他角色（如 pda/财务/访客） | ❌ 未勾选 | 所有字段都显示 |
| 任何角色 | ✅ 已勾选 | 所有 `SysFieldPermission.IsActive=true` 字段隐藏（姓名/手机/工号/房号/备注） |

| 1 | BUG #1 修复采用「删除 JS 回退」 | 最简单可预测；用户报告期望「URL 不带参数 = 默认 20」 |

## 八、教训（v2.13.99）

1. **JS localStorage 与服务端默认值冲突**：启动时 JS 不应主动覆盖服务端已渲染的默认值。PageModel 默认值是事实标准，localStorage 仅供"用户记忆"而非"自动应用"。
2. **EF Core EnsureCreated 不迁移**：项目若不用 EF Migrations，每次新增 DbSet + HasData 必须额外做"启动迁移"或文档化的手工 SQL 脚本。本项目 v2.13.92 漏做 → BUG。
3. **CriticalTables 是真相源**：任何新表必须加入白名单，否则 DetectMissingTablesAsync 检测不到，启动迁移也不会触发。
4. **三处必须同步**：EF HasData（开发）+ DatabaseInitializer 启动迁移（自动补漏）+ init_schema.sql（SQL Server 真相源），三处保持一致是基建原则。
