## 1. 概述

本规范用于统一所有列表型页面的视觉风格、布局结构和交互行为。**以"宿舍管理"页面为基准**，所有列表页面必须严格遵循本规范，包括页头、筛选条件区域、列表、页尾四大区域。

### 1.1 规范目标

| 目标 | 说明 |
|------|------|
| **视觉一致** | 所有列表页面外观统一，用户学习成本低 |
| **响应式适配** | 桌面/平板/手机均良好显示，筛选条件一行排列不换行 |
| **序号明确** | 列表第一列为序号，跨页连续编号 |
| **分页统一** | 页尾分页样式完全一致 |

## 2. 页头（Page Header）

### 2.1 标准结构

```html
<div class="d-flex justify-content-between align-items-center mb-3">
    <h2 class="mb-0">
        <i class="bi bi-{module-icon}"></i> {模块名称}
        <small class="text-muted fs-6">（共 <span id="totalCount">{总数}</span> 条）</small>
    </h2>
    <div class="btn-group" role="group">
        <button class="btn btn-success" onclick="showAddModal()">
            <i class="bi bi-plus-lg"></i> 新增
        </button>
        <button class="btn btn-primary" onclick="showManualEntryModal()">
            <i class="bi bi-pencil-square"></i> 手动补录
        </button>
        <button class="btn btn-info text-white" onclick="showBatchImportModal()">
            <i class="bi bi-upload"></i> 批量导入
        </button>
        <a href="/api/{module}/export" class="btn btn-outline-success">
            <i class="bi bi-file-earmark-excel"></i> 导出Excel
        </a>
        <!-- 其他操作按钮 -->
    </div>
</div>
```

### 2.2 规范要点

| 元素 | 规范 |
|------|------|
| **标题图标** | Bootstrap Icons，每个模块对应固定图标 |
| **标题文字** | h2 大小，左对齐，模块名称 |
| **总数显示** | 小字号灰色 `(共 X 条)` |
| **操作按钮** | 右对齐，使用 `btn-group` 排列在同一行 |

### 2.3 操作按钮排列规范（v2.11.4 UI.2 新增）

> **新规则**：所有操作按钮必须使用 `<div class="btn-group">` 排列在同一行，宽度自适应。

**按钮排列原则**：

| 原则 | 说明 |
|------|------|
| **同一行** | 所有按钮必须放在 `btn-group` 内，视觉上呈一行 |
| **宽度自适应** | 按钮宽度由内容决定，不强制等宽 |
| **按钮数量** | 建议不超过 5 个，超过时可分组显示 |
| **颜色区分** | 主操作绿色/蓝色，功能性按钮用其他颜色 |

**抄表记录按钮对照**：

| # | 按钮 | 图标 | 颜色 | 功能 |
|---|------|------|------|------|
| 1 | 新增记录 | `bi-plus-lg` | `btn-success` | 单条新增 |
| 2 | 手动补录 | `bi-pencil-square` | `btn-primary` | 单条补录 |
| 3 | 批量导入 | `bi-upload` | `btn-info` | 文本框批量录入 |
| 4 | 导出Excel | `bi-file-earmark-excel` | `btn-outline-success` | CSV 下载 |

### 2.5 共用页头与 Tab 页签协同（v2.12.0 新增 — 强制）

> ⚠️ **强制规则（v2.12.0 新增）**：自 v2.12.0 起，所有列表型页面 **必须** 升级为「共用页头 + Tab 页签切换」模式，不再使用 v2.11 的"每页独立绘制 + 单层菜单"模式。

#### 2.5.1 模式升级对照

| 维度 | v2.11（已废弃） | v2.12.0（强制） |
|------|----------------|----------------|
| 页头绘制 | 每个页面独立绘制菜单导航 | 全局共用一份 `_Layout.cshtml` |
| 菜单形态 | 图标+文字横向排列 | **紧凑型图标导航**（仅图标 + Tooltip） |
| 页面切换 | 整页 URL 跳转 | 点击图标 **新增 Tab**，原 Tab 保留 |
| Tab 数量 | 无 Tab 概念 | 多 Tab 可关闭、可固定、可拖拽 |
| 状态持久化 | 仅依赖浏览器 history | localStorage 持久化（跨刷新恢复） |

#### 2.5.2 四层架构（必须遵循）

| 层 | 名称 | 高度 | 职责 | 列表页相关 |
|----|------|------|------|----------|
| Tier 1 | 顶部品牌栏 | 48px | 品牌标识 + 用户信息 | 全局共享 |
| Tier 2 | 紧凑型图标导航条 | 56px | 一级菜单入口 | 全局共享 |
| Tier 3 | Tab 页签栏 | 40px | 已打开页面切换 + 关闭 | 全局共享 |
| Tier 4 | 页面内容区 | 自适应 | 当前 Tab 的列表内容 | 各页独立 |

#### 2.5.3 列表页面页头规范（与 Tab 协同）

- **页头范围调整**：原 §2.1 页头（图标 + 标题 + 总数 + 操作按钮）**仅指 Tier 4 内容区顶部**，不再包含菜单导航；
- **页头位置**：Tier 4 内容区顶部，距 Tab 栏底部 1rem；
- **操作按钮位置**：仍在页头右侧 `btn-group` 内，**不**进入 Tier 3 Tab 栏；
- **跨页连续编号**：列表第一列"序号"逻辑不受 Tab 切换影响，按 `(PageIndex-1)*PageSize+行号` 计算；
- **筛选条件区域（§3）**：保持原 `flex-nowrap` 一行排列 + 90×38px 按钮规范不变；
- **页尾分页（§5）**：保持原"统计信息 + 分页器"样式不变。

#### 2.5.4 Tab 切换对列表状态的影响

| 场景 | 行为 |
|------|------|
| 切换 Tab 离开列表页 | 列表筛选条件 + 分页 + 排序 **保留在内存**，回到 Tab 时原样恢复 |
| 关闭 Tab | 弹出确认（如有未保存修改），确认后丢弃列表状态 |
| 刷新 Tab | 列表回到默认状态（筛选/分页重置），通过 URL 参数可恢复 |
| 跨账号登录 | 列表 Tab 状态按 userId 隔离 localStorage，互不干扰 |

#### 2.5.5 列表页与 Tab 的渲染实现

| 技术栈 | 实现方式 |
|--------|---------|
| Razor Pages | `_Layout.cshtml` 内含 Tab 容器；每个列表页通过 `@page` + `@RenderBody()` 注入 Tab 内容 |
| HTML 原型 | `_shared/layout.html` 提供共用布局；列表页通过 iframe 嵌入或 fetch-html 局部切换 |
| 原型 Web 部署 | 与原型方案一致，确保离线可访问 |

- [ ] 点击图标导航 → 新增 Tab 而非整页跳转
- [ ] 列表页筛选条件 + 分页 + 排序在 Tab 切换时保留

## 3. 筛选条件区域（Filter Card）

### 3.1 标准结构（一行排列，响应式）

```html
<form method="get" class="card mb-3 filter-card">
    <div class="card-body py-2">
        <div class="row g-2 align-items-end flex-nowrap filter-row">
            <div class="col-auto flex-grow-1 filter-item">
                <label class="form-label mb-1">{标签1}</label>
                <input type="text" name="{字段1}" class="form-control" placeholder="...">
            </div>
            <div class="col-auto filter-item">
                <label class="form-label mb-1">{标签2}</label>
                <select name="{字段2}" class="form-select">...</select>
            </div>
            <!-- 更多筛选字段 -->
            <div class="col-auto filter-item">
                <button type="submit" class="btn btn-primary">
                    <i class="bi bi-search"></i> 查询
                </button>
            </div>
            <div class="col-auto filter-item">
                <a href="/{Controller}" class="btn btn-outline-secondary">
                    <i class="bi bi-arrow-clockwise"></i> 重置
                </a>
            </div>
        </div>
    </div>
</form>
```

### 3.1.1 查询和重置按钮规范（强制要求）

> **强制规则（v2.11.4 UI.3 + UI.4）**：所有包含筛选条件区域的页面，**必须**同时包含"查询"和"重置"两个按钮，且：
> - **位置**：始终位于筛选区域的**最右侧**
> - **固定尺寸**：宽度 90px、高度 38px，强制一致（`!important`）
> - **图标**：必须带有 Bootstrap Icons 图标
> - **顺序**：查询 → 重置
> - **CSS 类**：必须使用 `.filter-btn` 类

#### 标准代码

```html
<div class="col-auto filter-item">
    <button type="submit" class="btn btn-primary filter-btn">
        <i class="bi bi-search"></i> 查询
    </button>
</div>
<div class="col-auto filter-item">
    <a href="/{Controller}" class="btn btn-outline-secondary filter-btn">
        <i class="bi bi-arrow-clockwise"></i> 重置
    </a>

```

| 禁止 | 原因 |

### 3.5 筛选区强制一行排列规则（v2.12.4 新增 — 强制）

> ⚠️ **强制规则（v2.12.4 新增 — 全项目统一）**：所有显示筛选区的页面（含列表页、详情查询页等），**必须**强制约束所有筛选项+按钮在同一行内排列，**禁止换行**。

#### 3.5.1 核心要求

// 1. 初始化 datalist 候选（页面加载时执行）
function initDormDatalist() {
    var dl = document.getElementById('dormList');
    if (!dl || typeof getAllDormCodes !== 'function') return;
    var codes = getAllDormCodes(); // 从数据源获取所有房号
    for (var i = 0; i < codes.length; i++) {
        var opt = document.createElement('option');
        opt.value = codes[i];
        dl.appendChild(opt);
    }
}

// 2. 筛选逻辑（输入时实时模糊匹配）
function getFiltered() {
    var dormVal = (document.getElementById('fDorm').value || '').trim();
    return PERSONNEL.filter(function(p) {
        // ... 其他筛选条件 ...
        if (dormVal && typeof getLatestDormCode === 'function') {
            var dc = getLatestDormCode(p);
            // ⚠️ 使用 includes() 模糊匹配，不是 === 精确匹配
            if (!dc || dc.toLowerCase().indexOf(dormVal.toLowerCase()) === -1) return false;
        }
        return true;
    });
}
```

## 3.6 表单设计规范（v2.12.14 新增 — 强制）

> ⚠️ **强制规则（v2.12.14 新增 — 全项目统一）**：所有"新增/编辑"表单页面（如新增人员、编辑人员、办理登记、新增宿舍等）**必须**采用双列布局 + 字段分组 + 操作按钮置右规范，**禁止**全部单列左侧排列造成右侧大量空白。
>
> ⚠️ **强制规则（v2.12.26 新增 — 全项目统一）**：所有"新增/编辑"表单页面**必须**做到**专业设计紧凑、一屏完整展示**：
> ① **去掉规范信息**：删除字段下方的 `form-hint` 提示（如"关联引用基础资料 DEPARTMENTS 字典"）、顶部信息提示卡片（`form-info-card`）、表单标题旁的副标题（`header-subtitle`）、底部信息提示（如"数据将实时保存至 PERSONNEL 表"）等规范文件相关说明；

> ③ **一屏完整展示**：在不滚动的情况下能看到所有字段和操作按钮。

### 3.6.1 表单布局原则

| 原则 | 说明 |
|------|------|
| **双列布局** | 使用 Bootstrap `col-md-6` 让两个字段并排显示，节省垂直空间 |
| **字段分组** | 用 `fieldset` 或 `form-section` + `form-section-title` 划分逻辑区块 |
| **关联字典下拉** | 下拉选项 value 必须是基础资料字典的 ID（如 `DEPARTMENTS.id`），而非字符串 name |
| **操作按钮置右** | 取消 / 重置 / 提交 按钮统一放在表单底部右侧，置 `form-actions` 容器 |
| **去除规范信息**（v2.12.26） | 不显示字段关联引用提示、顶部信息卡片、底部"数据将保存至 XXX 表"等规范说明 |
| **必填红星** | `required` 字段 label 后加 `<span class="required">*</span>` |
| **占位符友好** | input 加 `placeholder`，如 `EMP-2026-NNN` |
| **紧凑一屏**（v2.12.26） | 减小区块/字段间距，确保一屏可见所有字段和操作按钮 |

    if (b.bookingDate === today && b.status === 3)
        btns.push('<button class="btn btn-sm btn-outline-info" onclick="undoCheckout(' + b.id + ')">撤销</button>');

    // 3. 入住 — v2.11.8
    if (b.type === 1 && b.status === 1)
        btns.push('<button class="btn btn-sm btn-outline-success" onclick="confirmCheckin(' + b.id + ')">入住</button>');

    // 4. 退房 — v2.11.12 + v2.11.17
    if (b.status === 2 || (b.type === 2 && b.status === 1)) {
        var handler = b.status === 2 ? 'checkoutCreate' : 'confirmCheckout';
        btns.push('<button class="btn btn-sm btn-outline-warning" onclick="' + handler + '(' + b.id + ')">退房</button>');
    }

    // 5. 撤销（在宿）— v2.11.17
    if (b.type === 1 && b.status === 2 && b.bookingDate === today)
        btns.push('<button class="btn btn-sm btn-outline-danger" onclick="cancelToday(' + b.id + ')">撤销</button>');

    // 6. 撤销（预约）— v2.11.11
    if (b.status === 1)
        btns.push('<button class="btn btn-sm btn-outline-danger" onclick="cancelReservation(' + b.id + ')">撤销</button>');

    return btns.join(' ');
}
```

#### 4.6.5 禁止事项

|---------|------|

## 7.7 客户端筛选条件持久化（v2.12.10 新增 — 强制）

> ⚠️ **强制规则（v2.12.10 新增 — 全项目统一）**：所有列表型页面的筛选区字段值必须自动持久化到 localStorage，切换 Tab 页签或刷新页面后自动恢复，避免用户重复操作筛选条件。

### 7.7.1 核心行为

| 行为 | 说明 |
|------|------|
| **自动保存** | 用户修改任意筛选字段（input / select / date）时，自动将当前模块所有筛选值写入 localStorage |
| **自动恢复** | 页面加载时自动从 localStorage 读取当前模块的筛选值，填入对应 DOM 元素 |
| **Tab 切换保留** | 切换 Tab 页签再返回时，筛选值自动恢复（不丢失） |
| **刷新页面保留** | 刷新浏览器页面时，筛选值自动恢复（不丢失） |
| **跨模块隔离** | 每个模块的筛选值独立存储，互不干扰 |
| **重置清空** | 点击"重置"按钮时，清空当前模块的 localStorage 筛选值并重置 DOM |

### 7.7.2 localStorage 存储结构

| 键名 | 格式 | 示例 |
|------|------|------|
| `dormmanage:filter:v1:{moduleKey}:admin` | JSON 对象，key 为字段 ID，value 为字段值 | `{"keyword":"张三","type":"1","status":""}` |

**模块键映射**：

| 模块 | ModuleKey | localStorage Key 示例 | 筛选字段 ID |
|------|-----------|----------------------|------------|
| 宿舍档案 | `dorms` | `dormmanage:filter:v1:dorms:admin` | `building`, `floor`, `isActive`, `keyword` |
| 人员清单 | `personnel` | `dormmanage:filter:v1:personnel:admin` | `fKw`, `fDept`, `fType`, `fAttend`, `fStatus`, `fDorm` |
| 办理登记 | `booking` | `dormmanage:filter:v1:booking:admin` | `keyword`, `department`, `dormCode`, `type`, `status`, `dateFrom`, `dateTo` |
| 宿舍账单 | `dormBills` | `dormmanage:filter:v1:dormBills:admin` | `billingMonth`, `dormCodeKw`, `building`, `floor` |
| 员工分摊 | `employeeBills` | `dormmanage:filter:v1:employeeBills:admin` | `billingMonth`, `empKeyword`, `fDept`, `fType`, `fReside`, `dormCodeKw` |
| 费用标准 | `billing` | `dormmanage:filter:v1:billing:admin` | `applicableType`, `status`, `keyword` |
| 抄表记录 | `meter` | `dormmanage:filter:v1:meter:admin` | `month`, `building`, `operator`, `status`, `keyword` |

> **变更**：所有列表页"重置"按钮从原来的 `<a href="xxx.html">` 整页跳转改为 `<button onclick="FilterPersistence.resetFilters('moduleKey')">` JS 调用，避免整页跳转导致的筛选值丢失。
