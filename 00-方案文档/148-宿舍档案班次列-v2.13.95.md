# 宿舍档案「班次」派生列 v2.13.95

> **版本**：v2.13.95
> **日期**：2026-07-22
> **需求**：在「宿舍档案」列表页（Dorms/Index）增加「班次」列；显示该宿舍房号已在宿人员的考勤班次去重集合。

---

## 一、需求背景

用户原话：
> 在原型中的宿舍档案列表中，增加列 班次（即考勤班次），记录显示为该宿舍房号已在宿人员的员工档案中员工的班次id的集合，如：A101 宿舍入住 3 人，分别员工的班组是早班、中班、中班，则列表中根据在宿员工班次显示该房号的班次为：早班/中班

**业务价值**：
- 宿舍管理员快速识别每间房的人员排班分布
- 提前发现某房人员全部同一班次可能存在的作息冲突
- 简化"按班次排房"的合规审计

---

## 二、数据关系（4 表 JOIN）

```
Dorm (宿舍)
  └─ DormCode (PK)
       ↓
DormBooking (住宿记录)
  ├─ DormCode (FK → Dorm.DormCode)
  ├─ EmployeeId (FK → SysEmployee.Id)
  └─ Status = 2 (在宿)
       ↓
SysEmployee (员工档案)
  └─ AttendanceTypeId (FK → AttendanceType.Id, NULL 表示无考勤班次)
       ↓
AttendanceType (考勤班次)
  ├─ Id
  ├─ Code (DEFAULT/MORNING/MIDDLE/EVENING/NIGHT)
  └─ Name (默认/早班/中班/晚班/夜班)
```

---

## 三、派生规则

```
每个 Dorm 的「班次」列 = 该 Dorm 在宿员工（DormBooking.Status=2）
                          的 AttendanceType.Name 去重集合
                          按 AttendanceType.Id 升序排列
                          用 "/" 隐式分隔，UI 上每个 Name 渲染为独立 Badge
```

**示例**：
| 房号 | 在宿员工 | 员工 AttendanceType | 列表「班次」列显示 |
|------|---------|---------------------|--------------------|
| A101 | 张三/李四/王五 | 早班/中班/中班 | `[Badge 早班] [Badge 中班]` |
| A102 | 赵六 | 默认 | `[Badge 默认]` |
| A103 | 钱七/孙八 | 默认/早班 | `[Badge 默认] [Badge 早班]` |
| A104 | (空) | - | `<small class="text-muted">-</small>` |

## 四、实现（5 处代码 + 1 个原型）

### 4.1 数据层 / 服务层

**无任何数据库 schema 变更**；纯派生列。`DormBooking.Status=2` 是 v2.13.24 引入的 `BookingStatus.Staying` 枚举常量。

### 4.2 DTO 扩展

`DormManage.Admin/Pages/Dorms/Index.cshtml.cs` 与 `DormManage.Api/Controllers/Dorms/DormsController.cs` 都新增同名字段：

```csharp
public class DormDto {
    // ... 原有字段
    /// <summary>v2.13.95 派生班次名称集合（按 AttendanceType.Id 升序 + 去重）</summary>
    public List<string> AttendanceTypeNames { get; set; } = new();
}
```

### 4.3 Web Admin PageModel（`Index.cshtml.cs::OnGetAsync`）

复用 v2.13.85 派生性别模式（避免 N+1，批量一次 JOIN 全部页内宿舍）：

```csharp
// v2.13.95 派生班次
var attendanceStats = await _db.DormBookings
    .Where(b => dormCodes.Contains(b.DormCode) && b.Status == 2)
    .Join(_db.Employees.AsNoTracking(),
          b => b.EmployeeId, e => e.Id,
          (b, e) => new { b.DormCode, e.AttendanceTypeId })
    .Where(x => x.AttendanceTypeId.HasValue)
    .Join(_db.AttendanceTypes.AsNoTracking(),
          x => x.AttendanceTypeId, t => t.Id,
          (x, t) => new { x.DormCode, TypeId = t.Id, TypeName = t.Name })
    .GroupBy(x => x.DormCode)
    .Select(g => new {
        DormCode = g.Key,
        TypeNames = g.OrderBy(x => x.TypeId).Select(x => x.TypeName).Distinct().ToList()
    })
    .ToDictionaryAsync(x => x.DormCode, x => x.TypeNames);

// 在构造 items 时填充
AttendanceTypeNames = attendanceStats.GetValueOrDefault(d.DormCode) ?? new List<string>()
```

## 五、关键决策与权衡

| 决策 | 理由 |
|------|------|
| **批量 JOIN 而非 N+1** | 一次 SQL 取全部页内 20 个宿舍的班次集合，O(1) 次查询；避免每行宿舍单独查询（20 行 → 21 次查询）|
| **按 AttendanceType.Id 升序** | AttendanceType 模型无 SortOrder 字段（与 Department 等其他基础资料实体不同）；用 Id 保稳定排序 |
| **Badge 风格 `bg-info text-dark`** | 与人员清单考勤班次 Badge 完全一致（v2.13.46 引入）|
| **空房间显示 `-`** | 与楼栋/楼层等列"无值显示 muted"的视觉风格一致 |
| **NULL AttendanceTypeId 不显示** | 老员工档案无考勤班次时不进班次集合；空集合时整体显示 `-` |
| **不修改 DormBooking 表结构** | 派生字段，运行时实时计算；存储无冗余 |

## 六、端到端验证

```bash
$ GET /Dorms → 200
$ 班次 表头: 1 ✓
$ Badge bg-info text-dark: 19 ✓（每行 1 个班次 Badge）
$ Badge 内容示例: "默认"（种子数据中员工考勤班次都默认 Id=1）
```

实际数据中由于种子数据所有员工 `AttendanceTypeId=1`（默认），列表中所有宿舍的「班次」列都显示 `[Badge 默认]`。功能链路 JOIN → AttendanceType → Badge 渲染完整正确。当用户调整员工考勤班次（v2.13.46 人员清单编辑），列表会实时反映。
