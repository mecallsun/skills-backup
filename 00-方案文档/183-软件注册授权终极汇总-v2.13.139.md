## 三、机器码显示规范（v2.13.138 终极样式）

### 3.1 算法（NPGS，与原 Kingdee.NPGS 完全一致）

```
机器码（24 位 hex 大写）= CPU + Volume

CPU   = Win32_Processor.ProcessorId (前 16 hex)
       示例：BFEBFBFF000A06A4
       含义：Intel Family 6 Model 158 (如 i7-10700)

Volume = Win32_LogicalDisk VolumeSerialNumber (后 8 hex)
       示例：AA2E3B0E
       含义：C 盘 NTFS 卷序列号

拼接：(CPU + Volume).Substring(0, 24)
       = BFEBFBFF000A06A4AA2E3B0E
```

### 3.2 视觉展示（v2.13.138 5-5-5-5-4 分组）

```
┌─────────────────────────────────────────────────────────┐
│  机器码：BFEBF-BFF00-0A06A-4AA2E-3B0E                  │
└─────────────────────────────────────────────────────────┘
```

**字段约定**：
- `RegItem.SN` / `RegStateDto.SN` / `machine.dat` 文件：**恒为 24 位 raw hex**（业务/存储/IPC）
- UI 展示：**5-5-5-5-4 视觉分组 28 字符**（`LicenseForm.FormatMachineCodeDisplay`）
- 复制按钮：**复制 24 位 raw**（供应商生成 CDKEY 必须用 raw）

## 四、CDKEY 格式规范

### 4.1 算法

```
CDKEY（25 位 hex）= 验证段（20 位）+ 日期段（5 位）

验证段 = MD5(SN + LTDName + SECRET_KEY).Substring(0, 20).ToUpper()
        SECRET_KEY = "JINGE-DORM-MANAGE-2026-LICENSE"
        示例：a3f5c8e1b9d2f4c7e8a1

日期段 = HEX_ENCODED(到期日 YYYY-MM-DD)
        YYYY  → 2 hex 位
        MM    → 1 hex 位（0-based, 12 月 = 0B）
        DD    → 2 hex 位
        示例：到期 2026-12-31 → year=20 1E → 1E0C1F

CDKEY：a3f5c8e1b9d2f4c7e8a1 1E0C1F
```

### 4.2 视觉展示（5-5-5-5-5 输入分组）

```
┌─────────────────────────────────────────────────────────┐
│  注册码：XXXXX-XXXXX-XXXXX-XXXXX-XXXXX（自动分组输入）    │
└─────────────────────────────────────────────────────────┘
```

## 六、完整业务流程（端到端）

### 6.1 全新安装

```
1. 用户安装 DormManage.TrayApp.exe
2. 用户双击 DormManage.TrayApp.exe
3. 单实例 Mutex → 暗桩校验 → 机器码 WMI 初始化
4. machine.dat 写入 BFEBFBFF000A06A4AA2E3B0E
5. 托盘图标显示
6. ProcessManager.StartAllAsync → IsLicenseValid() = false (UseTimes=1<30 但 RegInt=-1)
   → 仍可启动子进程（试用模式）
7. Web Admin + Api 启动成功
8. LicenseMonitor 周期探测 → 日志记录
9. 用户右键托盘 → 软件注册授权 → LicenseForm 显示
10. 看到机器码：BFEBF-BFF00-0A06A-4AA2E-3B0E
11. 复制按钮 → 剪贴板：BFEBFBFF000A06A4AA2E3B0E
12. 发给供应商 → 获取 CDKEY
```

### 6.2 注册流程

```
13. 用户在 LicenseForm 输入：
    - 公司名称：金戈测试有限公司
    - 注册码：ABCDE-12345-FGHJK-67890-LMNOP（5-5-5-5-5）
14. 点击「注册」按钮
15. CheckRegCDKey 校验：
    - MD5("BFEBFBFF000A06A4AA2E3B0E" + "金戈测试有限公司" + SECRET_KEY).Substring(0, 20) == CDKEY 前 20 位？
    - 日期段解码 → 到期日 2026-12-31
16. 校验通过 → WriteRegItem 写入 HKLM/HKCU/license.dat
17. LicenseGuard.ResetCache() → 通知 Web/Api 中间件刷新缓存
18. LicenseMonitor 5s 内检测到状态变化 → 推送 regstate.changed
19. LoadRegState() → labRegInfo = "✅ 此软件已注册"
20. 提示："🎉 注册成功！有效期至 2026年12月31日"
```

### 6.3 取消注册流程

```
21. 用户点击「取消注册」按钮（btnReg.Text != "注册"）
22. 弹确认框："确认取消注册？"
23. 用户确认 → DeleteRegItem
24. LicenseGuard.ResetCache() → Web/Api 进入只读模式
25. LicenseMonitor 5s 内检测 → 推送
26. labRegInfo = "❌ 此软件尚未注册"
```

### 6.4 注册过期流程

```
27. 到期日 < 当前日期
28. RegisterSdk.CheckReg() → RegInt = 0
29. labRegInfo = "⚠️ 许可已过期"
30. LicenseGuard.IsReadOnly() = true（v2.13.137 IPC 查询）
31. Web/Api 中间件：POST/PUT/DELETE → 403 JSON
32. 用户必须重新注册或清理后试用
```

## 八、永久教训（v2.13.94 → v2.13.139 共 12 条）

### 8.1 架构层面

1. **Web 端是「被验证者」不是「验证者」**（v2.13.136）—— 所有 CDKEY 写入/校验逻辑必须在托盘端
2. **决策权威必须唯一收敛**（v2.13.137）—— 1 个进程（托盘）独占注册表访问权 + 6 个 IPC 端点
3. **进程从属必须显式**（v2.13.137）—— 4 层约束（启动权 / 运行依赖 / 业务权限 / 物理可达性）
4. **默认只读策略**（v2.13.137）—— 托盘不可用 → 子进程一律进入只读模式

### 8.2 UI 层面

5. **机器码视觉分组 5-5-5-5-4**（v2.13.138）—— NPGS 规范，与 CDKEY 输入风格对齐
6. **SN 字段约定必须明确**（v2.13.138）—— raw（24 hex）vs display（28 字符），业务层恒用 raw
7. **不要让数据层做展示格式化**（v2.13.138）—— `GetSN()` 不应返回 display 形式

### 8.3 算法层面

8. **NPGS 算法纯 hex 拼接**（v2.13.94）—— `(CPU + Volume).Substring(0, 24)`，不经过任何哈希
9. **WMI VolumeSerialNumber 是 hex 字符串**（v2.13.139）—— 不要 `long.TryParse` 后再 `ToString("X8")`（会失败）
10. **三层降级顺序**（v2.13.94）—— env > file > MD5 fallback
11. **去连字符兼容层是 BUG 滋生地**（v2.13.138）—— `CheckRegCDKey(SN.Replace("-",""))` 掩盖了 raw vs display 混用

### 8.4 安全层面

12. **暗桩 vs 注册授权是两套独立机制**（v2.13.135）—— 取较早到期日（最严格优先）
