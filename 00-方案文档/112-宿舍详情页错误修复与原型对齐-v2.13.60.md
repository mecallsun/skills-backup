## 二、深度根因排查

### 2.1 开发模式错误堆栈

```
fail: Microsoft.EntityFrameworkCore.Query[10100]
System.Data.SqlTypes.SqlNullValueException: Data is Null.
This method or property cannot be called on Null values.
   at Microsoft.Data.SqlClient.SqlBuffer.ThrowIfNull()
   at Microsoft.Data.SqlClient.SqlBuffer.get_String()
   at Microsoft.Data.SqlClient.SqlDataReader.GetString(Int32 i)
   at lambda_method460(Closure, DbDataReader, Int32[])
   at Microsoft.EntityFrameworkCore.Query.Internal.BufferedDataReader.BufferedDataRecord.ReadObject(...)
```

### 2.2 第一层错误：Dorm 表 5 列缺失

```
Microsoft.Data.SqlClient.SqlException (0x80131904):
列名 'LastColdMeter' 无效。
列名 'LastElectricMeter' 无效。
列名 'LastHotMeter' 无效。
列名 'LastReadAt' 无效。
列名 'LastReadMonth' 无效。
```

**根因**：`Dorm.cs` 模型在 v2.13.24 P77 新增了 5 个 PDA 抄表缓存字段（`LastColdMeter` / `LastHotMeter` / `LastElectricMeter` / `LastReadAt` / `LastReadMonth`），但生产数据库 Dorm 表是早期手工创建，缺少这 5 个列。EF Core 物化 Dorm 实体时 SELECT 包含全部映射字段 → 列名无效异常。

### 2.3 第二层错误：Barcode 列全表 NULL

修复 5 列后再次访问，触发 `SqlNullValueException`：

```sql
SELECT DormId, DormCode, Building, Floor, RoomNo, DormAddress, DormType,
       HasColdMeter, HasHotMeter, HasElectricMeter, Barcode, ...
FROM Dorm
```

**审计生产数据**：
```python
cur.execute("SELECT COUNT(*) FROM Dorm WHERE Barcode IS NULL")
# 140 (all rows!)
```

**根因**：所有 140 条 Dorm 行 `Barcode = NULL`，但 EF 模型中 `Barcode` 是 `[Required] string`，EF Core 物化时调用 `GetString()` 抛错。

### 2.4 与 v2.13.57/58/59 同模式（生产数据库早期手工建表）

| 表 | v2.13.57/58 修复 | v2.13.59 修复 | v2.13.60 修复 |
|----|----------------|---------------|---------------|
| DormBooking | DDL 缺失 | 4 字段 nullable | — |
| SysEmployee | DDL 缺失 | — | — |
| Dorm | — | — | 5 列缺失 + Barcode NULL 填充 |

## 三、修复方案

### 3.1 SQL 数据修复（P0）

```sql
-- 1. 补充 5 个 Dorm 列（v2.13.24 P77 缺失）
ALTER TABLE dbo.Dorm ADD LastReadMonth     NVARCHAR(7) NULL;
ALTER TABLE dbo.Dorm ADD LastColdMeter     DECIMAL(12,2) NULL;
ALTER TABLE dbo.Dorm ADD LastHotMeter      DECIMAL(12,2) NULL;
ALTER TABLE dbo.Dorm ADD LastElectricMeter DECIMAL(12,2) NULL;
ALTER TABLE dbo.Dorm ADD LastReadAt        DATETIME NULL;

-- 2. 填充 Barcode NULL（v2.13.24 P77 之前 Dorm 表无 Barcode 字段，140 行 NULL）
UPDATE dbo.Dorm SET Barcode = DormCode WHERE Barcode IS NULL;
```

执行结果：
- 5 列成功添加
- 140 行 Barcode 已用 DormCode 填充（合理默认值，Barcode 是 PDA 扫码关键字段，必须保留非空）

## 七、教训总结（v2.13.60）

### 7.1 两个核心问题

1. ❌ **生产数据库早期手工建表** 与 EF 模型不一致（v2.13.24 P77 新增字段未执行 DDL）
2. ❌ **历史脏数据**：`Barcode` 字段 140 行 NULL（v2.13.24 之前 Dorm 表无此字段）

### 7.2 后续强制检查清单（每次新增 EF 字段时）

- [ ] 在 `init_schema.sql` 中添加新字段 DDL（生产 DB 同步）
- [ ] 检查生产数据库表实际列约束（不是仅依赖 EF 模型）
- [ ] 检查生产数据库历史 NULL 数据，必要时 SQL UPDATE 回填
- [ ] P0 BUG 修复后必须实际访问页面验证 HTTP 200 + 内容正确（不只检查 API）

### 7.3 运维强制检查清单（早期手工建表）

- [ ] 新增 EF 字段时同步通知 DBA 执行 SQL
- [ ] 提供 EF 模型与生产 DB 的字段对账报告
