## 三、列表异常可见化（v2.13.174 增强）

### 3.1 问题复盘

v2.13.174 给 `Index.cshtml.cs` 的 `equipmentreading` tab 数据加载加了 try-catch，但 catch 块仅写 `System.Diagnostics.Debug.WriteLine`：

```csharp
catch (Exception ex)
{
    System.Diagnostics.Debug.WriteLine($"[BASICS] equipmentreading 加载失败: {ex}");
    EquipmentReadings = new List<EquipmentReadingDto>();
}
```

生产环境中**Debug.WriteLine 不可见**——用户只看到空列表 + "暂无设备记录数据（共 0 条）"，但实际可能是 SQL 异常、表不存在、列名不匹配等。

### 3.2 修复方案：TempData + 红色错误横幅

#### 3.2.1 后端：`Index.cshtml.cs`（第 185-192 行）

```csharp
catch (Exception ex)
{
    // v2.13.174 try-catch：异常时通过 TempData 显示错误提示而非空白列表
    // Debug.WriteLine 仅开发环境可见，TempData 在前端渲染警告横幅
    System.Diagnostics.Debug.WriteLine($"[BASICS] equipmentreading 加载失败: {ex}");
    EquipmentReadings = new List<EquipmentReadingDto>();
    TempData["EquipmentReadingError"] = $"设备记录加载失败：{ex.Message}。请查看浏览器控制台(F12)获取详情。";
}
```

#### 3.2.2 前端：`Index.cshtml`（第 342-349 行）

```html
@if (Model.ActiveTab == "equipmentreading")
{
    <!-- v2.13.177：设备记录加载错误提示（try-catch 捕获的异常通过 TempData 显示） -->
    @if (TempData.ContainsKey("EquipmentReadingError"))
    {
        <div class="alert alert-danger py-2 mb-3" role="alert">
            <i class="bi bi-exclamation-triangle-fill"></i>
            @(TempData["EquipmentReadingError"] as string ?? "设备记录加载失败，请查看浏览器控制台(F12)获取详情。")
        </div>
    }
    <div class="card">...
```

### 3.3 永久教训

1. **catch 块不能只写 Debug.WriteLine**——必须将异常信息传递给前端可见层（TempData / ViewBag / ViewData）
2. **空列表与加载失败要有视觉差异**——只有明确区分"无数据"和"加载失败"，用户才能正确判断下一步
3. **错误信息要含「该怎么做」**——"请查看浏览器控制台(F12)获取详情"是引导式提示，告知用户下一步操作
