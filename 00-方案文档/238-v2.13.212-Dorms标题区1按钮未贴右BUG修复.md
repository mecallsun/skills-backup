## 2. BUG 根因分析（v2.13.165 时代遗留 + v2.13.211 修复遗漏）

### 2.1 PageHeader 组件 DOM 结构

`DormManage.Admin/Pages/Shared/Components/PageHeader/Default.cshtml` 第 20-21 行：

```html
<!-- 修复前：v2.13.165 时代遗留的中间层 space-between -->
<div class="page-header mb-3">
    <div class="d-flex justify-content-between align-items-center">      ← BUG 在这里
        <h2 class="mb-0 d-flex align-items-center">...</h2>
        <div class="d-flex align-items-center gap-2 page-header-actions flex-nowrap ms-auto">
            <a href="/Dorms/Create" class="btn btn-success btn-sm text-nowrap">
                <i class="bi bi-plus-lg"></i> 新增宿舍
            </a>
        </div>
    </div>
</div>
```

### 2.2 CSS 优先级分析

| 层 | class | CSS | 实际效果 |
|---|-------|-----|---------|
| 外层 | `.page-header` | `display:flex; justify-content:flex-start`（v2.13.211 改） | 控制中间层位置 |
| 中间层 | `.d-flex.justify-content-between`（Bootstrap） | **`space-between`** | **h2 和按钮组两端对齐** ❌ |
| 按钮组 | `.page-header-actions.ms-auto` | `margin-left:auto` | 期望贴右 |

### 2.3 问题表现

**当 PageHeader 只有 1 个 PrimaryAction（Dorms/BillingStandard 场景）**：
- 中间层 `space-between`：h2 贴左 + 按钮组贴右 + **中间留最大间距**
- 按钮组被推到距离 h2 最远的位置
- **视觉上按钮组不贴 page-header 最右边缘**，而是与右边缘有一段距离

**当有 2+ 个按钮时（Personnel/Meter/Booking）**：
- 按钮组总宽度较大，可能视觉上接近贴右
- 但仍有空间被 `space-between` 浪费，**不严格贴右**

### 2.4 v2.13.211 修复遗漏点

v2.13.211 修复时只改了**外层** `.page-header { justify-content: flex-start }`，**漏改了中间层** `<div class="d-flex justify-content-between align-items-center">`：

- v2.13.165 commit `cdf44bc`：引入中间层 `justify-content-between`（space-between）
- v2.13.211：仅改外层 `.page-header`，**中间层仍是 space-between**

## 3. 修复方案（v2.13.212）

### 3.1 修改 `Default.cshtml:21`

```html
<!-- 旧 -->
<div class="d-flex justify-content-between align-items-center">

<!-- 新 -->
<div class="d-flex align-items-center">
```

### 3.2 完整三层防线（v2.13.212 最终方案）

| 层 | 元素 | CSS / Class | 作用 |
|---|------|-------------|------|
| 外层 | `.page-header` | `display:flex; justify-content:flex-start` | h2 与按钮组都从左对齐开始 |
| 中间层 | `<div class="d-flex align-items-center">`（v2.13.212 删除 space-between） | 不再有 space-between 干扰 | 仅保留对齐 |
| 按钮组 | `.page-header-actions.ms-auto` | `margin-left:auto` | 吸收所有剩余水平空间，贴右 |

**三者缺一不可**：
- 仅有外层 `flex-start` + 按钮组 `ms-auto`（无中间层修复）：中间层 `space-between` 会抵消效果
- 仅有中间层修复 + 按钮组 `ms-auto`（无外层）：外层 `space-between` 会干扰

### 3.3 修复前后对比

| 页面 | 修复前（v2.13.211） | 修复后（v2.13.212） |
|------|---------------------|---------------------|
| 宿舍档案（1 按钮） | 按钮距 page-header 右边缘有较大空白 | 按钮严格贴右 ✅ |
| 费用标准（1 按钮） | 同上 | 按钮严格贴右 ✅ |
| 人员清单（3 按钮） | 接近贴右但仍有微小空白 | 严格贴右 ✅ |
| 智能抄表（3 按钮 + 副标题） | h2 副标题挤压按钮组 | 按钮组位置完全独立 + 贴右 ✅ |
| 办理登记（4 按钮） | 同上 | 严格贴右 ✅ |

## 6. 永久教训（v2.13.212+ 强制沉淀）

### 6.1 三层防线必须一起改

修改 flex 布局靠右时，**任何一层都可能破坏效果**。本次 v2.13.211 只改了外层 `.page-header`，漏改了中间层 `<div class="d-flex justify-content-between">`，导致 BUG。**修复时必须三层全部检查**：外层 + 中间层 + 子元素 margin。

### 6.2 1 按钮场景特别容易暴露 BUG

当有 2+ 个按钮时，按钮组总宽度较大，肉眼难以察觉 space-between 带来的空白；当只有 1 个按钮时，按钮组被推到 h2 右侧最大间距处，BUG 非常明显。**修复时必须考虑最少按钮的场景**。

### 6.3 DOM 结构审查 = BUG 排查的第一步

用户反馈「程序没有按需求靠右，但原型是正确」时，**第一步永远是审查程序的 DOM 结构与原型的差异**。本次 BUG 是因为程序多了一层 `justify-content-between` 的中间 div，原型没有这层。

### 6.4 PageHeader 组件是全站共享的，单点修复全局生效

本次仅修改 1 个文件（`Default.cshtml:21`），但全站 8 个列表页 + Settings 用户管理 Tab 全部生效。PageHeader 组件作为全局共享组件，**修改时要特别谨慎，必须考虑所有调用场景**（1 按钮 / 2 按钮 / 3 按钮 / 4 按钮 / 有副标题）。
