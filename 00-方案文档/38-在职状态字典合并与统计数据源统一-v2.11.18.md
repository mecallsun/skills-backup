## 1. 变更背景

### 1.1 用户反馈的 BUG

> 当前原型首页的统计显示"入住人数"为 571 人，但我在人员清单中，查询 房号 值非空 的记录数 为 550 条记录，请检查不一致的原因并修复 BUG

### 1.2 BUG 根因分析

经 mock-data.js 数据分析发现：

| 项目 | 数量 | 计算逻辑 |
|------|------|---------|
| PERSONNEL 总记录 | 650 | — |
| **首页 KPI 1 入住人数** | **571** | `PERSONNEL.filter(p => p.dormCode !== null && p.dormCode !== '').length` |
| **人员清单房号非空** | **550 / 548** | `getLatestDormCode(p)` 基于 BOOKINGS 最后一条有效记录 |
| **差异** | **21-24 条** | PERSONNEL.dormCode 与 BOOKINGS 状态不同步 |

**24 条差异记录示例**（ID=41, 55, 60, 70, 88, 90, 93, 125, 143, 155…）：

| ID | 姓名 | PERSONNEL.dormCode | BOOKINGS 最后一条 | 差异原因 |
|----|------|-------------------|------------------|---------|
| 41 | 阎思 | D-185 | type=1, status=1, dormCode=D-107 | 预约未入住但 PERSONNEL 仍有房号 |
| 55 | 常涛 | D-143 | type=1, status=4, dormCode=D-078 | 已取消但 PERSONNEL 仍有房号 |
| 88 | 夏小红 | D-175 | type=2, status=3, dormCode=D-175 | 已退房但 PERSONNEL 仍有房号 |
| 93 | 朱洋 | D-152 | type=1, status=3, dormCode=D-152 | 入住但已退房 |

**根因总结**：
- PERSONNEL.dormCode 字段是**冗余缓存字段**，但 BOOKINGS 操作（入住/退房/预约/撤销）从未同步更新此字段
- 单一数据源原则被破坏：KPI 1 使用 PERSONNEL.dormCode（缓存），人员清单使用 BOOKINGS 派生（实时）

## 2. 核心规则（v2.11.18 起强制执行）

### 2.1 入住人数统计规则

> **入住人数 = count(PERSONNEL where DormCode IS NOT NULL AND DormCode <> '')**

| 项目 | 内容 |
|------|------|
| **数据源** | PERSONNEL（人员清单） |
| **统计字段** | `DormCode`（NVARCHAR(20)，FK→Dorm.DormCode） |
| **统计条件** | `DormCode IS NOT NULL AND DormCode <> ''` |
| **是否包含在职状态** | **否**（无论 employmentStatusId 是 1=在职 / 2=待入职 / 3=已离职） |
| **统计时机** | 实时（每次页面渲染时从 PERSONNEL 表查询） |

### 2.2 异常人员统计规则（v2.11.18 修订）

> **异常人员 = A + B + C**

| 分项 | 含义 | 数据源 | 统计规则 |
|------|------|--------|---------|
| **A** | 在职状态非"在职" 且 房号不为空 | PERSONNEL | `employmentStatusId != 1 AND dormCode IS NOT NULL AND dormCode <> ''` |
| **B** | 在职但未到入职日期提前入住 | PERSONNEL | `employmentStatusId == 1 AND dormCode IS NOT NULL AND hireDate > today` |
| **C** | 超期未按时办理入住/退房 | BOOKINGS | `status == 1 AND bookingDate < today` |

**v2.11.18 修订要点**：
- A 项原 v2.11.6 规则 `status == 3`（仅已离职）改为 `employmentStatusId != 1`（非"在职"，包括待入职+已离职）
- 关联引用基础资料-在职状态表 EmploymentStatus：`name = "在职"` 对应 `id = 1`
- 未来如新增"停薪留职"等状态，规则自动适配（仅需在 EmploymentStatus 表新增条目）

### 2.3 办理登记同步规则（v2.11.18 强制）

> **办理登记的所有操作必须同步更新 PERSONNEL.dormCode 和住宿状态**

| 操作 | PERSONNEL.dormCode 变化 | 住宿状态（基础资料 ResidenceStatus） |
|------|------------------------|-----------------------------------|
| **入住 / 快速确认入住** | 同步更新 = 该记录 dormCode | LODGED（已住宿） |
| **撤销退房** | 同步更新 = 该记录 dormCode | LODGED（已住宿） |
| **退房 / 创建退房记录** | 同步清空 = NULL | NOT_LODGED（未住宿） |
| **撤销在宿（仅今日）** | 同步清空 = NULL | NOT_LODGED（未住宿） |
| **撤销预约（未生效）** | 不变更（预约从未生效过 dormCode） | NOT_LODGED（未住宿） |
| **修改记录（非状态变更）** | 不变更 | 不变更 |

**实现位置**：`DormManage.Shared/Services/BookingService.cs` → 新增 `SyncEmployeeDormCodeAsync()` 私有方法

## 3. 在职状态字典合并（v2.11.18 强制）

### 3.1 单一数据源原则

> **基础资料-在职状态表（EmploymentStatus）是"在职状态"取值的唯一数据源**

| 关联对象 | 数据库存储字段 | 显示字段 | 关联引用 |
|---------|--------------|---------|---------|
| **SysEmployee** | `EmploymentStatusId INT` | `EmploymentStatus.Name` | FK→EmploymentStatus.Id |
| **PERSONNEL** | `employmentStatusId INT` | `employmentStatusName` | 引用 EMPLOYMENT_STATUSES 字典 |
| **人员清单 Badge** | — | "在职"/"待入职"/"已离职" | 通过 FK JOIN 获取 |

### 3.2 强制规范

| # | 规则 | 强制级别 |
|---|------|---------|
| 1 | SysEmployee.EmploymentStatusId 必须引用 EmploymentStatus.Id 有效值（1-3） | 🔴 强制 |
| 2 | 所有"在职状态"展示必须通过 FK 关联 EmploymentStatus 获取 Name | 🔴 强制 |
| 3 | 不得在业务表/前端硬编码"在职"等枚举值 | 🔴 强制 |
| 4 | SysEmployee.Status int 字段保留为向后兼容（标记 [Obsolete]），新代码必须用 EmploymentStatusId | 🟡 警告 |
| 5 | 任何页面新增的"在职状态"下拉必须从 EmploymentStatus 表读取 | 🔴 强制 |

### 3.3 数据迁移

**现有数据迁移（v2.11.18 一次性迁移）**：
```sql
-- 为现有 SysEmployee 记录补全 EmploymentStatusId
UPDATE SysEmployee SET EmploymentStatusId = Status WHERE EmploymentStatusId = 0 OR EmploymentStatusId IS NULL;
```
