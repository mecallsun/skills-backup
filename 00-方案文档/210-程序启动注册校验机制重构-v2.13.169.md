## 一、问题与需求

### 用户原话（2026-07-26 反馈）
> "启动 本项目程序时，提示：启动失败：注册校验未通过，禁止启动Web服务。这个机制与之前的系统方案不符，现在统一更正所有文档及开发方案、功能需求为：当未检测到注册信息时，则启动 **试用模式**（之前已定义规则机制），进行 试用次数 计数且有 数据 记录条数的 约束；当 注册校验 的 有效期 小于当前主机时间或服务端主机时间时，则进入 **只读模式**（之前版已定义规则机制）；当 注册校验 失败【即指 服务端的 机器码 或 公司名称 经过 调用注册校验方法 都与 注册码 的信息 不相符，即认定为非合法注册信息（如：其他 合法注册的 主机 注册后，再复制程序 到另一台主机上运行等类似非法场景），即显示 **注册校验失败**】；因此当主机已有注册信息，仅是注册许可的有效期 的日期 已小于当前 服务端主机 日期 或 浏览器访问客户端主机的 日期时，则仅提示 许可已过期，必须进入 只读模式 仍然可以正常启动程序；请全面理解 深度分析 前面描述功能与机制逻辑关系的意思 并专业处理这个 在程序启动 校验注册信息的机制；然后全面梳理并统一整理到最新版 项目相关文档中，清理旧版过时描述。"

### 核心矛盾（排查结论）
1. **v2.13.137 `ProcessManager.IsLicenseValid()` 硬阻断启动 [v2.13.194 起逐步修订, v2.13.196 完全移除]**：旧逻辑对过期/超试用一律拒绝启动，违反「程序永远能启动」原则。v2.13.196 后：所有注册状态都允许启动，仅运行模式（试用/注册/只读）不同，超试用次数时强制弹窗确认。
2. **`RegisterSdk.CheckReg()` 的 `RegInt==0` 混淆两种情况**：把「合法注册但过期」与「机器码/公司名不符=非法复制」混为一谈，无法差异化提示。
3. **v2.13.135 暗桩**（`RuntimeWindowGuard` + `TamperDialog` + `5-2-0` 解锁）：过期时 Api 静默退出 / Admin 返回 503 伪装错误框；2027-01-30 后会重现"启动失败"。
4. **v2.13.149/150 试用次数 UseTimes 门槛**：从未生效（仓库内无 `IncrementUseTimes()` 调用方）；用户改用「仅记录条数上限」即可。
5. **客户端日期校验缺失**：仅服务端 `DateTime.Today` 校验，未对比浏览器本地日期。

## 二、最终授权状态矩阵（唯一权威）

| 状态 RegStatus | int | 判定 | 启动 | IsReadOnly | IsTrial | 提示 |
|---|---|---|---|---|---|---|
| **Unregistered** | -1 | 无 CDKEY | ✅ | false | **true** | 试用模式（住宿 500/宿舍 5/人员 5 记录上限） |
| **Valid** | 1 | 校验通过 + RegDate≥今天 | ✅ | false | false | 正常（绿色徽章） |
| **Expired** | 2 | 校验通过 **但** RegDate<今天 | ✅ | **true** | false | ⚠ 许可已过期，只读模式 |
| **Invalid** | 3 | 机器码或公司名 与 CDKEY 不符 = 非法复制 | ✅ | **true** | false | 🚫 注册校验失败（疑似非法复制），只读模式 |

**不变量**：程序永远能启动（5 状态全部 ✅），运行期降级由 `LicenseGuard.IsReadOnly()` + `LicenseReadOnlyMiddleware` 落地。

**RegInt 兼容映射**（保留向后兼容）：Valid→1，Expired/Invalid→0，Unregistered→-1。

public static bool IsReadOnly()
{
    var state = GetCachedState();
    if (state is null) return true;  // 托盘不可用 → 默认只读（安全）
    var status = (RegStatus)state.RegStatus;
    if (status == RegStatus.Expired || status == RegStatus.Invalid) return true;

}

## 七、永久教训（5 条）

1. **「程序永远启动，只决定运行模式」应是基础假设**——v2.13.137「未注册/过期拒绝启动」属反模式，仅在**业务硬约束不可降级**场景（数据完整性、安全认证）才适用。授权/版本/试用类约束均应降级而非阻断。
2. **状态枚举必须早于布尔判定**——`RegInt` 三态（-1/0/1）把 0 留给两种情况（过期/校验失败）属命名空间过载；任何 0 值含义超过一种的枚举/常量都应立即拆为独立枚举。这是经典 N+1 bug（一个返回码混多个语义）。
3. **「未引用的方法」也是文档谎言**——`RegisterSdk.IncrementUseTimes()` 定义了但全仓库无人调用，文档却仍描述 UseTimes 门槛生效。定义 ≠ 实装 ≠ 跑通，三者必须都有验证证据（grep 调用方 + 端到端 HTTP）。
4. **客户端日期与服务端日期要双校验**——攻击者改本地日期让"过期"判定失效；同时合法用户的本地时间可能漂移（笔记本时区）。服务端用 `DateTime.Today` 服务端时区，客户端在徽章后再做一次 client-side `new Date()` 比较，是双层防护。
5. **废弃代码必须 4 维度清零**——删除某个安全机制（暗桩）时需 grep 4 个维度：① 实现文件 ② Program.cs 启动块 ③ Obfuscar 配置 ④ 中间件白名单 + 文档引用。仅删文件、Program.cs 还残留 `if (TamperDialog.Show())` 是常见漏洞。
