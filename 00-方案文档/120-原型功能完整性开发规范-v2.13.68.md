- `console.log('[v2.13.x] xxx')` 调试日志，OK
- `Resources/strings.resx` 翻译文本，OK

### ✅ 检查 2：每个按钮都有可执行入口

| UI 元素 | 必须配置 |
|---------|---------|
| `<button>` | `onclick` / `asp-page-handler` / `<form>` 内 + `type=submit` |
| `<a class="btn">` | `href` 真实有效路由 |
| `<button data-bs-toggle="modal">` | `data-bs-target="#xxxModal"` 指向已存在的 modal |
| 后端 handler | Controller / PageModel 必须有对应方法，否则 404 |

**自动测试**：
```bash
# 抽取所有 onclick 和 href 调用
grep -rn "onclick=\|href=" DormManage.Admin/Pages/ | \
  grep -oE "(onclick=\"[a-zA-Z_]+\(|href=\"[^\"]+\")" | sort -u
```
对每个函数名 / URL，必须能在 PageModel / Controller / JS 中找到实现。

### ✅ 检查 3：业务硬约束在 Service 层真实实现

| 业务规则 | 必须落地点 |
|---------|----------|
| 状态机 `status=1/2` 不可覆盖 | `*Service.SaveXxxAsync` 含 `existing.Status == 1/2 → reject` |
| 读数必须 ≥ 上月 | `*Service` 含 `if (new < prev) return error` |
| 字段必填校验 | `[Required]` + 后端双重校验 |
| FK 约束 | Service 含 `existing == null → reject` |

**禁止**仅前端 JS alert 阻断 —— 后端必须独立校验。

### ✅ 检查 4：操作真实落库

| 操作 | 禁止模式 | 必须模式 |
|------|---------|---------|
| 新增 | `TempData["msg"]=...;RedirectToPage()` | `_db.Add(); await SaveChangesAsync();` |
| 编辑 | 同上 + 演示文字 | `existing.X = ...; await SaveChangesAsync();` |
| 删除 | 仅前端隐藏 | `_db.Remove(); await SaveChangesAsync();` |
| 导入 | 仅返回校验报告 | 校验通过的行 → `Add` 或 `Update` + SaveChanges |
| 导出 | `<a href="#" onclick="alert()">` | 真实生成 Excel / CSV 流返回 |

### ✅ 检查 5：变更前先对比原型

**强制 5 步**：
1. **读原型**：定位 `00-方案文档/04-HTML原型/.../目标页.html`
2. **读代码**：定位当前 `Pages/.../目标页.cshtml` + `.cshtml.cs`
3. **逐字段对比**：原型有的字段/按钮，代码也要有
4. **逐交互对比**：原型的 `onclick` / `fetch` / `submit` 都要真实实现
5. **输差异清单**：在 PR 描述或文档中列出 ✅ 已实现 + ⚠️ 待实现

### ✅ 检查 6：无法 1:1 时主动提示

**必须显式告知**（不得隐藏）：
- ✅ 已完成：清单 + 截图/日志证据
- ⚠️ 降级实现：哪些字段/按钮没做，原因（如"分页由前端切分代替 API"）
- 🔴 未做：哪些原型功能完全不实现（如"扫码上传硬件依赖"）

**对话固定格式**：
```
## 实现情况
✅ 已完成：xxx (证据: file_path + line)
⚠️ 降级实现：xxx (原因: ...)
🔴 未做：xxx (原因: 依赖外部硬件 / 用户后续确认)
```

### ✅ 检查 7：commit 描述含原型对比

`feat({module}): v{ver} {页面名} 100% 原型对齐`

提交信息必须包含：
- 原型路径（`00-方案文档/04-HTML原型/{module}/{page}.html`）
- 已实现清单
- 占位符清零证据（grep 数量）

## 四、自动化检测脚本

### 4.1 占位符扫描

```bash
#!/bin/bash
# scan_placeholders.sh — 项目根目录执行

echo "=== 占位符全局扫描（P0 反例） ==="
echo ""

patterns=(
  "alert('原型演示"
  "alert(\"原型演示"
  "placeholder.*待实现"
  "TODO.*实现"
  "演示："
  "演示:"
  "原型演示"
)

total=0
for p in "${patterns[@]}"; do
    count=$(grep -rn "$p" DormManage.Admin/Pages/ DormManage.Api/ 2>/dev/null | wc -l)
    if [ "$count" -gt 0 ]; then
        echo "❌ $p : $count 处"
        grep -rn "$p" DormManage.Admin/Pages/ DormManage.Api/ 2>/dev/null | head -5
        total=$((total + count))
    fi
done

if [ "$total" -eq 0 ]; then
    echo "✅ 0 命中 — 项目通过检查"
else
    echo ""
    echo "⚠️  共 $total 处需要修复"
fi
```

### 4.2 按钮可达性验证

```bash
#!/bin/bash
# check_buttons.sh — 验证所有 onclick 函数都被实现

echo "=== onclick 函数引用 ==="
grep -rohE "onclick=\"[a-zA-Z_]+\(" DormManage.Admin/Pages/ 2>/dev/null | \
    grep -oE "[a-zA-Z_]+" | sort -u > /tmp/used_funcs.txt

echo "=== JS 中的函数定义 ==="
grep -rhE "function [a-zA-Z_]+\(" DormManage.Admin/Pages/ 2>/dev/null | \
    grep -oE "function [a-zA-Z_]+" | grep -oE "[a-zA-Z_]+$" | sort -u > /tmp/def_funcs.txt

echo "=== 未定义的函数引用 ==="
comm -23 /tmp/used_funcs.txt /tmp/def_funcs.txt | grep -v "^$"
```

### 4.3 Handler 可达性验证

```bash
#!/bin/bash
# check_handlers.sh — 验证所有 asp-page-handler 都有对应方法

grep -rohE 'asp-page-handler="[A-Za-z]+"' DormManage.Admin/Pages/ 2>/dev/null | \
    grep -oE '"[A-Za-z]+"' | tr -d '"' | sort -u > /tmp/used_handlers.txt

grep -rhE "public.* OnPost[A-Za-z]+Async" DormManage.Admin/Pages/ 2>/dev/null | \
    grep -oE "OnPost[A-Za-z]+Async" | sed 's/^OnPost//;s/Async$//' | sort -u > /tmp/def_handlers.txt

comm -23 /tmp/used_handlers.txt /tmp/def_handlers.txt
```
