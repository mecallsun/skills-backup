### 4.3 PDA 上传验证

```
POST /api/v1/pda/upload
Header: X-Machine-SN: <24位hex>
Body: { metadata, coldImage, hotImage, electricImage }

→ 优先读 X-Machine-SN
→ fallback: DORM_MACHINE_SN 环境变量
→ fallback: machine.dat 文件
→ fallback: MD5(MachineName + ProcessorCount + OSVersion)
→ RegisterSdk.CheckReg() 返回 RegInt != 1 → 返回 LICENSE_INVALID
```

### 5.1 RuntimeWindowGuard.GetEffectiveDeadline

```csharp
public static DateTime GetEffectiveDeadline()
{
    var tamperLimit = ValidTo;
    try
    {
        var reg = RegisterSdk.CheckReg();
        if (reg.RegInt == 1 && reg.RegDate.HasValue && reg.RegDate.Value < tamperLimit)
        {
            return reg.RegDate.Value;
        }
    }
    catch { }
    return tamperLimit;
}
```

### 5.2 UnlockSequenceBuffer.Feed

```csharp
public static bool Feed(int keyCode)
{
    lock (_lock)
    {
        _buffer.Add(keyCode);
        if (_buffer.Count > _targetSequence.Length) _buffer.RemoveAt(0);
        if (_buffer.Count == _targetSequence.Length)
        {
            bool match = true;
            for (int i = 0; i < _targetSequence.Length; i++)
                if (_buffer[i] != _targetSequence[i]) { match = false; break; }
            if (match) { Reset(); return true; }
        }
    }
    return false;
}
```

## 七、永久教训

### 7.1 暗桩 vs 注册授权是两套独立机制

| 维度 | 暗桩（v2.13.135）| 注册授权（v2.13.94）|
|------|------------------|--------------------|
| 时间窗口 | 硬编码 2026-06-01 ~ 2027-01-30 | CDKEY 内 RegDate 字段（可变）|
| 校验时机 | 启动时同步阻塞 | API 端点按需校验 |
| 过期表现 | 伪装内存错误框 + 5-2-0 解锁 | API 返回 LICENSE_INVALID |
| 用户感知 | "系统内存出错"（无业务信息）| "终端未注册"（业务信息）|

**两者取较早**：双层防御时**最严格优先**。否则用户会在 2027-01-31 解锁暗桩后继续使用，但实际授权已 2026-12-01 过期。

### 7.2 5-2-0 解锁序列是「维护通道」

| 项目 | 实现要点 |
|------|---------|
| **TrayApp** | WinForms KeyDown 监听；`KeyPreview = true` 让 Form 在控件前接收 KeyDown |
| **Admin** | 全局 JS keydown 监听；页面跳转不丢失状态（JS 在 503 页面内嵌）|
| **Api** | ❌ 无界面，无法实现 |

**教训**：维护通道必须有，但**不能让用户轻易发现**。当前序列 `5-2-0` 是 3 位纯数字，可改为更隐蔽的多键组合（如 `Ctrl+Shift+L, Ctrl+Shift+I, Ctrl+Shift+C`）。

### 7.3 Obfuscar 跳过规则是反混淆与可调试性的平衡

- **必须跳过**：入口 Program 类（含 Main + 暗桩代码 + 启动流程）
- **必须跳过**：RegisterSdk 命名空间（外部注册机依赖方法名）
- **必须跳过**：Security 命名空间（暗桩逻辑需可读）
- **可全量混淆**：业务 Service 层、DTO 类、EF 实体

**教训**：混淆是「源码可读性」对抗，「业务功能正确性」无关。混淆后**必须**做端到端功能测试，否则可能因 skipTypes 配置错误导致运行时崩溃（EF 字段反射、JSON 序列化都会失效）。

### 7.4 BitMono 仅适用单文件 EXE

仓库物料汇总测试报告：6 项稳定保护与 WPF + CommunityToolkit.Mvvm 兼容。本项目 TrayApp 是 WinForms + .NET 8，**理论兼容但需验证**。**Api/Admin 是 ASP.NET Core，加壳会破坏反射（运行时 JIT/路由解析），故仅 TrayApp**。

**教训**：PE 级别加壳会破坏 .NET 反射元数据，**只适用于单文件 EXE 部署**且不能包含反射依赖。本项目仅 TrayApp 走 BitMono。

### 7.5 「假进度条」式时间窗口要双向验证

很多软件的"试用期"机制只校验"晚于截止"，但**漏校验"早于起始"**（用户调系统时钟）。本实现**双向校验**（早于起始静默退出 + 晚于截止弹错误框），任何方向绕过都失败。

## 八、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| Obfuscar 混淆后 EF 字段反射失败 | 中 | 高 | 默认不启用 csproj 自动混淆；维护人员手动跑前必做 E2E 测试 |

| Admin 全局 JS 监听被 CSP 拦截 | 低 | 低 | JS 内联在 503 响应中，绕过 CSP |
| PDA 端未传 X-Machine-SN | 中 | 中 | RegisterSdk 三层 fallback（环境变量 / 文件 / Web 算法）|
| 时间窗口硬编码 2027-01-30 到了 | 中 | 高 | 维护人员按需调整 `RuntimeWindowGuard.ValidTo` 常量 |
| 暗桩在 Debug 模式也触发 | 低 | 低 | 仅 Release 编译启用（Obfuscar 集成）；暗桩逻辑无 #if DEBUG 包裹，按需可加 |
