## 一、Context（背景）

### 1.1 用户原话

> "增加功能需求和设计：增加 系统设置 菜单 下 字段权限 二级子菜单，与 角色定义 同级并排 ，功能与逻辑规则 为：显示 人员清单 的关键字段（如果有则包括：姓名、手机号、身份证号等），允许 勾选 这个关键字段 的复选按钮，当勾选的 字段，则可保存此清单 到数据库 对应的 字段权限 数据表中；在角色定义 的权限矩阵 中增加 隐私字段权限 复选框，当角色的权限有此选项勾选时，则在所有相关页面 显示/引用 该 字段权限 的清单中的 字段 时，则默认不显示，不在 此 字段权限 清单中的 字段 ，则为显示；请你深度理解这个 字段权限  控制 的目的及用途、功能逻辑，梳理和处理相应的功能，补充到 原型 更正，及相关的 开发文档；生成最新版程序"

### 1.2 业务目标

**「字段权限」** 是数据脱敏 / 隐私保护机制：把系统中所有「敏感/可识别个人信息」（PII）字段集中管理，并通过**角色级总开关**控制哪些角色看不到这些字段。

**典型场景**：
- 公司人事档案里某员工"手机号"是敏感字段
- 默认 admin / 财务 角色看得到（业务需要）
- 新建一个 "外部审计员" 角色时，勾选「隐私字段权限」总开关 → 该角色看任何页面都看不到"手机号"列
- 字段隐藏对**该角色的所有用户**生效
- 字段清单是**全局**的（一份清单，所有角色共享）

### 1.3 与现有 RBAC 的关系（不是替代，是补充）

| 维度 | RBAC 现有 | 字段权限（新增） |
|------|----------|-----------------|
| 控制对象 | 菜单 / 页面 / 按钮 | **数据列（Field）** |
| 控制粒度 | 路由级 + 操作级 | **字段级（手机号、姓名...）** |
| 关联方式 | Role → SysPermission M:N | Role → 「隐私字段权限」单开关 + SysFieldPermission 全局清单 |
| 权限类型 | `PermissionType ∈ {1,2,3}`（3=数据 已预留未用） | **`PermissionType=3` 落地** |

**核心复用**：
- `SysPermission.PermissionType=3` 已预留（v2.13.76 设计）
- 现有 `IPermissionService.CurrentUserHasCode("privacy:field:enable")` 机制
- 现有 `HasPermissionAsync()` HtmlHelper 扩展

public async Task<HashSet<string>> GetHiddenFieldKeysAsync(int userId)
{
    if (!await HasPrivacyFieldEnabledAsync(userId)) return new HashSet<string>();
    var keys = await _db.SysFieldPermissions.Where(p => p.IsActive).Select(p => p.FieldKey).ToListAsync();
    return new HashSet<string>(keys);
}

### 5.8 渲染层 — HtmlHelper 扩展

```csharp
public static class FieldPermissionHtmlHelperExtensions
{
    public static async Task<bool> IsFieldHiddenAsync(this IHtmlHelper html, string fieldKey)
    {
        var ctx = html.ViewContext?.HttpContext;
        if (ctx == null) return false;
        var perm = ctx.RequestServices.GetService(typeof(IPermissionService)) as IPermissionService;
        if (perm == null) return false;
        var userId = ctx.GetCurrentUserId();
        if (userId <= 0) return false;

        // HttpContext.Items 缓存
        var cacheKey = "__FIELD_HIDDEN_KEYS__";
        if (ctx.Items.TryGetValue(cacheKey, out var cached) && cached is HashSet<string> keys)
            return keys.Contains(fieldKey);
        var hiddenKeys = await perm.GetHiddenFieldKeysAsync(userId);
        ctx.Items[cacheKey] = hiddenKeys;
        return hiddenKeys.Contains(fieldKey);
    }

    public static async Task<IHtmlContent> RenderFieldAsync(this IHtmlHelper html, string fieldKey, string? value, string placeholder = "***")
    {
        if (await IsFieldHiddenAsync(html, fieldKey))
            return new HtmlString($"<span class=\"text-muted\">{placeholder}</span>");
        return new HtmlString(System.Net.WebUtility.HtmlEncode(value ?? ""));
    }
}
```

## 附录 v2.13.195：动态字段权限扩展说明

### 195.1 功能背景

原始设计仅支持 5 个硬编码种子字段（姓名、手机号、工号、房号、备注），但实际业务中可能需要保护更多字段（如"班组"、"班次"、"邮箱"等）。为实现灵活的隐私字段管理，v2.13.195 新增动态添加功能。

### 195.2 架构变更

| 组件 | 变更内容 |
|------|---------|
| **数据层** | 无需修改，`SysFieldPermission` 表结构保持不变 |
| **服务层** | 新增 `ISysFieldPermissionService.CreateAsync(SysFieldPermissionCreateDto)` |
| **API 层** | 新增 `POST /api/v1/system/field-permissions` |
| **UI 层** | Settings → 字段权限 面板新增「新增字段」按钮与 Modal |
| **权限控制** | 创建操作受 `settings:fields` 权限保护（与编辑权限相同） |

### 195.3 字段权限创建 DTO

```csharp
public class SysFieldPermissionCreateDto
{
    [Required] string FieldKey;      // 如 "employee.team"
    [Required] string Module;        // 如 "Personnel"
    [Required] string FieldName;     // 如 "班组"
    string FieldType = "string";     // string/number/date/datetime/boolean
    [Range(1,3)] byte SensitivityLevel = 2; // 1=高 2=中 3=低
    [Required] string Description;   // 隐私保护说明
    bool? IsActive = true;           // 默认启用
}
```

### 195.4 使用流程

1. 用户点击「新增字段」按钮
2. 填写模块代码（需与 `GetModuleDisplayName` 映射一致）
3. 填写字段键（格式：`模块.字段名`，系统唯一）
4. 填写显示名、敏感等级、描述
5. 提交后后端验证 FieldKey 唯一性，保存并自动分配 SortOrder
6. 页面刷新后新字段出现在列表中，可按需勾选保护

### 195.5 注意事项

- **模块代码**：新增的 Module 代码必须在 `IndexModel.GetModuleDisplayName()` 中添加中文映射，否则列表中将显示原始代码而非易读名称
- **字段键唯一性**：整个表中 FieldKey 不能重复，包括大小写敏感
- **内置字段保护**：Id 1-8 为种子内置字段，建议仅通过 `IsActive` 开关控制，不建议删除
- **权限要求**：只有拥有 `settings:fields` 权限（通常为管理员）才能访问新增接口

### 195.6 错误处理

| 错误码 | 场景 | 响应 |
|--------|------|------|
| `VALIDATION_ERROR` | 必填字段为空、格式非法 | 400 + 错误消息 |
| `FIELD_KEY_DUPLICATE` | FieldKey 已存在 | 400 + 提示更换 |
| `CREATE_FAILED` | 数据库保存失败 | 500 + 内部错误 |

## 附录 v2.13.196：模块与字段下拉联动升级

### 196.1 升级背景

v2.13.195 基础版采用**手动填写**模块代码和字段键的方式，存在以下问题：
- 拼写错误可能导致数据不一致（如 `Personel` vs `Personnel`）
- 字段名记错导致隐私保护失效
- 用户需查阅文档才能确定可用的模块和字段

v2.13.196 升级为**下拉选择 + 智能填充**模式：
- 模块从主菜单中包含列表页面的模块自动加载
- 字段从该模块对应数据库表的实际列自动加载
- 选择字段后自动填充显示名、类型、敏感等级、描述建议

### 196.2 架构变更

| 组件 | v2.13.195（基础版） | v2.13.196（升级版） |
|------|---------------------|---------------------|
| 模块选择 | 手动输入文本 | 下拉选择（基于主菜单模块） |
| 字段选择 | 手动输入文本 | 下拉选择（基于数据库表字段） |
| 字段显示名 | 手动输入 | 自动填充（可编辑） |
| 字段类型 | 手动选择 | 自动填充（只读） |
| 敏感等级 | 默认 2（手动调） | 根据字段类型推荐（可调） |
| 描述 | 手动输入 | 自动填充建议（可编辑） |
| 已存在字段 | 无提示 | 标记为 `[已存在]` 不可选 |

### 196.3 新增 API：GET /api/v1/system/field-permissions/meta

**响应结构**：

### 196.5 操作流程

1. **点击「新增字段」按钮** → Modal 弹出 → 自动加载 meta 数据
2. **选择模块**（如「人员清单」）→ 「字段键」下拉自动刷新
3. **选择字段**（如「手机号」）→ 自动填充：
   - 显示名：手机号
   - 字段类型：string
   - 敏感等级：1（高）
   - 描述：联系电话（高 PII）
4. **调整**（可选）：修改敏感等级或描述
5. **点击「保存新增」** → 提交 POST 请求
6. **结果反馈**：
   - 成功 → 列表自动刷新，新字段按模块分组显示
   - 失败 → 红色提示框显示具体错误

### 196.6 智能推荐规则

| 字段类型 | 默认敏感等级 | 描述模板 |
|---------|-------------|---------|
| string（姓名/电话/邮箱等） | 1（高） | "{fieldName} 包含个人身份信息，建议设置高敏感保护" |
| string（其他） | 2（中） | "{fieldName} 可能包含隐私信息，请评估敏感等级" |
| date/datetime | 2（中） | "{fieldName} 记录日期信息，涉及个人隐私" |
| boolean | 3（低） | "{fieldName} 状态标记，通常不敏感" |
| number | 3（低） | "{fieldName} 数值统计，一般不包含敏感信息" |

### 196.7 永久教训

1. **下拉选择 > 手动输入**：永远让用户从已验证的数据源选择，而不是输入自由文本
2. **缓存策略**：元数据不常变化，前端缓存可减少请求次数
3. **已存在检测**：在选项中标记已存在项，避免重复添加造成主键冲突
4. **回退机制**：当元数据加载失败时，提供清晰的错误提示而非静默失败
5. **撤销缓存**：新增成功后清空缓存，确保下次打开看到最新状态
