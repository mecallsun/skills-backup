# 分页器少数据 BUG 修复（v2.13.75）

> **版本**：v2.13.75
> **日期**：2026-07-21
> **类型**：P1 BUG 修复（_PaginationPartial 设计行为改进）
> **触发需求**：用户反馈"当记录数少于 10 条时，则不显示列表底部翻页数码"——v2.13.74 修复后用户发现新场景：partial 在 TotalCount < PageSize 时**完全不渲染**（包括 dropdown）
> **结论**：✅ **根因：v2.13.71 partial 的 `@if (totalPages > 0)` 让 partial 在 TotalCount < 默认 PageSize（20）时**完全不渲染**，导致 dropdown 也消失，用户无法切换 pageSize。修复：改为 `@if (Model.TotalCount > 0)`，dropdown + 统计信息始终显示；翻页数字 «1 2 3» 改为 `@if (totalPages > 1)`，避免单页时显示无意义的单数字。**

## 二、根因调查

### 2.1 v2.13.71 partial 设计行为审计

`_PaginationPartial.cshtml` 第 60 行：

```cshtml
@if (totalPages > 0)
{
    <div class="card-footer ...">
        ...dropdown + 翻页数字...
    </div>
    <script>...</script>
}
```

**计算**：`totalPages = Math.Ceiling(TotalCount / PageSize)`

**问题**：
- 当 `TotalCount <= PageSize` 时，`totalPages = 0` 或 `1`
- 如果是 0 → **整 partial 不渲染**（dropdown + 翻页数字都没了）
- 如果是 1 → 渲染，但「« 1 »」单数字显示无意义

**实际数据**：
- `/Settings?tab=users`：4 users，`PageSize=20` → `totalPages=0` → **partial 不渲染** → 用户看不到 dropdown
- `/BillingStandard`：几条，`PageSize=20` → `totalPages=0` → 同上
- `/DormBilling`：3 条，`PageSize=20` → `totalPages=0` → 同上

### 2.2 用户预期

**用户视角**：列表底部的「每页 N 条」dropdown 应该是**始终可用**的控件——不管有多少数据，都能切换 pageSize。即使切到 50 后只有 4 条数据，dropdown 也应保留选项状态。

**设计误区**：v2.13.71 把 `totalPages` 当作「是否需要分页」的开关——但 dropdown 是 pageSize 控件，与分页逻辑独立。

### 2.3 修复方向

**分离两个职责**：

| 职责 | 是否需要 TotalCount > 0 | 是否需要 totalPages > 1 |
|------|------------------------|------------------------|
| **dropdown + 统计信息**（"共 N 条 · 第 X-Y 条 · 共 Z 页"） | ✅ 需要 TotalCount > 0 | ❌ 与 totalPages 无关 |
| **翻页数字**（"« 1 2 3 … »"） | ✅ 需要 TotalCount > 0 | ✅ 需要 totalPages > 1（避免单页显示单数字） |

## 三、修复方案

### 3.1 partial 条件重构

**修复前**（v2.13.74）：
```cshtml
@if (totalPages > 0)
{
    <div class="card-footer ...">
        <div>
            统计信息 + dropdown          <!-- TotalCount=0 时也隐藏 -->
        </div>
        <nav>
            翻页数字                    <!-- totalPages=1 时显示 « 1 » -->
        </nav>
    </div>
    <script>...</script>
}
```

**修复后**（v2.13.75）：
```cshtml
@* v2.13.75 BUG 修复：dropdown + 统计信息始终显示（即使 totalPages=0），让用户随时切换 pageSize
    只有翻页数字（« 1 2 3 … »）在 totalPages > 1 时才显示（无意义时不显示） *@
@if (Model.TotalCount > 0)
{
    <div class="card-footer ...">
        <div>
            统计信息 + dropdown          <!-- TotalCount > 0 时始终显示 -->
        </div>
        @* v2.13.75：翻页数字仅当 totalPages > 1 时才渲染 *@
        @if (totalPages > 1)
        {
            <nav>
                翻页数字                <!-- totalPages > 1 时才显示 -->
            </nav>
        }
    </div>
    <script>...</script>
}
```

### 3.2 不修改 PageModel

- ✅ 8 个 PageModel 已修复（v2.13.74）
- ✅ 仅修改 `_PaginationPartial.cshtml` 一个文件

## 六、教训

### 6.1 关键教训

1. **dropdown 是 pageSize 控件，与分页逻辑独立**：v2.13.71 错误地把 dropdown 与翻页数字绑定到同一条件 `totalPages > 0`。实际上 dropdown 应该由 `TotalCount > 0` 控制（要有数据才能显示每页条数），翻页数字由 `totalPages > 1` 控制（避免单数字）。
2. **设计条件要按职责分离**：UI 控件的条件不应混用业务计算结果。每个控件独立判断：dropdown 看 TotalCount，翻页数字看 totalPages。
3. **用户视角优先**：用户认为 dropdown 是「页面设置」，应在整个列表页面生命周期内可用。设计者不能因为「翻页没意义」就一起隐藏 dropdown。

### 6.2 防御性编程

建议未来任何 partial 都遵循「职责分离」原则：

| UI 元素 | 控制条件 |
|---------|---------|
| **dropdown**（pageSize / 排序 / 视图）| `TotalCount >= 0`（始终显示）|
| **翻页数字** | `totalPages > 1` |
| **空状态提示** | `TotalCount == 0` |
| **加载指示** | 服务端无关 |

### 6.3 强制检查清单（PR Review 自检）

任何修改 `_PaginationPartial.cshtml` 的 PR，必须确认：

- [ ] 外层 `@if (Model.TotalCount > 0)`：TotalCount > 0 时渲染整个 footer
- [ ] 内层 `@if (totalPages > 1)`：翻页数字仅在 totalPages > 1 时渲染
- [ ] dropdown（page-size-select）在 TotalCount > 0 时始终显示
- [ ] 翻页数字（« 1 2 3 … »）在 totalPages ≤ 1 时不显示（避免无意义单数字）

违规 grep：
```bash
# v2.13.71 旧版硬编码 totalPages > 0 应为 0 命中
grep -n '@if (totalPages > 0)' DormManage.Admin/Pages/Shared/_PaginationPartial.cshtml
# 期望 0 命中
```
