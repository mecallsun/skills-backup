## 根本原因

### 🔴 BUG #1：过期日期临界值判断错误

**文件**：`DormManage.Admin/Services/AuthService.cs`

```csharp
// v2.13.93 旧代码（有 BUG）
if (user.ExpiresAt.HasValue && DateTime.Today > user.ExpiresAt.Value.Date)
    return (false, "账号已过期，请联系管理员", null);
```

**问题分析**：
- 假设 `ExpiresAt = 2026-07-27 00:00:00`（账号 7月27日到期）
- 当 `Today = 2026-07-27` 时：
  - `Today > 2026-07-27` → **false**（条件不满足）
  - 用户**今天仍能登录**！
- 当 `Today = 2026-07-28` 时：
  - `Today > 2026-07-27` → **true**
  - 用户**明天才被拒绝**

**用户期望**：账号「今天到期」即生效 → 不允许今天登录

**设计冲突**：
- 真实业务：账号有效期到 2026-07-27 23:59:59 终止
- 但代码用 `>` 而非 `>=` → 这一天还能登录

### 🔴 BUG #2：OnValidatePrincipal 中同样的 `>` 问题

**文件**：`DormManage.Admin/Program.cs`

```csharp
// v2.13.93 旧代码
if (user == null || !user.IsActive || user.IsLocked
    || (user.ExpiresAt.HasValue && DateTime.Today > user.ExpiresAt.Value.Date))
{
    context.RejectPrincipal();
    ...
}
```

**问题**：与 BUG #1 完全相同。cookie 验证的过期日判断也错误。

### 🔴 BUG #3：前端 Badge 显示

**文件**：`DormManage.Admin/Pages/Settings/_UserPanel.cshtml`

```csharp
var days = (u.ExpiresAt.Value.Date - DateTime.Today).Days;
if (days < 0)  // 旧：只有已过 N 天才红色
{
    <span class="badge bg-danger" title="已过期 @(-days) 天">@u.ExpiresAt.Value.ToString("yyyy-MM-dd")</span>
}
else if (days <= 30)  // 今天（days == 0）也进入黄色"剩 0 天过期"
{
    ...
}
```

**问题**：今天过期（days == 0）显示**黄色** "剩 0 天过期"，但实际上**今天应失效**——前后端不一致。

### 🔴 架构缺陷：3 处分散实现导致一致性难以保证

| 位置 | 实现 | 一致性风险 |
|------|------|----------|
| `AuthService.LoginAsync` | 登录时校验 | ❌ 与前端不一致 |
| `Program.cs OnValidatePrincipal` | cookie 校验 | ❌ 与 LoginAsync 不一致 |
| `_UserPanel.cshtml Badge` | 显示判断 | ❌ 与 LoginAsync 不一致 |

**根因**：3 处独立实现，没有统一的判断函数，导致语义不同步。

## 实施方案（v2.13.193）

### 修复 1：新建统一判断助手

**文件**：`DormManage.Shared/Extensions/UserExpiryHelper.cs`（新建）

```csharp
/// <summary>
/// v2.13.193：账号有效期判断助手
/// 统一 LoginAsync + OnValidatePrincipal + 前端 Badge 显示的判断逻辑
///
/// 规则（deny-by-default）：过期当天即视为已过期（使用 >= 语义）
/// - Today >= ExpiresAt.Date → 已过期
/// - Today <  ExpiresAt.Date → 未过期
/// </summary>
public static class UserExpiryHelper
{
    /// <summary>判断账号是否已过期（null = 永久有效）</summary>
    public static bool IsExpired(DateTime? expiresAt, DateTime? now = null)
    {
        if (!expiresAt.HasValue) return false;  // 永久有效
        var today = (now ?? DateTime.Today).Date;
        return today >= expiresAt.Value.Date;  // v2.13.193: 过期当天即视为已过期
    }

    /// <summary>计算到过期的剩余天数（负数 = 已过期 N 天；null = 永久）</summary>
    public static int? DaysUntilExpiry(DateTime? expiresAt, DateTime? now = null)
    {
        if (!expiresAt.HasValue) return null;
        return (int)(expiresAt.Value.Date - (now ?? DateTime.Today).Date).TotalDays;
    }
}
```

### 修复 2：AuthService.LoginAsync 使用 helper

```csharp
// v2.13.193 修复

    return (false, "账号已过期，请联系管理员", null);
```

### 修复 3：Program.cs OnValidatePrincipal 使用 helper

```csharp

options.Events.OnValidatePrincipal = async context =>
{

    if (user == null || !user.IsActive || user.IsLocked
        || UserExpiryHelper.IsExpired(user.ExpiresAt))
    {

        await context.HttpContext.SignOutAsync(...);
    }
```

### 修复 4：前端 Badge 使用 helper

```html
@using DormManage.Shared.Extensions
...
@if (u.ExpiresAt.HasValue)
{
    var daysLeft = UserExpiryHelper.DaysUntilExpiry(u.ExpiresAt);
    if (daysLeft.HasValue && daysLeft.Value <= 0)
    {
        // daysLeft <= 0：已过期或今天到期
        var overdueDays = (daysLeft ?? 0) < 0 ? -(daysLeft ?? 0) : 0;
        <span class="badge bg-danger" title="@(overdueDays > 0 ? $"已过期 {overdueDays} 天" : "今天已过期，请联系管理员")">
            @u.ExpiresAt.Value.ToString("yyyy-MM-dd")
        </span>
    }
    else if (daysLeft.HasValue && daysLeft.Value <= 30)
    {
        <span class="badge bg-warning text-dark" title="剩 @daysLeft 天过期">@u.ExpiresAt.Value.ToString("yyyy-MM-dd")</span>
    }
    else
    {
        <span>@u.ExpiresAt.Value.ToString("yyyy-MM-dd")</span>
    }
}
```

## 永久教训

1. **同一业务规则不要有多个独立实现**：3 处 ExpiresAt 判断导致不一致 → 必须用单一助手函数
2. **临界日期判断用 `>=` 而非 `>`**：当 ExpiresAt 是日期字符串（如 `2026-07-27`），业务语义是「这一天结束前有效」，但用户在「当天的下午」已经不应该登录，**用 `>=` 更严格、更符合安全原则**
3. **deny-by-default 是默认安全选择**：账号到期时不应有任何"宽限"，直接拒绝
4. **前端 Badge 与后端校验语义必须一致**：都是 `daysLeft <= 0` 显示红色
5. **统一助手函数降低复杂度**：1 个 `UserExpiryHelper` 替代 3 处散落实现
