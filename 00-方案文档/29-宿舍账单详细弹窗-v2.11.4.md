## 1. 变更背景

宿舍账单列表当前仅展示各宿舍的费用汇总数据（冷水费/热水费/电费/合计），但无法直接查看该宿舍费用组成的明细数据（即各员工分摊明细）。

实际业务中，管理员常有如下需求：
1. **核对账单来源**：查看某间宿舍的费用是如何分摊到每位员工的
2. **排查异常**：发现某宿舍电费异常高时，需要查看是谁用了多少
3. **员工对账**：员工询问分摊金额时，需要快速展示明细

本次需求在宿舍账单列表增加"**操作**"列，提供"**详细**"按钮，点击后弹窗显示该房号的员工分摊明细。

#### 2.3.5 在住人数字段（v2.11.6 新增；v2.11.7 标题简化）

**字段位置**：宿舍信息卡第 2 列（在"宿舍"与"计费月份"之间）

**v2.11.7 关键变更**：
- **列标题简化为"在住人数"**（与宿舍档案字段名一致 / 与 ResideStatus、ReserveStatus 等命名风格保持一致）
- **保留显示风格"在住人数/最大容量数"**（即值仍以 `X/Y` 格式呈现，如 `3/4`）
- **弹窗宽度 +300px**（v2.11.7 加宽，详见 §2.3.6）

**字段定义**：

| 属性 | 内容 |
|------|------|
| **列标题（v2.11.7）** | `在住人数`（与宿舍档案字段名一致） |
| **显示格式** | `在住人数/最大容量数`（如 `3/4`，值格式与标题分离） |
| **数据来源** | 派生字段 |
| **在住人数（分子）** | `residentCount`：该宿舍当月在宿员工数，**优先取自 `DormBilling.ResidentCount`**（已在 `DormBilling` 表中持久化）；如 `DormBilling` 中无记录则回退到 `findDorm(dormCode).residentCount`（含 BOOKINGS 实时推断）；原型 mock 数据 `DORM_BILLS_202607[].residentCount` |
| **最大容量数（分母）** | `capacity`：该宿舍档案容量（来自 `Dorm.Capacity` 字段，对应 `findDorm(dormCode).capacity`） |
| **检索函数** | `dormBill.residentCount` / `findDorm(dormCode).capacity` |
| **显示风格** | 与其他信息卡列保持一致（小标题 + 加粗值） |

> ⚠️ **数据源关键说明**：
> - `residentCount` **必须**从 `DormBilling` 表（账单快照）读取，原因是同一房号在"生成账单"那一刻其同住员工数会被冻结；如果直接从 BOOKINGS 实时统计，可能出现"详情弹窗内显示 3 人，但表格下方员工分摊明细却有 4 条"的诡异情况，破坏一致性。
> - `capacity` 从 `Dorm` 档案表读取，是**配置数据**而非动态数据，不会随月份变化。

#### 2.4.1 "考勤班次"列数据源（v2.11.7 强制 FK 关联引用）

**强制规则**：员工分摊明细列表的"考勤班次"列**必须**关联引用该员工档案（`SysEmployee`）的"考勤班次"，不得使用任何冗余、缓存或 EMPLOYEE_BILLS 表存储的字段。

**数据链路**：

```
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────────┐
│  员工分摊记录（EMPLOYEE_BILLS）│ → │  人员档案（SysEmployee）          │ → │  考勤类型（AttendanceType）       │
│  employeeId（外键）          │    │  AttendanceTypeId（外键）            │    │  Code（编码）                    │
│  dormCode = 当前宿舍         │    │  ← 人员档案就是"数据源"          │    │  Name（中文名：默认/早班/...）    │
└──────────────────────┘    └──────────────────────┘    └──────────────────────────┘
```

**字段映射**：

| 显示层 | 取值字段 | 数据源 | 说明 |
|--------|---------|--------|------|
| 员工分摊明细列表"考勤班次"列 | `AttendanceType.Name`（中文名） | `SysEmployee → AttendanceTypeId → AttendanceType` | 通过 FK 关联引用人员档案 |
| 存储层（`SysEmployee`） | `AttendanceTypeId`（int） | 外键关联到 `AttendanceType.Id` | **单一数据源** |
| 字典层（`AttendanceType`） | `Code` + `Name` | 基础资料表 | 全局共享 |
| Badge 颜色映射 | `ATTENDANCE_BADGE[Code]` | `mock-data.js` 字典 | 6 种颜色 |

**Badge 颜色映射**（同 30 §3.3 / 15-考勤班次需求）：

| 考勤班次 | Code | Badge 样式 |
|----------|------|-----------|
| 默认 | DEFAULT | 灰 `bg-secondary` |
| 早班 | MORNING | 橙 `bg-warning text-dark` |
| 中班 | MIDDLE | 黄 `bg-warning text-dark` |
| 晚班 | EVENING | 蓝 `bg-primary` |
| 夜班 | NIGHT | 紫 `bg-dark` |
| 其他 | OTHER | 青 `bg-info text-dark` |

**强制要求**：

| # | 要求 | 原因 |
|---|------|------|
| 1 | **"考勤班次"列的值只能从 `SysEmployee.AttendanceTypeId` → `AttendanceType.Name` 链路获取** | 单一数据源，避免多个数据副本不同步 |
| 2 | **不得在 `EMPLOYEE_BILLS` 表中冗余存储"考勤班次"字段** | 一旦人员调岗/转班次，员工分摊明细列表必须实时反映 |
| 3 | **`SysEmployee` 应添加 EF Core 导航属性 `AttendanceType AttendanceType`**（v2.11.7 推荐） | 简化查询：`emp.AttendanceType.Name` 即可获取中文名 |
| 4 | **当人员档案的"考勤班次"发生变更时**，员工分摊明细列表不需任何额外操作即可看到新值 | FK 关联 + 实时查询保证数据一致性 |
| 5 | **同一员工在不同月份/不同宿舍的分摊记录中显示一致的考勤班次** | FK 关联确保全局一致 |

**JavaScript 实现（v2.11.7）**：

```javascript
// 渲染员工分摊明细（v2.11.7 新增考勤班次列）
function renderEmployeeBills(employeeBills) {
    const tbody = document.getElementById('modalEmployeeBills');
    if (employeeBills.length === 0) {
        tbody.innerHTML = '<tr><td colspan="9" class="text-center text-muted py-3">该宿舍暂无员工分摊记录</td></tr>';
        return;
    }
    
    // v2.11.7：考勤班次按 FK 关联引用（SysEmployee.AttendanceTypeId → AttendanceType）
    const attendanceNameByFk = (attendanceTypeId) => {
        const t = ATTENDANCE_TYPES.find(x => x.id === attendanceTypeId);
        return t ? t.name : '-';
    };
    const attendanceBadgeByFk = (attendanceTypeId) => {
        const t = ATTENDANCE_TYPES.find(x => x.id === attendanceTypeId);
        if (!t) return 'bg-secondary';
        return ATTENDANCE_BADGE[t.code] || 'bg-secondary';
    };
    
    let html = '';
    employeeBills.forEach(function(b) {
        // 通过 employeeId 关联查找 SysEmployee（人员档案）
        const emp = findEmployee(b.employeeId);
        const attName = attendanceNameByFk(emp?.attendanceTypeId);
        const attBadge = attendanceBadgeByFk(emp?.attendanceTypeId);
        
        html += '<tr>' +
            '<td>' + b.employeeCode + '</td>' +
            '<td>' + b.employeeName + '</td>' +
            // v2.11.7 新增：考勤班次（关联引用 SysEmployee.AttendanceTypeId）
            '<td><span class="badge ' + attBadge + '" title="来源：SysEmployee.AttendanceTypeId → AttendanceType.Name">' + attName + '</span></td>' +
            '<td>' + b.dormCode + '</td>' +
            '<td>' + b.stayDays + '天</td>' +
            '<td class="text-end">¥' + b.coldShareAmount.toFixed(2) + '</td>' +
```

```javascript

    // ❌ 缺少 attendanceTypeId 字段
}

// 而 EMPLOYEE_BILLS_202607 中对应记录（line 19891）：
{
    "employeeId": 228,           // 引用 PERSONNEL
    "employeeCode": "EMP-2026-228",
    ...
    "attendanceType": "早班"      // ❌ 冗余缓存，违反 v2.11.7 §2.4.1
}
```

PERSONNEL 数组中存在**数据格式不一致**问题——619 条记录使用旧格式字符串代码，仅 31 条使用新格式 FK 引用。导致**任何依赖 FK 关联引用的代码在 95% 员工记录上失效**。

**修复方案**（详见 `mock-data.js` 末尾 `normalizeData()` IIFE）：

| 步骤 | 修复 |
|------|------|
| 1 | PERSONNEL 数组加载完成后自动规范化：把旧格式 `attendanceType: "MIDDLE"` 补全为 `attendanceTypeId: 3` + `attendanceTypeName: "中班"` |
| 2 | 同样规范化 `employeeType`/`department`/`status` 字段 |
| 3 | EMPLOYEE_BILLS 记录删除冗余的 `attendanceType`/`employeeType` 字段（遵循 v2.11.7 §2.4.1 单一数据源） |
| 4 | 增强 `findEmployee()` 支持按 employeeCode 字符串查找 |
| 5 | 所有原型 JS 增加 fallback 逻辑（兼容新旧两种格式） |

**修复后验证**：
