## 三、BUG 审计 + 修复（5 项）

### 3.1 BUG #1：客户端 INSERT NULL 列 `ClientRecordId` → HTTP 500

**症状**：
```bash
curl -X POST http://localhost:5100/api/meter/manual-entry -d '{...}'
→ HTTP 500 {"code":"DB_ERROR","message":"不能将值 NULL 插入列 'ClientRecordId'，表 'WaterMeterDB.dbo.MeterRecord'；列不允许有 Null 值。INSERT 失败。"}
```

**根因**：DB schema `[ClientRecordId] NVARCHAR(64) NOT NULL`，但 `MeterRecord` EF 模型声明 `public string? ClientRecordId { get; set; }`（nullable），且 `MeterController.SaveRecord` 在新建 MeterRecord 时**未赋值** `ClientRecordId` / `DeviceSn`：
```csharp
// 之前（BUG）：
record = new MeterRecord { ..., Operator = request.Operator ?? "管理员" };
// 缺 DeviceSn、ClientRecordId、ClientCreatedAt 赋值 → EF 提交 NULL → SQL NOT NULL 拒绝
```

**修复**：`DormManage.Api/Controllers/Meter/MeterController.cs` line 208-228：
```csharp
record = new MeterRecord
{
    ...
    Operator = request.Operator ?? "管理员",
    // v2.13.80 修复：手动补录场景 DeviceSn="" + ClientRecordId="MANUAL-{Guid}"
    DeviceSn = request.DeviceSn ?? "",
    ClientRecordId = !string.IsNullOrWhiteSpace(request.ClientRecordId)
        ? request.ClientRecordId
        : $"MANUAL-{Guid.NewGuid():N}".Substring(0, 32),
    ClientCreatedAt = request.ClientCreatedAt ?? DateTime.Now,
    ...
};
```

### 3.2 BUG #2：`MeterRecordSaveRequest` DTO 缺 DeviceSn / ClientRecordId / ClientCreatedAt 字段

**症状**：API Controller 编译失败或运行时绑定失败。

**修复**：`DormManage.Api/Controllers/Meter/MeterController.cs` line 543-558：
```csharp
public class MeterRecordSaveRequest
{
    ...
    // v2.13.80 新增：PdaDeviceSn + ClientRecordId（手动补录时不填，由系统生成）
    public string? DeviceSn { get; set; }
    public string? ClientRecordId { get; set; }
    public DateTime? ClientCreatedAt { get; set; }
}
```

### 3.3 BUG #3：`DeviceSn` / `ClientRecordId` NVARCHAR 长度不一致（EF 128 ↔ DB 64）

**症状**：潜在 DbUpdateException（如果 PDA 端写入 ≥ 64 字符），且 schema 文档与代码不一致。

**修复**：
- `DormManage.Shared/Data/DormDbContext.cs` line 384-385：`HasMaxLength(128)` → `HasMaxLength(64)`
- `DormManage.Shared/Models/MeterRecord.cs` line 138-143：`[MaxLength(128)]` → `[MaxLength(64)]`

```csharp
// v2.13.80 修正：DB schema DeviceSn/ClientRecordId 都是 NVARCHAR(64)，原 HasMaxLength(128) 与 DB 不一致
entity.Property(e => e.DeviceSn).HasMaxLength(64);
entity.Property(e => e.ClientRecordId).HasMaxLength(64);
```

### 3.4 BUG #4：`EntityTypeConfiguration` `IsRequired()` 与 seed data 冲突

**症状**：DbContext 在 `EnsureCreated()` 时 seed data 报错「cannot be added because no value was provided for the required property 'ClientRecordId'」。

**根因**：seed data `Id=1~10` 没有 `ClientRecordId` 字段，但 `IsRequired()` 让 EF 拒绝。

**修复**：保留 EF 模型为 `string?`（nullable），由 Service 层（`MeterController.SaveRecord` + `EntryModel.OnPostSaveReadingsAsync`）保证非空写入。
```csharp
// 注意：虽然 DB NOT NULL，但 EF 模型保留 string?，由 Service 层保证非空写入
entity.Property(e => e.DeviceSn).HasMaxLength(64);   // 不加 IsRequired()
entity.Property(e => e.ClientRecordId).HasMaxLength(64);  // 不加 IsRequired()
```

### 3.5 BUG #5：`/api/meter/manual-entry` 端点缺默认 operator 处理

**症状**：直接调用 manual-entry 而不传 `operator` 字段时，Operator 字段为 null。

**修复**：`MeterController.SaveRecord` line 222：`Operator = request.Operator ?? "管理员"`，已存在。

## 八、关键决策与权衡

| 决策 | 理由 |
|------|------|
| **保留 EF 模型 `ClientRecordId` 为 `string?`（不加 IsRequired）** | 兼容 seed data；DB NOT NULL 由 Service 层强制；与 v2.13.59 SqlNullValueException 修复原则一致 |
| **手动补录自动生成 `ClientRecordId="MANUAL-{Guid}"`** | 与 `Entry.cshtml.cs` line 197-198 一致；保证 PDA 端幂等键唯一 |
| **`DeviceSn=""` 空字符串（不是 NULL）** | 避免 DB NOT NULL 违反；标记「非 PDA 录入」 |
| **`MeterRecordSaveRequest` 新增 3 个可选字段** | PDA 端 API 调用时可填；手动补录不填由系统兜底 |
| **不修改 SQL Server DDL** | DB schema 已正确（NVARCHAR(64) NOT NULL）；仅修复 EF 模型对齐 |

## 十一、核心教训

1. **DB NOT NULL 字段必须在 Service 层兜底**：C# EF 模型可保持 `string?`，但 INSERT 前必须赋值；纯依赖 EF `IsRequired()` 在 seed data + DB schema 演进时会爆雷
2. **NVARCHAR 长度必须 EF/DB 一致**：`HasMaxLength(128)` vs DB `NVARCHAR(64)` 不会立即报错，但潜在 DbUpdateException + 数据迁移隐患
3. **「多个端点共享 Service」必须统一兜底逻辑**：`MeterController.SaveRecord` + `EntryModel.OnPostSaveReadingsAsync` + PdaController 三个端点都必须保证 `DeviceSn/ClientRecordId/ClientCreatedAt` 非空
4. **`HasData` seed data 不应包含 DB NOT NULL 但 EF nullable 字段**：要么全部赋值，要么模型改为 `string.Empty` 初始化
5. **API Controller 失败信息要可追溯**：v2.13.79 起 `Development` 环境开启后 `{"message":"不能将值 NULL 插入列 'ClientRecordId'..."}` 直接定位根因，避免「黑洞」式 INTERNAL_ERROR
