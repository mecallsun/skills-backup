### 2.2 数据分布（与列标题"语义"对照）

| Excel 标题 | 实际唯一值 | 数量 | 与 DB 字段关系 |
|---|---|---|---|
| col 6 "考勤班次" | 默认 / A班 / B班 / C班 / D班 / E班 / F班 / H班 / J班 / K班 | 475/80/72/72/69/54/46/17/13/8 | **A-K 字母码** → 匹配 DB **Team**（不是 AttendanceType）|
| col 9 "班组" | 默认 / 中班 / 早班 / 晚班 | 475/219/123/89 | **4 个倒班名** → 匹配 DB **AttendanceType**（不是 Team）|

### 2.3 重大发现：Excel 列标题"互换"

**Excel 标题与数据语义的对应关系如下：**

```
Excel 标题                实际数据内容              DB 字段
col 6 "考勤班次"  →    A班-K班 字母码       →  DB Team（11 个字母班组）
col 9 "班组"      →    中班/早班/晚班 倒班名  →  DB AttendanceType（4 个倒班次）
```

**这是 Excel 文件的标题错误**：标题写"考勤班次"但列内是字母班组；标题写"班组"但列内是倒班名。

但**用户的真实意图**（用 DB 字段语义理解字段名）：
- **班组** = DB **Team**（字母班组 A-K）
- **班次（同考勤班次）** = DB **AttendanceType**（倒班次 早/中/晚/夜/默认）

### 2.4 正确的数据映射（swap 解释）

| 用户目标字段 | Excel 来源列 | 转换 |
|---|---|---|
| **姓名** | col 1 | 直接 |
| **性别** | col 5 | 男→1, 女→2 |
| **班组** (DB Team) | **col 6**（标题为"考勤班次"，实含字母码） | `A班` 去掉"班"后缀 → `A` → 查 Team.Id=2 |
| **班次** (DB AttendanceType) | **col 9**（标题为"班组"，实含倒班名） | `中班` → 查 AttendanceType.Id=3（直接匹配）|
| **入职日期** | col 10 | 直接解析 |
| **员工类型** | col 8 | 临时→临时工, 实习→实习生, 正式→合同工 |

## 六、永久教训

| # | 教训 |
|---|------|
| 1 | **「Excel 标题 ≠ Excel 数据语义」**。本次最大发现：Excel 列"考勤班次"实际含字母班组，"班组"实际含倒班名——标题与内容完全互换。数据处理前必须做**列值分布**与**字典**的交叉验证，否则按标题字面映射会全错。 |
| 2 | **「数据治理不存在'直接映射'」**。用户原话字段名 ≠ DB 字段名 ≠ Excel 列名 = 三方语义不一致是常态。需用 `DB 字典∩Excel 唯一值` 实际数据匹配来发现真相。 |
| 3 | **「用户的"即同X"语义注释是线索」**。「班次（即同考勤班次）」提示用户实际指 AttendanceType 字段——结合 Excel 列内容反向推导即可对齐语义。 |
| 4 | **「v2.13.159 误诊是因为只看标题不看值」**。v2.13.159 因 Excel 标题错位误以为语义错位而跳过 431 行更新。v2.13.160 用"剥班后缀 + swap 解释"恢复更新，纠正了误诊。教训：**所有字段异动前先看真实数据，不要凭标题猜测。** |
| 5 | **「数据治理是迭代的」**。v2.13.159 与 v2.13.160 是同一主题的两个版本，分别覆盖不同字段，最终完整对齐 906 行的 6 字段到花名册真源。**永远不要因为第一次没看清就放弃更新——多次审视能逐步接近真源。** |
| 6 | **「每步骤必须有备份」**。SysEmployee_BAK_20260725（17 行 v2.13.159 备份）+ SysEmployee_BAK_20260725_v160（431 行本次备份）= 共 448 行原始记录可回滚。 |
| 7 | **「DTO 层缺陷与数据治理要分开处理」**。本次发现 PersonnelService DTO 缺 FK 导航属性字段，但属代码缺陷不属于数据治理范围（DB 值正确）。提交时应明确告知 DBA 后续跟进。 |
