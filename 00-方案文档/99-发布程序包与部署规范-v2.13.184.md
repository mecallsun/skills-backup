## ⚠️ 系统核心规则（v2.13.184 强托管 — 不可妥协）

> **用户原话**：「所有程序 必须 由 托盘程序守卫并拉起服务运行，禁止其他方式运行」

### 1. 启动关系矩阵（系统级唯一真相）

| 程序 | 启动方式 | 独立运行 | 备注 |
|------|---------|---------|------|
| **DormManage.TrayApp.exe** | 用户双击 / `start.bat` / Windows 服务 | ✅ 允许 | **唯一权威入口** |
| **DormManage.Admin.exe** | 必须由 TrayApp 拉起 | ❌ 严禁（v2.13.155 强制） | 双击 → `[TRAY-GUARD]` 拒绝并退出 |
| **DormManage.Api.exe** | 必须由 TrayApp 拉起 | ❌ 严禁（v2.13.184 恢复强制） | 双击 → `[TRAY-GUARD]` 拒绝并退出 |

### 2. 程序永远启动原则（v2.13.169 + v2.13.184 双固化）

> **核心承诺**：在所有 5 种运行模式下，托盘都成功拉起 Web/Api 子进程。

| 注册状态 | TrayApp 行为 | 子进程运行模式 |
|---------|------------|---------------|
| Valid(1) | ✅ 拉起 | 全功能 |
| Expired(2) | ✅ 拉起 | 只读「许可已过期」（LicenseGuard + LicenseReadOnlyMiddleware 拦截写操作） |
| Invalid(3) | ✅ 拉起 | 只读「注册校验失败」 |
| Unregistered(-1) | ✅ 拉起 | 试用模式（LicenseGuard 限制 3 模块 POST + 分模块上限） |
| 托盘不可用 | ✅ 拉起（兜底） | 子进程默认只读模式（LicenseGuard 默认） |

**禁止**：TrayApp 在任何状态下 throw `InvalidOperationException` 拒绝启动子进程。

## 一、发布包结构

### 1.1 统一目录结构

所有发布程序（含 `dotnet publish` 产物、Release zip 包、exe/dll 等可执行文件）**必须**遵守以下目录结构：

```
<项目根目录>\
├── release\                          ← 项目专用发布根目录（必备）
│   ├── latest\                       ← 当前最新可发布的二进制（已解压的可部署目录）
│   │   ├── Admin\                    ← Web 管理后台（Razor Pages UI，端口 5001）
│   │   ├── Api\                      ← REST API 服务端（Kestrel，端口 5100）
│   │   └── TrayApp\                  ← 托盘守护进程（WinForms，负责启动 + 进程管理）
│   └── _archive\                     ← 历史发布 zip 包归档
│       └── DormManage-v2.13.184_20260727_XXXXXX.zip     ← 唯一整合包（兄弟目录式）
└── <其他源码目录>\
```

> **v2.13.184 组件目录命名规范（修订 3）**：组件目录名**只保留组件名**（`Admin` / `Api` / `TrayApp`），**不带版本号后缀**（禁止 `Admin-v2.13.XXX/`）。版本信息**只**体现在：
> 1. 整合压缩包文件名（`DormManage-v{X.Y.Z}_{时间戳}.zip`）
> 2. `appsettings.json` 的注释（`_comment_v2_13_XXX`）
> 3. 启动程序.bat 输出的标题文字
>
> **理由**：① 简化目录结构，运维一眼看清组件；② 升级版本时无需改动路径引用（只需覆盖文件）；③ 与 .NET 生态标准目录命名一致（生产环境 dll/exe 不带版本号）。

### 1.2 严禁行为

| ❌ 禁止 | 原因 |
|---------|------|
| 根目录放 `*.zip`、`*.dll`、`*.exe` | 污染工作区，git diff 无法区分源码和产物 |
| 使用 `publish-final/` / `dist/` / `out/` / `bin/` 作为发布根目录 | 与 .NET 内置编译产物 `bin/obj/` 混淆，且不符合规范要求 |
| 把 zip 包放在源码目录下 | 增加仓库体积，git clone 极慢 |
| 未命名版本号直接覆盖 `release/latest/` | 无法回滚到旧版本 |
| 双击 Admin.exe 或 Api.exe 启动 | 违反 v2.13.155 + v2.13.184 强托管规则 |
| **额外打包各组件独立 zip**（如 `DormManageAdmin-vX.Y.Z.zip` / `DormManageApi-vX.Y.Z.zip` / `DormManageTrayApp-vX.Y.Z.zip`） | 与整合包内容重复；运维易误用单独部署而违反强托管规则 |
| 在 `_archive/` 中保留多份同一版本的独立 zip | 增加存储冗余且违反"每个版本只 1 个包"原则 |
| **组件目录名带版本号后缀**（如 `Admin-v2.13.XXX/`） | 增加升级复杂度；版本信息冗余（已含在压缩包文件名中） |
| 在组件目录名中使用日期/构建号等长字符串后缀 | 同上，组件目录名应保持简洁 |

## 二、发布包内容规范

### 2.1 单一压缩包原则

**每次发版必须生成一个完整的整合 zip 压缩包**，包含全部三个组件（Admin + Api + TrayApp），解压即可直接运行，无需手动复制多个文件夹。

> **唯一发布原则（v2.13.184 强化）**：每个版本**只允许存在 1 个**整合压缩包。**禁止**额外打包各组件独立 zip（`DormManageAdmin-vX.Y.Z.zip`、`DormManageApi-vX.Y.Z.zip`、`DormManageTrayApp-vX.Y.Z.zip` 等）——这些独立包与整合包内容重复，且容易让运维误用单独部署而违反强托管规则。

**命名规则**：`DormManage-v{主版本}.{次版本}.{修订版本}_{YYYYMMDD_HHMMSS}.zip`

**命名反例（禁止）**：
- ❌ `DormManage-v2.13.184_YYYYMMDD_HHMMSS.zip` + 额外 `DormManageAdmin-v2.13.184_full.zip` / `DormManageApi-v2.13.184_full.zip` / `DormManageTrayApp-v2.13.184_full.zip`
- ❌ `DormManage-v2.13.184.zip`（无时间戳，不便于回滚）

### 2.2 压缩包内部结构（v2.13.184 修订 3 标准 — 组件目录不带版本号）

```
DormManage-v2.13.184_20260727_XXXXXX.zip
├── 📄 start.bat                       ← 一键启动（自动 cd 到 TrayApp 目录）
├── 📄 stop.bat                        ← 一键停止所有服务
├── 📄 install-service.bat             ← 将 TrayApp 注册为 Windows 服务（可选）
├── 📄 README.md                       ← 快速部署指南
└── 📁 TrayApp\                       ← 入口目录（不带版本号）
    ├── DormManage.TrayApp.exe         ← 双击入口
    ├── appsettings.json               ← 配置文件（注册码、数据库连接等）
    ├── 📁 Admin\                      ← 并列兄弟目录（ConfigService 自动找到）
    │   ├── DormManage.Admin.exe       ← 禁止独立双击
    │   ├── appsettings.json
    │   └── ...
    └── 📁 Api\                        ← 并列兄弟目录
        ├── DormManage.Api.exe         ← 禁止独立双击
        └── ...
```

**关键设计**：
1. 兄弟目录式布局使 ConfigService.TryFindExeUnderBase 自动发现 `..\Api\` 与 `..\Admin\`
2. 启动脚本采用 ASCII 文件名（`start.bat` / `stop.bat`）避免 Windows + PowerShell Compress-Archive 中文文件名编码问题
3. 升级新版本时仅需覆盖压缩包内的文件，目录名不变

### 2.3 启动脚本规范（v2.13.184 修订 — ASCII 文件名）

> **注意**：脚本采用 ASCII 文件名（`start.bat` / `stop.bat`）而非中文文件名，避免 PowerShell `Compress-Archive` 在某些环境下的 UTF-8 编码问题。

#### `start.bat`

```batch
@echo off
chcp 65001 >nul
setlocal
set "ROOT=%~dp0"
set "TRAY_DIR=%ROOT%TrayApp"
set "TRAY_EXE=%TRAY_DIR%\DormManage.TrayApp.exe"

echo ========================================
echo   金智住宿管理系统 v2.13.184
echo ========================================
echo.

if not exist "%TRAY_EXE%" (
    echo [ERROR] 找不到托盘程序：%TRAY_EXE%
    echo 请确认 zip 包解压完整，包含 TrayApp\ 目录。
    pause
    exit /b 1
)

echo [1/3] 正在启动托盘守护进程...
start "" /D "%TRAY_DIR%" "%TRAY_EXE%"
timeout /t 3 /nobreak >nul
echo [2/3] 托盘进程已启动，正在拉起 Web/Api 服务...
timeout /t 2 /nobreak >nul
echo [3/3] 启动完成！托盘图标已在系统托盘中显示。
echo.
echo - 右键托盘图标可查看状态 / 注册 / 退出
echo - 管理后台地址: http://localhost:5001
echo - API 接口地址: http://localhost:5100
echo.
echo 注意：根据 v2.13.184 强托管规则，禁止直接双击 Admin.exe 或 Api.exe
echo       所有服务必须由托盘进程拉起。
pause
endlocal
```

#### `stop.bat`

```batch
@echo off
chcp 65001 >nul
echo 正在停止金智住宿管理系统...
taskkill /IM "DormManage.Admin.exe" /F 2>nul
taskkill /IM "DormManage.Api.exe" /F 2>nul
taskkill /IM "DormManage.TrayApp.exe" /F 2>nul
echo 已停止所有服务。
timeout /t 2 /nobreak >nul
```

## 三、发布流程（v2.13.184 标准化 — 唯一整合包）

> **重要**：每次发版**只**生成 1 个整合包。**禁止**额外生成各组件独立 zip。

```powershell
# === Step 1: Release 构建 ===
dotnet build DormManage.sln -c Release --no-restore

# === Step 2: Publish 三个组件到 release/latest/ ===
dotnet publish DormManage.Admin/DormManage.Admin.csproj -c Release -r win-x64 --self-contained true -o release/latest/Admin
dotnet publish DormManage.Api/DormManage.Api.csproj -c Release -r win-x64 --self-contained true -o release/latest/Api
dotnet publish DormManage.TrayApp/DormManage.TrayApp.csproj -c Release -r win-x64 --self-contained true -o release/latest/TrayApp

# === Step 3: 组件目录直接用稳定名（兄弟目录式）===
# 无需重命名，dotnet publish 输出已直接使用 stable 目录名：
# release/latest/Admin、release/latest/Api、release/latest/TrayApp
#（v2.13.184 修订：组件目录名不带版本号后缀）

# === Step 4: 在 TrayApp 内创建兄弟目录（Admin + Api）===
Copy-Item -Recurse release/latest/Admin  release/latest/TrayApp/Admin
Copy-Item -Recurse release/latest/Api    release/latest/TrayApp/Api

# === Step 5: ⭐ 重写 TrayApp appsettings.json — 关键步骤（v2.13.184 强化）===
# 原因：dotnet publish 直接复制源码项目中的 appsettings.json，可能含开发机绝对路径
# 必须改写为相对路径引用兄弟目录，让生产机器无需任何配置即可正确找到子进程
$cfgPath = "release/latest/TrayApp/appsettings.json"
$cfg = Get-Content $cfgPath -Raw | ConvertFrom-Json
$cfg.Tray.ApiExecutable    = "..\Api\DormManage.Api.exe"
$cfg.Tray.AdminExecutable  = "..\Admin\DormManage.Admin.exe"
$cfg | ConvertTo-Json -Depth 10 | Set-Content $cfgPath -Encoding UTF8

# === Step 6: 创建唯一整合包（兄弟目录式）===
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
Compress-Archive -Path "release/latest/TrayApp/*" `
                  -DestinationPath "release/_archive/DormManage-v2.13.XXX_$ts.zip" -Force

# === Step 7: 验证 ===
# 1. _archive/ 中该版本仅 1 个 zip
Get-ChildItem release/_archive | Where-Object { $_.Name -match "v2.13.XXX" }
# 2. 不应出现: DormManageAdmin-v2.13.XXX*.zip / DormManageApi-v2.13.XXX*.zip / DormManageTrayApp-v2.13.XXX*.zip
# 3. zip 内 TrayApp/appsettings.json 中 ApiExecutable/AdminExecutable 必须是相对路径（不含绝对路径如 C:\ 或 E:\）
Expand-Archive "release/_archive/DormManage-v2.13.XXX_$ts.zip" -DestinationPath /tmp/verify -Force
Select-String -Path "/tmp/verify/TrayApp/appsettings.json" -Pattern "ApiExecutable|AdminExecutable"
# 4. 端到端：解压 zip → 双击 启动程序.bat → 验证 TrayApp 拉起 Api(:5100) + Admin(:5001)
```

### 3.1 为什么必须唯一整合包？

| 反例（禁止） | 危害 |
|-------------|------|
| 同时提供整合包 + 独立 Admin zip | 运维可能误用 Admin zip 单独部署 → 违反 v2.13.155 强托管规则（独立 Admin 启动应被 `[TRAY-GUARD]` 拒绝，但用户可能跳过该 zip 而直接双击老版本） |
| 仅提供独立包（无整合包） | 部署需运维手动复制 3 个目录 → 路径配置易出错 → 与强托管脱钩 |
| 整合包 + TrayApp 单独 zip | TrayApp 单独运行 + 错误 Api/Admin 路径 → 启动失败 |

### 3.2 ⭐ TrayApp appsettings.json 强制重写规则（v2.13.184 实测发现）

> **真实事故**：v2.13.184 初次发布时，`appsettings.json` 沿用了开发机的绝对路径（`E:\...\DormManage.Api\bin\Debug\net8.0\...`），导致生产机器启动后 TrayApp **找不到** Api/Admin 子进程（用户报告「启动托盘后 web 及 api 程序不存在」）。

**根因**：`dotnet publish` 直接复制源代码目录的 `appsettings.json`，里面写死的开发机绝对路径带到生产环境**必然失效**。

**强制规则**：

| # | 规则 | 说明 |
|---|------|------|
| 1 | **必须**在 Step 5 中**重写** `appsettings.json` 的 `ApiExecutable` 和 `AdminExecutable` 字段 | 将绝对路径改为相对路径引用兄弟目录 |
| 2 | 路径格式必须是 `..\Api\DormManage.Api.exe` 与 `..\Admin\DormManage.Admin.exe` | `..` 指向 `release/latest/`，组件目录名**不带版本号**（v2.13.184 修订） |
| 3 | **禁止**使用绝对路径（含 `C:\`、`E:\`、`/home/` 等） | 跨机器部署必然失效 |
| 4 | 重写后必须用 `Select-String` 验证路径正确性 | 见 Step 7 第 3 步 |
| 5 | 验证后必须做端到端启动测试 | 见 Step 7 第 4 步（解压 zip → 启动 TrayApp → Api(:5100) + Admin(:5001) 监听） |

**ConfigService 兜底机制（即使配置错误也能自愈）**：

`ConfigService.AutoHealPathsIfInvalid()` 在启动时检测 `ApiExecutable` / `AdminExecutable` 是否存在：
- **存在** → 使用配置路径（不修改）
- **不存在** → 自动用 `TryFindExeUnderBase()` 探测候选路径列表，写回配置文件
- **仍找不到** → 输出 ERROR 日志（用户需检查）

候选路径优先级详见 §五「路径自动修复」。

## 五、路径自动修复（v2.13.157 + v2.13.184 增强）

### 4.1 候选路径探测顺序（ConfigService.TryFindExeUnderBase — v2.13.184 修订）

新目录结构（组件名不带版本号）下的探测顺序（共 9 项，原 13 项精简）：

| # | 路径格式 | 适用场景 |
|---|---------|---------|
| 1 | `BaseDirectory/<exe>` | all-in-one 单目录部署 |
| 2 | `BaseDirectory/Api/<exe>` | dev mode 嵌套目录 |
| 3 | `BaseDirectory/Admin/<exe>` | dev mode 嵌套目录 |
| 4 | `BaseDirectory/../Api/<exe>` | v2.13.184 发布版（兄弟目录） |
| 5 | `BaseDirectory/../Admin/<exe>` | v2.13.184 发布版（兄弟目录） |
| 6 | `BaseDirectory的父目录/Api/<exe>` | dev mode 父目录 |
| 7 | `BaseDirectory的父目录/Admin/<exe>` | dev mode 父目录 |
| 8 | `工作目录/Api/<exe>` | 工作目录兜底 |
| 9 | `工作目录/Admin/<exe>` | 工作目录兜底 |

### 4.2 版本号动态提取（v2.13.184 修订 2 — 非必须）

`ExtractVersionTagFromPath()` 从 BaseDirectory 路径中动态提取版本标签：

| BaseDirectory | 提取结果 | 说明 |
|---------------|---------|------|
| `release/latest/TrayApp/` | ``（空字符串）| 新标准：目录名无版本后缀 |
| `release/latest/TrayApp-v2.13.XXX/` | `v2.13.XXX` | 兼容旧版本（已不再使用） |

> **注意**：该函数在新标准下已降级为非必须，因为 appsettings.json 中写死的相对路径 `..\Api\` 和 `..\Admin\` 不包含版本号，ConfigService 自动探测时直接匹配这些稳定目录名。
