## 1. 背景

V1.0 测试版交付后，Web 管理端（DormManage.Admin，端口 5200）多个核心页面访问返回 **HTTP 500**，无法打开：
- 首页 `/`
- 办理登记 `/Booking`
- 住宿管理 `/Dorms`
- 费用标准 `/BillingStandard`
- 抄表记录 `/Meter`（附带发现）

编译状态为 **0 错误**，故属运行时错误。本次通过实际启动服务、逐页复现、抓取异常堆栈，定位并修复全部根因。

## 3. 根因清单与修复

### BUG #1：Admin 项目未注册任何应用服务（DI 解析失败）✅ 已修复
- **症状**：`InvalidOperationException: Unable to resolve service for type 'IBookingService' / 'IBasicsService'`
- **根因**：`DormManage.Admin/Program.cs` 仅注册了 `DormDbContext` 与 `AddRazorPages()`，完全遗漏业务服务注册；而 `DormManage.Api/Program.cs` 已正确注册。两个站点为独立进程，DI 容器不共享。
- **影响页面**：`/Booking`、`/Booking/Edit`、`/Dorms`、`/Dorms/Create`、`/Dorms/Edit`（共 5 个注入点）
- **修复**：`DormManage.Admin/Program.cs` 补齐 4 行服务注册
  ```csharp
  builder.Services.AddScoped<IBasicsService, BasicsService>();
  builder.Services.AddScoped<IBookingService, BookingService>();
  builder.Services.AddScoped<IPersonnelService, PersonnelService>();
  builder.Services.AddScoped<IDormService, DormService>();
  ```

### BUG #2：DormBooking.Type 列名映射缺失 ✅ 已修复
- **症状**：`SqlException: 列名 'Type' 无效`（首页 OnGetAsync:104）
- **根因**：模型属性 `DormBooking.Type`，实际 DB 列名为 `BookingType`，DbContext 未做列名映射。
- **修复**：`DormDbContext.cs` DormBooking 实体配置增加 `entity.Property(e => e.Type).HasColumnName("BookingType")`

### BUG #3：DormBooking.Type / Status 类型不匹配（Byte→Int32）✅ 已修复
- **症状**：`InvalidCastException: Unable to cast object of type 'System.Byte' to type 'System.Int32'`（首页、办理登记列表）
- **根因**：DB 列 `BookingType`、`Status` 为 `tinyint`（byte），模型属性为 `int`，EF 读取时按 int 取值抛异常。
- **修复**：DbContext 对两列声明 `.HasColumnType("tinyint")`，EF 按 byte 读取并转 int。

### BUG #4：BillingStandard 表不存在 ✅ 已修复
- **症状**：`SqlException: 对象名 'BillingStandard' 无效`
- **根因**：EF 模型与 DbSet 已定义 BillingStandard，但生产/测试 DB 从未建表（DDL 与 v2.12.42 修复脚本均未覆盖）。
- **修复**：新增幂等脚本 `01-Database/_create_billingstandard_v1243.py`，建表 + 3 条种子数据（合同工/临时工/外包水电气单价）；DbContext 增加 fluent 配置并补 `HasPrecision(10,2)`（消除 decimal 静默截断警告）。

### BUG #5：MeterRecord 缺失审计字段列 ✅ 已修复
- **症状**：`SqlException: 列名 'CreatedAt' / 'IsActive' / 'UpdatedAt' 无效`（抄表 OnGetAsync:90）
- **根因**：模型继承 `BaseEntity`（含 CreatedAt/UpdatedAt/IsActive），但 MeterRecord 表建表时遗漏这三列，与其它实体表（Dorm/DormBooking/SysEmployee/Team 均有）不一致。
- **修复**：`_create_billingstandard_v1243.py` 为 MeterRecord 表补齐 `CreatedAt / UpdatedAt / IsActive`，统一 BaseEntity 审计字段规范。

### BUG #6：Dorm 模型缺 RoomCount 属性（数据静默丢弃）✅ 已修复
- **症状**：新增/编辑住宿时用户填写的"房间数"被静默丢弃，DB 恒为默认值。
- **根因**：DB 表已有 `RoomCount` 列、`DormCreateDto/DormEditDto` 已声明该字段、表单已绑定，但 EF 模型 `Dorm` 缺少 `RoomCount` 属性，构造/更新时未赋值。
- **修复**：`Dorm.cs` 增加 `RoomCount` 属性；`Create.cshtml.cs`、`Edit.cshtml.cs` 补齐读取/持久化赋值。

### BUG #7：详情/编辑页路由模板不匹配（导航 404）✅ 已修复
- **症状**：列表页点击"详情/修改/编辑"跳转 404。
- **根因**：列表链接为路径式 `/Dorms/Details/{id}`，但目标页 `@page`（无路由参数，仅认查询串），与 History、Booking/Edit 已有的 `@page "{id:int}"` 约定不一致。
- **修复**：统一 `Dorms/Details`、`Dorms/Edit`、`BillingStandard/Edit` 的 `@page` 为 `@page "{id:int}"`，路由规范全站对齐。

### BUG #8：住宿详情住宿历史时间线显示 undefined ✅ 已修复
- **症状**：详情页"查看住宿历史"所有字段显示 undefined。
- **根因**：JS 模板按 camelCase 读取（`r.checkInDate` 等），.NET 8 `Json.Serialize` 默认输出 PascalCase。
- **修复**：改用 `System.Text.Json.JsonSerializer.Serialize(..., new JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase })`。

## 8. 遗留项补充修复（R1–R5）

### 8.0 根因升级：Admin 前端 `/api/v1/*` 调用无法路由
排查 R1 时发现更深根因：`DormManage.Admin` **不引用 Api 项目、无 Controllers、无 MapControllers、无代理**，而前端 JS 全部以相对路径 `/api/v1/bookings/...` 调用（落到 Admin 源 5200）。因此办理登记的所有操作按钮（含 check-in/employee-search）均 404，不止缺失的 4 个。

**修复方案（自包含）**：Admin 引用 `DormManage.Api` 项目，通过 `AddControllers().AddApplicationPart(...)` + `MapControllers()` **进程内自托管全部 5 个 API 控制器**（Basics/Booking/Dorms/Meter/Personnel）。Admin UI 的所有 `/api` 调用在进程内闭环，不依赖独立 Api（5100）进程；独立 Api 仍供 PDA/移动端使用。

### 8.1 R1：办理登记 5 个操作端点
- 新增 Service 方法 `ConfirmReservedCheckOutAsync`（v2.11.12：Type=2 && Status=1 → Status=3）
- `BookingController` 补齐 5 个 POST 端点：
  | 端点 | 语义 | Service 方法 |
  |------|------|------|
  | `{id}/confirm-checkin` | 快速确认入住 v2.11.8 | ConfirmCheckInAsync |
  | `{id}/undo-checkout` | 撤销退房 v2.11.10 | UndoCheckOutAsync |
  | `{id}/cancel-reservation` | 撤销预约 v2.11.11 | CancelReservationAsync |
  | `{id}/confirm-checkout` | 确认预约退房 v2.11.12 | ConfirmReservedCheckOutAsync（新增） |
  | `{id}/cancel-today` | 撤销在宿 v2.11.17 | CancelTodayAsync |
- **验证**：不存在 id 返回 `{"success":false,"code":"NOT_FOUND"}`（200，正确路由，非 404）。

### 8.2 R2：撤销在宿按钮
- `Booking/Index.cshtml` 操作列新增按钮：`Type=1 && Status=2 && BookingDate=今天` 时显示"撤销在宿"，调用 `cancelToday()` → `/cancel-today`。

### 8.3 R3：在宿状态枚举口径统一
- 06 文档（v2.10 DormResidency）头部新增"状态口径变更说明"，标注其 `Status=1 在宿` 语义已被 07 办理登记（DormBooking）取代；现行权威口径：`Type` 1=入住/2=退房，`Status` 1=预约/2=在宿/3=已退房/4=已取消，当前在住 = `Type=1 && Status=2`。依 CLAUDE.md §2.1.1「最新需求文档优先」。

### 8.4 R4：全局 camelCase JSON
- Admin 与 Api 的 `AddControllers().AddJsonOptions(...)` 均设 `PropertyNamingPolicy = CamelCase`。
- **验证**：`employee-search` 返回 `{"realName":"李信伟","employeeCode":"JG002723",...}`，前端 `e.realName` 正常取值（原 undefined 修复）。

### 8.5 R5：BillingStandard.IsActive 重构
- 移除 `public new bool IsActive`，直接继承 `BaseEntity.IsActive`，消除 EF 双属性映射隐患。
