## 2. 设计哲学与原则

### 2.1 三大核心原则

#### 原则 1：**数据先行 ≠ UI 就绪**（v2.13.187 教训）

> 数据库已 seed 的字段，必须在 Razor 模板中调用 `IsFieldHiddenAsync()` 才能真正生效。
> 否则数据层声明了「这是隐私字段」，UI 层却忽视该声明，依然按老规则渲染 → 隐私保护失效。

#### 原则 2：**deny-by-default + OR-across-roles**（v2.13.176 + v2.13.185）

> 「允许显示隐私字段」为「角色级总开关」，未勾选 = 全部隐藏；勾选 = 全部可见。
> 多角色语义：用户任一角色勾选即视为拥有该权限。
> 实现：`Distinct()` + `SysPermissions × SysRolePermissions × SysUserRoles` 三表 JOIN 自然实现。

#### 原则 3：**文档"隐含"≠ 实际完成**（v2.13.187 + v2.13.191 教训）

> v2.13.169 文档设计的 RegStatus 拆分：文档先于实现 → untracked 文件夹 → 发布包丢失 → 用户功能失效。
> 任何文档提到的新功能必须有对应的：
> ① 代码实现完成
> ② 编译通过（0 error）
> ③ 端到端测试矩阵验证
> ④ 发布包确实包含实现

### 2.2 UI 设计哲学

#### 哲学 A：**最小化原则**（v2.13.183 + v2.13.189 演进）

| 维度 | 原则 |
|------|------|
| **按钮** | 列表行内禁止彩色 / 带 icon 按钮，只用纯文字 `.op-btn` |
| **图标** | 列表行内禁止 icon（占用空间且无法控制大小），仅页面头部使用 |
| **字段** | 长字段强制 `text-truncate` + `title`，避免表格变形 |
| **行数** | 列表每行强制一行：`white-space: nowrap` |
| **列宽** | 固定列宽，列宽由表头 `width` 决定（`table-layout: fixed`）|

#### 哲学 B：**单一数据源原则**（v2.13.188 + 统一的设计规范）

> 所有字段显示必须 JOIN 真源表（如 `SysEmployee.Gender`、`SysUser.LastLoginIp`），禁止使用冗余快照字段。

#### 哲学 C：**操作链路完整性原则**（v2.13.191 教训）

> 数据链路必须 4 层完整：
> ① DTO 字段定义
> ② 端点方法实现
> ③ Controller 序列化映射
> ④ 前端 badge 显示逻辑
> 缺一层 = 链路断裂。

## 6. 调用链路

### 6.1 隐私字段权限调用链路（v2.13.187）

```
user → /Dorms → Razor 渲染 → Html.IsFieldHiddenAsync("dorm.capacity")
                                  ↓
                              HttpContext.Items 缓存
                                  ↓
                              PermissionService.GetHiddenFieldKeysAsync(userId)
                                  ↓
                              GetUserPermissionCodesAsync(userId)
                                  ↓
                              三表 JOIN (SysPermissions × SysRolePermissions × SysUserRoles)
                                  ↓
                              检查 codes.Contains("privacy:field:enable")
                                  ↓
                              真 → 不隐藏；假 → 隐藏字段集合返回
                                  ↓
                              页面渲染时 column 通过 d-none CSS 隐藏
```

### 6.2 注册状态同步链路（v2.13.191）

```
托盘 TrayAppContext.HandleGetRegState
    ↓ ReadRegValue(CDKEY/LTDName/RegDate)
    ↓ RegisterSdk.CheckReg() → reg.RegInt ∈ {-1, 0, 1}
    ↓ LicenseGuard.ConvertRegIntToRegStatus(reg.RegInt) → regStatus ∈ {-1, 1, 2, 3}
    ↓ 序列化 ServiceIpc.RegStateDto { RegInt, RegStatus, ... }
    ↓ IPC TCP :5099 响应 Web Admin
    
Web Admin LicenseGuard.GetCachedStateAsync
    ↓ 进程内 30s 缓存（避免每 HTTP 请求都调 IPC）
    ↓ LicenseGuard.GetLicenseBanner() → (code, message, level)
    ↓ 5 case 覆盖

Web LicenseStatusController.GetLicenseStatus
    ↓ return Ok(ApiResponse.Ok({ status: state.RegStatus, code, message, level, ... }))

前端 license-status-badge.js (30s 轮询)
    ↓ renderLevel({ status: 1, level: 'success', ... })
    ↓ paintBadge → 显示「已注册」绿色徽章
```

## 11. 永久教训

### 11.1 数据与 UI 一致性

> DB seed 21 字段但 Razor 模板只接 2 字段 → 用户期待隐私保护实际失效。
> **强制规则**：每增加一个 `SysFieldPermission` 字段，必须在 24h 内完成所有引用页面的 `IsFieldHiddenAsync()` 接线 + E2E 测试。

### 11.2 设计先于实现的危险

> v2.13.169 的 RegStatus 拆分：文档先写好，代码 untracked 留到版本 22 后才实装。
> **强制规则**：任何文档中的"新设计"必须同步在文档归档前完成代码合入 + 编译通过，不允许 untracked 文件夹漂移。

### 11.3 临时禁用编译 = 隐藏 BUG

> v2.13.190 为完成发布，将 `LicenseStatusController.cs` 重命名为 `.disabled` 排除编译。
> **强制规则**：禁用编译只能是临时调试手段，不能跨版本遗留；发布前必须恢复或修复原编译错误。

### 11.4 UI 一致性的工程价值

> 用户管理面板与角色管理页面的对齐：用户明确要求"按角色管理页面风格统一"。
> **强制规则**：所有列表页 UI（页头按钮、操作列、字段截断）必须有统一样式规范，新页面必须按规范落地，不再允许 ad-hoc 样式。

### 11.5 数据链路 4 层完整性

> 注册状态从托盘到前端：DTO → IPC → LicenseGuard → Controller → Badge。
> 任何一层缺失都导致链路断裂（如 v2.13.191 的 RegStatus 字段缺失）。
> **强制规则**：每次设计新功能必须 4 层完整检查清单（DB / Model / Controller / View）。
