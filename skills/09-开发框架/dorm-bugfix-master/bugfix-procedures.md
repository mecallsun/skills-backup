# 标准 BUG 修复流程（7 步法）

> Skill: dorm-bugfix-master
> 创建日期：2026-07-28
> 基于 v2.13.187-193 全部 BUG 修复经验整理

---

## 概述

本流程是 DormManage 项目 BUG 修复的**标准操作流程**。
任何 BUG 修复都应按此 7 步进行，避免遗漏关键步骤（如发布同步、跨权限测试、文档归集）。

---

## 7 步流程

### 步骤 1：确认症状（用户原话）

**目标**：准确理解用户报告的 BUG

**操作**：
- 直接引用用户原话（不要二次转述）
- 记录复现步骤：操作 → 预期 → 实际
- 记录 BUG 出现的环境：浏览器、URL、用户角色

**反模式**：
- ❌ "好像有 BUG"（无具体复现）
- ❌ "改一下试试"（无明确症状）

**模板**：
```
症状：用户报告"......"（原话）
复现步骤：1) ... 2) ... 3) ...
预期：...
实际：...
环境：用户角色=xxx，浏览器=xxx
```

---

### 步骤 2：复现 BUG

**目标**：确认 BUG 真实存在且可复现

**操作**：
- 在自己的环境中重现
- 用 curl 模拟用户请求
- 必要时用 Diag 工具（如 `tmp/DiagPassword/`）验证

**关键点**：
- 如果 BUG 不可复现 → 直接问用户更多细节
- 复现成功 → 进入步骤 3

---

### 步骤 3：5 步深度排查（methodology）

按 5 步排查定位 BUG 所在层（参见 `methodology.md`）：

1. **源码层确认**：`grep -c "关键字" source.cs`
2. **编译层确认**：`dotnet build`
3. **发布时间戳确认**：`stat -c '%y' release/latest/Admin/DormManage.Admin.dll`
4. **DLL 内容确认**：注意 .NET 中文字符串是 UTF-16 LE 编码
5. **运行环境确认**：TrayApp 加载的是哪个目录的 DLL

**关键点**：
- 95% 的 BUG 能在前 3 步找到
- 第 5 步最容易遗漏（发布路径问题）

---

### 步骤 4：定位根因

**目标**：找到 BUG 产生的根本原因

**根因类型**：
| 根因类型 | 案例 | 解决方案 |
|---------|------|---------|
| 数据先行 ≠ UI | v2.13.187 | 必须同步接线 |
| 文档先行 ≠ 代码 | v2.13.176 翻转 | 必须同步 commit |
| 发布路径 ≠ 运行路径 | v2.13.193 双胞胎 | sync 脚本 |
| 临界日期 `>` 应为 `>=` | v2.13.193 有效期 | 修正判断 |
| datetime-local 用户场景不符 | v2.13.193 有效期 | 改用 date |
| TypeLoadException | v2.13.193 Shared | sync DLL |

**关键点**：
- 区分"症状"和"根因"
- 5 个症状可能来自 1 个根因
- 1 个根因可能引发 5 个症状

---

### 步骤 5：设计修复方案

**目标**：设计最小变更修复方案

**设计原则**：
- ✅ **最小变更**：只改需要改的代码
- ✅ **统一助手函数**：3 处独立实现改为 1 个统一函数
- ✅ **语义清晰**：方法名要反映真实行为
- ✅ **向后兼容**：保持接口和数据库兼容

**修复方案清单**：
- [ ] 改动的源文件清单
- [ ] 数据库 schema 变更（如需）
- [ ] API 变更（如需）
- [ ] 配置变更（如需）
- [ ] 文档更新清单

---

### 步骤 6：实施修复

**目标**：安全实施修改

**操作**：
1. 先备份（git stash 或 cp 备份）
2. 修改代码
3. 编译 0 错误
4. 立即 `git diff` 确认修改已保存
5. 跨权限测试（admin + 未授权角色）
6. 用 sync 脚本发布

**关键检查点**：
- ✅ Edit 后立即 `git diff`
- ✅ 编译 0 错误
- ✅ 跨权限测试
- ✅ 真实数据验证（不是 HTTP 200 就信）

---

### 步骤 7：验证 + 文档 + 发布

**目标**：完成端到端验证并归集文档

**验证清单**：
- [ ] 编译 0 错误
- [ ] 跨权限测试通过
- [ ] 真实数据验证
- [ ] DLL 时间戳最新
- [ ] 兄弟目录同步

**文档清单**：
- [ ] 00-方案文档/XXX-BUG修复描述-v2.13.X.md
- [ ] 00-方案文档/232-BUG解决经验与防错指南（如果新类别）
- [ ] skills/dorm-bugfix-master/known-bugs.md（更新案例库）
- [ ] CLAUDE.md（Important Notes 段落）

**发布清单**：
- [ ] 完整发布三个项目到 release/latest/
- [ ] 用 sync 脚本同步到 TrayApp 兄弟目录
- [ ] 打包 ZIP 到 release/_archive/
- [ ] 验证 md5 一致

## 快速参考：按 BUG 类别选流程

| BUG 类别 | 关键步骤 | 工具 |
|---------|---------|------|
| 发布/部署问题 | 步骤 3.3 + 3.5 | sync 脚本 |
| 隐私/权限 | 步骤 3.1 + 步骤 4 语义检查 | 跨权限测试 |
| UI 不一致 | 步骤 4 + 步骤 5 UI 规范 | grep 模式 |
| 编译错误 | 步骤 3.2 + 步骤 4 字符串检查 | dotnet build |
| 数据/业务 | 步骤 4 + 步骤 6 真实验证 | Diag 工具 |
| 部署/运行 | 步骤 3.5 + 步骤 6 真实启动 | 进程检查 |

## 反模式（必须避免）

| 反模式 | 案例 | 正确做法 |
|--------|------|----------|
| "改一下试试" | 盲目修改 | 先复现+根因 |
| "看似好了" 不测跨权限 | admin OK 但 test 仍可见 | 强制 2 角色测试 |
| 只看 HTTP 200 | API 返回 success 但 hash 未变 | 真实数据验证 |
| 单独 `dotnet publish` | 漏 sync 兄弟目录 | 必用 sync 脚本 |
| "文档先行" | 文档改但代码没改 | 文档+代码同 commit |
| 多次实现 | 3 处 ExpiresAt 独立写 | 统一助手函数 |
| 不写文档 | 修完不归集 | 必建文档 + 更新索引 |
| 不记录教训 | 修复后无沉淀 | 写教训到 known-bugs |

## 流程示例：v2.13.193 隐私字段修复

```
步骤 1: 用户报告"未授权角色仍能看到容量、在住人数"
步骤 2: 用 test:test 用户复现，确认 BUG
步骤 3: 
  3.1 grep IsFieldHiddenAsync → 6 处存在
  3.2 dotnet build → 0 错误
  3.3 stat DLL → 最新
  3.4 python3 UTF-16 LE → 含 性别
  3.5 ps -W → TrayApp 加载 release/latest/TrayApp/Admin/ → 找到！

步骤 4: 根因
  - 5 处 IsFieldHiddenAsync 调用，但 deny-by-default 未实施
  - v2.13.176 文档说"不勾选 → 隐藏"，但代码说"不勾选 → 显示"

步骤 5: 设计修复
  - 重命名 HasPrivacyFieldEnabledAsync → AllowDisplayPrivacyFieldsAsync
  - 逻辑反转：不勾选 → 隐藏
  - 不改表结构

步骤 6: 实施
  - PermissionService.cs 修改
  - 编译 0 错误
  - git diff 确认
  - 跨权限测试：admin 看得到，test 看不到

步骤 7: 验证+文档+发布
  - curl test:test 用户 → /Dorms → 含 22 个 d-none
  - 创建 226/231 文档
  - 更新 CLAUDE.md
  - sync 脚本发布
  - ZIP 包 330MB
```

## 紧急 BUG 流程

如果是 🔴 P0 紧急 BUG：
1. **立即停止发布**（如果有未发布修改）
2. **快速 patch**：最小变更修复
3. **快速测试**：只测核心功能
4. **快速发布**：用 sync 脚本紧急发布
5. **延后详细文档**：先用 commit message 记录，后续补完整文档
