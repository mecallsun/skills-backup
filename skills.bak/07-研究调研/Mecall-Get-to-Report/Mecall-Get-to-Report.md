# Mecall-Get-to-Report

## 研究报告生成技能 (Research-to-Report Skill)

### 技能概述

本技能用于将网络搜索、信息收集、深度研究与HTML报告生成整合为完整的端到端流程。适用于生成企业战略咨询报告、行业分析报告、投资研究报告等专业文档。

---

## 一、核心方法论

### 1.1 信息获取方法

| 渠道类型 | 获取方法 | 适用场景 |
|---------|----------|----------|
| **官方披露** | 招股说明书（注册稿/申报稿）、监管公告、企业公告 | 公司工商信息、财务数据、股权结构 |
| **监管平台** | 北交所官网、证监会官网、全国股转系统 | IPO进度、审核问询函 |
| **工商查询** | 天眼查(qcc.com)、企查查(qixin.com)、国家企业信用信息公示系统 | 法人、注册资本、股东信息 |
| **金融数据** | 东方财富网、同花顺、巨潮资讯网 | 股票代码、财务指标、股东户数 |
| **行业研究** | 头豹研究院、国金证券研究所、智研咨询 | 市场规模、竞争格局、行业数据 |
| **新闻资讯** | 百度百科、公司官网、媒体报道 | 企业动态、发展历程、团队信息 |
| **网络搜索** | tavily_search（高级搜索） | 实时信息补充验证 |

### 1.2 数据验证原则

```
验证层级优先级（从高到低）：
┌─────────────────────────────────────────────────────────┐
│ 1. 官方核实（官方核实）：招股说明书、监管文件           │
│    → 高可信度，直接引用                                 │
├─────────────────────────────────────────────────────────┤
│ 2. 企业自报（企业自报）：企业公告、官网披露             │
│    → 中等可信度，标注来源                               │
├─────────────────────────────────────────────────────────┤
│ 3. 推断（推断）：行业研究报告、分析推理                 │
│    → 参考性信息，需标注"推断"                           │
├─────────────────────────────────────────────────────────┤
│ 4. 待核实（待核实）：未能确认的信息                     │
│    → 需进一步查证，明确标注                             │
└─────────────────────────────────────────────────────────┘
```

```
标准章节架构（10章结构）：

│   ├── 1.1 发展历程时间线

├── 第三章：竞争格局与核心优势
```

## 二、标准操作流程 (SOP)

### 阶段一：信息采集与研究

```
步骤 1.1：基础信息搜索
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
输入：企业名称 + "招股说明书/工商信息/组织架构"
工具：tavily_search (max_results=15, search_depth=advanced)
输出：招股说明书PDF、监管问询函、企业工商信息

步骤 1.2：深度网络检索
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
输入：企业全称 + 管理人员姓名
工具：tavily_search (多次搜索，关键词组合)
重点：董事会成员、高管团队、股权结构

步骤 1.3：行业数据收集
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
输入：行业名称 + "市场规模/竞争格局/驱动因素"
工具：tavily_research (全面研究)
输出：行业分析数据、竞争对手信息
```

### 阶段二：报告生成

```
步骤 2.1：建立基础模板
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
输入：V11.0或历史版本HTML文件（参考样式）
操作：
  1. 读取原HTML的CSS样式（550+行）
  2. 提取章节结构（9-10章）
  3. 复制样式到新文件

步骤 2.2：构建报告骨架
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
输出文件结构：
  ├── <head>：元数据 + CSS样式（从模板复制）
  ├── <cover>：深蓝色渐变封面
  ├── <topnav>：顶部导航菜单
  ├── <main>：报告正文
  │   ├── 执行摘要（KPI指标卡）
  │   ├── 十章内容
  │   └── 附录
  └── <footer>：页脚版权信息
```

### 阶段三：内容填充

```
步骤 3.1：执行摘要设计
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
组件：4个metric-card指标卡
  - 称号/资质（如：专精特新小巨人）
  - 营收/净利润
  - IPO状态
  - 核心优势

步骤 3.2：章节内容编写
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
原则：
  1. 每章包含概述段落
  2. 使用card组件组织内容
  3. 关键数据标注来源badge
  4. 避免重复，使用交叉引用

步骤 3.3：数据来源标注
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
格式：<span class="sourcebadge official">官方核实</span>
类型：official / company / inference / unverified
位置：章节标题右侧
```

### 阶段四：UI优化迭代

```
步骤 4.1：版本命名规范
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
格式：V{X}.0_{风格}版.html
示例：V15.0_标准版.html

步骤 4.2：顶部菜单优化
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
原则：
  1. 菜单名称精简为2-4字
  2. 避免换行
  3. 使用章节主题而非"第X章"

步骤 4.3：样式调整
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
常见优化项：
  - 指标卡横向排列（flex布局）
  - 删除敏感词（麦肯锡→标准）
  - 修复重复文字（标准标准→标准）
  - 删除版本号标识
```

## 四、数据来源Badge规范

| Badge | 含义 | 使用场景 |
|-------|------|----------|
| `official` | 官方核实 | 招股说明书、监管文件、工商数据 |
| `company` | 企业自报 | 企业公告、官网信息 |
| `inference` | 推断 | 行业分析、市场估算 |
| `unverified` | 待核实 | 未能确认的信息 |

## 五、敏感词处理规范

| 敏感词 | 替换词 | 原因 |
|--------|--------|------|
| 麦肯锡 | 标准 | 避免特定公司名称 |
| V14.0 | 删除 | 版本号不需显示 |
| 审慎推荐 | 删除 | 投资评级过于主观 |
| · xxx · | xxx | 去掉末尾多余分隔符 |
